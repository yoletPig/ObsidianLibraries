# 数据库与存储系列教程：从 SQL 语法到手写存储引擎

> 面向以 Python 为主、WSL2/Ubuntu 环境、目标成为**算法工程师**的学习者。库里的分布式系统系列已经把复制、分区、事务的理论建好了；Agent 开发 05 篇的记忆系统要用向量库，量化投资 02 篇的行情数据要落库——但"数据库本体"始终是黑盒：索引为什么快？事务怎么实现的？向量检索凭什么不用扫全表？本系列补上这块工程地基：SQL 能力、索引原理、事务实现（MVCC）、缓存、向量检索，最后一章手写一个 mini KV 存储引擎，把 B+树/LSM/WAL/compaction 全部亲手打通。
> 全系列为中文原创，共 12 章。以 SQLite（Python 自带）和 PostgreSQL 16 为主实验平台，Redis 7 讲缓存与数据结构，所有 SQL/命令在 Ubuntu 直接可跑、输出真实；关键论断标注出处（DDIA 即《数据密集型应用系统设计》、B-tree 原始论文 Bayer & McCreight 1970、LSM 论文 O'Neil et al. 1996、PostgreSQL 官方文档章节）；无法查证的经验一律标注"经验做法"。

### 阶段划分

1. **入门与地基篇（01–02）**：为什么需要数据库、SQL 语言本体。建立动机与最小可用能力——学完就能用 sqlite3 做日常的增删改查与分析查询。
2. **原理篇（03–06）**：索引、事务与 MVCC、执行计划、存储引擎内幕。这是本系列的核心：把"数据库为什么快、为什么对"拆到页、版本链和 LSM 层级，并横向对比 B+树与 LSM 两大流派。
3. **工程实战篇（07–09）**：PostgreSQL 实战、Redis 与缓存、向量数据库。三个真实系统逐一上手，覆盖算法工程师的高频场景：业务库、缓存层、Agent 记忆与语义检索。
4. **综合与闭环篇（10–12）**：手写 MiniKV 存储引擎、数据建模与选型、运维与备份监控。用一个全量代码的综合项目把原理打通，再补上建模方法论和生产运维，最后以面试清单收束。

## 与本仓库其他方向的衔接

- **分布式系统 07/08（事务与隔离级别、分布式事务）= 本系列理论篇的姊妹篇**：04 章讲"单机事务怎么实现"（MVCC、锁、undo/redo），分布式 07 章讲"隔离级别有哪些异常"、08 章讲"跨节点事务怎么活"。两章的并发异常三例互相引用而不重复：那边从异常现象出发，这边从实现机制（版本链/ReadView/vacuum）出发。读完 04 章再回看 2PL 与 SSI 的取舍，会多一层"代价来自哪"的体感。
- **Agent 开发 05（记忆与上下文管理）← 09 章（向量数据库）**：Agent 05 篇说"不要一上来就上向量数据库"，什么时候该上、上了之后怎么建表（embedding 列 + 元数据过滤 + 去重），就是本系列 09 章 HNSW 与 pgvector 实操要补的内容。
- **量化投资 02（数据获取与 Python 工具链）← 11 章（数据建模）**：02 篇抓下来的 OHLCV 行情往哪放、怎么建索引、要不要分区，是 11 章事件表设计的完整实例；08 章的缓存三问也适用于行情 API 的限流与重试场景。
- **数学基础 01 篇 ← 09 章**：余弦相似度、单位向量的几何直觉在数学基础篇建立，09 章用它证明"归一化后内积=余弦=L2 排序"，并解释向量库为什么都假设归一化。
- **操作系统系列 = 本系列的物理地基**：顺序 vs 随机 IO 的数字、页缓存、fsync 的代价（分布式 07 章已演示）在 OS 篇有完整铺垫；06 章的 WAL 与 OS 08 篇崩溃一致性一脉相承。10 章手写引擎的 append+fsync 就是那些概念的直接落地。
- **分布式系统 04（复制）/12（分布式存储案例）**：本系列聚焦单机存储引擎内部；数据怎么复制、怎么分区到多机，是分布式系列的领地。Redis 持久化与分布式系统 12 章 Redis 案例互为补充：这边讲 RDB/AOF 细节，那边讲集群与哨兵。

## 约定

- 平台约定：Ubuntu 22.04+ / WSL2 验证。SQLite 以 Python 内置 `sqlite3` 模块与 `sqlite3` 命令行为主（零安装）；PostgreSQL 以 16.x 为准（`apt install postgresql`）；Redis 以 7.x 为准。三条工具链的安装命令在对应章节首节给出。
- SQL 约定：正文用标准 SQL 语法书写，方言差异随文标注（如 `AUTOINCREMENT` vs `SERIAL` vs `GENERATED ALWAYS AS IDENTITY`、`ON CONFLICT` vs `ON DUPLICATE KEY`）。演示输出以 SQLite 3.37 与 PostgreSQL 16 实测为准，同一查询两库输出不同处会并列展示。
- 代码约定：Python 3.10+。演示依赖标准库（sqlite3/hashlib/struct/os），接入类演示用到 psycopg（v3）/redis-py 时单独注明并给出安装命令；所有代码完整可运行、关键处有中文注释。
- 性能数字约定：文中所有吞吐/延迟数字为编写时 WSL2 环境实测（说明硬件），你的机器必然不同——**关注数量级与相对倍数，不要背绝对值**。
- 引用约定：DDIA 指 Martin Kleppmann《数据密集型应用系统设计》（*Designing Data-Intensive Applications*, 2017）中文版章节号；B-tree 指 Bayer & McCreight, *Organization and Maintenance of Large Ordered Indices* (1970)；LSM 指 O'Neil et al., *The Log-Structured Merge-Tree (LSM-Tree)* (1996)；HNSW 指 Malkov & Yashunin (2016)；SQLite 指官方文档 *How SQLite Works*，PostgreSQL 指官方文档（给出章节号）；经验做法不冒充定论。
- 本系列不使用 Obsidian 双链以外的特殊语法，任何 markdown 阅读器都能正常渲染。
