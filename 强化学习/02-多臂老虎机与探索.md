多臂老虎机（k-armed bandit）是"只有一个状态"的退化 MDP，但**探索-利用这个 RL 的核心矛盾在这里最纯粹**——没有状态转移来搅浑水，每个机制的作用看得清清楚楚。Sutton & Barto 把它放在第 2 章不是没道理的。

## 1. 问题设定：k 臂老虎机与 regret

**问题**：面对 $k$ 台老虎机，每台拉一次有随机奖励，奖励分布未知且固定。反复拉 $T$ 次，最大化总奖励（Sutton & Barto, 2nd ed., §2.1–2.3）。

形式化：每个动作（臂）$a$ 有真实期望 $q_*(a) = \mathbb{E}[r \mid a]$。每一步你只能观察到一个**带噪声的样本** $r \sim \mathcal{N}(q_*(a), 1)$，永远拿不到 $q_*(a)$ 本身。

**遗憾（regret）**是探索问题的量化标尺（单步即时遗憾，Sutton & Barto §2.4 中称 opportunity loss）：

$$\rho_t = q_*(a^*) - q_*(a_t), \qquad a^* = \arg\max_a q_*(a)$$

你选了次优臂，就"遗憾"了它与最优臂的差距。**累计遗憾** $R_T = \sum_{t=1}^T \rho_t$ 是评价 bandit 算法的黄金标准：

- **对数 regret**：$R_T = O(\log T)$——遗憾增长越来越慢，算法最终"锁死"最优臂，这是理论最优阶；
- **线性 regret**：$R_T = O(T)$——算法一直在犯固定比例的错，哪怕比例很小，总量也无限增长。

先造实验床（全章复用，种子固定可复现）：

```python
import numpy as np

class Bandit:
    """k 臂老虎机：每臂奖励 N(q_true[a], 1)，q_true ~ N(0,1) 生成"""
    def __init__(self, k=10, seed=0):
        rng = np.random.default_rng(seed)
        self.q_true = rng.normal(0, 1, k)        # 真实价值，agent 不可见
        self.k = k
        self.rng = np.random.default_rng(seed + 10000)
        self.best = int(np.argmax(self.q_true))  # 最优臂（仅供评估用）

    def step(self, a):
        """拉臂 a，返回一个奖励样本"""
        return self.rng.normal(self.q_true[a], 1.0)

b = Bandit(seed=0)
print("真实价值:", np.round(b.q_true, 3))
print("最优臂:", b.best, " 价值:", round(b.q_true[b.best], 3))
```

运行结果（种子固定）：

```text
真实价值: [ 0.126 -0.132  0.64   0.105 -0.536  0.362  1.304  0.947 -0.704 -1.265]
最优臂: 6   价值: 1.304
```

10 个臂里最优臂价值 1.304，第二优 0.947——差距只有 0.357，而单步奖励噪声 $\sigma=1$。**分辨好坏臂必须靠大量重复采样**，这正是探索困难的根源。

## 2. ε-greedy：最朴素的探索

**策略**：以概率 $\epsilon$ 随机均匀探索，以概率 $1-\epsilon$ 选当前估计值最高的臂（Sutton & Barto, 2nd ed., §2.3）。价值估计用**增量式均值**（增量更新公式，后文 04 章 MC 还会再用一次）：

$$Q_{n+1} = Q_n + \frac{1}{n}\left(r_n - Q_n\right)$$

```python
def run_epsilon_greedy(bandit, steps=2000, eps=0.1, seed=0):
    rng = np.random.default_rng(seed)
    Q = np.zeros(bandit.k)          # 每臂价值估计，乐观初始化为 0
    N = np.zeros(bandit.k)          # 每臂被拉次数
    rewards, regrets = np.zeros(steps), np.zeros(steps)
    for t in range(steps):
        if rng.random() < eps:      # 探索：均匀随机
            a = int(rng.integers(bandit.k))
        else:                       # 利用：贪心
            a = int(np.argmax(Q))
        r = bandit.step(a)
        N[a] += 1
        Q[a] += (r - Q[a]) / N[a]   # 增量式均值
        rewards[t] = r
        regrets[t] = bandit.q_true[bandit.best] - bandit.q_true[a]
    return rewards, regrets, Q, N

rewards, regrets, Q, N = run_epsilon_greedy(b, steps=2000, eps=0.1, seed=0)
print(f"平均奖励(2000步)={rewards.mean():.3f}   理论上限≈{b.q_true.max():.3f}")
print(f"累计 regret={regrets.sum():.1f}")
print("各臂估计 Q:", np.round(Q, 2))
print("真实值 q*:", np.round(b.q_true, 2))
```

运行结果（种子固定，单实例）：

```text
平均奖励(2000步)=1.153   理论上限≈1.304
累计 regret=321.9
各臂估计 Q: [-0.16  0.09  0.63  0.03 -0.42  0.36  1.18  0.92 -0.3  -1.1 ]
真实值 q*:  [ 0.13 -0.13  0.64  0.11 -0.54  0.36  1.3   0.95 -0.7  -1.26]
```

### 2.1 为什么 ε-greedy 的 regret 是线性的

关键在"$\epsilon$ 概率均匀探索"这个动作**永远不退休**。就算 2000 步后你已经完全确定臂 6 是最优的，仍会有约 $\epsilon/10$ 的时间浪费在剩下 9 个次优臂上——每一步都贡献固定大小的期望遗憾。所以：

$$\lim_{T\to\infty} \frac{R_T}{T} = \epsilon \cdot \frac{1}{k}\sum_{a \neq a^*} (q_*(a^*) - q_*(a)) = c(\epsilon) > 0$$

遗憾斜率恒为正常数 → 线性 regret。减小 $\epsilon$ 只能压低斜率，不能改变阶。这也解释了常见的调参现象：**$\epsilon$ 大早期好后期差，$\epsilon$ 小则反过来**。工程折中是让 $\epsilon$ 随时间衰减（§5），但衰减多快才算"对"，没有免费午餐——UCB1 和 Thompson 采样给出的是"自适应衰减"的答案：不确定性高的臂自动多探索，不确定性低的自动少探索。

> **经验做法**：ε-greedy 是所有 RL 库的默认探索方式（DQN、PPO 里都有它的变体），不是因为效果好，而是因为**零成本、不会灾难性失效**。生产环境先用 ε-greedy 拿到 baseline，再考虑换 UCB/Thompson。

## 3. UCB1：按不确定性决策

### 3.1 推导（Hoeffding 不等式视角）

ε-greedy 探索时**不区分"没拉过的臂"和"已确认很差的臂"**——这是它的浪费所在。UCB1（Upper Confidence Bound，Auer, Cesa-Bianchi & Fischer, 2002, *Machine Learning* 期刊版；原始思想源自 Lai & Robbins 1985）的核心：为每臂维护一个**置信上界**，永远选上界最高的臂。

$Q(a)$ 是 $n_a$ 个样本的均值。Hoeffding 不等式给出：真实值偏离样本均值超过 $\delta$ 的概率不超过 $2e^{-2n_a\delta^2}$。想让"真值超过上界"的概率压到 $\frac{1}{T^{α}}$ 以下，解出需要的裕量：

$$\delta = \sqrt{\frac{\alpha \ln T}{2 n_a}} \;\; \xrightarrow{\text{取 } \alpha=4,\text{ 吸收常数}} \;\; UCB(a) = Q(a) + c\sqrt{\frac{\ln T}{n_a}}, \quad c \approx 2$$

三项直觉拆解：

- $Q(a)$：历史均值——**利用**项；
- $\sqrt{\ln T / n_a}$：不确定性项——**探索**项，被拉得越多越小；
- $\ln T$：时间项——早期大家都不确定，晚期探索项整体收缩，算法自动从"探索为主"过渡到"利用为主"，**没有任何外部调度**。

**平局打破机制**藏在分母里：$n_a = 0$ 时上界为无穷大 → 没拉过的臂必然先被拉。所以 UCB1 天然先做一轮完全遍历（前 $k$ 步每臂拉一次）。

### 3.2 实现

```python
def run_ucb1(bandit, steps=2000, c=2.0, seed=0):
    rng = np.random.default_rng(seed)
    Q = np.zeros(bandit.k); N = np.zeros(bandit.k)
    rewards, regrets = np.zeros(steps), np.zeros(steps)
    for t in range(steps):
        if t < bandit.k:            # 前k步：每臂各拉一次（n=0 时上界为inf）
            a = t
        else:
            ucb = Q + c * np.sqrt(np.log(t + 1) / N)   # 向量化算所有臂的上界
            a = int(np.argmax(ucb))
        r = bandit.step(a)
        N[a] += 1
        Q[a] += (r - Q[a]) / N[a]
        rewards[t] = r
        regrets[t] = bandit.q_true[bandit.best] - bandit.q_true[a]
    return rewards, regrets

rewards, regrets = run_ucb1(b, steps=2000, c=2.0, seed=0)
print(f"UCB1 平均奖励={rewards.mean():.3f}, 累计 regret={regrets.sum():.1f}")
```

运行结果（同一实例，种子固定）：

```text
UCB1 平均奖励=1.135, 累计 regret=262.5
```

单实例上 UCB1（262.5）优于 ε=0.1（321.9）。注意一个实现细节：`np.log(t+1)` 在 $t=0$ 时为 0 会导致除零，所以先用"前 $k$ 步完全遍历"绕开；另一种写法是给 $N$ 加小常数 $\epsilon_{\min}=10^{-8}$。**经验做法**：UCB 对 $c$ 不敏感（1.0–2.0 量级变化不大），但把 $\ln$ 写成 $\log_2$ 或漏掉 $t+1$ 的 off-by-one 会显著改变探索节奏——复现论文时优先对齐公式而不是结果。

## 4. Thompson 采样：按信念行动

### 4.1 贝叶斯直觉

前两种方法维护"点估计" $Q(a)$；Thompson 采样（Thompson, 1933, *Biometrika*——比 RL 这个词还早十年）维护**完整的后验分布**，然后：

1. 从每个臂的后验中**抽样**一个"可能的真实值"；
2. 选抽样值最大的臂；
3. 观察奖励，按贝叶斯法则更新该臂后验。

妙处在于探索率是**自动涌现**的：臂 3 的后验是"均值 0.64、很确定"（窄分布），臂 6 是"均值 1.1、还不太确定"（宽分布）——抽样时臂 6 有更大概率抽到高值而被选中。**不确定的臂自动获得探索机会，探索率随信念收敛自然衰减到 0**。这比 ε-greedy 的固定探索和 UCB 的固定公式都优雅。

### 4.2 正态-正态共轭实现

已知奖励方差 $\sigma^2=1$，对每臂维护后验 $\mathcal{N}(\mu_a, 1/\lambda_a)$（$\lambda$ 是精度=方差的倒数），先验 $\mathcal{N}(0, 1)$。观测到 $r$ 后的共轭更新：

$$\lambda_a \leftarrow \lambda_a + \frac{1}{\sigma^2}, \qquad \mu_a \leftarrow \frac{\lambda_a^{old}\mu_a + r/\sigma^2}{\lambda_a^{new}}$$

```python
def run_thompson(bandit, steps=2000, seed=0):
    rng = np.random.default_rng(seed)
    mu = np.zeros(bandit.k)     # 后验均值，先验 N(0,1)
    lam = np.ones(bandit.k)     # 后验精度（1/方差），先验精度 1
    sigma2 = 1.0                # 已知奖励方差
    rewards, regrets = np.zeros(steps), np.zeros(steps)
    for t in range(steps):
        samples = rng.normal(mu, 1.0 / np.sqrt(lam))   # 从每臂后验抽样
        a = int(np.argmax(samples))                    # 选抽样值最大的臂
        r = bandit.step(a)
        lam[a] += 1.0 / sigma2                         # 贝叶斯共轭更新
        mu[a] += (r - mu[a]) / lam[a]                  # 等价于加权平均形式
        rewards[t] = r
        regrets[t] = bandit.q_true[bandit.best] - bandit.q_true[a]
    return rewards, regrets, mu

rewards, regrets, mu = run_thompson(b, steps=2000, seed=0)
print(f"Thompson 平均奖励={rewards.mean():.3f}, 累计 regret={regrets.sum():.1f}")
print("Thompson 后验均值:", np.round(mu, 3))
print("真实值 q*:          ", np.round(b.q_true, 3))
```

运行结果（同一实例，种子固定）：

```text
Thompson 平均奖励=1.174, 累计 regret=285.7
Thompson 后验均值: [-0.152  0.305  0.678  0.015 -0.073  0.342  1.292  0.996 -0.216 -0.262]
真实值 q*:          [ 0.126 -0.132  0.64   0.105 -0.536  0.362  1.304  0.947 -0.704 -1.265]
```

后验均值与真实值的对应关系一目了然：拉得多的臂后验收得紧、拉得少的臂（如臂 1，被抽到过但很快被排挤）后验还偏着——**后验宽度本身就是"我有多确定"的公开账本**。10 章会再遇到这个思想：RLHF 里奖励模型的不确定性利用，就是 Thompson 思想的 LLM 版。

> **经验做法**：实现贝叶斯更新最容易错的是 $\mu$ 更新式的分子分母权重。调试技巧：初始化 $\lambda=1$，只喂一个观测 $r$，手工核对更新后 $\mu$ 应严格等于 $\frac{1\cdot 0 + r/1}{1+1} = r/2$——先验占一半权重。任何不对，立刻能发现。

## 5. 三方法对比实验

单实例噪声太大（bandit 任务一个实例的结论不可信），标准做法（Sutton & Barto §2.3 的实验设计）是**大量独立实例取平均**：

```python
def run(bandit, algo, steps=2000, seed=0, param=0.1):
    """三算法统一入口，返回每步即时遗憾序列"""
    rng = np.random.default_rng(seed)
    k = bandit.k
    Q = np.zeros(k); N = np.zeros(k)
    mu = np.zeros(k); lam = np.ones(k)
    regrets = np.zeros(steps)
    for t in range(steps):
        if algo == 'eps':
            a = int(rng.integers(k)) if rng.random() < param else int(np.argmax(Q))
        elif algo == 'ucb':
            a = t if t < k else int(np.argmax(Q + param * np.sqrt(np.log(t + 1) / N)))
        elif algo == 'ts':
            a = int(np.argmax(rng.normal(mu, 1.0 / np.sqrt(lam))))
        r = bandit.step(a)
        if algo == 'ts':
            lam[a] += 1.0; mu[a] += (r - mu[a]) / lam[a]
        else:
            N[a] += 1; Q[a] += (r - Q[a]) / N[a]
        regrets[t] = bandit.q_true[bandit.best] - bandit.q_true[a]
    return regrets

n_tasks, steps = 200, 2000
results = {}
for algo, param, name in [('eps', 0.1, 'ε-greedy(0.1)'), ('ucb', 2.0, 'UCB1'),
                          ('ts', 0, 'Thompson')]:
    total = np.zeros(steps)
    for task in range(n_tasks):
        b = Bandit(seed=task)                 # 每个任务独立的一组臂
        total += run(b, algo, steps, seed=1000 + task, param=param)
    results[name] = np.cumsum(total) / n_tasks  # 平均累计遗憾曲线

print("200 实例平均累计 regret（转折点检查）:")
print(f"{'算法':12s} {'200步':>8s} {'1000步':>8s} {'2000步':>8s}")
for name, cum in results.items():
    print(f"{name:12s} {cum[199]:8.1f} {cum[999]:8.1f} {cum[1999]:8.1f}")
```

真实运行结果（种子固定，200 实例平均）：

```text
200 实例平均累计 regret（转折点检查）:
算法           200步    1000步    2000步
ε-greedy(0.1)   78.2    217.4    376.1
UCB1            79.4    149.9    186.7
Thompson        44.2     66.5     78.5
```

三个可从数字里读出的事实：

1. **斜率即命运**：ε-greedy 从 1000 步到 2000 步新增 regret 158.7（线性段，斜率 ≈ 0.16/步）；UCB1 同区间只增加 36.8，Thompson 只增加 12.0——对数增长段，曲线肉眼可见地变平。
2. **早期差距在中期被追平**：200 步时三者接近（探索成本人人都要付），分水岭在 500–1000 步之间——好算法的探索成本是**一次性投资**，坏算法是**持续租金**。
3. **Thompson 全面领先**：2000 步 regret 78.5，约为 UCB1 的 42%、ε-greedy 的 21%。Chapelle & Li (2011, NIPS) 在 Yahoo! 真实点击数据上的大规模实验同样如此——这是 Thompson 采样在工业界流行的实证基础。

## 6. 探索 vs 利用：推荐系统与 AB 测试的映射

多臂老虎机不是玩具，它是"**串行决策 + 每个决策消耗真实机会**"问题的最小抽象：

| Bandit 概念 | 推荐系统 | AB 测试（广告/网页） |
| --- | --- | --- |
| 臂 $a$ | 候选内容/排序策略 | 实验方案（A 版/B 版） |
| $q_*(a)$ | 内容的真实点击率/停留时长 | 方案的真实转化率 |
| 一步交互 | 曝光一次给一位用户 | 一个流量单位分到某方案 |
| regret | 错过点击/流失用户 | 实验期间损失的转化 |
| ε-greedy | 固定流量跑新策略 | 固定 10% 流量长期试新方案 |
| Thompson | 按 CTR 后验抽样决定曝光 | 动态流量分配（多臂 bandit AB 测试） |

**经典案例**：固定 50/50 的 AB 测试，若 A 版明显更好，实验期间一半流量持续受损；Thompson 式动态分配会在证据积累过程中自动把流量滑向赢家，总 regret 小得多（Scott, 2010 的"Bayesian bandit"广告投放实践）。代价是引入了"peeking 问题"——多次提前查看结果会放大假阳性，需要贝叶斯框架或组序贯检验来兜底。

**经验做法**：业务里落地 bandit 的第一步不是选算法，而是**确认问题真的能建模成 bandit**——用户状态不随交互改变（上下文无关）才算。用户兴趣会漂移的任务（今天的点击改变明天的展示）本质是上下文 bandit/RL，硬套普通 bandit 会系统性失效；上下文 bandit（LinUCB 等）是"每步带特征的 bandit"，正好是通向完整 RL 的中间站。

## 7. 常见误区

1. **用"选中最优臂的比例"当唯一指标。** 一个算法可以早早锁死最优臂（比例 100%）但前期探索代价巨大，累计 regret 反而更高；也可以长期保留 1% 探索而总 regret 更低。**regret 曲线的形状比终点更说明问题**——看曲线是变平（对数）还是直线（线性）。
2. **单实例下结论。** 本章 §2–§4 的单实例数字（321.9 vs 262.5 vs 285.7）与 §5 的 200 实例平均（376.1 vs 186.7 vs 78.5）**排序都不完全一致**（单实例里 UCB1 好于 Thompson，平均后反过来）。任何 bandit/RL 实验必须多实例/多种子平均，10 个以下种子不可信。
3. **乐观初始化与 ε 探索混用而不自知。** $Q$ 初始化为 0（本章写法）在奖励全负的环境里本身就是一种乐观初始化探索（前几步必然尝试所有被低估的臂）；若把奖励偏移为全正（如 +5），$Q=0$ 初始化会变成"悲观初始化"，早期行为完全不同。Sutton & Barto §2.6 专门讨论这一点。
4. **UCB 的 $n_a=0$ 除零。** $\sqrt{\ln T / 0}$ 直接产生 `inf`/NaN。要么前 $k$ 步完全遍历，要么 $N + 10^{-8}$。这个 bug 的症状很典型：训练前期动作选择完全随机化（每个未拉臂的 inf 上界轮流赢）。
5. **把 Thompson 采样当"又一个 ε-greedy"**。它需要指定**先验与观测分布**（本章：正态-正态，方差已知）；伯努利奖励（点击/不点击）应换 Beta-Bernoulli 共轭。共轭分布选错，后验更新在数学上就是错的——不是"效果差点"而是"根本不是贝叶斯"。

## 本篇小结

- bandit = 单状态 MDP，探索-利用矛盾的纯净标本；regret 是它的量化标尺，对数 regret 是理论最优阶。
- ε-greedy：简单可靠但 regret 线性——固定探索率是"持续租金"。价值估计的增量式均值更新 $Q \leftarrow Q + \frac{1}{n}(r-Q)$ 是全系列复用的原语。
- UCB1：$Q(a) + c\sqrt{\ln T / n_a}$，由 Hoeffding 不等式导出；探索项随确定性提高自动收缩，regret 对数级。Auer et al. 2002。
- Thompson：维护后验、按后验抽样、贝叶斯更新；探索率从信念中自动涌现，实验与工业数据上常优于 UCB1。Chapelle & Li 2011。
- 推荐系统的动态流量分配、AB 测试的 bandit 化都是同一套数学；落地前先确认问题确实是"状态无关"的 bandit。
- "多实例平均 + 看 regret 曲线形状"的方法论，将在 04/06 章的收敛实验中原样复用。

## 练习

1. 把本章实验的奖励分布改为 $\mathcal{N}(q_*(a), 0.5^2)$（噪声减半），重跑 §5 对比实验。预期：三种方法的 regret 都下降、但排序不变——解释为什么噪声变小让"分辨臂"更容易。
2. 实现 ε-greedy 的线性衰减版本（$\epsilon_t = \max(0.01, 0.5/t)$），与固定 ε=0.1 在 200 实例上比较 2000 步累计 regret。它比固定版好多少？为什么仍不及 Thompson？
3. 实现乐观初始化：$Q$ 全部初始化为 +3，ε=0 固定（纯贪心）。在 200 实例上跑 2000 步，画出 regret 曲线，与 ε=0.1 比较——Sutton & Barto §2.6 的经典结论应能在你的实验里复现。
4. 推导题：从 Hoeffding 不等式出发，说明"要求真值高于样本均值的概率 ≤ $1/T^2$"如何导出 $\delta \approx \sqrt{\ln T / n_a}$ 量级的置信半径。（提示：$2e^{-2n\delta^2} \le T^{-2}$，两边取对数解出 $\delta$。）
5. 思考题：一个内容平台用 Thompson 采样分配曝光，3 个月后某条冷门内容的后验精度 $\lambda$ 很大但均值中等。解释为什么它几乎再也得不到曝光（"富者愈富"），以及这对应冷启动问题的什么本质困难。你会如何缓解？（提示：偶尔强制曝光/后验注入噪声/上下文特征。）
