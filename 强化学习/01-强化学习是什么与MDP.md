## 1. 与监督学习的本质区别

监督学习你已经很熟：给定固定数据集 $\{(x_i, y_i)\}$，最小化 $\mathbb{E}_{x \sim D}[L(f(x), y)]$。强化学习不同在哪里？不是"没有标签"这么简单，而是三条结构性区别（Sutton & Barto, 2nd ed., §1.1、§3.1）：

**区别一：数据分布由你自己决定。** 监督学习的训练集是给定的、静态的；RL 中 agent 的每个动作决定了下一步**看到什么状态**。你把车开向悬崖，接下来看到的就是悬崖边的画面——数据分布 $\rho_\pi(s)$ 依赖策略 $\pi$ 本身。这带来一个鸡生蛋问题：想学好策略需要好数据，想采到好数据需要好策略。深度 RL 大部分"不收敛"的病根都在这里（06 章经验回放、09 章 PPO 的 ratio 裁剪，全是围绕这一条的补救）。

**区别二：奖励延迟。** 监督学习每条样本立刻有 $y_i$；RL 的奖励可能稀疏且滞后——下棋只有终局有输赢，LLM 生成 500 个 token 后才知道对错。于是必须解决**信用分配（credit assignment）**：终局赢了，前面哪几步是关键好棋？（04 章 TD、07 章策略梯度都是对这一条的机制设计。）

**区别三：评价方式是"试错"而非"对错"。** 监督学习告诉你正确答案；RL 只告诉你这个动作"得了多少分"，从不告诉你**最优动作是什么**。agent 必须自己探索（02 章整个主题）。

| 维度 | 监督学习 | 强化学习 |
| --- | --- | --- |
| 数据 | 静态数据集，i.i.d. 采样 | 交互产生，分布随策略漂移 |
| 反馈 | 每样本的正确标签 | 标量奖励，可能延迟/稀疏 |
| 目标 | 拟合固定分布 | 最大化长期累积回报 |
| 难点根源 | 过拟合/泛化 | 探索-利用 + 信用分配 + 分布漂移 |
| 评价指标 | loss / accuracy | 回报（噪声极大，要多次评估取均值） |

> **经验做法**：监督学习里 loss 下降 ≈ 在进步；RL 里平均回报上升经常是**假信号**（一次幸运探索、熵太低后偶然走运），必须固定评估协议（如 10 个评估 episode 取均值、多随机种子）再下结论。这是从监督学习转 RL 最容易踩的坑。

## 2. Agent-Environment 交互回路

RL 的世界模型只有一张图（Sutton & Barto, 2nd ed., §3.1 图 3.1）：

```text
        ┌──────────────────────────────────────────┐
        │                                          │
        │   状态 s_t                    动作 a_t    │
        └──────────→  ┌────────┐        ┌────────┐ ─┘
        ┌──────────── │ Agent  │ ─────→ │  环境   │
        │             │ (策略)  │        │(游戏/物理│
        ↑             └────────┘        │/用户/LLM)│
        │                               └────────┘
        │        奖励 r_{t+1}                  │
        └──────────────────────────────────────┘
                  （时间步 t → t+1）
```

每个时间步 $t$ 发生两件事：

1. Agent 观测状态 $s_t$，按策略输出动作 $a_t \sim \pi(\cdot|s_t)$；
2. 环境返回**奖励** $r_{t+1}$ 和**新状态** $s_{t+1}$。

注意一个细节：奖励记作 $r_{t+1}$ 而不是 $r_t$，因为它是环境对 $(s_t, a_t)$ 的**响应结果**，属于"未来"（Sutton & Barto §3.2 的记号约定）。这个记号会在后面反复出现：TD 误差写成 $r_{t+1} + \gamma V(s_{t+1}) - V(s_t)$。

把三个熟悉的世界塞进这张图，检验你是否真的理解了：

| 任务 | Agent | 环境 | 状态 $s_t$ | 动作 $a_t$ | 奖励 $r_{t+1}$ |
| --- | --- | --- | --- | --- | --- |
| CartPole（本系列主力） | 控制器 | 物理仿真 | [位置, 速度, 杆角, 角速度] | 向左/向右推 | 存活每步 +1 |
| 推荐系统 | 排序策略 | 用户 | 用户画像+历史点击 | 推荐哪些物品 | 是否点击/停留 |
| LLM 对话（Stage 6/7 视角） | 语言模型 | 用户+评分器 | prompt+已生成前缀 | 下一个 token | 奖励模型打分/验证器判对错 |

LLM 那一行值得多看一眼：**生成一个 token 就是走一步 RL**。SFT（Stage 2）在模仿固定数据分布，是监督学习；RLHF/RLVR 在优化模型自己生成轨迹的长期得分——这正是本系列 10 章的主题。

## 3. MDP 五元组

**马尔可夫决策过程**形式化定义为五元组 $(S, A, P, R, \gamma)$（Sutton & Barto, 2nd ed., §3.5）：

- $S$：状态集合；
- $A$：动作集合；
- $P(s'|s,a) = \Pr\{s_{t+1}=s' \mid s_t=s, a_t=a\}$：**转移函数**，环境动力学；
- $R(s,a) = \mathbb{E}[r_{t+1} \mid s_t=s, a_t=a]$：奖励函数；
- $\gamma \in [0,1]$：折扣因子。

**马尔可夫性**是整个体系的承重墙：$s_t$ 包含了预测未来所需的全部信息，历史 $s_0,\dots,s_{t-1}$ 不再有用。两条推论：

- 推论一：所有学习算法（Q 表、Q 网络、策略网络）都可以只以"当前状态"为输入，不必维护历史。真实任务不满足马尔可夫性时怎么办？加历史窗口（帧叠加，Atari 标配 4 帧）、RNN/Transformer 状态——但底层算法不变。
- 推论二：部分可观测任务（POMDP）在工程上常被"状态堆叠"近似成 MDP 处理。**经验做法**：调试 RL 不收敛时，先问一句"我的观测是否遗漏了决策必需的信息"——这是排在前五的高频病因。

以 CartPole 为例把五元组落到具体（gymnasium 1.4.0 实测）：

```python
import gymnasium as gym
import numpy as np

np.random.seed(0)
env = gym.make("CartPole-v1")
obs, info = env.reset(seed=0)
print("状态向量:", np.round(obs, 4))       # 4 维连续：位置/速度/角度/角速度
print("动作空间:", env.action_space)      # Discrete(2)：0=向左推, 1=向右推
print("状态空间:", env.observation_space)
print("奖励:", env.step(1)[1])   # 1.0（每存活一步 +1）
```

运行结果（种子固定，gymnasium 1.4.0 实测）：

```text
状态向量: [ 0.0137 -0.023  -0.0459 -0.0483]
动作空间: Discrete(2)
状态空间: Box([ 4.8 -inf  0.4189 -inf], [ 4.8  inf  0.4189  inf], (4,), float32)
          # 角度边界 ±0.4189 rad ≈ ±24°，位置 ±4.8；速度无硬边界（靠终止条件控制）
奖励: 1.0
```

CartPole 的转移函数 $P$ 没有显式给出（藏在物理仿真里），奖励恒为 +1，折扣因子由算法自选。**已知 $P$ 与 $R$ → 03 章动态规划；未知 → 04 章起的无模型方法**。这条分界线贯穿全系列。

## 4. 回报与折扣因子

agent 的目标不是单步奖励，而是**回报（return）**——从当前时刻起的累积折扣奖励（Sutton & Barto, 2nd ed., §3.3）：

$$G_t = r_{t+1} + \gamma r_{t+2} + \gamma^2 r_{t+3} + \cdots = \sum_{k=0}^{\infty} \gamma^k r_{t+k+1}$$

回报满足一个对实现极其重要的递归：

$$G_t = r_{t+1} + \gamma G_{t+1}$$

"未来的回报 = 立刻的奖励 + 折扣后的未来回报"——这一个式子就是贝尔曼方程的种子（03 章展开），也是所有 RL 算法自举（bootstrapping）的来源。

用代码验证两种等价算法（从后往前 vs 递归展开）：

```python
rewards = [1.0, 2.0, 0.0]   # 一条轨迹的奖励序列
gamma = 0.9

# 法一：倒序递推（工程标准写法，O(n) 一次遍历）
G = 0.0
for r in reversed(rewards):
    G = r + gamma * G
print("倒序递推 G_0 =", round(G, 4))        # 2.8

# 法二：定义直接展开（等价，用于理解）
G2 = sum(gamma**k * r for k, r in enumerate(rewards))
print("定义展开 G_0 =", round(G2, 4))       # 2.8
```

### 4.1 $\gamma$ 的两重身份

**身份一：收敛保险。** $\gamma < 1$ 保证无穷和有界：$\sum \gamma^k r_{\max} = r_{\max}/(1-\gamma)$。continuing 任务（无终点）必须靠它；episodic 任务理论上可以 $\gamma=1$，但实践中也常用 $\gamma<1$。

**身份二：有效视野（effective horizon）。** $\gamma$ 决定 agent 多在乎未来：

| $\gamma$ | 轨迹 $[1, 2, 0]$ 的 $G_0$ | 含义 |
| --- | --- | --- |
| 0.0 | 1.0 | 极端短视：只看眼前一步 |
| 0.5 | 2.0 | 半步未来 |
| 0.9 | 2.8 | 约 10 步视野（$1/(1-\gamma)=10$） |
| 0.99 | 2.98 | 约 100 步视野 |
| 1.0 | 3.0 | 完全不折扣 |

"视野 ≈ $1/(1-\gamma)$"这个换算非常实用：想让 agent 看远 100 步，$\gamma=0.99$；棋类/多回合任务常用 0.99–0.999，CartPole 这类短任务 0.99 足够。**经验做法**：$\gamma$ 是比学习率更容易被忽视的超参——回报异常大（数值发散前兆）或 agent 明显短视时，先查 $\gamma$。

continuing 任务下 $\gamma \to 1$ 的极端后果，用"每步奖励恒为 1"验证：

```python
for g in [0.9, 0.99]:
    G = sum(g**t for t in range(1000))          # G = 1 + g + g^2 + ...
    print(f"gamma={g}: 理论 1/(1-gamma)={1/(1-g):.2f}, 1000 步实际={G:.4f}")
# gamma=0.9: 理论 1/(1-gamma)=10.00, 1000 步实际=10.0000
# gamma=0.99: 理论 1/(1-gamma)=100.00, 1000 步实际=99.9957
```

## 5. Episodic vs Continuing

**回合制（episodic）任务**：有明确的终止状态，交互分成一个个回合，回合之间互相独立。CartPole 杆倒了/撑过 500 步即终止；下棋终局即终止。终止状态（terminal state）的值恒为 0——这一点在实现里就是 `done`/`terminated` 标志的语义（06 章 DQN 的 target 计算里 `(1 - done)` 项就是它）。

**连续型（continuing）任务**：没有终点，理论上无限进行。股票交易、推荐系统、恒温控制。

工程上的灰色地带：很多任务是"名义 episodic、实际 continuing"——推荐系统一天的会话可以当回合，但用户第二天回来，跨回合信息仍在。**经验做法**：不确定时按 episodic 建模（简单），但注意把"人为截断"与"真实终止"区分开。gymnasium 1.x 的 `terminated`（环境真终止，value 应记 0）与 `truncated`（时间上限截断，value 不该记 0）两个返回值正是为此设计的——老代码里笼统的 `done` 是 06/09 章难以复现的常见原因。

```python
env = gym.make("CartPole-v1", max_episode_steps=200)   # 人为截断
obs, info = env.reset(seed=0)
s, r, terminated, truncated, info = env.step(1)
print(terminated, truncated)    # False False —— 单步时两个都是 False
# terminated=True：杆真的倒了 → target 里 value 记 0
# truncated=True ：只是到 200 步上限 → target 里 value 不记 0
```

## 6. 智能体分类谱系图

RL 算法可以用三个问题切片，每个问题一个维度（Sutton & Barto, 2nd ed., §1.5 的分类思想）：

```text
Q1: 学什么？
 ├─ 值函数法：学 V/Q，策略由值导出（argmax）
 │    MC（04）→ TD(0)（04）→ Q-learning/SARSA（05）→ DQN（06）
 ├─ 策略梯度法：直接学 π(a|s)，值只当"减方差的配角"
 │    REINFORCE（07）→ A2C/GAE（08）→ PPO/TRPO（09）
 └─ Actor-Critic：两者都要（08）

Q2: 要不要学环境模型？
 ├─ 无模型（model-free）：直接从数据学值/策略
 │    MC、TD、Q-learning、DQN、PPO（本系列 04–10 全部）
 └─ 基于模型（model-based）：先学 P(s'|s,a)，再规划/生成虚拟数据
      Dyna（11）、MuZero（11）

Q3: 更新时用谁的策略？
 ├─ on-policy：评估并改进"正在采数据的那条"策略（SARSA、REINFORCE、PPO）
 └─ off-policy：评估目标策略，数据来自另一条行为策略（Q-learning、DQN）
```

三个维度是**正交**的：PPO 是 on-policy 的策略梯度法（无模型）；DQN 是 off-policy 的值函数法（无模型）；MuZero 是 model-based 的策略+值混合。看任何新论文先在这张图上定位，学习成本立减一半。

**经验做法**：本系列按"值函数线（04–06）→ 策略梯度线（07–09）"两条线推进，因为深度 RL 的两大门派（DeepMind 系 DQN、OpenAI 系 PPO）分别源于这两条线；10 章会看到 LLM 对齐几乎全部落在策略梯度线——这就是为什么 RLHF 用 PPO 而不用 DQN。

## 7. 常见误区

1. **把 RL 当"没标签的监督学习"，直接拿单步奖励当标签回归。** 单步奖励 $r_{t+1}$ 不等于"这个动作的好坏"——一个好动作可能跟在坏状态后面得到低奖励。动作好坏要看**回报**（长视角），这正是 04 章 TD 误差、08 章优势函数存在的意义。
2. **忽略数据分布漂移，用监督学习思维评估。** 在"固定测试集"上评估 RL 策略没有意义——策略改了，访问到的状态分布就变了。评估必须用当前策略实际交互若干 episode 的平均回报。
3. **以为 $\gamma$ 只是个防发散的小数，随手取 0.99 就完事。** $\gamma$ 直接定义了优化目标本身：0.9 和 0.999 的最优策略可能是完全不同的行为（短视 vs 远谋）。调参先定 $\gamma$，再谈学习率。
4. **混淆 `terminated` 与 `truncated`**（详见 §5）。把"到时间上限"也当成真实终止去 bootstrap=0，会系统性低估长活策略的值，表现为：训练后期回报不升反降、学出"故意送死"的行为（早死不亏）。
5. **期望一步到位看懂收敛曲线。** 监督学习曲线平滑，RL 曲线锯齿满地。单次运行甚至单次评估的波动是常态，结论必须来自多种子平均——这也是全系列代码固定种子的原因：先保证"可复现"，再谈"变好"。

## 本篇小结

- RL 与监督学习的本质区别：数据分布由策略决定、奖励延迟稀疏、只给分数不给对错。由此派生 RL 三大难点：探索-利用、信用分配、分布漂移。
- 交互回路：$s_t \xrightarrow{\pi} a_t \xrightarrow{环境} r_{t+1}, s_{t+1}$。LLM 生成 token = RL 的一步，这是 10 章的接口。
- MDP 五元组 $(S,A,P,R,\gamma)$；马尔可夫性让算法只需当前状态。已知 $P,R$ 走 DP（03），未知走无模型（04 起）。
- 回报 $G_t = \sum \gamma^k r_{t+k+1}$，递归式 $G_t = r_{t+1} + \gamma G_{t+1}$；$\gamma$ 既是收敛保险也是视野旋钮（视野 ≈ $1/(1-\gamma)$）。
- episodic vs continuing，且必须区分真终止（terminated）与截断（truncated）。
- 算法谱系三正交维度：学什么（值/策略/混合）、要不要模型、on/off-policy。后续章节全部可以在这张图上定位。
