# 06-移动语义与完美转发

## 1. 为什么需要移动

05 篇 `AudioBuffer` 的拷贝构造是：分配新内存 + 复制几百万个采样点，**O(n)**。但很多场景下源对象马上就要消亡：

```cpp
std::vector<AudioBuffer> buffers;
buffers.push_back(make_buffer());  // 临时对象马上销毁，为什么要深拷贝它的内容？
```

临时对象"行将就木"，它手里的堆内存与其复制一份，**不如直接把指针抢过来**：接管指针、置空对方，几条指令完事，**O(1)**。这就是移动语义的全部动机。语音引擎里无处不在：音频块沿管道流动（下游接管）、`std::vector<AudioBuffer>` 扩容搬迁元素（搬指针而非搬数据）、把大缓冲返回给调用者（"上浮"而非深拷贝）。

## 2. 左值与右值：先建立直觉

值类别初看唬人（glvalue/xvalue/prvalue），先用直觉建地图：

- **左值（lvalue）**：有名字、能取地址、通常能出现在 `=` 左边——变量 `a`、`*p`、返回引用的函数调用。它的"位置"是主角。
- **右值（rvalue）**：临时的、没有名字、即将消亡——字面量 `42`、表达式 `a + b`、**按值返回的对象**、`std::move(x)` 的结果。它的"内容"是主角，反正马上就没了，随便抢。

再补两个术语（面试用，写代码用不到）：**prvalue（纯右值）**是货真价实的临时对象，如 `42`、`make_buffer()` 的返回值；**xvalue（将亡值）**是本有名字、被标记为"可抢"的对象，如 `std::move(a)` 的结果。glvalue = lvalue + xvalue（"有位置"），rvalue = prvalue + xvalue（"可移动"）——xvalue 是交点，**`std::move` 干的就是"把左值标成 xvalue"这件事**。

## 3. 右值引用 `&&` 与 `std::move` 的真相

**右值引用 `T&&`**：专门绑定右值的引用——给行将消亡的对象"续命"，并让重载决议能区分"请拷贝我"（`const T&`）和"请抢走我"（`T&&`）。

**`std::move(x)` 的真相：它是一个类型转换，一个字节的移动都没做**。它只把表达式 `x` 转成右值，真正"移动"的是随后被选中的移动构造/移动赋值。读代码看到 `std::move` 应默念："**宣布：我不再需要 x 的内容，可以抢**"。

```cpp
#include <algorithm>
#include <cstddef>
#include <iostream>
#include <utility>

// 一个"昂贵"的资源类：持有大块音频采样
class BigBuffer {
public:
    explicit BigBuffer(std::size_t n) : data_(new float[n]), size_(n) {
        std::cout << "  构造 " << size_ << '\n';
    }
    ~BigBuffer() {
        std::cout << "  析构 size=" << size_ << '\n';
        delete[] data_;
    }

    BigBuffer(const BigBuffer& other)  // 拷贝：分配 + 复制，O(n)
        : data_(new float[other.size_]), size_(other.size_) {
        std::copy(other.data_, other.data_ + size_, data_);
        std::cout << "  拷贝构造（分配 + 复制，O(n)）\n";
    }

    BigBuffer(BigBuffer&& other) noexcept  // 移动：只偷指针，O(1)
        : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr;  // 掏空对方
        other.size_ = 0;
        std::cout << "  移动构造（只偷指针，O(1)）\n";
    }

    std::size_t size() const { return size_; }

private:
    float* data_;
    std::size_t size_;
};

BigBuffer make_buffer() { return BigBuffer(1000); }  // 返回 prvalue

int main() {
    BigBuffer a(10);              // a 是左值：有名字、能取地址、能出现在 = 左边
    BigBuffer b = a;              // 左值 -> 拷贝构造
    BigBuffer c = std::move(a);   // std::move 把 a 转成右值 -> 移动构造
    std::cout << "  被移动后的 a.size() = " << a.size() << "（合法但已掏空）\n";

    BigBuffer&& rref = BigBuffer(500);  // && 给行将消亡的对象"续命"
    std::cout << "  rref.size() = " << rref.size() << '\n';

    BigBuffer d = make_buffer();  // C++17 保证直接在 d 里构造（连移动都省略）
    return 0;
}
```

预期输出（第 4 步没有"移动构造"字样——C++17 的**保证的拷贝省略**让 prvalue 直接在 `d` 里构造；末尾按构造相反顺序析构，`size=0` 就是被掏空的 `a`）：

```text
  构造 10
  拷贝构造（分配 + 复制，O(n)）
  移动构造（只偷指针，O(1)）
  被移动后的 a.size() = 0（合法但已掏空）
  构造 500
  rref.size() = 500
  构造 1000
  析构 size=1000
  析构 size=500
  析构 size=10
  析构 size=10
  析构 size=0
```

**被移动后的状态**：标准只要求"合法但未指定"——可以安全析构、赋新值，但不要假设它的内容（掏空为"空壳"是惯例而非标准要求）；读它的采样数据是未定义行为。
## 4. `noexcept`：`std::vector` 在乎的事

`std::vector` 扩容时要**搬迁所有旧元素**。假设搬到一半，某个元素的移动构造抛异常——旧内存里的元素已被掏空，新内存又没搬完，数据损坏且无法回滚。标准库的对策是 `std::move_if_noexcept`：**只有移动构造标了 `noexcept`，扩容搬迁才用移动；否则退回拷贝**（拷贝失败时原 vector 完好）。这就是"移动构造必须写 `noexcept`"的工程理由——不写，移动语义在容器里形同虚设。

```cpp
#include <iostream>
#include <vector>

// 两个几乎一样的类，唯一区别：移动构造函数有没有 noexcept
class CopyOnly {  // 移动构造没有 noexcept
public:
    explicit CopyOnly(int v) : v_(v) {}
    CopyOnly(const CopyOnly& other) : v_(other.v_) { std::cout << "  拷贝 " << v_ << '\n'; }
    CopyOnly(CopyOnly&& other) : v_(other.v_) { std::cout << "  移动 " << v_ << '\n'; }  // 没有 noexcept
private:
    int v_;
};

class MoveFast {  // 移动构造标了 noexcept
public:
    explicit MoveFast(int v) : v_(v) {}
    MoveFast(const MoveFast& other) : v_(other.v_) { std::cout << "  拷贝 " << v_ << '\n'; }
    MoveFast(MoveFast&& other) noexcept : v_(other.v_) { std::cout << "  移动 " << v_ << '\n'; }  // 有 noexcept
private:
    int v_;
};

int main() {
    std::cout << "A. 移动构造【没有】noexcept，vector 扩容时：\n";
    std::vector<CopyOnly> v1;
    for (int i = 1; i <= 3; ++i) v1.push_back(CopyOnly(i));

    std::cout << "B. 移动构造【有】noexcept，vector 扩容时：\n";
    std::vector<MoveFast> v2;
    for (int i = 1; i <= 3; ++i) v2.push_back(MoveFast(i));
    std::cout << "  对比：A 搬迁旧元素时退化为拷贝，B 全程移动\n";
    return 0;
}
```

预期输出（`push_back` 临时对象本身总走移动，差异出现在**搬迁旧元素**时；A 的 `拷贝 1 / 拷贝 1、2` 都是扩容搬迁）：

```text
A. 移动构造【没有】noexcept，vector 扩容时：
  移动 1
  移动 2
  拷贝 1
  移动 3
  拷贝 1
  拷贝 2
B. 移动构造【有】noexcept，vector 扩容时：
  移动 1
  移动 2
  移动 1
  移动 3
  移动 1
  移动 2
```

一个 `noexcept` 关键字，决定容器扩容是 O(n) 次深拷贝还是 O(n) 次指针偷取。

## 5. 完美转发

**问题**：包装函数把参数转手给内部函数时，形参 `arg` 一旦有了名字，它自己就是**左值**——哪怕调用者传进来的是右值。无脑转发会把所有右值变成左值，白白触发拷贝。**解决**：万能引用 + `std::forward`。

- **万能引用**：`T&&` 出现在**模板参数推导**语境里时，既能绑左值也能绑右值——传左值 `s` 时 `T` 推导为 `std::string&`，传右值时 `T` 是 `std::string`。注意它只在 `T` 待推导时成立，写死 `std::string&&` 就是普通右值引用。
- **引用折叠一句话**：`& + & = &`，`& + && = &`，`&& + && = &&`——左值进来 `T = string&`，`T&&` 折叠成 `string&`；右值进来保持 `string&&`。
- **`std::forward<T>(arg)`**：按 `T` 里藏的引用信息还原值类别——左值仍转发为左值，右值仍转发为右值。它和 `std::move` 一样只是类型转换。

```cpp
#include <iostream>
#include <string>
#include <utility>

void inspect(const std::string& s) {  // 左值版本
    std::cout << "  [左值版本] " << s << '\n';
}
void inspect(std::string&& s) {       // 右值版本
    std::cout << "  [右值版本] " << s << '\n';
}

template <typename T>
void relay(T&& arg) {  // 万能引用：左值、右值都能绑（不是普通右值引用！）
    // 直接写 inspect(arg)：arg 有名字，永远是左值，右值信息丢失；
    // std::forward<T> 按 T 里记录的信息还原原始值类别
    inspect(std::forward<T>(arg));
}

int main() {
    std::string s = "hello";
    relay(s);                     // -> 左值版本
    relay(std::string("world"));  // -> 右值版本
    relay(std::move(s));          // -> 右值版本
    return 0;
}
```

预期输出：

```text
  [左值版本] hello
  [右值版本] world
  [右值版本] hello
```

## 6. `emplace_back` vs `push_back`

`push_back(Task("decode", 1))` 的旅程：**构造临时对象 → 移动进容器 → 析构临时对象**，三步。`emplace_back("decode", 1)` 借助完美转发把构造参数**直接送进容器内存里构造对象**，一步到位：

```cpp
#include <iostream>
#include <string>
#include <utility>
#include <vector>

class Task {
public:
    Task(std::string name, int priority)
        : name_(std::move(name)), priority_(priority) {
        std::cout << "  构造 " << name_ << '\n';
    }
    Task(Task&& other) noexcept
        : name_(std::move(other.name_)), priority_(other.priority_) {
        std::cout << "  移动（偷走了对方的 string）\n";
    }
    ~Task() { std::cout << "  析构 " << name_ << '\n'; }

private:
    std::string name_;
    int priority_;
};

int main() {
    std::vector<Task> queue;
    queue.reserve(4);  // 预留空间，避免扩容干扰观察

    std::cout << "push_back(Task(\"decode\", 1))：\n";
    queue.push_back(Task("decode", 1));  // 构造临时 -> 移动进容器 -> 临时析构

    std::cout << "emplace_back(\"vad\", 2)：\n";
    queue.emplace_back("vad", 2);        // 参数转发进容器，原地只构造一次

    std::cout << "程序结束，容器析构：\n";
    return 0;
}
```

预期输出（`push_back` 后那个名字为空的 `析构`，就是内容已被移走的临时对象）：

```text
push_back(Task("decode", 1))：
  构造 decode
  移动（偷走了对方的 string）
  析构 
emplace_back("vad", 2)：
  构造 vad
程序结束，容器析构：
  析构 decode
  析构 vad
```

对 `AudioBuffer` 这类大缓冲区，`emplace_back` 省掉一次完整移动；把已有左值放进容器时记得 `push_back(std::move(obj))`。

## 7. 综合实战：拷贝 vs 移动计时

给 05 篇的 `AudioBuffer` 实测：同样"得到一份 3.8 MB 的 10 秒双声道音频"，深拷贝和移动差多少？

```cpp
#include <algorithm>
#include <chrono>
#include <cstddef>
#include <iostream>
#include <utility>

// 与 05 篇第 7 节同源的 AudioBuffer（只保留本实验需要的成员函数）
class AudioBuffer {
public:
    AudioBuffer(std::size_t channels, std::size_t frames)
        : channels_(channels), frames_(frames),
          data_(new float[channels * frames]) {}

    AudioBuffer(const AudioBuffer& other)
        : channels_(other.channels_), frames_(other.frames_),
          data_(new float[other.channels_ * other.frames_]) {
        std::copy(other.data_, other.data_ + channels_ * frames_, data_);
    }

    AudioBuffer(AudioBuffer&& other) noexcept
        : channels_(other.channels_), frames_(other.frames_),
          data_(other.data_) {
        other.data_ = nullptr;
        other.channels_ = 0;
        other.frames_ = 0;
    }

    ~AudioBuffer() { delete[] data_; }

    std::size_t frames() const { return frames_; }

private:
    std::size_t channels_;
    std::size_t frames_;
    float* data_;
};

using Clock = std::chrono::steady_clock;

int main() {
    constexpr std::size_t kChannels = 2;
    constexpr std::size_t kFrames = 48000 * 10;  // 10 秒 48 kHz 双声道 ≈ 3.8 MB
    constexpr int kOps = 50;
    std::size_t sink = 0;  // "吃掉"结果，防止编译器把整个循环优化掉

    // ---- 拷贝：每次都要分配新内存 + 复制全部采样 ----
    AudioBuffer source(kChannels, kFrames);
    auto t0 = Clock::now();
    for (int i = 0; i < kOps; ++i) {
        AudioBuffer dst = source;  // 拷贝构造
        sink += dst.frames();
    }
    auto t1 = Clock::now();

    // ---- 移动：每次只偷一个指针（构造成本两种循环里都一样） ----
    auto t2 = Clock::now();
    for (int i = 0; i < kOps; ++i) {
        AudioBuffer tmp(kChannels, kFrames);
        AudioBuffer dst = std::move(tmp);  // 移动构造
        sink += dst.frames();
    }
    auto t3 = Clock::now();

    auto copy_us =
        std::chrono::duration_cast<std::chrono::microseconds>(t1 - t0).count();
    auto move_us =
        std::chrono::duration_cast<std::chrono::microseconds>(t3 - t2).count();
    std::cout << "拷贝 " << kOps << " 次（每次 "
              << kChannels * kFrames * sizeof(float) << " 字节）: 共 "
              << copy_us << " us，平均 " << copy_us / kOps << " us/次\n";
    std::cout << "移动 " << kOps << " 次: 共 " << move_us << " us，平均 "
              << move_us / kOps << " us/次\n";
    std::cout << "（sink = " << sink << "，防止优化；数值因机器而异）\n";
    return 0;
}
```

实测输出（`g++ -std=c++17 -O2`；数值因机器而异，量级关系稳定）：

```text
拷贝 50 次（每次 3840000 字节）: 共 7114 us，平均 142 us/次
移动 50 次: 共 0 us，平均 0 us/次
（sink = 48000000，防止优化；数值因机器而异）
```

一次深拷贝约 150 微秒（3.8 MB 的分配 + 逐字节复制），一次移动是**纳秒级的几条指令**——差三个数量级。对实时语音管道来说，热路径上每一次不必要的拷贝都是可感知的延迟。

## 8. 常见坑

- **以为 `std::move` 会移动**：它只是类型转换；类没实现移动操作时，`std::move` 之后照样走拷贝。
- **移动构造忘了标 `noexcept`**：容器扩容退回拷贝（第 4 节实测），优化静默失效。
- **移动构造忘了掏空对方**：源指针没置空，两个对象析构时 double-free——比漏拷贝更致命。
- **对 `const` 对象 `std::move`**：产生 `const T&&`，绑不到 `T&&`，重载决议退回拷贝——白写，编译器可能不警告。
- **被移动后继续读内容**：合法但未指定状态，只能析构或赋新值，读数据是未定义行为。
- **对右值引用形参再使用时忘了 `std::move`/`std::forward`**：`void f(T&& x) { g(x); }` 里 `x` 是左值；转发场景用 `std::forward<T>`，确定不要了用 `std::move`。

## 9. 小结

- 移动 = 接管资源而非复制：O(n) 深拷贝变 O(1) 指针偷取；`std::move` 只是"标记可抢"的类型转换。
- 移动构造/赋值要 `noexcept`（否则容器扩容退回拷贝）、要掏空源对象（否则 double-free）；被移动对象是"合法但未指定"状态。
- 完美转发 = 万能引用 `T&&` + 引用折叠 + `std::forward<T>`，`emplace_back` 是它的头号受益者。
- 性能要实测：3.8 MB 缓冲区拷贝 ~150 us，移动 ~0 us。

## 10. 自测题

1. `std::move(x)` 执行后，`x` 的内存被释放了吗？
   <details><summary>答案</summary>
   没有。`std::move` 只是转换，什么都没发生；`x` 的资源是否被偷走取决于后续是否触发移动构造/赋值。即便触发了，`x` 作为对象本身仍活着，离开作用域才析构（析构的可能已是空壳）。
   </details>

2. 为什么第 4 节示例 A 中，`push_back(CopyOnly(i))` 的第一个操作是"移动"而非"拷贝"？
   <details><summary>答案</summary>
   `CopyOnly(i)` 是 prvalue 临时对象，从右值构造新元素时无条件用移动构造。`std::move_if_noexcept` 的保守策略只作用于**扩容搬迁旧元素**那一步——那里才要求 noexcept。
   </details>

3. `template <typename T> void f(T&& x);` 传入左值 `s` 时，`T` 和 `x` 的类型分别是什么？
   <details><summary>答案</summary>
   `T = std::string&`（以 `s` 的类型为例），参数类型经引用折叠为 `std::string&`（左值引用）。这也是 `f` 内部 `x` 是左值的原因：有名字的变量永远是左值，与它的类型无关。
   </details>
