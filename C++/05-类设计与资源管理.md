## 1. class vs struct

两者**唯一**的语法区别：`struct` 成员默认 `public`，`class` 成员默认 `private`。区别在设计意图：

```cpp
struct RawConfig   { int sample_rate = 16000; };  // 数据聚合：外界随便读写，合理
class EngineConfig { int sample_rate_ = 48000; }; // 不写 public 就访问不到，藏住了
```

- **`struct`**：没有不变式要守护的一堆数据（一帧参数包），成员开放、可用聚合初始化 `RawConfig c{16000}`；
- **`class`**：有不变式要维护（"采样率必须有效""指针非空"），数据藏起来，只暴露接口。
语音代码里，配置结构体用 `struct`；引擎、解码器、缓冲区这类对象用 `class`。

## 2. 构造函数与成员初始化列表

构造函数负责"让对象出生即有效"，析构函数是 RAII 的释放点（03 篇）。这里聚焦一个细节：**成员初始化列表**（冒号后那一段）。它好于在函数体里赋值，因为：

1. 函数体里是"先默认构造、再赋值"，白干一遍活；初始化列表直接一步构造到位；
2. `const` 成员和引用成员**只能**用初始化列表，函数体赋值编译不过；
3. 成员实际初始化顺序 = **声明顺序**，与列表书写顺序无关——这是常见陷阱。

```cpp
#include <iostream>
#include <string>
#include <utility>

class Decoder {
public:
    // 初始化列表：成员"出生即成形"，而不是先默认构造再在函数体里赋值
    Decoder(std::string name, int threads)
        : name_(std::move(name)), threads_(threads) {}

    const std::string& name() const { return name_; }
    int threads() const { return threads_; }

private:
    std::string name_;
    int threads_;
};

int main() {
    Decoder d("vad-model", 4);
    std::cout << "  " << d.name() << " 用 " << d.threads() << " 线程\n";
    return 0;
}
```

预期输出：

```text
  vad-model 用 4 线程
```

## 3. 拷贝：浅拷贝事故与 Rule of Three

不手写拷贝函数时，编译器自动生成**逐成员拷贝**。对 `std::string`、`std::vector` 这没问题；但对象里有**裸指针**时，逐成员拷贝只复制指针值——两个对象指向同一块内存，析构时释放两次。这是**浅拷贝**。

事故现场（真实编译运行，ASan 抓到 double-free）：

```cpp
// 危险示范：浅拷贝导致 double-free。仅供编译验证 + ASan 观察，不要模仿！
#include <cstddef>

class IntBuffer {
public:
    explicit IntBuffer(std::size_t n) : size_(n), data_(new int[n]) {}
    // 故意【不写】拷贝构造：编译器生成的默认拷贝是浅拷贝，两个对象共享 data_
    ~IntBuffer() { delete[] data_; }

private:
    std::size_t size_;
    int* data_;
};

int main() {
    IntBuffer src(4);
    IntBuffer dst = src;  // 浅拷贝：dst.data_ == src.data_
    return 0;
}  // dst 先析构释放内存，src 再析构 -> 同一块内存释放两次
```

用 `g++ -std=c++17 -fsanitize=address` 编译运行，程序崩溃并报告：
`ERROR: AddressSanitizer: attempting double-free ... SUMMARY: double-free in operator delete[]`。

修复 = **深拷贝**：拷贝时分配自己的内存、逐元素复制。这也正好凑齐 **Rule of Three**：手写了析构、拷贝构造、拷贝赋值三者之一，三个都要写——它们围着同一份资源转：

```cpp
#include <algorithm>
#include <cstddef>
#include <iostream>

class IntBuffer {
public:
    explicit IntBuffer(std::size_t n) : size_(n), data_(new int[n]) {
        std::cout << "  分配 @ " << data_ << '\n';
    }
    IntBuffer(const IntBuffer& other)  // 深拷贝：新内存 + 逐元素复制
        : size_(other.size_), data_(new int[other.size_]) {
        std::copy(other.data_, other.data_ + size_, data_);
        std::cout << "  深拷贝 -> @ " << data_ << '\n';
    }
    ~IntBuffer() {
        std::cout << "  释放 @ " << data_ << '\n';
        delete[] data_;
    }

private:
    std::size_t size_;
    int* data_;
};

int main() {
    IntBuffer src(4);
    IntBuffer dst = src;  // 触发深拷贝构造：两个地址不同，析构互不干扰
    return 0;
}
```

预期输出（两个地址不同是关键）：

```text
  分配 @ 0x5f8f060b8eb0
  深拷贝 -> @ 0x5f8f060b9ee0
  释放 @ 0x5f8f060b9ee0
  释放 @ 0x5f8f060b8eb0
```

拷贝赋值 `operator=` 与拷贝构造的区别：赋值时对象**已经持有旧资源**，要"先分配成功、再释放旧内存"（异常安全），第 7 节的综合示例里有完整写法。

## 4. Rule of Zero / Rule of Five

最好的一条规则：**一个特殊成员函数都不写**，把资源交给会自我管理的成员（`std::string` / `std::vector` / 智能指针，见 04 篇）。

```cpp
#include <iostream>
#include <string>
#include <utility>
#include <vector>

// Rule of Zero：不写任何特殊成员函数，拷贝/移动/析构全部自动正确
class Transcript {
public:
    Transcript(std::string speaker, std::vector<std::string> lines)
        : speaker_(std::move(speaker)), lines_(std::move(lines)) {}

    void show() const {
        std::cout << "  [" << speaker_ << "] " << lines_.size() << " 行\n";
    }

private:
    std::string speaker_;
    std::vector<std::string> lines_;
};

int main() {
    Transcript t1("asr", {"hello", "world"});
    Transcript t2 = t1;             // 拷贝：string/vector 自动深拷贝
    Transcript t3 = std::move(t1);  // 移动：string/vector 自动"偷"资源
    t2.show();
    t3.show();
    return 0;
}
```

预期输出：

```text
  [asr] 2 行
  [asr] 2 行
```

三条规则的分工：**Rule of Three** = 手写资源才需要（析构 + 拷贝构造 + 拷贝赋值，第 3 节的 `IntBuffer`）；**Rule of Five**（C++11 起）= 再加移动构造、移动赋值两个；**Rule of Zero** = 默认选择。Rule of Five 的完整实战见第 7 节，五个函数的签名一眼看全：

```cpp
~AudioBuffer();                            // 1) 析构
AudioBuffer(const AudioBuffer&);           // 2) 拷贝构造
AudioBuffer& operator=(const AudioBuffer&);// 3) 拷贝赋值
AudioBuffer(AudioBuffer&&) noexcept;       // 4) 移动构造（noexcept 见 06 篇）
AudioBuffer& operator=(AudioBuffer&&) noexcept; // 5) 移动赋值
```

## 5. `=default`、`=delete` 与 `explicit`

`= default` 明确采用编译器生成的版本（写了析构后想保留默认构造时必需）；`= delete` 禁止某个操作，编译器替你把关；`explicit` 禁止单参数构造函数的隐式转换——`set_gain(-3.0)` 悄悄把 `-3.0` 变成 `Decibels` 往往不是你想要的，宁可编译报错。

```cpp
class Engine {
public:
    Engine() = default;                      // 明确采用编译器生成的默认构造
    Engine(const Engine&) = delete;          // 禁止拷贝：引擎持有唯一的设备句柄
    Engine& operator=(const Engine&) = delete;
};
```

```cpp
#include <iostream>
#include <type_traits>

class Decibels {
public:
    explicit Decibels(double db) : db_(db) {}  // explicit：拒绝隐式转换
    double value() const { return db_; }

private:
    double db_;
};

void set_gain(Decibels db) { std::cout << "  增益 " << db.value() << " dB\n"; }

int main() {
    Decibels d(-6.0);          // OK：直接初始化
    set_gain(d);               // OK：类型完全匹配
    set_gain(Decibels(-3.0));  // OK：想转换就明确写出来
    // set_gain(-3.0);         // 编译错误：explicit 挡住 double 的隐式转换

    static_assert(!std::is_convertible_v<double, Decibels>,
                  "explicit 保证 double 不会隐式变成 Decibels");
    std::cout << "  static_assert 通过：不存在 double 的隐式转换\n";
    return 0;
}
```

预期输出：

```text
  增益 -6 dB
  增益 -3 dB
  static_assert 通过：不存在 double 的隐式转换
```

经验：**单参数构造函数默认加 `explicit`**，确有"字面量到处传"的需求再去掉。

## 6. `const` 正确性与运算符重载

`const` 是写给调用者的合同：**`const` 成员函数**（签名末尾）承诺不修改成员，`const` 对象只能调它们；**`const` 引用参数**不拷贝、只读、能接收临时对象；同名成员函数还能**按 `const` 重载**。`this` 在成员函数里是"当前对象自己的地址"（const 成员函数里是 `const T*`），`operator==` 就通过 `*this` 拿到自己。而 `operator<<` 的左操作数是 `std::ostream`，**不可能**是本类的成员函数，只能写成**友元**（有权访问 private 成员的外部函数）：

```cpp
class Waveform {
public:
    double peak() const;                     // const 成员函数：只读
    void normalize();                        // 非 const：要修改对象
    const std::vector<double>& samples() const;  // 只读视图
    std::vector<double>& samples();              // 按 const 重载：可写视图
};

void print_stats(const Waveform& w);  // const 引用参数：不拷贝、只读

class Clip {
public:
    bool operator==(const Clip& rhs) const {  // 成员运算符：左操作数是 *this
        return name_ == rhs.name_ && start_ms_ == rhs.start_ms_;
    }
    friend std::ostream& operator<<(std::ostream& os, const Clip& c) {
        return os << "Clip(" << c.name_ << " @" << c.start_ms_ << "ms)";
    }
private:
    std::string name_;
    int start_ms_;
};
```

用法：`std::cout << clip` 直接打印对象；`operator<<` 返回 `std::ostream&`，所以能像 `std::cout << clip << '\n'` 一样链式调用。

## 7. 综合实战：Rule of Five 的 `AudioBuffer`

所有知识合体：管理动态音频缓冲区的类，五个特殊成员函数一个不落（06 篇深挖移动的原理）。**这只是教学**——真实工程里 `std::vector<float>` 成员 + Rule of Zero 就够了。

```cpp
#include <algorithm>
#include <cstddef>
#include <iostream>
#include <utility>

class AudioBuffer {
public:
    AudioBuffer(std::size_t ch, std::size_t fr)
        : ch_(ch), fr_(fr), data_(new float[ch * fr]) {
        std::cout << "  构造 " << ch_ << "x" << fr_ << '\n';
    }

    ~AudioBuffer() {  // 1) 析构：唯一负责释放的地方
        if (fr_ == 0) std::cout << "  析构（空壳，被移动过）\n";
        else std::cout << "  析构 " << ch_ << "x" << fr_ << '\n';
        delete[] data_;
    }

    AudioBuffer(const AudioBuffer& o)  // 2) 拷贝构造：深拷贝
        : ch_(o.ch_), fr_(o.fr_), data_(new float[o.ch_ * o.fr_]) {
        std::copy(o.data_, o.data_ + ch_ * fr_, data_);
        std::cout << "  拷贝构造（深拷贝）\n";
    }

    AudioBuffer& operator=(const AudioBuffer& o) {  // 3) 拷贝赋值
        if (this == &o) return *this;               //    自赋值 a = a，直接返回
        float* fresh = new float[o.ch_ * o.fr_];    //    先分配成功（异常安全）
        std::copy(o.data_, o.data_ + o.ch_ * o.fr_, fresh);
        delete[] data_;                             //    再释放旧内存
        data_ = fresh; ch_ = o.ch_; fr_ = o.fr_;
        std::cout << "  拷贝赋值\n";
        return *this;                               //    支持 a = b = c 链式写法
    }

    AudioBuffer(AudioBuffer&& o) noexcept  // 4) 移动构造：偷指针，O(1)
        : ch_(o.ch_), fr_(o.fr_), data_(o.data_) {
        o.data_ = nullptr; o.ch_ = 0; o.fr_ = 0;  // 掏空对方
        std::cout << "  移动构造（只偷了指针）\n";
    }

    AudioBuffer& operator=(AudioBuffer&& o) noexcept {  // 5) 移动赋值
        if (this != &o) {
            delete[] data_;                     //    释放自己的旧资源
            data_ = o.data_; ch_ = o.ch_; fr_ = o.fr_;
            o.data_ = nullptr; o.ch_ = 0; o.fr_ = 0;  // 掏空对方
            std::cout << "  移动赋值（只偷了指针）\n";
        }
        return *this;
    }

    std::size_t frames() const { return fr_; }

private:
    std::size_t ch_, fr_;
    float* data_;
};

int main() {
    AudioBuffer src(2, 1024);           // 构造
    AudioBuffer copied = src;           // 拷贝构造
    AudioBuffer other(1, 16);
    copied = other;                     // 拷贝赋值（两个具名对象之间）
    AudioBuffer moved = std::move(src); // 移动构造：src 变成空壳
    copied = AudioBuffer(4, 2048);      // 右侧是临时对象 -> 移动赋值（06 篇解释）
    AudioBuffer& ref = copied;
    copied = ref;                       // 自赋值：安全，无输出
    return 0;
}
```

预期输出（末四行按声明相反顺序析构，`空壳` 就是被掏空的 `src`）：

```text
  构造 2x1024
  构造 1x16
  拷贝构造（深拷贝）
  拷贝赋值
  移动构造（只偷了指针）
  构造 4x2048
  移动赋值（只偷了指针）
  析构（空壳，被移动过）
  析构 2x1024
  析构 1x16
  析构 4x2048
  析构（空壳，被移动过）
```

读点：拷贝赋值**先 `new` 成功再 `delete` 旧内存**（反过来，分配失败时对象已残废）；自赋值检查 `this == &other`（`a = a` 时先删自己再抄自己必崩）；移动操作把对方**掏空**——被移动后的对象是"合法但内容未指定"的空壳，只能赋新值或销毁。

## 8. 常见坑

- **写了析构就丢掉隐式移动**：编译器不再隐式生成移动构造/赋值，`std::move` 后退化为深拷贝——要么补齐 Rule of Five，要么 Rule of Zero。
- **浅拷贝不一定马上崩**：两对象共享内存可能"没事"跑很久，直到一方析构、另一方悬空；测试用 `-fsanitize=address` 当场抓。
- **拷贝赋值忘记自赋值检查**，或先 `delete` 后 `new`（分配失败时对象已残废）。
- **初始化顺序想当然**：列表里写 `b_(a_ + 1)` 不代表 `a_` 先初始化——只看声明顺序。
- **`explicit` 忘加**：隐式转换悄悄通过，单位/参数张冠李戴。
- **`operator<<` 试图写成成员函数**：左操作数是流不是本类，必须友元或普通函数。

## 9. 小结

- `struct` 默认 public（数据聚合），`class` 默认 private（有不变式）；初始化列表是"初始化"不是"赋值"，`const`/引用成员只能用它，实际顺序 = 声明顺序。
- 编译器默认逐成员拷贝对裸指针是浅拷贝；手写资源就要凑齐 Rule of Three/Five，能 Rule of Zero 就 Zero。
- `=default`/`=delete`/`explicit` 是精修工具，`const` 是调用者能依赖的合同。

## 10. 自测题

1. 只手写了析构函数的类，`std::move` 之后会发生什么？
   <details><summary>答案</summary>
   编译器不再隐式生成移动构造/赋值，重载决议选中拷贝构造——本想 O(1) 的移动退化成 O(n) 深拷贝。要么补齐 Rule of Five，要么 Rule of Zero。
   </details>

2. 拷贝赋值里为什么"先 new 成功、再 delete 旧内存"，而不是反过来？
   <details><summary>答案</summary>
   若先 delete 再 new，`new` 抛 `bad_alloc` 时数据指针已悬空，对象残废。先分配成功，中途任何异常都不影响原对象完整性（异常安全的基本功）。
   </details>

3. 为什么 `operator<<` 不能写成 `Clip` 的成员函数？
   <details><summary>答案</summary>
   成员函数的左操作数永远是本类对象（`*this`），而 `std::cout << clip` 的左操作数是 `std::ostream`。必须是友元/普通函数：`std::ostream& operator<<(std::ostream&, const Clip&)`。
   </details>
