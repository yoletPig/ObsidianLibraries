## 1. 为什么需要模板：一次编写，处处适用

Python 里你写 `min(a, b)`，从不关心 a、b 是 int 还是 float——类型是运行时的事。C++ 是静态类型语言，朴素做法只能靠重载复制粘贴：

```cpp
int    min_i(int a, int b)    { return a < b ? a : b; }
double min_d(double a, double b) { return a < b ? a : b; }
// float、long long……无限套娃
```

逻辑一字不差，只有类型不同。**函数模板**让编译器替你做这份复制工作：你写一份带类型占位符 `T` 的代码，编译器在每次调用时按实参类型生成一份真正的函数（这个过程叫**实例化**）。

这就是 `std::min`、`std::sort`、`std::accumulate`（第 08 篇用过的所有算法）能服务任意类型的机制。语音/推理引擎里同样到处是模板：whisper.cpp 的向量运算、dr_wav 之外的各类采样格式转换，都是"一份逻辑，float/int16 多种实例"。

## 2. 基本语法：template、typename 与 class

```cpp
// 09_ex1_min.cpp
#include <iostream>

// 函数模板：T 是类型占位符，等调用时由实参推导（或显式指定）
template <typename T>
T my_min(T a, T b) {
    return (a < b) ? a : b;
}

int main() {
    std::cout << my_min(2, 3) << '\n';            // 隐式：T 推导为 int
    std::cout << my_min<double>(2, 3.4) << '\n';  // 显式：T = double，2 被转换
    std::cout << my_min('a', 'b') << '\n';        // T 推导为 char
    // my_min(2, 3.4);   // 编译错误：T 推导出 int 和 double 两个候选，冲突。
                        // 模板不做隐式转换来"调和"两个实参。
}
```

预期输出：

```
2
2
a
```

要点：

- `template <typename T>` 声明了一个类型参数 `T`（作用域只到这个函数结尾）。`class T` 与 `typename T` 在这里**完全等价**——旧教材常写 `class`，现代风格统一用 `typename`，因为 `class` 容易让人误以为只能传类类型（其实 `my_min(2, 3)` 的 T 是 int，照样行）。
- **隐式调用**：`my_min(2, 3)` 让编译器从实参推导 `T = int`。
- **显式调用**：`my_min<double>(2, 3.4)` 手动指定 `T = double`，此时普通函数的隐式转换规则生效（`2` 转成 `double`）。
- 关键限制：**推导阶段不做隐式转换**。`my_min(2, 3.4)` 推导出两个矛盾的 `T`，直接编译失败——要么显式指定类型，要么自己在调用点转好。

## 3. 模板 vs 同名普通函数：重载决议的差异

当模板和普通函数同名共存时，编译器的挑选规则里最重要的一条差异是：**普通函数的实参可以做隐式转换，模板只能"精确匹配"（实参类型决定 T，不做二次转换）**。完整优先级：精确匹配的普通函数 > 精确匹配的模板 > 需要转换的普通函数。

```cpp
// 09_ex2_overload.cpp
#include <iostream>

template <typename T>
T max_of(T a, T b) {
    std::cout << "[模板]     ";
    return (a > b) ? a : b;
}

// 与模板同名的普通函数：它的实参允许隐式转换
double max_of(double a, double b) {
    std::cout << "[普通函数] ";
    return (a > b) ? a : b;
}

int main() {
    std::cout << max_of(1.5, 2.5) << '\n';   // 两个候选都精确匹配 → 普通函数优先
    std::cout << max_of(3, 4) << '\n';       // 模板精确匹配；普通函数要 int→double → 模板赢
    std::cout << max_of(3, 4.5) << '\n';     // 模板推导冲突（int/double）；普通函数可行 → 普通函数
    std::cout << max_of<>(3, 4) << '\n';     // 尖括号：只在模板里挑 → 强制走模板
}
```

预期输出：

```
[普通函数] 2.5
[模板]     4
[普通函数] 4.5
[模板]     4
```

逐条解释：

1. `max_of(1.5, 2.5)`：模板能推导出 `T = double`（精确匹配），普通函数也是精确匹配——**普通函数胜出**。这是最反直觉的一条：明明模板"更专用"，但同分时普通函数优先。
2. `max_of(3, 4)`：模板推导 `T = int` 精确匹配；普通函数要把两个 int 转成 double（次一等）——**模板胜出**。
3. `max_of(3, 4.5)`：模板推导冲突，直接出局；普通函数靠隐式转换接盘——**普通函数**。
4. `max_of<>(3, 4)`：空的尖括号意思是"我知道有模板，只在模板里选"——**模板**。排查重载问题时用它强制二分。

旧课堂笔记里"模板不做隐式转换"这句话是对的，但要补全另一半：普通函数做转换的能力恰恰让它在混合类型调用中"兜底"成功，这正是第 3 条输出走普通函数的原因。

## 4. 全特化：为某个具体类型重写一份

主模板对 `const char*` 是错的：`a > b` 比较的是**指针地址**，不是字符串内容。办法是给这个类型写一份**全特化**——`template <>` 开头、把 T 全部落实：

```cpp
// 09_ex3_specialize.cpp
#include <cstring>
#include <iostream>
#include <string>

template <typename T>
T max_of(T a, T b) {
    return (a > b) ? a : b;
}

// 全特化：为 const char* 单独提供实现（按字符串内容比较，而不是比较指针地址）
template <>
const char* max_of<const char*>(const char* a, const char* b) {
    std::cout << "[特化] ";
    return (std::strcmp(a, b) >= 0) ? a : b;
}

int main() {
    std::cout << max_of(3, 9) << '\n';                    // 主模板
    std::cout << max_of(std::string("abc"), std::string("abd")) << '\n';

    // 字面量 "apple" 是 const char[6]，"banana" 是 const char[7]，
    // 不显式指定 T 就会推导冲突，所以要写 max_of<const char*>(...)
    std::cout << max_of<const char*>("apple", "banana") << '\n';

    const char* s1 = "xbv";
    const char* s2 = "xyce";
    std::cout << max_of(s1, s2) << '\n';                  // T = const char*，自动命中特化
}
```

预期输出：

```
9
abd
[特化] banana
[特化] xyce
```

规则：程序中同时存在主模板和它的特化时，**特化优先被选中**（最后一行没写 `<const char*>`，也自动命中了特化）。但注意第 4 篇讲过的教训：与其对裸指针做特化，不如接口上直接用 `std::string` / `std::string_view`，让这个特化根本不需要存在。

## 5. decltype 与尾置返回类型

问题：`add(T1 a, T2 b)` 的返回类型是什么？是 `T1`？`T2`？都不是——它取决于 `a + b` 这个表达式，而表达式在函数签名处还不可见。C++11 的解法是**尾置返回类型 + decltype**：

```cpp
// 09_ex4_decltype.cpp
#include <iostream>
#include <string>

// 返回类型依赖两个参数类型的组合，写函数时还不知道它是什么：
// 用尾置返回类型 + decltype 让编译器"照着表达式推"
template <typename T1, typename T2>
auto add(T1 a, T2 b) -> decltype(a + b) {
    decltype(a + b) s = a + b;   // decltype 也可以用来声明同类型变量
    return s;
}

int main() {
    std::cout << add(1, 2) << '\n';                     // int + int → int
    std::cout << add(1, 2.5) << '\n';                   // int + double → double
    std::cout << add(std::string("he"), "llo") << '\n'; // string + const char* → string
    std::cout << add(1, 2.5f) << '\n';                  // int + float → float（按 double 打印）
}
```

预期输出：

```
3
3.5
hello
3.5
```

语法拆解：`auto add(...) -> decltype(a + b)` 读作"返回类型写在参数列表后面，由表达式 `a + b` 的类型决定"。`decltype` 只查类型不求值。

> **旧课堂笔记里的编译错误**：同样的示例曾把变量声明了两遍——
> ```cpp
> decltype(x + y) z = x + y;
> auto z = x + y;      // 错误：z 重复定义，编译不过
> ```
> 一个变量只能定义一次，两种写法二选一。本文示例已修正为只保留 `decltype(a + b) s = a + b;`。
> 另外注意 C++14 起单 `return` 的函数可以直接写 `auto` 返回让编译器从 return 语句推导，但**多 return 路径类型必须一致**，否则编译错误；尾置 decltype 则是显式约定，更稳。

## 6. C++17 新能力一：CTAD 类模板实参推导

第 08 篇之前你已经习惯了函数模板自动推导——`std::count_if` 从没让你写过 `<float>`。但**类模板**一直要手写：`std::pair<int, double> p(1, 3.14);`。C++17 的 **CTAD**（Class Template Argument Deduction）把函数模板的推导体验带到了类模板上：

```cpp
// 09_ex5_ctad.cpp
#include <iostream>
#include <string>
#include <utility>

// 回顾：函数模板的实参推导早就自动化了
template <typename T>
T twice(T x) {
    return x + x;
}

// 自定义类模板：构造函数能拿到实参，C++17 就能自动推导
template <typename T>
class Holder {
public:
    explicit Holder(T v) : v_(std::move(v)) {}
    const T& value() const { return v_; }
private:
    T v_;
};

int main() {
    std::cout << twice(21) << '\n';

    std::pair<int, double> p1(1, 3.14);   // C++17 之前的唯一写法：手写实参
    std::pair p2(1, 3.14);                // C++17 CTAD：推导为 std::pair<int, double>
    std::pair p3(std::string("age"), 18); // std::pair<std::string, int>

    Holder h(42);                         // 推导为 Holder<int>（来自构造函数实参）

    std::cout << p2.second << ' ' << p3.first << ' ' << h.value() << '\n';
}
```

预期输出：

```
42
3.14 age 42
```

逻辑是一致的：**函数模板靠调用实参推导，类模板靠构造函数实参推导**。构造函数"看不到"实参的场合（比如想要 `Stack<std::string>` 但构造时不传元素），需要自己写推导指引——完整讨论见第 10 篇。

## 7. C++17 新能力二：auto 非类型模板参数

模板参数不只有类型。`std::array<int, 1024>` 的 `1024` 就是**非类型模板参数**——编译期常量。C++17 之前必须先声明它的类型（`template <int N>`）；C++17 允许写 `auto`，让值自己决定类型：

```cpp
// 09_ex6_auto_nttp.cpp
#include <iostream>

// C++17 之前，非类型模板参数必须先声明具体类型（template <int N> ...）。
// C++17 允许写 auto，让"值"自己决定自己的类型。
template <auto N>
struct Constant {
    static constexpr auto value = N;
};

int main() {
    std::cout << Constant<42>::value << '\n';    // N 是 int
    std::cout << Constant<256u>::value << '\n';  // N 是 unsigned
    std::cout << Constant<'x'>::value << '\n';   // N 是 char
    std::cout << sizeof(Constant<true>::value) << '\n';  // N 是 bool → 1 字节
    // 注意：C++17 的非类型参数仍不支持浮点数和字符串字面量（C++20 才放开）
}
```

预期输出：

```
42
256
x
1
```

一个模板同时接纳 int / unsigned / char / bool，不再需要为每种非类型写一个版本。推理引擎里"通道数、帧长、块大小"这类编译期常量，现在可以 `template <auto N>` 一把梭。

## 8. C++17 新能力三：折叠表达式与变参模板

**变参模板**（variadic template）用一个参数包 `Args...` 接住任意数量的实参。C++17 之前想对包做加法，得写递归展开；C++17 的**折叠表达式**一行搞定：

```cpp
// 09_ex7_fold.cpp
#include <iostream>

// 变参模板：Args... 是一包类型，args... 是一包实参。
// 折叠表达式 (args + ... + 0) 让编译器展开成 ((a1 + a2) + a3) + 0。
// 初始值 0 保证了空包 sum() 也能编译、返回 0。
template <typename... Args>
auto sum(Args... args) {
    return (args + ... + 0);
}

// 逗号折叠：对每个实参依序执行一条语句（sep 技巧保证末尾不带空格）
template <typename... Args>
void print_all(const Args&... args) {
    const char* sep = "";
    ((std::cout << sep << args, sep = " "), ...);
    std::cout << '\n';
}

int main() {
    std::cout << sum() << '\n';          // 空包 → 0
    std::cout << sum(1, 2, 3) << '\n';   // 6
    std::cout << sum(1, 2, 3.5) << '\n'; // 6.5（int 提升后与 double 相加）
    print_all(1, 2.5, "voice", 'x');
}
```

预期输出：

```
0
6
6.5
1 2.5 voice x
```

语法速记：`(pack op ... )` 一元折叠，`(pack op ... op init)` 带初始值的二元折叠。`(args + ... + 0)` 中那个 `0` 很关键——没有它，`sum()` 空包展开后是空的，编译错误；有它，空包返回 0。逗号折叠 `(f(x), ...)` 则是把"对每个参数做一遍某事"展开成逗号分隔的语句序列。

## 9. C++17 新能力四：if constexpr 编译期分支

模板里最经典的痛点：某些分支只对部分类型合法。普通 `if` 要求**所有分支对所有实例都能编译**；`if constexpr` 在**编译期**选分支，被丢弃的分支不参与编译：

```cpp
// 09_ex8_ifconstexpr.cpp
#include <iostream>
#include <string>
#include <type_traits>

// if constexpr：条件在编译期求值，被丢弃的分支不参与编译（连语法都只做最低限度检查）。
// 一份模板同时服务多种类型，不再需要为每种类型写特化。
template <typename T>
const char* size_class(const T&) {
    if constexpr (sizeof(T) <= 8) {
        return "小对象(<=8字节)";
    } else {
        return "大对象(>8字节)";
    }
}

// 更实用的例子：只有整型才能安全转 long long，其他类型返回 -1 表示不支持。
// 若用普通 if，static_cast<long long>(v) 对 std::string 编译不过；
// if constexpr 把另一个分支整个丢掉，对不支持的类型也编译通过。
template <typename T>
long long to_int(const T& v) {
    if constexpr (std::is_integral_v<T>) {
        return static_cast<long long>(v);
    } else {
        return -1;
    }
}

int main() {
    std::cout << size_class(42) << '\n';
    std::cout << size_class(3.14) << '\n';
    std::cout << size_class(std::string("voice")) << '\n';  // libstdc++ 下 string 是 32 字节
    std::cout << to_int(7) << '\n';
    std::cout << to_int(3.9) << '\n';
}
```

预期输出：

```
小对象(<=8字节)
小对象(<=8字节)
大对象(>8字节)
7
-1
```

两个分支的条件都是**编译期**知道的：`sizeof(T)` 是编译期常量，`std::is_integral_v<T>` 是类型 traits。这在音频/推理代码里极其常用——比如"样本是 float 就直接用，是 int16 就先转 float"可以在一个模板里写完，而不是为每种样本格式写一份特化。

## 10. 为什么模板代码要放头文件

一句话：**模板不是代码，是生成代码的配方；编译器在实例化点必须看到完整配方**（模板的两阶段查找——第一阶段查模板定义里与参数无关的名字，第二阶段在实例化时才查依赖参数的名字——决定了依赖 `T` 的名字在定义处不能先假设）。

由此产生的经典链接错误：

```cpp
// ---- math_utils.h ----
template <typename T>
T square(T x);              // 只声明，没定义

// ---- main.cpp ----
#include "math_utils.h"
int main() { square(2); }   // 需要 square<int>，配方不全 → 编译通过，链接失败
// main.cpp:(.text+0x...): undefined reference to `int square<int>(int)'
```

编译器在 main.cpp 里实例化 `square<int>` 时只有声明，以为"这个函数在别的翻译单元里定义了"，于是留给链接器；而链接器永远找不到它。三种解法：

1. **首选：定义直接放头文件里**。这正是所有标准库头文件里全是模板实现、看不到 `.cpp` 的原因——模板定义放在头文件不算违反"声明在头、定义在源"的惯例。
2. 在使用它的那个 `.cpp` 里显式实例化：`template int square<int>(int);`（适合实例种类少且固定的场合）。
3. 定义放到 `.cpp` 并在那个文件里集中显式实例化所有需要的版本（可以缩短编译时间，代价是维护清单）。

## 常见坑

- **`my_min(2, 3.4)` 推导冲突**。模板不做隐式转换调和实参；显式指定 `my_min<double>(2, 3.4)` 或在调用点自己转换。
- **对 C 字符串写 `max_of("apple", "banana")`**。字面量类型是 `const char[6]` 和 `const char[7]`，数组长度参与类型，推导冲突。传 `std::string` / `std::string_view` 才是正路。
- **以为 `class T` 只能传类**。与 `typename` 等价，int、指针都行。
- **在 if/for 等语句块里定义模板**。模板必须定义在命名空间作用域，不能写在函数体内。
- **模板定义放 `.cpp` 导致 undefined reference**。见第 10 节；新手最常踩，报错出现在链接阶段而非编译阶段，容易懵。
- **`if constexpr` 丢弃分支里仍然不能有"语法级"错误**（如缺分号），且两个分支若是模板体内的不同 return 类型，要保证所选分支类型匹配。它是编译期剪枝，不是语法免检。

## 小结

- 函数模板 = 带类型占位符的配方，调用时**实例化**出具体函数；`typename`/`class` 等价，现代风格用 `typename`。
- 重载决议：精确匹配的普通函数 > 精确匹配的模板 > 需隐式转换的普通函数；`f<>(...)` 强制只在模板中选。
- 全特化 `template <>` 为具体类型整体重写；`decltype` + 尾置返回类型解决"返回类型依赖实参表达式"。
- C++17 四件套：**CTAD**（类模板也自动推导）、`template <auto N>`（非类型参数自动定型）、**折叠表达式**（变参一行展开）、**if constexpr**（编译期分支，取代大量特化样板）。
- 模板定义放头文件：实例化点必须看到完整配方，否则链接期 `undefined reference`。

## 自测题

1. `template <typename T> T f(T a, T b);` 与普通函数 `double f(double, double)` 共存，调用 `f(1, 2)` 和 `f(1, 2.5)` 各走哪个？
2. `my_min(3, 4.0)` 为什么编译失败？给出两种修法。
3. `(args + ... + 0)` 里最后的 `0` 去掉会发生什么？什么时候会暴露？
4. `if constexpr` 的条件可以是运行期变量吗？
5. 模板定义写在 `.cpp` 里、头文件里只有声明，别的 `.cpp` 一调用就报 `undefined reference`，为什么？最推荐的解法是什么？

**答案**

1. `f(1, 2)` 走**模板**（`T = int` 精确匹配，普通函数需要 int→double 转换）；`f(1, 2.5)` 走**普通函数**（模板推导冲突出局，普通函数靠隐式转换接盘）。
2. 编译器为 T 推导出 `int` 和 `double` 两个矛盾结果，模板不做隐式转换调和。修法一：显式指定 `my_min<double>(3, 4.0)`；修法二：调用点统一类型，如 `my_min(3.0, 4.0)`。
3. `(args + ...)` 变成一元折叠，空参数包时展开结果为空，`sum()` 无法产生返回值，**编译错误**；只要从未以空包调用，平时不会暴露，属于埋雷写法。
4. 不行。条件必须是编译期常量表达式（如 `sizeof(T)`、`std::is_integral_v<T>`）；运行期条件请用普通 `if`。
5. 模板实例化发生在调用点所在的编译单元，那里只看到声明没有定义，编译器只好把符号留给链接器，而定义所在的 `.cpp` 从未实例化过这个版本，于是链接失败。首选把模板定义直接放进头文件。
