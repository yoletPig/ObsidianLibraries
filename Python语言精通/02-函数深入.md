# 02 - 函数深入

## 本篇目标

1. 把"**函数是一等公民**"落到实处：函数可以赋值、传参、返回、存进容器——这是理解装饰器（03 篇）的前提；
2. 彻底搞懂**默认参数在 `def` 时求值一次**：可变默认参数陷阱是 Python 面试出场率最高的问题，也是真实事故源；
3. 掌握**闭包与变量捕获**：闭包捕获的是变量（名字绑定）而非值，会写会用 `nonlocal`，并解释 late binding 陷阱；
4. 会用 `*args/**kwargs` 转发参数、用 `__name__`/`__doc__`/`__defaults__` 等做函数内省。

## 1. 函数是一等公民

"一等公民（first-class）"指的是：函数和 `int`、`str` 一样是普通对象——可以绑定到名字、存入容器、作为参数传递、作为返回值。Python 官方 FAQ 与《Fluent Python》第 7 章都以此为核心。

```python
>>> def add(a, b):
...     return a + b
>>> def mul(a, b):
...     return a * b
>>> ops = {"add": add, "mul": mul}   # ① 存入字典（Agent 工具注册的原型！）
>>> ops["add"](3, 4)                 # 取出后直接调用
7
>>> import math
>>> sqrt = math.sqrt                 # ② 绑定到新名字
>>> sqrt(16)
4.0
>>> list(map(mul, [1, 2, 3], [10, 20, 30]))  # ③ 作为参数传给高阶函数
[10, 40, 90]
>>> def make_adder(n):               # ④ 作为返回值（工厂函数）
...     def inner(x):
...         return x + n
...     return inner
>>> plus5 = make_adder(5)
>>> plus5(3)
8
>>> type(plus5), plus5.__name__
(<class 'function'>, 'inner')
```

因为函数是对象，它有自己的属性和类型（`function` 类型本身可调用——01 篇说过"一切皆对象"）。**高阶函数**（接受或返回函数的函数）因此成为 Python 的常规武器：`map`/`sorted(key=...)`/`functools.reduce`，以及 03 篇的装饰器，全都建立在本节之上。

## 2. 默认参数：def 时求值一次（经典面试题）

这是 Python 语义中最容易被误解的一条：**默认值表达式在 `def` 语句执行时求值一次，得到的结果对象被存进函数对象，之后所有调用共享**（Python 官方 Tutorial 第 8 章 "More on Defining Functions" 明确写道："default values are evaluated at the point of function definition"）。

```python
>>> import time
>>> def log(msg, ts=time.time()):    # ts 在 def 那一刻定格
...     return f"{ts:.2f}: {msg}"
>>> time.sleep(0.1)
>>> log("a") == log("b")             # 两次调用的 ts 是同一个值
True
>>> log.__defaults__                 # 默认值就挂在函数对象上
(1719300000.123,)
```

**可变默认参数陷阱**——默认值若是 `[]`、`{}` 这类可变对象，跨调用被共享并污染：

```python
# 反例：这是真实事故的经典形态
def add_item(item, items=[]):        # ❌ 默认 [] 只创建一次
    items.append(item)
    return items

add_item(1)      # [1]
add_item(2)      # [1, 2]  ← 预期 [2]，实际累计了！同一个列表被共享
add_item(3)      # [1, 2, 3]

# 正解：哨兵 None + 函数体内创建
def add_item(item, items=None):      # ✅ None 不可变，当哨兵
    if items is None:
        items = []                   # 每次调用新建列表
    items.append(item)
    return items

add_item(1)      # [1]
add_item(2)      # [2]  ✓
```

为什么写成 `items=None` 是正确姿势：`None` 是单例且不可变，不可能被"共享后污染"；函数体内每次新建所需的可变对象。判断某函数是否有此隐患，一条命令即可：

```python
>>> def bad(x=[]): ...
>>> bad.__defaults__                 # 可变对象藏在这里
([],)
```

**经验做法**：代码评审看到 `def f(x=[], y={}, z=set())` 直接打回；团队可配置 ruff 规则 `B006`（flake8-bugbear 移植规则）在 CI 里自动拦截（14 篇工具链）。

## 3. 闭包与变量捕获

**闭包（closure）**：内层函数引用了外层函数作用域中的名字，且内层函数在外层返回后仍可被调用——它把"函数 + 该函数所需的自由变量环境"打包在了一起。被引用的外层名字存在内层函数的 `__closure__` 属性中（cell 对象）。

```python
>>> def counter():
...     n = 0                        # 自由变量：被 inner 引用
...     def inc():
...         nonlocal n               # 声明：n 指向外层函数的那个 n
...         n += 1
...         return n
...     return inc
>>> c1, c2 = counter(), counter()    # 每次调用 counter 产生独立环境
>>> c1(), c1(), c1()
(1, 2, 3)
>>> c2()                             # c2 的 n 是另一个 cell
1
>>> c1.__closure__                   # cell 对象持有 n 的当前值
(<cell at 0x...: int object at 0x...>,)
```

关键心智模型（承接 01 篇 LEGB）：**闭包捕获的是"变量"（名字与它的绑定环境），不是"变量当时的值"**。两个推论：

**推论一：没有 `nonlocal` 就不能重新绑定**，但可以**原地修改**可变对象（因为那不是重新绑定，只是顺着引用改对象）：

```python
def make_box():
    items = []
    def add(x):
        items.append(x)              # 原地修改：不需要 nonlocal
        return items
    return add
```

**推论二：循环内创建闭包 → late binding 陷阱。** 闭包存储的是名字，真正**调用时**才去取值——如果那时循环变量已经指到最后一个值，所有闭包都"迟到"了：

```python
funcs = []
for i in range(3):
    funcs.append(lambda: i)          # lambda 体引用名字 i，不在此时求值

[f() for f in funcs]                 # [2, 2, 2]  ← 全部读到循环结束后的 i
```

正解是用默认参数在**定义时**把当前值固定下来（默认值 def 时求值——本篇第 2 节的知识在这里反而成了工具）：

```python
funcs = []
for i in range(3):
    funcs.append(lambda i=i: i)      # 默认参数捕获"定义时的 i"

[f() for f in funcs]                 # [0, 1, 2]  ✓
```

同理的变体是"循环里用闭包引用外部可变循环变量"的 `async` 场景（`for task in tasks: asyncio.create_task(worker(task))` 里 task 变量），09 篇会再遇到它。

## 4. *args 与 **kwargs：参数转发与解包

规则（《Fluent Python》第 5 章 + 官方文档 Expressions → Calls）：

- `*args` 收集多余的**位置参数**为元组；`**kwargs` 收集多余的**关键字参数**为字典；
- 定义时是"收集"，调用时是"解包"：`f(*lst, **dct)` 把容器摊开成参数；
- 形参顺序固定为：位置参数 → `*args` → 仅关键字参数（keyword-only）→ `**kwargs`。

```python
>>> def report(a, b=0, *rest, scale=1, **opts):
...     return (a, b, rest, scale, opts)
>>> report(1, 2, 3, 4, scale=10, tag="x")
(1, 2, (3, 4), 10, {'tag': 'x'})
```

最常用、也最有价值的模式是**参数转发（forwarding）**——包装函数把一切参数原样转交内层函数，这是 03 篇通用装饰器的技术基础：

```python
import functools

def logged(func):
    @functools.wraps(func)           # 03 篇解释为什么必须有这一行
    def wrapper(*args, **kwargs):    # 收：无论 func 怎么定义都能接住
        print(f"call {func.__name__}, args={args}, kwargs={kwargs}")
        return func(*args, **kwargs) # 传：原样解包转发
    return wrapper

@logged
def create_user(name, *, role="member", tags=None):
    ...

create_user("alice", role="admin")   # call create_user, args=('alice',), kwargs={'role': 'admin'}
```

仅关键字参数（`*` 之后）是**经验做法**：布尔开关、可选项用 `*, force=False` 强制写关键字调用，调用点可读性大增，API 演化时也不怕位置参数错位。3.8+ 还有 `/` 声明仅位置参数（PEP 570），用于"参数名只是占位、不承诺稳定"的场合。

## 5. 函数内省：函数对象上有什么

函数是对象，元数据都挂在上面。读写它们，就能做出"理解自己"的代码（框架与装饰器的原材料）：

```python
>>> def create_user(name, role="member", *, active=True):
...     """创建用户。"""
...     ...
>>> create_user.__name__          # 函数名（改名的装饰器若不修复会暴露 wrapper）
'create_user'
>>> create_user.__doc__           # 文档字符串
'创建用户。'
>>> create_user.__defaults__      # 位置/关键字默认值（只含 '=' 之前的）
('member',)
>>> create_user.__kwdefaults__    # 仅关键字参数的默认值
{'active': True}
>>> import inspect
>>> inspect.signature(create_user)         # 完整签名（类型注解也在里面）
<Signature (name, role='member', *, active=True)>
>>> dict(inspect.signature(create_user).parameters).keys()
dict_keys(['name', 'role', 'active'])
```

`inspect.signature` 是官方推荐的签名读取方式（文档：inspect 模块），Agent 框架普遍用它把函数签名转成工具的 JSON Schema：遍历 `parameters`，按注解映射参数类型，按 `__doc__` 取描述。一个迷你示例：

```python
import inspect

def to_schema(func):
    """把函数签名转成简易 JSON Schema（LLM 工具定义的原型）。"""
    props = {}
    for name, p in inspect.signature(func).parameters.items():
        anno = p.annotation
        props[name] = {
            "type": getattr(anno, "__name__", "string").lower(),
            "required": p.default is p.empty,     # 没默认值 = 必填
        }
    return {"name": func.__name__, "parameters": props}

def get_weather(city: str, days: int = 3): ...
print(to_schema(get_weather))
# {'name': 'get_weather', 'parameters': {'city': {'type': 'str', 'required': True},
#  'days': {'type': 'int', 'required': False}}}
```

**经验做法**：给函数写好 `__doc__`（首行一句话说明用途）与类型注解，等于免费获得了文档、IDE 补全和工具元数据三件套；凡是"包装了别的函数"的代码（装饰器、代理），用 `functools.wraps` 修复元数据，否则内省到的都是 `wrapper`。

## 常见陷阱

**陷阱一：可变默认参数**（第 2 节详述）。检查方式 `f.__defaults__` 里有没有 list/dict/set；修复方式哨兵 `None`。

**陷阱二：闭包 late binding**（第 3 节详述）。循环里创建 lambda/闭包并"稍后调用"时，九成会踩；修复方式 `lambda i=i: ...` 或 `functools.partial(func, i)`。

**陷阱三：以为默认值每次调用都重新求值，把 `datetime.now()`/`random.random()`/`uuid.uuid4()` 写进默认值**——结果所有调用拿到同一个时间/随机数/ID：

```python
def make_user(name, uid=uuid.uuid4()):   # ❌ 所有用户的 uid 相同！
    ...
def make_user(name, uid=None):           # ✅
    return uuid.uuid4() if uid is None else uid
```

**陷阱四：在闭包里读外层可变名字但忘了它是延迟读取**，比如在 `for` 循环中 `create_task` 后任务读到的循环变量不是"创建那一刻"的值——同 late binding，正解同上（固定进默认参数或用 `partial`）。

**陷阱五：`lambda` 里塞复杂逻辑还试图赋值**（`f = lambda x: ...`）。PEP 8 明确反对"Assigning a lambda to an identifier"——它抹掉了函数名（`__name__` 变成 `<lambda>`），栈跟踪难读；超过一个表达式的逻辑写成 `def`。

## 本篇小结

- 函数是一等对象：可赋值、入容器、作参数、作返回值；`ops = {"add": add}` 这种字典分发就是 Agent 工具注册的原型；
- **默认值在 `def` 时求值一次**并存在 `__defaults__`：可变默认参数跨调用共享，正解哨兵 `None`；
- 闭包捕获**变量而非值**：重新绑定需 `nonlocal`；循环闭包 late binding 用默认参数固化；
- `*args/**kwargs` 定义时收集、调用时解包，是参数转发与通用装饰器的基石；
- 内省三件套：`__name__/__doc__/__defaults__` 手工看，`inspect.signature` 程序化读——框架把签名变成工具 Schema 就是这么来的。
