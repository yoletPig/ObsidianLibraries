## 1. 类型注解基础：注解是给检查器看的

**核心原则：注解默认对运行时零影响**（PEP 484 开篇即言 "type annotations should not impose any runtime overhead"）——函数照常能传任何类型的参数，注解只是元数据，静态检查器（mypy/pyright）据此在**运行前**发现类型错误。类型检查是可选的（PEP 484 的"gradual typing"理念）：可以逐函数、逐模块渐进引入。

```python
def process_batch(items: list[str], limit: int | None = None) -> list[str]:
    """PEP 585（3.9+）：内置类型直接当泛型用。"""
    out = items[:limit] if limit is not None else items
    return [x.strip().lower() for x in out]

>>> process_batch(["Hi ", "YO"], 1)
['hi']
```

历史演变要记住，否则会写出过时代码：

- **PEP 585（3.9+）**：`list[int]`、`dict[str, int]`、`tuple[int, ...]` 内置泛型**取代** `typing.List`/`Dict`（后者仍可用但已过时，官方文档 typing 页明确建议用内置形式）；
- **PEP 604（3.10+）**：`int | None`、`str | bytes` 管道联合**取代** `Optional[int]`/`Union[str, bytes]`（语义完全等价）；
- `tuple[int, ...]` 表示"任意长度 int 元组"，`tuple[int, str]` 表示"恰好两个元素"；
- `Callable[[int, str], bool]` 描述函数类型；`Any` 放弃检查；`object` 是"真的任何对象"（比 Any 严格：只能用 object 共有方法）。

**经验做法**：新代码一律 `list[str]`/`X | None`；维护老库遇到 `typing.List` 能顺手改就改（ruff 规则 `UP` 系列，pyupgrade 自动化，14 篇）。

`Optional` 的语义陷阱要单独强调：**`Optional[int]` 不是"参数可选"（那是默认值的事），而是"值可以是 None"**——它与 `int | None` 完全等价。

## 2. TypeVar 与 Protocol：泛型与静态鸭子类型

**TypeVar：跨位置的"同类型"约束**。最常见于"输入输出同型"或"容器元素类型保持"：

```python
from typing import TypeVar

T = TypeVar("T")

def first(items: list[T]) -> T:
    """返回第一个元素；输入 list[int] 则输出一定是 int。"""
    return items[0]

>>> first([1, 2, 3])     # T 被推断为 int
1
>>> first(["a", "b"])    # T 被推断为 str
'a'

from collections.abc import Callable

def apply(fn: Callable[[T], T], value: T) -> T:
    return fn(value)
```

约束型 TypeVar 限定取值范围：`T = TypeVar("T", bound=float)`（允许 int/float——它们都是 float 的"形状兼容"子类），`T = TypeVar("T", str, bytes)`（严格限定二选一）。PEP 695（3.12+）引入了更简洁的 `def first[T](items: list[T]) -> T` 语法，3.12+ 项目可优先使用。

**Protocol（PEP 544，3.8+）：静态鸭子类型**。`isinstance` 式结构化检查搬到类型层——只要"有这些方法"就匹配，**不需要显式继承**。这是 Python 鸭子类型哲学与静态检查的和解：

```python
from typing import Protocol, runtime_checkable

@runtime_checkable                       # 让 isinstance 也可用（只查方法名存在）
class Closable(Protocol):
    def close(self) -> None: ...

def cleanup(resource: Closable) -> None:
    resource.close()                     # 静态检查：有 close 方法就放行

class DBConn:                            # 没有继承任何东西
    def close(self) -> None:
        print("closed")

>>> cleanup(DBConn())                    # 运行时：鸭子类型，天然通过
closed
```

对比 ABC（抽象基类）：ABC 是**名义类型**（必须显式继承才算数），Protocol 是**结构类型**（形状对就行）。**经验做法**：第三方对象无法改继承关系时（文件句柄、httpx 响应……），用 Protocol 描述"我需要它的哪一面"，测试时也更容易写假件。

## 3. mypy 快速上手

安装 `uv add --dev mypy`（uv 系列 02 篇的 dev 依赖），最小用法：

```bash
mypy app.py                # 检查单文件
mypy src/                  # 检查整个包（uv 的 src 布局）
mypy --strict app.py       # 严格模式：要求全注解、禁 Any 隐式传播
```

```python
# demo.py
def area(width: int, height: int) -> int:
    return width * height

area(3, "4")               # ← 运行时才炸：TypeError: int * str
```

```text
$ mypy demo.py
demo.py:4: error: Argument 2 to "area" has incompatible type "str"; expected "int"  [arg-type]
Found 1 error in 1 file (checked 1 source file)
```

mypy 报错在**运行前**，这正是它对大型项目的价值——注解即文档、检查即测试的第一道防线。常用配置写进 `pyproject.toml`（mypy 官方文档支持）：

```toml
[tool.mypy]
python_version = "3.10"
check_untyped_defs = true        # 没注解的函数也检查函数体
warn_unused_ignores = true       # 多余的 # type: ignore 报警
```

**经验做法**：老代码不必一步到 strict；从 `check_untyped_defs = true` 起步，新模块全注解，`# type: ignore[error-code]` 只允许带错误码地用（可审计、可随升级清理）。

## 4. dataclass：消除样板 vs NamedTuple vs attrs

`@dataclass`（PEP 557，3.7+，`dataclasses` 模块）根据类属性注解**自动生成** `__init__`/`__repr__`/`__eq__`：

```python
from dataclasses import dataclass, field

@dataclass
class Message:
    role: str                       # 必填
    content: str                    # 必填
    tokens: int = 0                 # 有默认值
    tool_calls: list[dict] = field(default_factory=list)   # 可变默认！必须用工厂
    history: list["Message"] = field(default_factory=list, repr=False)

msg = Message(role="user", content="你好", tool_calls=[{"name": "search"}])
>>> msg
Message(role='user', content='你好', tokens=0, tool_calls=[{'name': 'search'}])
>>> msg == Message(role="user", content="你好")     # __eq__ 按字段比较
False
```

两个必记细节：① **可变默认值必须 `field(default_factory=list)`**——dataclass 在生成时会主动拒绝 `tool_calls: list = []`（抛 `ValueError: mutable default`），这是语言层面替你防 02 篇陷阱；② `frozen=True` 生成不可变实例（赋值抛 `FrozenInstanceError`），适合做 dict 键/线程安全的值对象：

```python
@dataclass(frozen=True)
class Point:
    x: float
    y: float

>>> p = Point(1.0, 2.0)
>>> p.x = 9
Traceback (most recent call last):
  ...
dataclasses.FrozenInstanceError: cannot assign to field 'x'
```

三兄弟的定位（《Fluent Python》第 5 章有专门对比）：

| 方案 | 定位 | 特点 |
| --- | --- | --- |
| `NamedTuple` | 不可变的记录 | 元组语义（可解包、可比较、有索引），类语法声明字段 |
| `dataclass` | 可变（或 frozen）的记录 | 常规类语义 + 自动生成方法，生态默认选择 |
| `attrs` | 第三方增强版 | 校验（validators）、转换（converters）、`slots=True` 等开箱能力更全 |

```python
from typing import NamedTuple

class Stock(NamedTuple):
    symbol: str
    price: float

>>> s = Stock("AAPL", 190.5)
>>> s[0], s == Stock("AAPL", 190.5)     # 元组语义
('AAPL', True)
```

**经验做法**：默认 `dataclass`；强调"值记录、不可变、可解包"用 `NamedTuple`；需要声明级校验/转换且不想手写时上 `attrs`（pydantic 则是"运行时校验 + JSON 序列化"场景的进一步升级，其字段注册机制在 11 篇解密）。

## 5. match 语句（3.10+）与 f-string 进阶

`match`（PEP 634，结构化模式匹配，3.10 引入）不是 C 的 switch：它做**解构匹配**——按形状拆开数据并绑定内部名字：

```python
def handle(event: dict) -> str:
    match event:
        case {"type": "message", "content": text}:
            return f"消息: {text}"                 # 键匹配 + 值绑定
        case {"type": "tool_call", "name": name, **rest}:
            return f"调用工具 {name}，参数 {rest}"  # **rest 收集剩余键
        case {"type": kind, **_}:
            return f"未知事件类型 {kind}"           # 捕获分支
        case _:
            return "非事件数据"                     # 通配兜底

>>> handle({"type": "message", "content": "hi"})
'消息: hi'
>>> handle({"type": "tool_call", "name": "search", "args": {"q": "py"}})
"调用工具 search，参数 {'args': {'q': 'py'}}"
```

类模式配合位置参数（`__match_args__`）与守护条件（`if`）：

```python
@dataclass
class Point:
    x: float
    y: float
    __match_args__ = ("x", "y")          # 让类模式支持位置匹配

def origin_kind(p: Point) -> str:
    match p:
        case Point(0, 0):        return "原点"
        case Point(0, y) if y > 0: return f"y 正轴, y={y}"
        case Point(x, y):        return f"普通点 ({x}, {y})"

>>> origin_kind(Point(0, 5))
'y 正轴, y=5'
```

**f-string 进阶**（PEP 498 基础上，3.12 PEP 701 解除嵌套限制）：`=` 自调试语法、格式说明符、表达式任意：

```python
>>> x, n = 3.14159, 1234567
>>> f"{x=}"                       # = 调试：输出"表达式=值"
'x=3.14159'
>>> f"{x=:.2f}"                   # 还能带格式
'x=3.14'
>>> f"{n:,}"                      # 千分位
'1,234,567'
>>> f"{n:b} | {n:#x}"             # 二进制 / 带前缀十六进制
'100101101011010000111 | 0x12d687'
>>> w = "结果"
>>> f"{w:>10}"                    # 右对齐宽度 10（:格式迷你语言，官方文档 Format String Syntax）
'        结果'
>>> now = "2026-11-08"
>>> f"日期 {now.split('-')[0]} 年" # 3.12+ 支持任意嵌套引号与表达式
'日期 2026 年'
```

## 常见陷阱

**陷阱一：把注解当运行时校验**——`def f(x: int)` 传字符串不报错，注解不是断言。要运行时校验用 pydantic/attrs（或手写），并在文档里写清"注解仅静态检查"。

**陷阱二：可变默认值绕过 dataclass 的保护**——`field(default_factory=...)` 之外的写法（如 `default=SomeMutable()`）在 Python 3.11+ 会被拒绝，但自写普通类没人拦你；普通类默认值陷阱见 02 篇。

**陷阱三：`Optional` 语义误解**——`def f(timeout: Optional[int] = None)` 里 Optional 与默认值是两件事：前者说"可以传 None"，后者说"不传时用什么"。写成 `Optional[int] = None` 通常本意就是"未设置"，两者恰好都满足，但概念别混。

**陷阱四：`typing.List` 风格与新语法混用**——`Union[List[str], None]` 合法但过时；统一 `list[str] | None`。

**陷阱五：match 漏写兜底分支 `case _`**——所有分支都不匹配时**静默跳过整个 match**（不像字典 KeyError 会炸），漏网事件无声丢失；防御性写法：兜底分支记日志或抛错。

## 本篇小结

- 注解是静态检查的元数据，运行时零开销（PEP 484）；3.9+ 内置泛型、3.10+ `X | Y`，`typing.List`/`Optional` 属过时风格；
- `TypeVar` 让"输入输出同型"可检查；`Protocol`（PEP 544）把鸭子类型静态化——形状匹配即可，不问出身；
- mypy：`mypy src/` 常态化、`--strict` 渐进推进、ignore 必须带错误码；
- `dataclass` 自动生成 init/repr/eq，可变默认用 `default_factory`，frozen 做值对象；NamedTuple=元组语义，attrs=更强声明式；
- `match` 是解构匹配不是 switch（漏匹配静默跳过，记得 `case _`）；f-string 的 `=` 调试与格式迷你语言是日常利器。
