# 02 - 机器级表示：读懂汇编

## 本篇目标

- 掌握 x86-64 的 16 个通用寄存器与职责分工，看懂 AT&T 语法下的 `mov`/`lea`/算术/比较/跳转/调用六大类指令。
- 吃透 System V AMD64 调用约定：参数怎么传、栈帧怎么开、caller/callee-saved 谁负责保存、red zone 是什么。
- 会用 `objdump -d`、`readelf`、`gdb` 三个工具把"一个 C 函数"拆到寄存器和栈的层面，亲眼看到 -O0 与 -O2 的产物差异。

前置：01 章的 ISA 概念与 gcc 四阶段；操作系统系列 04 篇（地址空间）有助于理解栈，但不强求。

## 1. 为什么要会读汇编

三个你绕不开的场景：① **性能归因**——性能工程系列的火焰图把热点指到一个函数，但"慢在哪一行"只有汇编能回答（向量化了没有？内联了没有？多了几次访存？）；② **没有源码的依赖库**——线上 so 出问题，objdump 是最后的眼睛；③ **验证编译器**——你写的"优化"可能被编译器做得更好或完全忽略（04 章的 cmov 实验就是现场）。

本系列默认 gcc 的 **AT&T 语法**（objdump 默认输出），与 Intel 语法的显著差异：源操作数在前（`mov %rax, %rbx` 是 rbx←rax，与 Intel 相反）、寄存器带 `%`、立即数带 `$`、内存寻址用 `offset(base,index,scale)`。**经验做法**：看惯一种语法后，用 `objdump -d -M intel` 可切换到 Intel 语法，两边都认识会省很多查资料的功夫。

## 2. 寄存器全景：16 个通用寄存器与它们的分工

x86-64 有 16 个 64 位通用寄存器（CSAPP 第 3 章图 3-2；完整细节见 Intel SDM Vol.1 第 3 章）。名字里的历史包袱要认清：`rax` 的前身是 16 位的 `ax`，`e` 前缀（`eax`）是 32 位时代加的，`r` 前缀（`rax`）是 64 位时代加的——所以 `mov %eax, %eax` 是把 rax 的低 32 位"扩展"回自己（高 32 位清零）。

| 寄存器 | 低 32 位 | 职责（System V AMD64 ABI） | 保存责任 |
| --- | --- | --- | --- |
| `%rax` | `%eax` | 累加器 / **函数返回值** / 乘除法隐式操作数 | caller-saved |
| `%rbx` | `%ebx` | 基址（历史） | callee-saved |
| `%rcx` | `%ecx` | 计数器 / **第 4 参数** | caller-saved |
| `%rdx` | `%edx` | 数据 / **第 3 参数** / 除法高位 | caller-saved |
| `%rsi` | `%esi` | 源索引 / **第 2 参数** | caller-saved |
| `%rdi` | `%edi` | 目的索引 / **第 1 参数** | caller-saved |
| `%rbp` | `%ebp` | 栈帧基址指针（-O2 常省略） | callee-saved |
| `%rsp` | `%esp` | **栈顶指针**（方向向下） | 专用 |
| `%r8`~`%r9` | — | **第 5/6 参数** | caller-saved |
| `%r10`~`%r11` | — | 临时（`r11` 常被 PLT 用） | caller-saved |
| `%r12`~`%r15` | — | 临时 | callee-saved |

另有专用寄存器：`%rip`（指令指针，程序计数器；x86-64 才能对它做相对寻址）、16 个 XMM 寄存器（`%xmm0`~`%xmm15`，浮点参数与 SIMD 用，04 章展开）。**caller-saved = 调用别人后内容可能被毁，调用者自己负责保存；callee-saved = 被调用者保证原样归还。** 这个分工决定了汇编里"谁在 push/pop"。

## 3. 数据传送与寻址模式

`mov` 家族是汇编里出现频率最高的指令，后缀表示操作数宽度：`movb`（1 字节）、`movw`（2）、`movl`（4）、`movq`（8）。注意两个特例（CSAPP 3.4.2）：`movzbl` 是"零扩展传送"（byte→long 补 0），`movsbl` 是"符号扩展传送"（补符号位）——**扩展比缩短要多一条指令**，因为高位必须被显式填上，这直接对应 05 章的符号扩展陷阱。

五种内存寻址模式（ Intel SDM Vol.1 第 3.7.5 节，`D(Rb, Ri, S)` 形式，有效地址 = Rb + Ri×S + D）：

```
 写法              含义                        等价 C
 (%rax)            *(rax)                      p[0]
 0x8(%rax)         *(rax+8)                    p[1]   （p 为 long*）
 (%rax,%rcx,4)     *(rax + rcx*4)              a[i]   （a 为 int*）
 0xc(%rax,%rcx,4)  *(rax + rcx*4 + 12)         a[i+3]
 symbol(%rip)      RIP 相对寻址：全局变量/常量    g     （位置无关代码的基础）
```

比例因子 S 只能是 1/2/4/8——因为它服务于"按元素宽度步进数组"，这正是 C 指针运算的机器真身：`a[i]` 的 `i` 乘的是**元素大小**而不是 1。

`lea`（load effective address）值得单独说：它本意是"算地址不访存"，但被编译器发扬成了**免费的算术单元**——

```asm
lea (%rdi,%rsi,4), %eax    # eax = rdi + rsi*4，未访存！
lea 0x7(,%rax,8), %eax     # eax = rax*8 + 7，一条指令完成"乘 8 加 7"
```

一条 `lea` 一次算三数之和（含一次移位），且不占用算术标志位，-O2 的代码里到处是"挂羊头卖狗肉"的 lea 算术（CSAPP 3.5.1）。**经验做法**：读优化代码时不要看到 `lea` 就以为在取地址。

## 4. 算术、比较与条件码

算术类指令一图流：

```asm
add %rbx, %rax        # rax += rbx
sub %rbx, %rax        # rax -= rbx
imul %rbx, %rax       # rax *= rbx（有符号乘，结果取低 64 位）
inc/dec %rax          # ++/--
neg %rax              # rax = -rax（补码取负，见 05 章）
shl/shr/sar $3, %rax  # 左移3 / 逻辑右移（补0）/ 算术右移（补符号）
xor %rax, %rax        # 清零的惯用法（比 mov $0 短）
```

真正让 C 的 `if` 能落地的是**条件码（condition codes）**：CPU 有一组一位标志寄存器（ZF 零、SF 符号、CF 进位、OF 溢出），算术/比较指令执行时顺带设置它们。`cmp %rbx, %rax` 实际执行 `rax - rbx` 但**丢弃结果只留标志**，随后的条件跳转读标志做决定：

```asm
cmp %rsi, %rdi
jl  L_less        # rdi < rsi（有符号：SF≠OF）
jle L_le          # ≤；无符号用 jb/jbe（CF），记法 j+后缀对应
jmp L_end         # 无条件跳转
```

有符号/无符号条件码是两套（`l/g` vs `b/a`），C 代码里 `int` 与 `unsigned` 比较的坑（05 章）在机器层就是编译器选了哪套条件码。除了跳转，还有 `setcc`（把条件写进 8 位寄存器）和 `cmovcc`（条件传送，分支消无化，04 章的主角）——它们一起构成"无分支编程"的工具箱。

## 5. 跳转、call/ret 与栈帧

x86-64 的栈向低地址增长，`push` = rsp 减 8 + 写内存，`pop` 反之。一次函数调用的栈布局：

```
            高地址
        ┌─────────────┐
        │ caller 栈帧  │
        │  ...        │
        ├─────────────┤ ◄── 进入 callee 时的 %rsp
        │ 返回地址     │   call 指令自动 push 的（rip+偏移）
        ├─────────────┤ ◄── push %rbp 之后的 %rbp 指向这里
        │ 保存的 %rbp  │
        ├─────────────┤
        │ 局部变量/     │
        │ 溢出的参数    │   第 7 个起参数放这里（见下节）
        └─────────────┘ ◄── 当前 %rsp（低地址）
```

三个关键事实：① **`call` 一条指令做了两件事**：把返回地址压栈 + 跳转；`ret` 弹出返回地址跳回去——这解释了为什么栈溢出（递归太深）会"毁掉"返回路径；② `rbp` 是可选的帧指针，-O2 下常被省略（rbp 挪去当通用寄存器），靠 `.cfi_*` 伪指令和 unwind 信息回溯栈，这就是火焰图仍能在无帧指针的二进制上工作却偶尔栈断的原因（性能工程 03 篇的坑）；③ **`leave` 等价于 `mov %rbp,%rsp; pop %rbp`**，是函数尾声的打包写法。

## 6. System V AMD64 调用约定：参数与返回值怎么走

Linux 上 x86-64 的函数调用规则由 **System V Application Binary Interface (AMD64 Architecture Processor Supplement)** 定义（下称 SysV ABI，2.3.2 节）。核心条款：

- **整型/指针参数按顺序走 6 个寄存器：`rdi, rsi, rdx, rcx, r8, r9`**，第 7 个起从右往左依次压栈，栈上每个参数 8 字节对齐。
- **浮点参数走 `xmm0`~`xmm7`**，返回值：整数在 `rax`，浮点在 `xmm0`。
- **栈指针 16 字节对齐**：在 `call` 指令执行**前** rsp 必须 16 字节对齐（call 压完返回地址后进入函数时 rsp ≡ 8 mod 16）。SSE 指令 `movaps` 要求 16 字节对齐，对齐破了会直接段错误——手写汇编最常见的翻车点。
- **red zone**：进入函数后、真正下探栈之前，rsp 之下的 **128 字节**区域允许函数直接使用（叶函数不用改 rsp 就有临时空间）。信号处理和中断会踩到 red zone，所以内核态不适用（内核用单独的内核栈）。
- **ARM 注**：ARM64 的约定是 AAPCS64：参数走 `x0`~`x7`（8 个），返回 `x0`，无 red zone，链接寄存器 `lr`（x30）保存返回地址——ARM 的 call 不压栈，而是写进 lr，需要更深的调用时才把 lr 入栈。这是两边汇编最重要的形状差异。

一个完整对照实验。C 代码：

```c
// abi.c —— 观察参数如何走寄存器
int add6(int a, int b, int c, int d, int e, int f) {
    return a + b + c + d + e + f;
}
int add7(int a, int b, int c, int d, int e, int f, int g) {
    return add6(a, b, c, d, e, f) + g;
}
```

```bash
$ gcc -O0 -S abi.c -o abi.s && sed -n '/^add6:/,/^add7:/p' abi.s | grep -v '\.'
add6:
	pushq	%rbp
	movq	%rsp, %rbp
	movl	%edi, -20(%rbp)      # a ← edi：第 1 参数
	movl	%esi, -24(%rbp)      # b ← esi
	movl	%edx, -28(%rbp)      # c ← edx
	movl	%ecx, -32(%rbp)      # d ← ecx
	movl	%r8d, -36(%rbp)      # e ← r8
	movl	%r9d, -40(%rbp)      # f ← r9：恰好用满 6 个
	movl	-28(%rbp), %edx
	movl	-24(%rbp), %eax
	addl	%edx, %eax
	...
```

再看 add7 的调用点（`gcc -O0 -c abi.c && objdump -d abi.o`）：

```asm
  sub    $0x10,%rsp          # 开 16 字节栈空间
  movl   %edi,0x8(%rsp)      # 第 7 个参数 g 被压到栈上！
  mov    %r9d,%r9d
  ...
  call   3f <add7+0x3f>      # call 后 rsp ≡ 8 mod 16，符合约定
  add    $0x10,%rsp
```

（第 7 参数确实走了栈；调用点负责把它放好——参数压栈是 caller 的义务。）

## 7. 实战工具箱：objdump / readelf / gdb

**objdump**——反汇编主力：

```bash
$ gcc -O2 -c abi.c -o abi.o && objdump -d abi.o
0000000000000000 <add6>:
   0:	8d 04 37             	lea    (%rdi,%rsi,1),%eax   # a+b
   3:	01 d0                	add    %edx,%eax            # +c
   5:	01 c8                	add    %ecx,%eax            # +d
   7:	44 01 c0             	add    %r8d,%eax            # +e
   a:	44 01 c8             	add    %eax,%r9d            # +f（结果直接进 r9d）
   d:	44 89 c8             	mov    %r9d,%eax
  10:	c3                   	ret
```

对比 01 章的 -O0 版本：**没有 push rbp、没有一次访存**——优化把"变量放栈上再搬来搬去"整个抹掉了，寄存器间直接算。`readelf -S abi.o` 可看节表（`.text` 代码、`.rodata` 只读数据、`.data` 已初始化数据、`.bss` 未初始化数据占位），与 01 章的链接故事衔接。

**gdb**——单步看栈。完整实操脚本（`gcc -O0 -g abi.c -o abi_g` 先带调试信息编译）：

```bash
$ gdb -q ./abi_g
(gdb) b add6                  # 在 add6 下断点
Breakpoint 1 at 0x1149
(gdb) run
Breakpoint 1, 0x0000555555555149 in add6 ()
(gdb) info registers rdi rsi rdx rcx r8 r9   # 参数真的在寄存器里
rdi            0x1                 1
rsi            0x2                 2
rdx            0x3                 3
rcx            0x4                 4
r8             0x5                 5
r9             0x6                 6
(gdb) x/4gx $rsp              # 看 rsp 处的栈内存：8 字单位
0x7fffffffe268:	0x0000555555555192	0x0000000000000000
                └── 这就是 call 压入的返回地址 ──┘
(gdb) p *(long*)($rsp) == 0x555555555192 ? "返回地址在栈顶" : "?"
返回地址在栈顶
(gdb) si                      # 单步一条指令
(gdb) bt                      # 回溯调用栈
#0  add6 () at abi.c:2
#1  add7 (a=1, b=2, c=3, d=4, e=5, f=6, g=7) at abi.c:6
#2  main () at abi.c:9
```

（地址里的 `0x5555...` 是 ASLR 关闭态下的典型基址；你的数字必然不同，看形状。）`bt` 能回溯正是靠着 5 节说的返回地址链/栈帧链；`disassemble add6` 可在 gdb 里直接反汇编，`layout asm` 开汇编窗口边跑边看。**经验做法**：调程序卡死时 `gdb -p <pid>` 附上去 `bt`，看它停在哪个系统调用——比重启复现快得多。

## 常见误区

1. **"汇编很难，先学完 C++ 再说"**：常用指令就 20 来个（mov/lea/add/cmp/jmp/call/push/pop/ret 占绝大头），其余现查。读不懂的真实原因是没建立"寄存器=变量、内存=数组/栈"的映射，本篇 2~5 节就是那张映射表。
2. **"AT&T 的 `mov %rax, %rbx` 是 rax←rbx"**：反了。AT&T 是源在前，Intel 语法才是目的在前。判别技巧：看偏移方向——`mov %eax, -4(%rbp)` 只能是"寄存器→内存"，因为右边是地址。
3. **"call 就是跳转"**：call 跳转前先把返回地址压栈，这 8 字节影响 rsp 对齐（进函数时 rsp ≡ 8 mod 16）和栈回溯。手写汇编写崩，九成是忘了这一条或忘了 16 字节对齐。
4. **"red zone 一直可用"**：它是叶函数的特权——一旦你 call 别人，red zone 就成了别人的栈。信号处理函数运行在你"以为的" red zone 上，所以依赖 red zone 的代码在信号场景会坏（内核栈不用 red zone 正是为此，SysV ABI 3.2.2）。
5. **"-O2 只是 -O0 的加速版"**：它经常改变程序形状——省略帧指针、内联、把分支变 cmov、循环变 SIMD（04 章）。在 -O0 上做的性能结论对 -O2 几乎无效；性能实验必须用与生产相同的优化级别编译。

## 本篇小结

- 16 个通用寄存器分工：前 6 参数 `rdi/rsi/rdx/rcx/r8/r9`、返回 `rax`、栈 `rsp`、帧 `rbp`（-O2 可省）；caller/callee-saved 决定谁 push 谁。
- 寻址 `D(Rb,Ri,S)` 是 C 指针运算的真身（比例因子=元素宽度）；`lea` 是免访存的地址算术，-O2 里当三数加法器用。
- 条件码 + `jcc`/`setcc`/`cmovcc` 把 C 的 if 落到机器；有符号（l/g）与无符号（b/a）条件码是两套，05 章的符号坑在这里现形。
- SysV AMD64 约定：6 寄存器传参、第 7 起走栈、16 字节栈对齐、red zone 128 字节（叶函数专用）；ARM64 是 8 寄存器 + lr 寄存器返回，call 不自动压栈。
- 工具链：`objdump -d` 看产物、`readelf -S` 看节、`gdb` 断点 + `info registers` + `x/4gx $rsp` + `bt` 把栈帧"看"出来；-O0 与 -O2 的产物形状完全不同，性能结论必须匹配生产编译选项。

1. 把 01 章练习里的 `add` 函数改成返回 `a*8 + 3`，用 `gcc -O2 -S` 编译，验证产物是否只有一条 `lea`（提示：`lea 0x3(,%rdi,8), %eax`）。再试 `a*12+5`，观察编译器如何拆（两次 lea + add）。
2. 写一个 8 参数的函数 `int f8(int a,...,int h)`，用 `objdump -d` 找出哪两个参数走了栈、它们的偏移是多少，并解释为什么偏移里含返回地址的 8 字节。
3. 用 gdb 复现 7 节实验，但在 `add7` 内部下断点，执行 `x/6gx $rsp` 把栈上 6 个 8 字节槽位逐个打印，标出哪个槽是第 7 参数、哪个是对齐填充。
