### 阶段三：CUDA 与算子优化——从读懂到写出第一个高性能 Kernel（6 周）

**阶段核心目标**：以「Python 为主、能读懂 C++、没写过 CUDA」的起点，六周内跨过 CUDA 编程门槛：理解 GPU 硬件模型（SM/warp/共享内存/访存合并），手写 MatMul 优化三阶（朴素 → 分块 → Tensor Core），读懂 FlashAttention 与主流融合算子，最终为 Stage 6-8 的推理引擎学习打下算子级基础。

> 📌 你的 C++ 只能读懂——本阶段刻意安排「先读懂再仿写」的爬坡路径，不要求你成为 C++ 高手，但要求你**亲手写出 5 个能跑、能测、能对比性能的 CUDA kernel**。

### 📅 逐周学习路线与 MVP 交付

#### 第 1 周：GPU 硬件模型与 CUDA 编程模型

* **学习重点**：
* **硬件层级**：GPU → GPC → TPC → SM → CUDA Core / Tensor Core；为什么「SM 数量 × 每 SM 线程」决定并行度。
* **线程层级**：grid / block / warp(32) / thread；occupancy 与寄存器压力。
* **访存层级**：寄存器 → 共享内存(可配) → L2 → 显存；**访存合并（Coalescing）**与 bank conflict——90% 的 kernel 慢在这。
* **Roofline 模型**：判断算子是算力瓶颈还是访存瓶颈（LLM decode 阶段是极端访存瓶颈——理解这个才理解所有推理优化）。
* **工具链**：`nvcc` 编译、`nsight-compute` 与 `nsight-systems` profiling（云上用 CLI 版 `ncu`）。

* **推荐资料**：
* 课程：NVIDIA《Fundamentals of Accelerated Computing with CUDA C/C++》（官方 lab，直接上手）
* 书：《Programming Massively Parallel Processors》(Kirk & Hwu) 第 1-5 章

* **💡 第 1 周 MVP 交付**：
> ① 手写 `vector_add` 与 `matrix_transpose` CUDA kernel，对比合并访存与非合并版本的性能差异（用 `ncu` 抓 memory throughput）；② 用 Roofline 模型手算一个 7B 模型 decode 阶段的理论上限：已知权重 14 GB、显存带宽 2 TB/s，每秒最多生成多少 token？（答案即 batch=1 decode 的天花板）

#### 第 2 周：MatMul 优化三阶——GPU 编程的试金石

* **学习重点**：
* **朴素 MatMul**：global memory 反复读取的性能灾难分析。
* **Shared Memory Tiling**：分块加载、`__syncthreads()` 同步、寄存器累加；性能 5-10× 的来源。
* **Tensor Core / WMMA**：`wmma::mma_sync` API，FP16 输入 FP32 累加；为什么 GEMM 必须吃 Tensor Core。
* **cuBLAS / CUTLASS 生态**：工业级 GEMM 怎么组织（Tiling + Epilogue 融合 + Swizzling），CUTLASS 的模板抽象速览。

* **推荐资料**：
* 经典仓库：`siboehm/CUDA-MODE`（GPU-MODE 讲座配套，MatMul 逐步优化范例）
* CUTLASS examples（读 00-03 号基础示例）

* **💡 第 2 周 MVP 交付**：
> MatMul 三级跳：① 朴素版 → ② shared memory tiling 版 → ③ WMMA Tensor Core 版，同一矩阵尺寸下三版与 `cublasGemmEx` 的 TFLOPS 对比表；你的第 ② 版应达到 cuBLAS 的 50% 以上，否则继续优化访存。

#### 第 3 周：融合算子——推理引擎的速度之源

* **学习重点**：
* **算子融合思想**：Kernel Launch 开销 + 中间结果显存往返是推理延迟大头；融合 = 一次读取做完多步计算。
* **三大必学融合算子**：
* **FlashAttention**：在线 softmax + tiling，不实例化 $N \times N$ 注意力矩阵（你 VLM Stage 8 已用过，本阶段读实现）；
* **RMSNorm / LayerNorm 融合**：elementwise 算子的 reduction 实现；
* **Fused MLP（SwiGLU）与 Add+Norm**：LLaMA 系模型的标准融合配方。
* **PyTorch 侧接口**：`torch.compile` 的算子融合是怎么自动做的（Triton 预热）。

* **推荐论文**：
* *FlashAttention: Fast and Exact Attention with IO-Awareness*（精读 + 对照官方 `flash-attn` 的 CUDA 入口）
* GitHub: `Dao-AILab/flash-attention` 的 `csrc/flash_attn/` 导读

* **💡 第 3 周 MVP 交付**：
> ① 手写 fused `add + rmsnorm` CUDA kernel，与 PyTorch 两步实现的延迟对比（bs=32, seq=4096, hidden=4096）；② 手绘 FlashAttention 的 tiling 数据流图，标注每块 SRAM 的用途，解释为什么显存从 $O(N^2)$ 降到 $O(N)$。

#### 第 4 周：Triton——Python 程序员的 CUDA 捷径

* **学习重点**：
* **Triton 编程模型**：block 级并行（不用手管 warp/block），自动处理访存合并与共享内存；为什么推理引擎新算子大量用 Triton 写。
* **对照学习**：用 Triton 重写你第 2-3 周写的 MatMul 与 fused RMSNorm，对比原生 CUDA 版本——理解「抽象层次换开发效率」。
* **autotune 机制**：`@triton.autotune` 网格搜索配置；vLLM 的部分自定义算子就是 Triton 写的（预读源码）。

* **推荐资料**：
* 官方教程：Triton tutorials 01-vector-add → 03-matrix-multiplication → 06-fused-attention 逐题刷完

* **💡 第 4 周 MVP 交付**：
> Triton 三连：① vector_add；② MatMul（autotune 后与 cuBLAS 对比）；③ FlashAttention 官方 tutorial 复现并测速。提交三题的 benchmark 表——这证明你「会写 GPU 算子」，面试可直接展示。

#### 第 5-6 周：Profiling 驱动优化 + 量化 Kernel 联动 + 复盘

* **学习重点**：
* **端到端 profiling 实战**：`nsys` 抓一次 Qwen2.5-7B 的 vLLM 推理 trace，找出真正的瓶颈算子（prefill vs decode 的差异）。
* **量化 kernel 联动**：GEMV（INT4 权重 × FP16 激活）的手写实现——把 Stage 2 的量化知识与本阶段的 kernel 技能焊在一起；Marlin kernel 源码导读（4-bit batch=1 极速的来源）。
* **算子级与系统级的边界**：什么时候该写算子、什么时候该改调度/批处理——建立工程判断。

* **💡 第 5-6 周 MVP 交付**：
> ① 手写 INT4 GEMV kernel（权重按 group=128 反量化 + FP16 累加），与 `torch.matmul` FP16 版在 batch=1 下对比延迟与带宽利用率；② 输出一份《7B 模型 vLLM 推理 Profiling 报告》：prefill/decode 两阶段的算子耗时 Top10、GPU 利用率、显存带宽利用率，并给出三条优化建议。
