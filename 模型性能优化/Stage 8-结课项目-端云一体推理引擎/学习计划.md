### 阶段八：结课项目——端云一体推理引擎（6 - 8 周）

**阶段核心目标**：把前七个 Stage 的成果焊成一个完整系统：**云端**用 vLLM/SGLang + 量化 + K8s 编排承载重负载，**端侧**（RK3588/310P）用 GGML/RKNN/MindIE 承载隐私与离线负载，中间由一个**智能路由层**根据负载/隐私/延迟自动分流——这就是「端云一体推理引擎」。它同时是你的语音结课项目（端侧语音助手）的云端镜像，两个结课项目合起来构成一个完整的「端云协同语音+LLM 系统」，即你的旗舰作品集。

> 🔗 与语音方向结课项目互为镜像：语音侧负责「听与说」的信号链路，本项目负责「想与答」的推理链路。建议两项目共用同一套监控与部署底座。

---

### 📅 逐周学习路线与 MVP 交付

#### 第 1-2 周：端云协同架构设计与分流策略

* **学习重点**：
* **分流决策维度**：隐私（数据是否出端）、延迟（端侧够不够快）、能力（端侧模型答不了的问题）、负载（云端排队时端侧兜底）。
* **一致性设计**：端云两侧模型的量化精度对齐、回答风格对齐、会话状态同步。
* **级联推理**：端侧先答 → 置信度低则升级云端 → 云端结果回填端侧缓存的知识蒸馏闭环。
* **降级与容灾**：云端不可达时的端侧兜底、断网重连、请求去重。

* **💡 第 1-2 周 MVP 交付**：
> 产出《端云一体推理引擎架构设计文档》：架构图（端侧集群/云端集群/路由层/状态同步）+ 分流决策表（隐私/延迟/能力/负载四象限）+ 级联推理时序图 + 风险清单。此文档为架构面试主答卷。

#### 第 3-4 周：云端侧搭建——量化模型 + 引擎 + 编排

* **学习重点**：
* **云端栈装配**：用 Stage 2 的最优量化模型（如 AWQ-4bit 7B）+ Stage 5 调优后的 vLLM 配置 + Stage 7 的 K8s/Ray Serve 编排，组装云端推理服务。
* **流式接口**：OpenAI 兼容 + SSE 流式输出，供路由层转发。
* **压测定标**：建立云端服务的吞吐/延迟基线，作为路由层分流的参考数据。

* **💡 第 3-4 周 MVP 交付**：
> 云上完成云端推理服务部署：量化模型 + 调优引擎 + K8s 编排，输出标准压测报告（吞吐、TTFT/TPOT、自动扩缩验证），并定义好对路由层暴露的 API 契约。

#### 第 5-6 周：端侧 + 路由层 + 级联闭环

* **学习重点**：
* **端侧栈装配**：RK3588 上的量化小模型（Stage 4 成果，llama.cpp CPU 或 rknn-llm）+ 语音侧助手共用底座。
* **路由层实现**：轻量路由服务（FastAPI），实现四象限分流逻辑与置信度级联；会话状态在端云间的一致性同步。
* **级联推理闭环**：端侧回答 → 置信度判定 → 云端升级 → 结果回填缓存的完整链路实测。
* **端到端压测**：混合负载下端云分流比例、整体延迟分布、成本对比（纯云端 vs 端云协同）。

* **💡 第 5-6 周 MVP 交付**：
> 跑通端云级联闭环：① 路由层按四象限分流 100 条混合请求，输出分流统计与延迟分布；② 实现至少一次「端侧答不好 → 云端升级 → 回填」的完整级联并展示；③ 对比「纯云端」与「端云协同」的成本与延迟。

#### 第 7-8 周：可观测性 + 结课报告 + 作品集

* **学习重点**：
* **全链路监控**：复用 Stage 7 的 Prometheus 大盘，增加端云分流指标；端到端追踪贯穿端侧→路由→云端。
* **结课复盘**：对照两个方向的全部自测清单做总验收；整理可展示的成果。
* **作品集包装**：录制端云协同演示、整理 GitHub 仓库（含设计文档/压测报告/踩坑手册）、撰写技术博客。

* **💡 第 7-8 周 MVP 交付（结课总交付）**：
> ① 可演示的端云一体推理引擎（端侧板 + 云主机 + 路由层联动，录屏 + 现场演示）；② 端云协同 vs 纯云端的成本/延迟对比报告；③ 两方向联合的完整作品集（端侧语音助手 + 端云推理引擎 = 完整端云协同系统），作为求职核心材料。
