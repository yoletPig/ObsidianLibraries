> **本周要回答的三个问题**

## 1. 第一性原理：路由层是"决策 + 转发 + 状态"三件事

### 1.1 路由层的职责拆解

```
决策：这个请求给端还是云？（四象限 + 置信度）
转发：把请求发到选中的执行方，拿回结果
状态：维护会话上下文、缓存回填、去重记录
```

三者都是**轻量**操作（路由层不跑模型），所以用 FastAPI 单服务即可，重点是逻辑正确与低开销。

### 1.2 端侧接入的关键：接口同构

让端侧和云端暴露**相同的接口契约**（第 3-4 周的 `/infer`），路由层就无需关心后端是谁——这是"无感切换"的前提。

## 2. 路由层实现（交付核心一）

### 2.1 四象限分流 + 级联状态机

```python
# router.py
from fastapi import FastAPI
import httpx, time, uuid, hashlib

app = FastAPI()
EDGE_URL = "http://<RK3588>:8081"
CLOUD_URL = "http://<云端>:8080"
CONF_THRESHOLD = 0.75          # 级联置信度阈值（用验证集标定）
EDGE_TIMEOUT = 0.5             # 端侧超时（秒），超则升级

@app.post("/route")
async def route(req: dict, client: httpx.AsyncClient):
    req["request_id"] = req.get("request_id", str(uuid.uuid4()))

    # ---- 四象限分流（按优先级短路）----
    if is_sensitive(req):                    # 1. 隐私 -> 端侧强制
        return await call(EDGE_URL, req, timeout=None)

    if not cloud_reachable():                 # 2. 云端不可达 -> 端侧兜底
        return await call(EDGE_URL, req, timeout=None)

    if is_too_hard(req):                      # 3. 超端侧能力 -> 直上云
        return await call(CLOUD_URL, req, timeout=req.get("timeout_ms"))

    if cloud_queue_overloaded():             # 4. 云端过载 -> 端侧兜底
        return await call(EDGE_URL, req, timeout=None)

    # ---- 5. 级联：端侧先试 ----
    return await cascade(req, client)

async def cascade(req, client):
    # 端侧先答（带超时）
    try:
        edge = await call(EDGE_URL, req, timeout=EDGE_TIMEOUT)
    except httpx.TimeoutException:
        edge = None

    # 端侧答出且置信度够 -> 直接返回
    if edge and edge.get("confidence", 0) >= CONF_THRESHOLD:
        edge["source"] = "edge"
        return edge

    # 置信度不足/超时 -> 升级云端
    cloud = await call(CLOUD_URL, req, timeout=req.get("timeout_ms"))
    # 回填缓存：让端侧下次能直答
    backfill_to_edge(req, cloud["text"])
    cloud["source"] = "cloud_cascaded"
    return cloud

async def call(url, req, timeout):
    async with httpx.AsyncClient(timeout=timeout) as c:
        r = await c.post(f"{url}/infer", json=req)
        return r.json()
```

### 2.2 分流决策的辅助函数

```python
def is_sensitive(req) -> bool:
    # 隐私检测：关键词/分类器。敏感（医疗、证件、财务）→ 强制端侧
    text = req["messages"][-1]["content"]
    return any(k in text for k in ["身份证", "病历", "银行卡"])

def is_too_hard(req) -> bool:
    # 复杂度评估：长度、是否需联网知识、问题类型
    text = req["messages"][-1]["content"]
    return len(text) > 200 or req.get("needs_web", False)

def cloud_queue_overloaded() -> bool:
    # 用第 3-4 周定标的阈值判断云端队列
    return get_cloud_queue_len() > CLOUD_QUEUE_THRESHOLD

def backfill_to_edge(req, answer):
    # 缓存键：问题归一化哈希；值：云端答案
    key = hashlib.sha256(normalize(req).encode()).hexdigest()
    edge_cache.set(key, answer)
```

**回填缓存键的设计**很重要：用"归一化问题"的哈希，让措辞略不同的同类问题也能命中。

## 3. 端侧接入（交付核心二）

### 3.1 端侧服务（RK3588）

端侧用 Stage 4 的量化小模型（llama.cpp CPU 或 rknn-llm），包成与云端**同构**的 `/infer` 接口：

```python
# edge_service.py（RK3588 上）
from fastapi import FastAPI
import subprocess

app = FastAPI()

@app.post("/infer")
async def infer(req: dict):
    prompt = build_prompt(req["messages"])
    # llama.cpp 推理
    text, confidence = run_llama_cpp(prompt, max_tokens=256)
    return {
        "request_id": req["request_id"],
        "text": text,
        "confidence": confidence,     # 级联判断依据
        "source": "edge",
    }
```

**端侧要输出 `confidence`**——这是级联能否工作的关键。实现方式：
- 生成 token 的平均 logprob 归一化；
- 或小分类器评估回答质量。

### 3.2 缓存查询前置

```
1. 请求 → 路由层
2. 路由层 → 端侧（非隐私、非复杂）
```

## 5. 工程权衡与失效模式

### 5.1 权衡

- **端侧超时**：太短 → 端侧没答完就升级（浪费端侧算力）；太长 → 级联总延迟高。0.5s 是起点，实测调。
- **置信度阈值**：级联分流的生命线，必须用验证集标定。
- **缓存一致性**：云端模型更新后，旧缓存可能过时。设缓存 TTL 或版本。

### 5.2 失效模式

1. **端云接口不一致**：字段名/格式不同，路由层解析崩。修复：严格契约 + 联调测试。
2. **置信度不可比**：端云置信度算法不同，无法统一判断。修复：统一到同一语义（或只用端侧置信度做级联）。
3. **缓存污染**：错误的云端答案被回填。修复：只回填高置信云端答案 + 抽检。
4. **级联超时叠加**：端侧 0.5s + 云端 N s，总延迟超 SLO。修复：端侧超时设短、云端流式尽早出首字。

## 6. 延伸思考题（含解析）

**Q1**：路由层为什么必须是轻量的？
**A**：路由层在每个请求的关键路径上，它慢则全链路慢。它只做决策+转发+状态（不跑模型），用单服务即可，重点是低延迟与逻辑正确。重逻辑会拖累整体。

**Q2**：端侧和云端接口同构有什么好处？
**A**：路由层无需关心后端是谁，同一套调用与解析逻辑即可。端云可无感切换、互为兜底，也便于做负载均衡与故障转移。

**Q3**：级联里端侧的置信度怎么来的？为什么关键？
**A**：常用生成 token 的平均 logprob 归一化，或小质量分类器。它决定"端侧答案够不够好、要不要升级云端"——是级联分流的核心信号，必须用验证集标定阈值。

**Q4**：回填缓存如何避免"缓存错误答案"？
**A**：① 只回填高置信度的云端答案；② 缓存键用归一化问题哈希，防误命中；③ 设 TTL，云端模型更新后失效旧缓存；④ 定期抽检缓存命中率与正确率。

**Q5**：怎么证明端云协同比纯云端划算？
**A**：对比表三指标：① 云端调用占比（端侧分担了多少）；② 平均/尾部延迟；③ 月成本。端云协同云端调用占比降、隐私本地、离线可用，成本省 X%。用实测 100 条的数据说话。
