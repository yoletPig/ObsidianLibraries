## 1. 第一性原理：蒸馏 = 用教师的分布形状当监督信号

### 1.1 软标签的信息量

分类的 one-hot 标签只说"答案是 3"，而教师的 softmax 输出说"答案是 3（0.85），但 5 也有点像（0.10），7 有一点点像（0.03）"。这些**类间相似性（dark knowledge，暗知识）**正是泛化的来源。Hinton et al.（2015, *Distilling the Knowledge in a Neural Network*）的原始配方：

$$
p_i^T = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}, \qquad
\mathcal{L}_{\text{KD}} = T^2 \cdot \mathrm{KL}\!\left(p^T_{\text{teacher}} \,\|\, p^T_{\text{student}}\right)
$$

- **温度 $T$**：$T \to 1$ 退化为一键分布；$T$ 升高把概率质量从头部摊向尾部，暴露类间结构。典型 $T \in [2, 10]$。
- **$T^2$ 系数**：温度升高后梯度幅度按 $1/T^2$ 缩小，乘回 $T^2$ 保持蒸馏损失与交叉熵同量级（这是推导题常考点：对 $z/T$ 求导多出一个 $1/T$，两处共 $1/T^2$）。

### 1.2 LLM 蒸馏的特殊性：逐 token 的序列蒸馏

语言模型的蒸馏天然发生在每个生成位置上：教师在上下文 $x_{<t}$ 下给出整个词表的分布 $p_T(\cdot \mid x_{<t})$，学生在同样上下文上拟合它：

$$
\mathcal{L}_{\text{KD}} = \sum_t \mathrm{KL}\!\left(p_T(\cdot \mid x_{<t}) \,\|\, p_S(\cdot \mid x_{<t})\right)
$$

教师与学生共享同一输入序列（on-policy/off-policy 的选择见 §1.4），无需任何标签——**教师本身就是标注器**。这正是 7B → 1.5B 蒸馏比"先标注再 SFT"便宜且信息更稠密的原因。

### 1.3 MiniLLM：反向 KL 避免模式覆盖

标准蒸馏用前向 KL $\mathrm{KL}(p_T \| p_S)$（教师在前）。它的失效模式是**模式覆盖（mode-covering）**：学生在教师概率低的地方也被迫分配概率，导致输出稀释、质量平庸。MiniLLM（Gu et al., 2023）改用**反向 KL**：

$$
\mathcal{L}_{\text{MiniLLM}} = \mathbb{E}_{y \sim p_S}\Big[\mathrm{KL}\big(p_S(\cdot \mid x) \,\|\, p_T(\cdot \mid x)\big)\Big]
$$

- 反向 KL 是**模式寻找（mode-seeking）**：学生集中拟合教师的高概率模式，在教师不支持的区域主动清零；
- 期望在学生自己采样的序列上计算（policy gradient + 长度归一化 + 单步分解技巧），这是它工程上比前向 KL 贵的原因。

一句话记忆：**前向 KL 让学生"处处讨好"，反向 KL 让学生"重点精通"**——生成式模型要的是后者。

### 1.4 蒸馏的三种数据路线

| 路线 | 学生看到的序列 | 代表 | 特点 |
| --- | --- | --- | --- |
| 教师离线生成语料 | 教师采样文本 | 数据集蒸馏（Alpaca 系） | 便宜，但学生只见教师"说出口"的分布 |
| 真实语料上对齐 | 人类语料 | 标准逐 token KD | 分布覆盖全，但受语料质量约束 |
| 学生自采样 | 学生自己的生成 | MiniLLM / GKD | 修训练-推理分布不一致，成本最高 |

### 1.5 组合拳：先蒸馏再量化的工业流水线

$$
\text{大教师} \xrightarrow{\text{蒸馏}} \text{小学生} \xrightarrow{\text{量化/剪枝}} \text{压缩模型} \xrightarrow{\text{QAT 收尾（可选）}} \text{部署}
$$

顺序的理由：① 蒸馏改变的是模型本身（权重全动），必须在量化定型之前做；② 小模型容量低，量化掉点更狠，反而更需要蒸馏把教师知识"灌满"再压；③ 若量化后仍有预算，加一段 QAT（Stage 2 第 4 周）收尾。你的语音方向同构：ASR/TTS 小模型几乎都走"大模型蒸馏 → 量化部署"这条链。

## 2. 系统架构与数据流

```
教师 7B（冻结，仅前向）
  │ 每个 batch：教师与学生同时吃同一批文本
  ▼
教师 logits z_T ──► softmax(z_T / T) ──┐
学生 logits z_S ──► softmax(z_S / T) ──┼──► T² · KL(p_T ‖ p_S)   （蒸馏损失）
                      softmax(z_S)    ──┼──► CE(labels)            （SFT 损失，可选加权）
  ▼
总损失 = α · L_KD + (1-α) · L_CE  ──► 只更新学生（或仅其 LoRA）
```

工程要点：教师与学生可不同卡放置（教师推理、学生训练）；教师前向开 `torch.no_grad()` 且用 `bfloat16`；词表必须一致（Qwen2.5 家族同词表，天然满足）。

## 3. 实现与验证（本周交付核心）

### 3.1 温度软标签损失（完整可运行，CPU 可验证）

```python
import torch
import torch.nn.functional as F

def kd_loss(student_logits, teacher_logits, labels=None,
            T=4.0, alpha=0.7):
    """
    温度蒸馏损失。返回 (total, kd_part, ce_part)。
    student/teacher_logits: (B, L, V)
    """
    log_ps = F.log_softmax(student_logits / T, dim=-1)
    p_t = F.softmax(teacher_logits / T, dim=-1)
    # KL(p_t || p_s) = Σ p_t (log p_t - log p_s)，对词表求和、对位置求均值
    kd = F.kl_div(log_ps, p_t, reduction="batchmean") * (T ** 2)
    ce = torch.tensor(0.0)
    if labels is not None:
        ce = F.cross_entropy(
            student_logits.view(-1, student_logits.size(-1)), labels.view(-1))
    return alpha * kd + (1 - alpha) * ce, kd.item(), ce.item()

# ---- 单元自检 ----
torch.manual_seed(0)
B, L, V = 2, 8, 100
zt = torch.randn(B, L, V)
zs = zt + 0.1 * torch.randn(B, L, V)      # 学生接近教师 → 损失应小
zs_far = torch.randn(B, L, V)              # 学生随机 → 损失应大
labels = zt.argmax(-1)
l_near, _, _ = kd_loss(zs, zt, labels, T=4.0)
l_far,  _, _ = kd_loss(zs_far, zt, labels, T=4.0)
assert l_near.item() < l_far.item(), "接近教师的学生损失应更小"
# T → 1 时 KD 应退化逼近一键 CE（教师=学生时两者都 → 0）
l_t1, kd_t1, _ = kd_loss(zt, zt, T=1.0)
assert kd_t1 < 1e-5, "教师=学生时 KL 应为 0"
print("蒸馏损失单元自检通过 ✓")
```

### 3.2 云上真实蒸馏：7B 教师 → 1.5B LoRA 学生

```python
# 云环境：建议单卡 A100-40G（教师 7B bf16 前向 + 学生 1.5B LoRA 训练）
# 或双卡：教师 device_map 单独一张
import torch
from datasets import load_dataset
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import LoraConfig, get_peft_model

TOK = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-7B")
teacher = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-7B", torch_dtype=torch.bfloat16,
    device_map="cuda:0").eval()
student = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-1.5B", torch_dtype=torch.bfloat16, device_map="cuda:0")
student = get_peft_model(student, LoraConfig(
    r=32, lora_alpha=64, target_modules="all-linear", task_type="CAUSAL_LM"))

data = load_dataset("tatsu-lab/alpaca", split="train[:2000]")

def collate(batch):
    texts = [b["instruction"] + "\n" + b["output"] for b in batch]
    enc = TOK(texts, return_tensors="pt", truncation=True,
              max_length=1024, padding=True)
    enc["labels"] = enc["input_ids"].clone()
    return enc.to("cuda:0")

opt = torch.optim.AdamW(student.parameters(), lr=1e-4)
student.train()
for step in range(200):                       # MVP 规模：200 步演示收敛趋势
    batch = collate(data[step*8:(step+1)*8])
    with torch.no_grad():
        zt = teacher(**batch).logits
    zs = student(**batch).logits
    loss, kd, ce = kd_loss(zs.float(), zt.float(), batch["labels"],
                           T=4.0, alpha=0.7)
    loss.backward(); opt.step(); opt.zero_grad()
    if step % 20 == 0:
        print(f"step {step}: total={loss:.3f} kd={kd:.3f} ce={ce:.3f}")
student.save_pretrained("qwen1.5b-distill-lora")
```

**对照实验（交付要求）**：同样的数据与步数，跑一组 `alpha=0`（纯 SFT，只用 labels），对比两组学生在同一测试集上的 PPL 与人评流畅度。预期：**蒸馏组 PPL 更低、长文本更连贯**——教师的分布形状补上了 2000 条数据喂不出的语言先验。

## 4. 工程权衡与失效模式

### 4.1 权衡

- **蒸馏成本**：需要教师全程前向，训练成本 ≈ 教师的推理 + 学生的训练；对 7B→1.5B，教师前向通常是大头 → 教师量化前向（INT8）是常见省钱手段。
- **温度选择**：$T$ 太小 ≈ 硬标签失去暗知识；$T$ 太大分布趋平，学生学到的是噪声。2~10 区间网格搜 3 个点即可。
- **工具链选型矩阵**（面试直接背）：

| 工具 | 定位 | 强项 | 适用场景 |
| --- | --- | --- | --- |
| **llm-compressor** | vLLM 官方一站式 | GPTQ/AWQ/SmoothQuant/FP8/QAT，产出 vLLM 直载格式 | 云端部署首选 |
| **AutoGPTQ** | 单一算法精耕 | GPTQ 成熟稳定、生态老 | 只要 GPTQ 时的稳妥选择 |
| **bitsandbytes** | 训练侧即时量化 | NF4/INT8 零配置、QLoRA 生态 | 微调/研究，不做部署产物 |
| **SparseML** | Neural Magic 剪枝+量化 | Wanda/SparseGPT、稀疏-量化联合 | 剪枝实验与 CPU 稀疏部署 |
| **torchao** | PyTorch 官方 | INT4/INT8/FP8 与 `torch.compile` 深度集成 | 训练推理一体、追新 |

一句话：**要部署产物选 llm-compressor，要训练时量化选 bitsandbytes，要剪枝选 SparseML，要 PyTorch 原生集成选 torchao**。

### 4.2 失效模式

1. **学生词表/分词器与教师不一致**：症状——KL 损失算出来无意义；根因——跨家族蒸馏时词表错位；修复——同家族蒸馏或加词表映射层。
2. **$T^2$ 系数漏写**：症状——蒸馏损失数值巨大或微小，$\alpha$ 怎么调都不对；根因——温度缩放后梯度量级失衡；修复——补 $T^2$（§3.1 已实现）。
3. **蒸馏数据过拟合教师口头禅**：症状——学生复读教师的格式化套话（如总以"当然！"开头）；根因——教师采样语料的风格偏差被当成知识；修复——混入真实语料的逐 token KD。
4. **评测基线漂移**：症状——不同周的数字对不上；根因——换了评测集版本/生成长度/设备；修复——评测脚本锁死所有超参，写进报告脚注。

## 5. 延伸思考题（含解析）

**Q1**：为什么蒸馏损失里要乘 $T^2$？不乘会怎样？
**A**：softmax 对 $z/T$ 求导带出 $1/T$，前向与反向各一次共 $1/T^2$，蒸馏梯度随 $T$ 增大而缩小；乘 $T^2$ 恢复与 CE 同量级，使 $\alpha$ 的加权有意义。不乘则需要把 $\alpha$ 调到接近 1 且随 $T$ 重调，失去可解释性。

**Q2**：MiniLLM 的反向 KL 为什么必须在学生自己的采样上算？
**A**：反向 KL $\mathrm{KL}(p_S \| p_T)$ 的期望下标是学生分布——在教师语料上算会系统性漏掉学生自己会走到的状态（分布不匹配），这正是 on-policy 采样修正训练-推理 gap 的动机。

**Q3**：学生比教师小很多时，为什么"蒸馏后再量化"比"直接量化大模型"常常更优？
**A**：大模型 INT4 已接近无损，但体积仍大、端侧跑不动；蒸馏出的小模型 FP16 就放得下，再量化是锦上添花。选型逻辑是**先满足部署预算（体积/延迟），再谈精度保留**。

**Q4**：llm-compressor 产出的模型为什么能被 vLLM 直接加载，AutoGPTQ 的却需要转换？
**A**：llm-compressor 输出 compressed-tensors 规范（量化配置写进 config，权重按 vLLM 加载器预期的布局打包）；AutoGPTQ 是自己的 checkpoint 格式，需要 vLLM 内置的 GPTQ 加载分支。格式与引擎匹配是 Stage 2 第 5-6 周的主题。

**Q5**：你的语音方向里，哪些模型会走"蒸馏 → 量化 → 端侧"这条链？
**A**：端侧 ASR（SenseVoice-Small 本身就是从大模型蒸馏来的家族）、TTS 声码器/轻量解码器、VAD/降噪小模型。共同点：教师提供质量上限，学生满足实时率与内存预算——与本方向完全同构。

## 6. 基线报告的脚本化：让评测"一次写好、处处复用"

### 6.1 四维指标的最小评测脚本（完整可运行）

```python
# eval_suite.py —— Stage 1 基线台的骨架：PPL + 延迟 + 显存 + 体积
import time, torch, os
from transformers import AutoModelForCausalLM, AutoTokenizer

def ppl_wikitext(model, tok, max_batches=8, stride=512, device="cuda"):
    """WikiText-2 滑动窗口 PPL（简化版，完整版加 padding 处理）。"""
    from datasets import load_dataset
    txt = "\n".join(load_dataset("wikitext", "wikitext-2-raw-v1",
                                 split="test")["text"])
    enc = tok(txt, return_tensors="pt").input_ids.to(device)
    nll, n = 0.0, 0
    with torch.no_grad():
        for i in range(0, enc.shape[1] - stride, stride):
            if i // stride >= max_batches: break
            seg = enc[:, i:i + stride * 2]
            out = model(seg, labels=seg)
            nll += out.loss.item() * seg.shape[1]; n += seg.shape[1]
    return torch.exp(torch.tensor(nll / n)).item()

def latency_tps(model, tok, prompt="介绍模型量化技术。", n_new=128, device="cuda"):
    inp = tok(prompt, return_tensors="pt").to(device)
    torch.cuda.synchronize(); t0 = time.time()
    out = model.generate(**inp, max_new_tokens=n_new, do_sample=False)
    torch.cuda.synchronize()
    n_gen = out.shape[1] - inp.input_ids.shape[1]
    return n_gen / (time.time() - t0)

def footprint_gb(model):
    """模型体积：参数总量 × 每参数字节数。"""
    total = sum(p.numel() * p.element_size() for p in model.parameters())
    return total / 1e9

# 用法：对 {FP16, INT8, INT4 手写, Wanda 50%} 逐一跑三个函数，填基线矩阵
# 断言式自检：任何一行 PPL < 1 或 > 100 都说明管线坏了，立刻停机排查
```

**纪律**：这个脚本从本周起冻结——所有后续 Stage 的量化方案都用它评测，参数一字不改。评测台的价值 = 可比性，可比性 = 不变性。
