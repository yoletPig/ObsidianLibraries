## 1. 第一性原理：稀疏 = 用"重要性排序"换参数预算

### 1.1 问题定义

剪枝要解的问题：给定预算（保留 $k\%$ 参数），找出使任务损失最小的参数子集。形式化为

$$
\min_{m \in \{0,1\}^{|W|}} \ \mathcal{L}(m \odot W) \quad \text{s.t.} \quad \|m\|_0 \le k|W|
$$

这是组合优化（NP 难），所有实用算法都是在用不同的**重要性代理（importance proxy）**做近似。

### 1.2 三代重要性代理

| 算法 | 重要性定义 | 需要重训？ | 代表 |
| --- | --- | --- | --- |
| Magnitude | $\|W_{ij}\|$ | 需要（经典 30 轮迭代剪枝） | Han et al. 2015 |
| Movement | 训练中 $\|W_{ij}\|$ 的移动量 | 需要 | Movement Pruning |
| **Wanda** | $\|W_{ij}\| \cdot \|X_j\|$（权重 × 输入激活范数） | **不需要** | Sun et al. 2023 |
| **SparseGPT** | 剪一列后的二阶输出误差（Hessian） | 不需要（一次性） | Frantar & Alistarh 2023 |

### 1.3 Wanda 为什么有效：一行输出的误差分解

考虑线性层 $y = Wx$。剪掉 $W_{ij}$ 造成的输出误差期望约为 $|W_{ij}| \cdot |x_j|$——**权重小但输入通道幅度大的连接，剪掉同样致命**。Wanda 的重要性即按列激活范数加权：

$$
S_{ij} = |W_{ij}| \cdot \|X_{\cdot j}\|_2, \qquad \text{每行保留 } S \text{ 最大的 } k\% \text{ 个}
$$

两个关键设计：① 按**输出行**独立剪（保持每行稀疏率一致，避免某些神经元被剪空）；② 激活范数用一小批校准数据统计——与第 2 周校准完全同构。这就是"不重训也能工作"的原因：它用的是**一阶泰勒项的幅度**，而 LLM 权重在预训练后已处于良好局部极小，一阶近似足够。

### 1.4 SparseGPT：把剪枝写成逐列最小二乘

SparseGPT 把每层剪枝视为

$$
\arg\min_{\hat W} \|XW^\top - X\hat W^\top\|_F^2 \quad \text{s.t. } \hat W \text{ 满足稀疏约束}
$$

用 Hessian $H = 2XX^\top$（与 GPTQ 完全同源的累积式，Stage 2 第 1 周会再推一遍）做二阶补偿：剪掉某元素后，把该行其余元素的误差按 $H^{-1}$ 最优摊还。相比 Wanda 的一阶近似，它在 60%+ 高稀疏率下显著更稳，代价是要逐层解小线性系统（慢一个量级，但仍免重训）。

### 1.5 LLM-Pruner：结构化剪枝的依赖图

非结构化剪枝产生稀疏矩阵，**通用硬件上并不加速**（稀疏存储格式与密集计算单元的矛盾）。LLM-Pruner 转向**结构化剪枝**：直接删整条通道/头/层。难点是 Transformer 内部存在耦合结构（残差、RoPE 多头、共享 FFN 门控），盲删会破坏形状一致。它的方案：

1. **依赖图（dependency graph）** 分析：识别必须同剪同留的结构组；
2. 对每个结构组用 **LoRA 式低秩恢复**：剪掉的主干旁挂一个低秩分支做少量数据恢复训练（通常 < 3 小时），避免全参微调。

### 1.6 2:4 稀疏：为硬件而生的结构化格式

NVIDIA Ampere 引入的 **2:4 结构化稀疏（2:4 Structured Sparsity）**：每连续 4 个权重中至多 2 个非零。

硬件机制（A100 稀疏 Tensor Core）：

- 权重侧：非零值按 2:4 模式压缩存储——只存 2 个非零值 + 2-bit 索引（记录位置），体积近减半；
- 激活侧：保持密集，但 Tensor Core 的 MMA 单元内置**选择逻辑**，每个时钟周期跳过索引标记为零的乘累加；
- 效果：等效算力翻倍（FP16 312 → 稀疏 624 TFLOPS 量级），且不需要稀疏矩阵格式（CSR/COO）的间接寻址。

$$
\text{2:4 压缩存储} = \underbrace{2 \times 16\text{-bit 值}}_{\text{非零权重}} + \underbrace{2 \times 2\text{-bit 索引}}_{\text{位置编码}} \Rightarrow \text{有效位宽 } \approx 9 \text{ bit / 4 权重}
$$

**为什么任意 50% 稀疏不加速而 2:4 可以**：普通稀疏需要索引间接访存 + 不规则计算，访存与调度开销抵消算力收益；2:4 的固定模式让硬件用确定性电路跳过零元素——**稀疏要变成硬件指令才有收益**。cuSPARSELt / `torch.sparse` 的 `to_sparse_semi_structured` 是软件入口。

## 2. 系统架构与数据流

```
FP16 模型 + 校准集（128 条）
  │ ① 逐层前向：收集每层输入激活的列范数 ‖X_·j‖
  ▼
重要性矩阵 S = |W| · ‖X‖        ← Wanda 核心
  │ ② 每行取 top-k% 保留，其余置零 → 掩码 m
  ▼
稀疏模型 W' = m ⊙ W
  │ ③（可选）2:4 重排：把任意掩码投影成最近的 2:4 模式
  ▼
评测：PPL / 下游任务     或     交给稀疏 Tensor Core 加速
```

结构化通道剪枝则多一步：剪完必须**微调恢复**（其余权重重新适配新容量），曲线先掉后回升。

## 3. 实现与验证（本周交付核心）

### 3.1 手写 Wanda（完整可运行，小模型本地可跑）

```python
import torch
import torch.nn as nn

class WandaPruner:
    """对 nn.Linear 做 Wanda 非结构化剪枝（按输出行保留 top-k%）。"""
    def __init__(self, sparsity: float = 0.5):
        self.sparsity = sparsity
        self.scaler = {}          # name -> 激活列范数累加

    def hook(self, name):
        def _hook(m, inp, out):
            x = inp[0].detach().float()
            # 列范数平方累加（跨 batch 累积，等价 ‖X_·j‖_2）
            norm_sq = x.reshape(-1, x.shape[-1]).pow(2).sum(dim=0)
            self.scaler[name] = self.scaler.get(name, 0) + norm_sq
        return _hook

    def prune(self, name, layer: nn.Linear):
        act = self.scaler[name].sqrt().to(layer.weight.device)
        score = layer.weight.detach().abs() * act[None, :]     # S_ij
        k = int(score.shape[1] * (1 - self.sparsity))
        topk = score.topk(k, dim=1).indices                    # 每行保留
        mask = torch.zeros_like(score, dtype=torch.bool)
        mask.scatter_(1, topk, True)
        layer.weight.data *= mask                              # 就地置零

# ---- 单元自检：验证掩码形状与稀疏率 ----
lin = nn.Linear(64, 32, bias=False)
p = WandaPruner(0.5)
x = torch.randn(8, 64)
p.hook("l")(lin, (x,), None)
p.prune("l", lin)
w = lin.weight.data
assert (w == 0).float().mean().item() == 0.5, "稀疏率应为 50%"
assert ((w == 0).float().sum(dim=1) == 32).all(), "每行应恰好剪一半"
print("Wanda 单元自检通过 ✓")
```

- **手写路线**：把 3.1 的 `WandaPruner` 挂到 `transformers` 模型全部 `q_proj/k_proj/v_proj/o_proj/gate_proj/up_proj/down_proj` 上，校准 128 条后统一剪枝，与官方版 PPL 对比（误差应 < 0.2，差异来自激活统计的 batch 聚合方式）。

### 3.3 通道剪枝 + 微调恢复（ResNet-18 CIFAR-10 曲线）

```python
import torch, torch.nn as nn
from torchvision.models import resnet18
from torchvision.datasets import CIFAR10
from torchvision import transforms
from torch.utils.data import DataLoader

tf = transforms.Compose([transforms.ToTensor(),
                         transforms.Normalize((.5,)*3, (.5,)*3)])
train = DataLoader(CIFAR10("~", True, tf, download=True), 128, True, num_workers=2)
test  = DataLoader(CIFAR10("~", False, tf, download=True), 256, num_workers=2)

def acc(model):
    model.eval(); ok = n = 0
    with torch.no_grad():
        for x, y in test:
            ok += (model(x).argmax(1) == y).sum().item(); n += len(y)
    return ok / n

def prune_channel(model, ratio):
    """按 L1 范数剪掉每个卷积层 ratio 比例的输出通道（演示版：逐层独立）。"""
    for m in model.modules():
        if isinstance(m, nn.Conv2d):
            l1 = m.weight.detach().abs().sum(dim=(1, 2, 3))
            k = max(1, int(l1.numel() * (1 - ratio)))
            keep = l1.topk(k).indices.sort().values
            m.weight = nn.Parameter(m.weight.data[keep])
            m.out_channels = k
    return model  # 注意：生产实现需同步修相邻层（用 torchpruner/llm-pruner 的依赖图思路）

# 实验循环：剪枝率 [0, .2, .4, .6] × {直接评测, 微调 5 epoch 后评测}
# 预期曲线：直接评测单调下降；微调后在 ≤40% 处几乎完全恢复，60% 出现不可恢复拐点
```

> 说明：上面是教学骨架——真实的通道剪枝要联动修改下游层的 `in_channels`、BatchNorm 与 shortcut，建议用 `torch-pruning` 库完成依赖图处理，把精力放在"剪枝率-精度"曲线本身。

### 3.4 2:4 投影：把任意掩码变成硬件能吃的形状（可运行）

任意 50% 稀疏掩码不能直接进稀疏 Tensor Core——必须投影到"每 4 个元素恰好 2 个非零"的 2:4 模式。最小投影算法：每个长度为 4 的窗口内，保留重要性最高的 2 个。

```python
import torch

def project_to_2_4(score: torch.Tensor) -> torch.Tensor:
    """把重要性矩阵投影成 2:4 结构化掩码（沿最后一维，每 4 保 2）。"""
    assert score.shape[-1] % 4 == 0
    g = score.view(*score.shape[:-1], -1, 4)       # 切成 4 元组
    idx = g.topk(2, dim=-1).indices                # 每组保留最大的 2 个
    mask = torch.zeros_like(g, dtype=torch.bool)
    mask.scatter_(-1, idx, True)
    return mask.view_as(score)

torch.manual_seed(0)
S = torch.randn(8, 64).abs()
m = project_to_2_4(S)
# 断言 1：稀疏率恰为 50%
assert m.float().mean().item() == 0.5
# 断言 2：每连续 4 个元素恰好 2 个非零（2:4 约束）
assert (m.view(8, -1, 4).sum(-1) == 2).all()
# 断言 3：保留的是组内重要性最高的 2 个
kept = (S * m).view(8, -1, 4).sum(-1)
total = S.view(8, -1, 4).sum(-1)
assert (kept >= total * 0.5).all(), "保留组应占组内重要性的一半以上"
print("2:4 投影自检通过 ✓")

# 误差视角：投影相比"自由 50% 掩码"损失了多少重要性质量？
free_mask = torch.zeros_like(S).scatter_(
    -1, S.flatten(-1).topk(32, dim=-1).indices, True)   # 按行自由 50%
print(f"保留重要性占比：2:4={ (S*m).sum()/S.sum():.3f}  "
      f"自由={ (S*free_mask).sum()/S.sum():.3f}")
# 预期：2:4 略低于自由掩码（约低几个百分点）——结构化的"格式税"
```

**预期输出**：三个断言通过；2:4 的保留占比略低于自由掩码——这个差值就是为硬件加速支付的"格式税"。面试讲 2:4 时把三层说全：① 硬件机制（索引压缩 + 选择逻辑）；② 投影算法（组内 top-2）；③ 格式税与训练感知稀疏（SparseGPT 2:4 变体在量化/剪枝时就按 2:4 约束选元素，避免事后投影的损失）。

### 3.5 剪枝-量化叠加：先剪后量的误差预算视角

本周收尾把"组合拳"的数值直觉补上：50% 剪枝后，剩余权重的分布通常**更集中**（大幅值权重更可能被保留，但整体方差结构变化），量化网格更容易贴合——这是"先剪后量常比单独量化更好"的经验来源。但两者误差会复合：

$$
\text{总误差} \approx \underbrace{\varepsilon_{\text{prune}}}_{\text{容量损失}} + \underbrace{\varepsilon_{\text{quant}}}_{\text{网格损失}} + \underbrace{\varepsilon_{\text{cross}}}_{\text{复合项（不可线性外推）}}
$$

实践规则：叠加后必须重测全指标（PPL + 长输出），绝不能用"剪枝掉 0.5 + 量化掉 0.3 = 共掉 0.8"的线性估计。第 5-6 周基线矩阵里预留一行"剪枝+量化"组合实验，正是为了实测这个交叉项。

## 4. 工程权衡与失效模式

### 4.1 权衡

- **非结构化精度高但无通用加速**：Wanda/SparseGPT 的 50% 稀疏只在稀疏 Tensor Core / cuSPARSELt 上有收益；CPU、普通 GPU、NPU 上推理速度不变甚至变慢（稀疏格式间接寻址）。
- **结构化直接减体积但精度代价大**：删通道 = 真减 FLOPs，任何硬件都加速；但容量硬损失，必须微调恢复，且高剪枝率下不可逆。
- **免重训剪枝的隐含假设**：模型处于良好极小点、校准集代表部署分布——微调过的下游模型上效果会打折。
- **剪枝-量化叠加**：先剪后量是可行方向（稀疏权重分布更集中，量化网格更好定），但两者误差会复合，叠加后必须重测全指标，不能线性外推。

### 4.2 失效模式

1. **剪枝后 PPL 正常、长文本崩坏**：与量化同款陷阱——局部指标不敏感于累积漂移；修复——加长输出评测（Stage 2 第 5-6 周）。
2. **按行剪导致神经元死亡**：症状——某些输出行非零元素极少，激活饱和；根因——全局 top-k 而非按行；修复——Wanda 的按行保留设计（§3.1 已实现）。
3. **2:4 投影误差**：把任意 50% 掩码强行投影到 2:4 模式会丢掉"重要但位置不合"的连接；修复——训练感知稀疏（SparseGPT 有 2:4 变体，直接按 2:4 约束选元素）。
4. **通道剪枝后忘记重校准 BN**：症状——剪完精度崩得离谱；根因——BatchNorm 统计量还对应旧通道集；修复——剪后先跑几个 batch 重建 BN 统计再微调。

## 5. 延伸思考题（含解析）

**Q1**：Wanda 为什么按输出行独立保留 top-k，而不是全层全局 top-k？
**A**：全局 top-k 会让"整行权重都偏小"的神经元被剪空（该行全零 → 神经元死亡、输出恒为 0）。按行保留保证每个神经元至少存活 $k\%$ 的连接，维持层内表达维度。

**Q2**：SparseGPT 的 Hessian $H = 2XX^\top$ 与 GPTQ 是同一个东西——这暗示了什么？
**A**：两者都在解"逐列修改权重使层输出重构误差最小"的 OBS 问题：剪枝把某列置零、量化把某列舍入到网格，都是对单列的受约束修改，都用 $H^{-1}$ 把误差摊给其余列。所以 GPTQ 可以看作"把量化当成一种特殊剪枝/约束投影"。（Stage 2 第 1 周推导。）

**Q3**：为什么 2:4 稀疏的加速只在 batch 较大（算力瓶颈）时明显？
**A**：batch=1 的 decode 是访存瓶颈（Stage 3 Roofline），稀疏 Tensor Core 翻的是算力上限，对访存瓶颈无用武之地；只有 batch 拉大、GEMM 变成算力瓶颈后，2:4 的 2× 算力才兑现。

**Q4**：LLM-Pruner 为什么用依赖图？直接删通道会发生什么？
**A**：Transformer 里残差分支要求加和两侧维度一致、多头注意力的头维耦合、门控 FFN 的两分支必须同维。盲删会产生形状不匹配直接报错，或（若只删一侧）语义破坏。依赖图把必须同剪的结构绑成组，保证剪后仍是合法网络。

**Q5**：同一个模型，50% 剪枝 vs INT4 量化，哪个对 LLM 更划算？
**A**：INT4 量化：体积 4×↓、精度损失小（配 GPTQ/AWQ）、所有引擎通吃；50% 剪枝：非结构化无通用加速、结构化掉点大。端侧/云端通用结论都是**量化优先，剪枝作为叠加项**——这也是本方向课程把量化放在主线的原因。

## 6. 本周方法论小结：三种压缩路线的误差预算视角

| 路线 | 动了什么 | 误差的性质 | 恢复手段 |
| --- | --- | --- | --- |
| 量化 | 数值的分辨率 | 网格舍入（有界、可补偿） | 校准、二阶补偿、QAT |
| 剪枝 | 参数的存在性 | 容量永久损失（无界、靠冗余吸收） | 微调恢复、依赖图 |
| 蒸馏 | 模型规模 | 知识损失（用教师分布补） | 软标签、反向 KL |

这张表就是第 4 周"组合拳"的路线图：三条路线的误差性质不同、恢复手段不冲突，所以可以叠加——但叠加顺序有讲究（先动结构的蒸馏/剪枝，后动数值的量化），第 4 周展开。
