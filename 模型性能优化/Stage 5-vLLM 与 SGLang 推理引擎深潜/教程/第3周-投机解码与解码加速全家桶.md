## 1. 第一性原理：decode 为什么慢，投机为什么能快

### 1.1 decode 的访存瓶颈（回顾）

自回归每生成一个 token 就要加载一次全部权重——生成 $k$ 个 token 就要加载 $k$ 次。权重加载的显存带宽是瓶颈，计算单元大量闲置。

**关键洞察**：既然每步都要把权重完整读一遍，不如**一次读入、多步共用**——这正是投机解码的思路。

### 1.2 投机解码的循环

每一轮：

1. **草稿**：用便宜的 draft 模型（或免模型的启发式）快速猜出 $k$ 个候选 token；
2. **验证**：把 $k$ 个候选喂给目标大模型，**一次前向**并行验证所有位置；
3. **接受**：从左到右比较，接受与目标分布一致的草稿，遇到第一个被拒的位置就停，并从目标分布重采样一个；
4. 每轮至少产出 1 个（重采样的）、最多 $k+1$ 个 token。

**为什么输出分布不变**：接受/拒绝规则（rejection sampling）经过精心设计，使得接受的 token 严格服从目标模型分布——**加速但不改变生成质量**，这是投机解码最漂亮的性质。

### 1.3 加速比公式推导（本周自测题）

设单步接受率 $\alpha$（草稿被接受的概率），草稿一次猜 $k$ 个。每轮接受的草稿数期望为：

$$
\mathbb{E}[\text{接受数}] = \alpha + \alpha^2 + \cdots + \alpha^k = \frac{\alpha(1-\alpha^k)}{1-\alpha}
$$

每轮还额外产出 1 个重采样 token。忽略 draft 开销时，加速比约为"每轮产出 / 验证一次的开销"。理想化公式：

$$
\text{Speedup} \approx \frac{1}{1-\alpha} \quad (\text{当 } k \to \infty)
$$

直觉：$\alpha = 0.5$ → 加速约 2 倍；$\alpha = 0.8$ → 约 5 倍。**接受率是投机的生命线**——草稿越准，加速越猛。

**验证开销**：验证 $k$ 个 token 的一次大模型前向，比单步略贵（算 $k$ 个位置）。所以真实加速比还要除以验证开销系数，且 $k$ 不是越大越好（$k$ 大→草稿开销与验证开销都升，接受数却受 $\alpha$ 限制）。

## 2. 草稿方案家族

### 2.1 独立 draft 模型（经典）

用一个小的同族模型当草稿（如 7B 目标配 0.5B 草稿）。草稿准但要额外显存与计算。

### 2.2 EAGLE / EAGLE-2：特征级草稿

不用独立模型，而是**在目标模型的特征层**接一个轻量头，自回归预测下一特征 → 解码成 token。草稿利用了目标模型自身的特征，**接受率显著更高**，且几乎不加显存。

### 2.3 Medusa：多头并行，免草稿模型

给目标模型加**多个解码头**，每个头独立预测未来不同位置的 token，再用树状注意力一次验证多条候选路径。**不需要独立草稿模型**，但接受率通常低于 EAGLE。

### 2.4 n-gram / self-speculative：免模型

用**当前上下文里出现过的 n-gram** 当草稿（如"刚才说过'机器学习'，后面可能又出现"）。零额外模型、零训练，在重复性文本上有效，接受率依赖文本特性。

### 2.5 对比表

| 方案 | 草稿来源 | 额外显存 | 接受率 | 适用 |
| --- | --- | --- | --- | --- |
| 独立草稿模型 | 小模型自回归 | 高 | 中 | 通用 |
| EAGLE | 目标特征 + 轻量头 | 低 | 高 | 通用（当前主流） |
| Medusa | 多头并行 | 中 | 中低 | 免草稿场景 |
| n-gram | 上下文历史 | 无 | 依赖文本 | 重复性内容 |

## 3. CUDA Graph：消掉 kernel launch 开销

### 3.1 问题：launch 开销

decode 每步要发起几十上百个小 kernel。每个 kernel 的 **launch（提交）开销**在 CPU 侧是固定的（几微秒到几十微秒）。当单 kernel 计算本身很短（访存瓶颈、小 batch），launch 开销占比变得可观，GPU 出现**空隙（gap）**。

### 3.2 CUDA Graph 的解法

把一整步的 kernel 序列**录制成一张图（graph）**，之后每步只"回放"这张图——一次提交、整图执行，消掉逐个 launch 的开销。

$$
\text{逐步 launch: } \underbrace{[L][k_1][L][k_2]\cdots}_{\text{大量 L 开销}} \;\;\to\;\; \text{Graph: } [L_{\text{一次}}][k_1 k_2 k_3 \cdots]
$$

### 3.3 为什么主要用于 decode

- **decode**：每步结构固定（固定算子序列、固定形状），适合录图；
- **prefill**：序列长度多变、形状不固定，难以复用同一张图（要为每个形状单独录，代价大）。

**限制**：图是静态的——形状必须固定。所以引擎为若干常见形状各录一张图，不在图内的走普通路径。这就是"graph capture 范围与限制"。

## 4. 其他解码优化

### 4.1 结构化输出（约束解码 / JSON mode）

让生成严格满足 JSON schema 等。实现：在采样时用**有限状态机/文法**屏蔽不合法 token（logits mask）。代价：每步要算状态转移与 mask，略增延迟；复杂文法开销更大。

### 4.2 logits processor 链路

温度、top-k、top-p、重复惩罚等都是作用在 logits 上的 processor，按链式顺序施加。它们本身开销小，但**约束解码的文法匹配**是主要成本来源。

### 5.2 接受率-加速比曲线（对照理论）

```python
import numpy as np
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt

alpha = np.linspace(0.05, 0.95, 50)
theoretical = 1 / (1 - alpha)          # 理想上限（k→∞，忽略验证开销）

# 实测点：不同负载/文本重复度下测得的 (接受率, 加速比)
measured_alpha = np.array([0.4, 0.6, 0.8])      # 填你的实测接受率
measured_speedup = np.array([1.5, 2.2, 3.8])    # 填对应实测加速比

plt.figure(figsize=(8, 5))
plt.plot(alpha, theoretical, label="理论上限 1/(1-α)")
plt.scatter(measured_alpha, measured_speedup, color="red", label="实测")
plt.xlabel("接受率 α"); plt.ylabel("加速比")
plt.title("投机解码：接受率-加速比")
plt.legend(); plt.grid(alpha=0.3); plt.tight_layout()
plt.savefig("spec_speedup_curve.png", dpi=110)
print("已保存 spec_speedup_curve.png")
```

**预期**：实测点在理论曲线**下方**（受验证开销、有限 $k$ 影响），且随 $\alpha$ 上升而上升。差距大小反映验证开销占比——这是你解释"实测为何低于理论"的依据。

## 6. 工程权衡与失效模式

### 6.1 权衡

- **草稿方案**：EAGLE 接受率高但需加载额外头；n-gram 零成本但吃文本特性；
- **$k$（草稿长度）**：大 → 单轮潜在产出多，但草稿+验证开销升、边际收益降；
- **CUDA Graph**：省 launch 开销，但要求形状固定、占额外显存存图。

### 6.2 失效模式

1. **接受率过低**：草稿与目标分布差异大（跨域文本），投机反而变慢（白付草稿开销）。修复：换更贴的草稿方案、或对特定负载关闭投机。
2. **n-gram 在创意文本失效**：内容不重复，n-gram 命中率趋零。修复：换 EAGLE 类。
3. **CUDA Graph 形状不匹配**：请求形状落在已录图之外，回退普通路径，收益消失。修复：了解引擎录了哪些形状。
4. **结构化输出拖慢**：复杂 JSON schema 的文法匹配成为瓶颈。修复：简化 schema、或用引擎原生优化实现。

## 7. 延伸思考题（含解析）

**Q1**：投机解码加速比的理论上限公式？接受率怎么影响？
**A**：理想上限约 $1/(1-\alpha)$。接受率 $\alpha$ 越高，每轮接受的草稿越多，加速越猛：$\alpha=0.5$ 约 2 倍、$\alpha=0.8$ 约 5 倍。实测低于理论，因验证开销与有限 $k$。

**Q2**：投机解码为什么"加速但不改输出分布"？
**A**：接受/拒绝用 rejection sampling 设计：草稿被目标分布校验，拒绝处从目标分布重采样。数学上保证最终 token 严格服从目标模型分布——纯加速、不损质量。

**Q3**：EAGLE 和 Medusa 的取舍？
**A**：EAGLE 用目标特征接轻量头做自回归草稿，接受率高、是当前主流，但需加载草稿头；Medusa 多头并行、免独立草稿模型，实现简单但接受率通常较低。要高质量选 EAGLE，要轻量免模型选 Medusa。

**Q4**：CUDA Graph 为什么主要用于 decode 而非 prefill？
**A**：图要求算子序列与张量形状固定。decode 每步形状固定、可复用同一张图；prefill 序列长度多变、形状不固定，需为每形状单独录图、代价大，故主要受益的是 decode。

**Q5**：什么时候该关闭投机解码？
**A**：当草稿接受率过低时——草稿开销白白付出，接受数却少，净收益为负。典型是草稿方案与目标负载不匹配（如 n-gram 用于创意文本）。应先实测接受率再决定开关。
