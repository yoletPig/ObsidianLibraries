### 阶段五：vLLM 与 SGLang 推理引擎深潜（6 周）

**阶段核心目标**：你在 VLM Stage 8 已掌握 vLLM/SGLang 的使用层（PagedAttention 概念、Prefix Caching 用法），本阶段直接下潜到**引擎内部**：调度器源码、连续批处理状态机、投机解码（Speculative Decoding）、CUDA Graph、量化格式接入，并能亲手做一次引擎级性能调优实验。目标不是「会用」，而是「能讲清每一个延迟数字从哪来」——这是推理岗面试的分水岭。

> 💰 全部实验上云：建议租 A100/A800 按小时跑吞吐压测，用完后即释放。

### 📅 逐周学习路线与 MVP 交付

#### 第 1 周：KV Cache 与 PagedAttention 实现层

* **学习重点**：
* **PagedAttention 再深入**：物理块表（block table）的管理、块分配器、copy-on-write（beam search/并行采样的块共享）；v1 引擎的新设计。
* **KV Cache 内存账本**：手算 7B 模型、4096 上下文、batch=32 的 KV 显存占用公式——理解为什么长上下文时代 KV 是显存第一杀手。
* **KV 量化与压缩**：FP8 KV、KIVI、Sliding Window/Sink（StreamingLLM）的引擎内实现位置。
* **Prefix Caching 实现**：哈希键的构造（block 内容哈希）、跨请求命中与逐出策略——SGLang RadixAttention 的对照。

* **推荐资料**：
* `vllm-project/vllm` 源码：`v1/core/`（调度与块管理）、`attention/backends/`
* 论文：*Efficient Memory Management for Large Language Model Serving with PagedAttention*（重读实现章节）

* **💡 第 1 周 MVP 交付**：
> ① 手写一个迷你版 PagedAttention 块管理器（Python，模拟块的分配/引用计数/释放，200 行内），用它跑一遍模拟请求流并画出块占用时间线；② 手算并实测：Qwen2.5-7B、ctx=8k、FP8 KV 下的单卡最大并发数，与 `vllm serve --max-num-seqs` 的实际行为对照。

#### 第 2 周：调度器与连续批处理状态机

* **学习重点**：
* **vLLM V1 调度器**：waiting/running 队列迁移、抢占（preemption: recompute vs swap）、chunked prefill 的预算分配。
* **Prefill vs Decode 分离**：两阶段计算特征差异（算力瓶颈 vs 访存瓶颈）、PD 分离（Disaggregated Serving）架构——Mooncake、DistServe 论文思路。
* **SGLang 调度器对照**：RadixAttention 树状前缀管理、cache-aware 调度（把共享前缀的请求排到一起）。
* **批处理形态**：static batching → continuous batching → chunked prefill → PD 分离的演进逻辑。

* **推荐论文**：
* *SGLang: Efficient Execution of Structured Language Model Programs*
* *DistServe: Disaggregating Prefill and Decoding for Goodput-optimized Large Language Model Serving*

* **💡 第 2 周 MVP 交付**：
> 压测对比实验（云上）：vLLM vs SGLang 对同一 7B 模型，三组负载 {长 prefill 短 decode、短 prefill 长 decode、混合}，测吞吐（tokens/s）、TTFT P50/P99、TPOT；用结果解释「什么负载形状下谁更强」。

#### 第 3 周：投机解码与解码加速全家桶

* **学习重点**：
* **投机解码原理**：draft 模型并行猜 $k$ 个 token → 目标模型一次验证 → 接受/拒绝；接受率 $\alpha$ 与加速比的关系式。
* **变体家族**：Eagle/Eagle-2（特征级 draft）、Medusa（多头并行草稿，免 draft 模型）、n-gram / self-speculative。
* **CUDA Graph 与 torch.compile**：decode 阶段消除 kernel launch 开销的实现；vLLM 的 graph capture 范围与限制。
* **其他解码优化**：structured output（约束解码/JSON mode）的实现成本、logits processor 链路。

* **推荐论文**：
* *Fast Inference from Transformers via Speculative Decoding*
* *EAGLE: Speculative Sampling Requires Rethinking Feature Uncertainty*

* **💡 第 3 周 MVP 交付**：
> ① 云上开启 vLLM 的 EAGLE/MTP 或 n-gram 投机，实测不同接受率下的加速比，画出「接受率-加速比」曲线并与理论公式对照；② 打开/关闭 CUDA Graph 测 decode 延迟差，用 `nsys` 抓 trace 证明 kernel launch 空隙的消失。

#### 第 4 周：量化接入与多模态推理

* **学习重点**：
* **量化格式在引擎中的通路**：Stage 2 的 {GPTQ, AWQ, FP8, INT8-SQ} 在 vLLM 中如何映射到 kernel（Marlin、cutlass scaled_mm）；`--quantization` 与模型的匹配验证机制。
* **低比特新前沿**：W4A4 的探索现状、KV 量化在生产中的采用度。
* **多模态推理（联动语音方向）**：音频/视觉输入在引擎中的预处理流水线；Qwen2-Audio / Qwen2.5-Omni 类模型的 serving 特点——你的跨方向知识在这里产生化学反应。
* **LoRA 服务**：multi-LoRA 共享底座、LoRA 权重热插拔的实现（S-LoRA 论文）。

* **推荐论文**：
* *S-LoRA: Serving Thousands of Concurrent LoRA Adapters*

* **💡 第 4 周 MVP 交付**：
> ① 把 Stage 2 横评中的 GPTQ/AWQ/FP8 三个量化模型逐个接入 vLLM，测吞吐与精度的一致性，验证「引擎内量化与离线量化的等价性」；② 用 vLLM 部署一个多模态模型（Qwen2-Audio 或同级别），走通「音频输入 → 引擎 → 文本输出」的 API 调用。

#### 第 5-6 周：引擎级调优方法论 + 复盘

* **学习重点**：
* **调优参数学**：`gpu-memory-utilization`、`max-num-batched-tokens`、`swap-space`、`enable-chunked-prefill` 各自的作用机制与相互制约。
* **评测方法学**：`benchmark_serving.py` 的标准用法、SLO（TTFT/TPOT 目标）驱动的容量规划、goodput 概念。
* **故障排查库**：OOM、请求排队爆炸、量化精度异常的排查流程。
* **与 Stage 7 的接口**：单引擎调优是生产 serving 的地基，本阶段产出的「单卡最优配置」直接进入 Stage 7 的集群配置。

* **💡 第 5-6 周 MVP 交付**：
> 产出《单引擎调优手册》：以 Qwen2.5-7B 为例，{默认配置 → 逐项调优} 的完整实验记录（每项参数变化的吞吐/延迟影响表），最终给出「7B 模型单卡 A100 最优配置」并复现验证；附三个典型故障的排查案例（自己制造并解决）。
