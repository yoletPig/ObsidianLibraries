### 阶段七：生产级推理服务——Ray Serve / K8s 与自动扩缩（6 周）

**阶段核心目标**：从「单引擎调优」上升到「生产级服务架构」：掌握推理服务的容量规划、负载均衡、自动扩缩、可观测性与成本治理。你在前一轮选择「本地/单云主机用 minikube + Kind 模拟多机，把部署架构写出来但不做真实压测」——本 Stage 严格遵循该约束：以架构设计与可复现的模拟环境为主，压测数据用小规模外推并明确标注。

> 🎯 交付形态：一套可在单台云主机上运行的完整 K8s 推理集群模拟环境 + 一份生产级部署设计文档（可直接作为架构面试的答卷）。

---

### 📅 逐周学习路线与 MVP 交付

#### 第 1 周：推理服务架构总览与容量规划

* **学习重点**：
* **生产架构分层**：接入层（网关/限流）→ 路由层（负载均衡、模型路由）→ 推理层（引擎集群）→ 存储层（模型仓库、KV 缓存）。
* **容量规划方法学**：QPS → 并发 → 实例数的换算；TTFT/TPOT SLO 驱动的副本数推导；GPU 利用率目标（不是越高越好，排队理论）。
* **负载形态分析**：在线对话（低延迟敏感）vs 离线批处理（吞吐敏感）的分池部署策略。
* **多模型多版本**：模型注册表、灰度发布、A/B 测试的推理侧实现。

* **💡 第 1 周 MVP 交付**：
> 产出一份容量规划计算书：给定假设业务量（如峰值 100 QPS、平均输入 512 token、输出 256 token、TTFT ≤ 500ms），推导所需实例数与机型，用 Stage 5 的实测单卡数据做换算并写明每一步假设。

#### 第 2 周：Ray Serve——Python 原生的推理编排

* **学习重点**：
* **Ray Serve 模型**：Deployment Graph（声明式推理流水线）、Replica 与 Autoscaling、动态批处理。
* **多模型编排**：级联模型（如你的语音链路：VAD → ASR → LLM → TTS 的 DAG 编排——语音方向的技能在这里复用）。
* **与 vLLM 集成**：`vllm` 作为 Serve backend 的标准写法；多引擎共存。
* **批处理与流式**：`@serve.batch` 装饰器、流式响应的背压处理。

* **推荐资料**：
* Ray 官方文档 Serve 章节 + `ray-project/ray` 的 serve examples

* **💡 第 2 周 MVP 交付**：
> 单机搭建 Ray Serve 集群（Docker 内）：部署「vLLM 后端 + 一个预处理 Deployment」的推理图，实现动态批处理；用 `locust` 压测，画出副本数与吞吐/延迟的关系曲线，验证自动扩缩配置生效。

#### 第 3 周：Kubernetes 上的推理集群（minikube/Kind 模拟）

* **学习重点**：
* **推理负载的 K8s 建模**：GPU 资源声明（nvidia-device-plugin）、副本集、滚动更新、Pod 亲和（同模型聚簇）。
* **KServe / Triton 生态速览**：KServe 的 InferenceService 抽象（Predictor/Transformer）、Triton Inference Server 的模型仓库布局——理解但不深挖，与 Ray Serve 做路线对比。
* **自动扩缩**：HPA（CPU/GPU 利用率）与 KEDA（基于自定义指标如队列长度）——推理服务更适合队列驱动的扩缩。
* **模拟环境搭建**：minikube/Kind + GPU 模拟（不接真卡的资源调度演示）；明确「模拟能验证什么、不能验证什么」。

* **推荐资料**：
* KServe 官方文档、`kserve/kserve` examples

* **💡 第 3 周 MVP 交付**：
> 在单台云主机上用 Kind 搭建 1 master + 2 worker 的模拟集群，部署一个推理 InferenceService（用小模型代替 7B），配置 HPA 与基于队列的 KEDA 扩缩，用压测流量触发扩缩容并录屏展示副本变化全过程。

#### 第 4 周：可观测性与故障治理

* **学习重点**：
* **推理专属指标**：TTFT/TPOT/吞吐/队列深度/抢占率的采集（Prometheus 格式）、告警阈值设计。
* **分布式追踪**：OpenTelemetry 贯穿「请求 → 网关 → 引擎 → 采样」的全链路。
* **故障模式库**：GPU OOM、KV cache 碎片、慢节点拖累（长尾）、模型加载失败的自愈策略。
* **优雅降级**：过载时丢弃低优请求、切换到更小模型、拒绝长上下文的熔断策略。

* **💡 第 4 周 MVP 交付**：
> ① 为模拟集群接入 Prometheus + Grafana，搭建推理指标大盘（至少 6 个核心指标 + 2 条告警规则）；② 编写《推理服务故障演练手册》：手工注入 3 种故障（OOM/慢节点/队列爆满），记录告警触发与恢复过程。

#### 第 5-6 周：成本治理 + 部署设计文档 + 复盘

* **学习重点**：
* **GPU 成本模型**：按秒计费、抢占式实例（Spot）的风险与适用场景、多租户共享（MIG / 时间片）。
* **降本三板斧**：量化降显存 → 提高单卡并发 → 潮汐扩缩（离线任务填谷）。
* **跨方向整合**：把语音云端服务（Stage 5/6 的 ASR/TTS serving 需求）纳入同一套架构设计——你两个方向的终点在此汇合。

* **💡 第 5-6 周 MVP 交付（Stage 总交付）**：
> 产出《生产级语音+LLM 推理服务设计文档》：完整架构图（接入/路由/推理/存储四层）+ 容量规划表 + 扩缩策略 + 可观测性方案 + 成本估算，全部基于你的模拟环境实证；附「真实多机部署与模拟环境的差异清单」，作为结课项目的云端侧设计蓝本。
