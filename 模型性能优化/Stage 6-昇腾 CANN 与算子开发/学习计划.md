### 阶段六：昇腾 CANN 与 Ascend C 算子开发（8 周）

**阶段核心目标**：以你手上的 **310P/Atlas 200I（推理）** 为本地阵地、**云上 910B** 为训练/开发阵地，完整走通昇腾生态：CANN 软件栈、ATC 模型转换、ACL 推理编程、MindIE 大模型服务、torch_npu 训练迁移，最终**用 Ascend C 写出两个可运行的自定义算子**——这是华为生态岗位最稀缺的硬技能，也是本方向学习曲线最陡的一个 Stage。

> ⚠️ 难度预警：本 Stage 是全计划最难的八周。策略是「推理先行、开发殿后」：前 4 周在 310P 上建立手感，后 4 周才碰 910B 与算子开发。文档不全时以昇腾社区与官方 example 为准。

---

### 📅 逐周学习路线与 MVP 交付

#### 第 1 周：昇腾生态全景与 CANN 架构

* **学习重点**：
* **硬件谱系**：达芬奇架构（Cube/Vector/Scalar 三单元）、910B（训练）与 310P（推理）的算力差异与定位。
* **CANN 软件栈分层**：驱动 → Runtime → 算子库（CANN Kernel）→ 图引擎（GE）→ 框架适配（torch_npu/MindSpore）；与 CUDA 生态的逐项对照（CANN↔CUDA、AscendCL↔CUDA Runtime、GE↔……）。
* **工具链地图**：ATC（模型转换）、msprof（Profiling）、msccl（集合通信）、MindStudio IDE。
* **环境搭建**：你的 310P/Atlas 200I 上的驱动、CANN、Python 环境确认；云上 910B 实例（ModelArts 或第三方算力）的申请流程。

* **推荐资料**：
* 昇腾社区官方文档《CANN 概述》《ATC 工具使用指南》
* 昇腾思享坛/Ascend 公众号的架构解读文章

* **💡 第 1 周 MVP 交付**：
> ① 完成 310P 环境体检：驱动版本、`npu-smi info` 输出、CANN 版本、样例程序跑通；② 画一张「CUDA 生态 ↔ 昇腾生态」对照大图（工具、库、概念逐项映射）——这张图同时是面试讲解材料。

#### 第 2 周：ATC 模型转换与离线推理（310P 主场）

* **学习重点**：
* **转换流水线**：PyTorch → ONNX → ATC → OM 模型；ATC 的关键参数（量化配置、动态 shape、算子选择）。
* **量化联动**：ATC 的 PTQ 选项与你 Stage 1-2 量化知识的对接；ONNX 量化 vs ATC 量化的精度对比。
* **ACL 推理编程**：单进程推理的 ACL API 流程（资源初始化 → 模型加载 → 输入输出 → 执行 → 释放）；Python 与 C++ 双接口。
* **性能调优**：AIPP（图像预处理硬件加速）、零拷贝、多模型多流的并发组织。

* **推荐资料**：
* 官方 samples：`ascend/samples` 仓库的 `python/level2_simple_inference` 系列

* **💡 第 2 周 MVP 交付**：
> 在 310P 上走通「PyTorch 模型（用一个语音方向的模型，如 DeepFilterNet 或小型 ASR）→ ONNX → ATC → OM → ACL 推理」全链路；输出转换前后精度对比与单帧延迟，并测试 AIPP 开关对延迟的影响。

#### 第 3 周：MindIE 大模型推理服务（310P/云）

* **学习重点**：
* **MindIE 定位**：昇腾版 vLLM——连续批处理、PagedAttention 昇腾实现、OpenAI 兼容接口；与 Stage 5 的 vLLM 知识逐项对照（概念全通，实现不同）。
* **权重格式**：HF 权重 → MindIE 权重的转换；昇腾上的量化模型支持谱系（W8A8/W8A16）。
* **部署实操**：在 310P 上部署 7B 级模型（如 Llama/Qwen 系的昇腾适配版）做推理服务；若在 310P 内存受限，则切到云上 910B。
* **性能基准**：昇腾 vs NVIDIA 同档硬件的 tokens/s 对比方法学。

* **推荐资料**：
* 《MindIE 安装与配置指南》《MindIE-LLM 开发指南》（昇腾社区）

* **💡 第 3 周 MVP 交付**：
> 用 MindIE 部署一个 7B 模型（310P 或云 910B），跑通 OpenAI 兼容 API 压测，输出吞吐/延迟报告；写一份「vLLM 配置项 ↔ MindIE 配置项」对照表。

#### 第 4 周：torch_npu 训练迁移（云上 910B）

* **学习重点**：
* **torch_npu 机制**：PyTorch 的 device 抽象扩展、算子映射表；哪些算子有 fallback 到 CPU 的坑。
* **迁移三板斧**：`device='npu'` 改造 → 精度对齐（dump 中间结果对比）→ 性能调优（混合精度、`torch_npu` 融合算子开关）。
* **精度问题排查**：BF16/FP16 在昇腾上的行为差异、算子精度模式（高精度模式开关）。
* **小任务实战**：在 910B 上跑一次语音/语言模型的小规模训练（延续你的微调习惯），全程用 `msprof` 观察。

* **💡 第 4 周 MVP 交付**：
> 云上 910B 完成一次「CUDA 训练脚本 → torch_npu 迁移」：拿你用过的任一微调脚本（如 Qwen2.5 LoRA），迁移到 910B 跑通，输出训练速度、loss 曲线与 GPU 版的对比；记录踩坑清单（至少 3 个坑及解法）。

#### 第 5-6 周：Ascend C 算子开发基础

* **学习重点**：
* **Ascend C 编程模型**：核函数（Kernel）→ Tiling → 流水编排；Host 侧算子注册（TBE/自定义算子包）与 Device 侧实现的分工。
* **三单元分工**：Cube（矩阵乘）/ Vector（向量计算）/ Scalar（标量控制）的编程接口；TQue/TQueBind/TBuf 的 buffer 抽象与 double buffer 流水。
* **开发流程**：算子工程创建 → Kernel 实现 → Tiling 参数计算 → 编译 → 单算子测试（mscclpp/op_test 框架）→ 接入模型。
* **对标学习**：把你 Stage 3 写的 CUDA fused RMSNorm 用 Ascend C 重写——同一算法双平台实现是最好的理解方式。

* **推荐资料**：
* 《Ascend C 算子开发指南》《Ascend C 入门教程》（昇腾社区，含配套 example 仓库 `ascend/ascendc`）

* **💡 第 5-6 周 MVP 交付**：
> 用 Ascend C 实现第一个自定义算子：**fused Add + RMSNorm**（复刻你 Stage 3 的 CUDA 版），完成 Kernel + Tiling + 单算子精度测试，输出与 PyTorch 参考实现的误差对比表。

#### 第 7-8 周：进阶算子 + 接入模型 + 复盘

* **学习重点**：
* **第二个算子（进阶）**：选一个有挑战的——**Softmax（含在线归约）** 或 **RoPE 融合算子**（呼应你 VLM 阶段的 RoPE 知识）；涉及归约、跨核数据分块的完整设计。
* **算子接入模型**：自定义算子注册到 torch_npu / ONNX Runtime（昇腾 EP）并在真实推理中调用。
* **Profiling 驱动优化**：用 `msprof` 抓算子的 Cube/Vector 利用率、流水气泡，迭代优化。
* **生态判断力**：什么场景用现有算子库、什么场景必须自研——昇腾岗位面试的必答题。

* **💡 第 7-8 周 MVP 交付（Stage 总交付）**：
> ① 第二个 Ascend C 算子完成并接入真实模型推理；② 两个算子的性能优化报告（优化前后延迟/利用率对比）；③ 《昇腾算子开发踩坑手册》：环境、编译、精度、性能四类问题各至少 3 条实战记录。
