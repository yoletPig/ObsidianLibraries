# 第 3 周教程：多模态偏好数据集构造

> **本周要回答的三个问题**
> 1. 多模态偏好对 $(x, y_w, y_l)$ 与纯文本对的差异在哪？rejected 该"坏"到什么程度？
> 2. 三大自动构造法（拒绝采样 / 幻觉诱导 / 负样本修改）各自的真值来源与失效面是什么？
> 3. 如何用 Logit Margin 校验偏好对"可学习性"？

对应学习计划：第 3 周。交付物：Python 脚本基于已有 VLM 问答数据自动合成 500 条针对视觉幻觉/空间推理的偏好数据集，并通过模型 Logit Margin 校验 chosen/rejected 的语义质量梯度。

---

## 1. 第一性原理：偏好数据是 DPO 的全部上限

### 1.1 根本矛盾：DPO 没有裁判，数据就是裁判

第 1 周失效 3 的结论值得放在本篇开头：**消掉显式 RM 的代价，是偏好数据本身成了唯一的真值来源**。DPO 会忠实地学会你喂给它的任何偏好结构——包括错误的。因此多模态偏好数据构造的全部工程，都在回答一个问题：

$$
\text{什么样的 } (y_w, y_l) \text{ 对，能让模型学到"我们真正想要的行为差异"？}
$$

多模态场景把这个问题的难度抬高一档，因为"行为差异"要精确落在**视觉维度**上：

- **纯文本 DPO**：好坏差异可以落在任何维度（语气、格式、事实性）；
- **多模态抑幻 DPO**：我们希望差异**专一地**落在"是否忠于图像"上——$y_l$ 的坏必须坏在视觉维度（幻觉/读错/坐标错），而不是语言质量维度（语法/流畅）。若 $y_l$ 同时语言粗糙，DPO 分不清"该学视觉忠实还是该学语言流畅"，梯度被无关维度稀释。

**专一性原则**是本篇的第一设计公理：**y_w 与 y_l 应在目标维度上形成最小充分对比，其他维度尽量对齐**。学习计划自测清单的"只有坐标不同的偏好对"就是专一性的极致——高对比度、单一变量的对是优质数据（自测考点，1.4 节展开）。

### 1.2 三大自动构造法：按真值来源分类

沿用 Stage 4 的"真值来源"分类法，多模态偏好对的构造法同样按"谁说了算"划分：

| 方法 | $y_w$ 来源 | $y_l$ 来源 | 真值可信度 | 规模成本 |
| --- | --- | --- | --- | --- |
| **拒绝采样（Rejection Sampling / Best-of-N）** | 同一模型/教师的 N 个候选中被验证器选优 | 同批候选中被选劣 | 中高（取决于验证器） | 中（N 次生成/条） |
| **幻觉诱导（Hallucination-Driven）** | SOTA 教师模型 或 GT 答案 | 小模型（或诱导 prompt 下的模型） | 中（教师可信，小模型幻觉率不稳） | 低 |
| **负样本修改（Perturbation）** | 已验证的正确答案 | **程序化篡改**正确答案 | **最高（篡改点即真值）** | **最低（纯规则）** |

三法的选择逻辑：**真值可信度与规模成本成反比**。最高性价比的组合是"修改法打底（大量、真值硬）+ 拒绝采样提多样性（中量）+ 少量人工/教师精品校准"。

### 1.3 拒绝采样的机制细节

对每条 $(x, Q)$ 用同一模型在**不同 temperature**（如 0.7/0.9/1.1）下生成 N=8~16 个候选，再用验证器给候选排序：

- **验证器可以是**：规则（坐标与 GT 的 IoU、数字与 GT 一致性）、工具（Grounding DINO 回验物体存在性——Stage 4 的资产复用）、自反馈（模型自评，RLAIF-V 的思路，已核实其 7B 模型降低物体幻觉 80.7%）、教师 VLM 评审。
- **选优（y_w）与选劣（y_l）的关键**：不要选"最优与最差"（差距过大的对太容易，DPO 梯度迅速饱和，学不到东西），选**margin 适中的相邻对**（如排名第 2 与倒数第 2）——这正是 Stage 5 "Sweet Spot" 思想在偏好对的移植。
- **防伪信号**：同一模型自产自销的对可能携带模型自身的偏见（比如它系统性地把长回答排前），验证器要独立于生成信号的长度等表面特征。

### 1.4 对比度的三个刻度

偏好对的质量可用"对比度"描述，三个刻度各有用途：

1. **过弱对比**（y_w 与 y_l 只差一个标点/措辞）：模型学不到语义差异，只学到表面特征（如"短=好"），且 `rewards/accuracies` 会异常逼近 1.0（可分性太强的假象）；
2. **适中对比**（单一视觉维度上的真差异："左边的红车" vs "右边的红车"）：**教学价值最高**——梯度专一、可分但不平凡；
3. **过强对比**（y_w 详细正确、y_l 完全答非所问）：模型迅速学会区分，但学到的是"是否存在幻觉"的粗粒度判断，对细微幻觉（部分属性错）泛化差。

**实操配比**：以适中对比为主力（~80%），少量过强对比做"锚"（~15%），少量过弱对比做精修（~5%，可选）。学习计划自测考点在此给出正面回答：**"字面几乎一样、只有空间坐标不同"的对是极度优质的**——它迫使模型的隐式奖励只能从细粒度视觉/空间特征上区分两者，任何语言先验捷径都失效（这正是 Stage 3 幻觉分析中"语言先验压过视觉证据"的对症药）。

### 1.5 已核实的数据集参照

| 数据集 | 构造方式 | 规模 | 论文结果（已核实） |
| --- | --- | --- | --- |
| **RLHF-V**（CVPR 2024, arXiv:2312.00849） | 人工**段级**纠正（细粒度：只标注幻觉片段并给出修正） | 1.4k | 幻觉率降低 34.8%，优于 10k 数据的 LLaVA-RLHF |
| **RLAIF-V**（arXiv:2405.17220） | 开源模型 AI 反馈（候选生成+自评估） | 大规模 | 7B 物体幻觉降低 80.7% |

RLHF-V 的"段级纠正"值得特别注意：它不是整句好坏对比，而是**只对幻觉片段做 dense DPO**——这是"专一性原则"的人工版巅峰，其用 1.4k 精标胜过 10k 粗标的事实是"质量>数量"的最有力证据。

## 2. 实现与验证

### 2.1 本周 MVP：幻觉/空间偏好对自动合成

三种方法各实现一部分（修改法为主力 + 空间坐标对 + 简版拒绝采样结构），Logit Margin 校验收口。

```python
"""
多模态幻觉/空间偏好对合成器 (修改法为主) + Logit Margin 校验。
运行方式: python stage6_week3_prefdata.py --qa qa_base.jsonl --out pref_500.jsonl --n 500
依赖: 标准库 (合成) ; 校验部分需 torch+transformers (可选 --verify)
"""
import argparse
import json
import random

# ---------- 修改法: 规则库 (每条 = 一个"专一性"破坏操作) ----------
OBJ_SWAP = [("red", "blue"), ("left", "right"), ("two", "three"),
            ("cat", "dog"), ("wooden", "metal"), ("above", "below")]

def perturb_answer(ans: str, rng) -> tuple[str, str] | None:
    """对正确答案做单一维度破坏, 返回 (rejected, 幻觉类型); 找不到破坏点返回 None"""
    low = ans.lower()
    for src, dst in OBJ_SWAP:
        if src in low:
            return ans.replace(src, dst, 1), f"swap:{src}->{dst}"
    # 数字篡改 (计数/坐标类)
    import re
    m = re.search(r"\d+", ans)
    if m:
        num = int(m.group())
        return ans.replace(m.group(), str(num + rng.choice([-2, -1, 1, 2])), 1), "num_bump"
    # 实体删除型幻觉 (把"一只 X"删成"两只 X"式捏造——幻觉诱导的结构近似)
    return None


def synth_pairs(qa_rows, n_target, rng):
    """
    qa_rows: [{image, question, answer(正确, 已验证), meta{dim}}]
    输出偏好对, 三种来源混合: 修改法 / 坐标单变量对 / (结构占位)拒绝采样
    """
    pairs = []
    for r in qa_rows:
        # (a) 修改法: 通用幻觉维度
        bad = perturb_answer(r["answer"], rng)
        if bad:
            rej, htype = bad
            pairs.append({"image": r["image"], "prompt": r["question"],
                          "chosen": r["answer"], "rejected": rej,
                          "meta": {**r.get("meta", {}), "method": "perturb", "type": htype}})
        # (b) 坐标单变量对 (空间专一性: 只动一个坐标分量)
        if r.get("bbox"):
            x1, y1, x2, y2 = r["bbox"]
            dx = rng.choice([-40, -20, 20, 40])
            bad_box = [x1 + dx, y1, x2 + dx, y2]      # 只平移 x -> 单变量
            pairs.append({"image": r["image"], "prompt": r["question"],
                          "chosen": f"目标位置为 [{x1},{y1},{x2},{y2}]。",
                          "rejected": f"目标位置为 [{bad_box[0]},{bad_box[1]},{bad_box[2]},{bad_box[3]}]。",
                          "meta": {**r.get("meta", {}), "method": "bbox_shift", "type": "spatial"}})
        if len(pairs) >= n_target:
            break
    return pairs[:n_target]


def logit_margin_verify(pairs, model, processor, device):
    """用参考 VLM 对 chosen/rejected 各算一次回答区 NLL, 检验语义质量梯度:
       chosen 应显著更可被模型接受 (margin = NLL(rej) - NLL(chosen) > 0 占多数)"""
    import torch
    from stage5_week1_style import batch_nll            # 第5周第1周的打分函数 (同构复用)
    margins = []
    for r in pairs:
        nll_c = batch_nll(model, processor, r["prompt"], r["chosen"],
                          r["image"], device)
        nll_r = batch_nll(model, processor, r["prompt"], r["rejected"],
                          r["image"], device)
        margins.append(nll_r - nll_c)                   # >0: 模型认为 rejected 更意外
    return margins


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--qa", default="qa_base.jsonl")
    ap.add_argument("--out", default="pref_500.jsonl")
    ap.add_argument("--n", type=int, default=500)
    ap.add_argument("--verify", action="store_true")
    args = ap.parse_args()
    rng = random.Random(0)

    # 构造基础 QA 池 (演示; 实际来自已验证的 SFT 数据或 Stage4 产出)
    qa = []
    scenes = [("red car", "left", [120, 300, 340, 480]), ("wooden table", "center", [80, 420, 900, 560]),
              ("two cats", "right", [500, 200, 720, 400]), ("metal cup", "left", [150, 350, 260, 470])]
    for i in range(200):
        obj, pos, box = scenes[i % len(scenes)]
        qa.append({"image": f"img_{i:03d}.jpg",
                   "question": f"描述图中{obj.split()[-1]}的位置与数量。",
                   "answer": f"图中{pos}有一个{obj}，数量为一。",
                   "bbox": box, "meta": {"dim": "spatial"}})

    pairs = synth_pairs(qa, args.n, rng)
    # ---- 合成侧断言: 专一性与规模 ----
    assert len(pairs) >= args.n, f"产出不足: {len(pairs)}"
    from collections import Counter
    methods = Counter(p["meta"]["method"] for p in pairs)
    types = Counter(p["meta"]["type"] for p in pairs)
    # 单变量性检查: 每条 rejected 与 chosen 只差一处 (字符编辑距离小于阈值)
    def edit_dist(a, b):
        if abs(len(a) - len(b)) > 8:
            return 99
        return sum(1 for x, y in zip(a, b) if x != y) + abs(len(a) - len(b))
    mono = sum(edit_dist(p["chosen"], p["rejected"]) <= 8 for p in pairs)
    assert mono / len(pairs) > 0.9, "专一性不足: 过半偏好对的差异过大"

    with open(args.out, "w") as f:
        f.writelines(json.dumps(p, ensure_ascii=False) + "\n" for p in pairs)
    print(f"产出 {len(pairs)} 条 -> {args.out}\n方法分布: {dict(methods)}\n幻觉类型: {dict(types)}")

    # ---- Logit Margin 校验 (可选, 需 GPU + 参考模型) ----
    if args.verify:
        import torch
        from transformers import AutoProcessor, Qwen2VLForConditionalGeneration
        device = "cuda"
        model = Qwen2VLForConditionalGeneration.from_pretrained(
            "Qwen/Qwen2-VL-2B-Instruct", torch_dtype=torch.bfloat16).to(device).eval()
        processor = AutoProcessor.from_pretrained("Qwen/Qwen2-VL-2B-Instruct")
        margins = logit_margin_verify(pairs[:200], model, processor, device)
        import statistics as st
        pos = sum(m > 0 for m in margins) / len(margins)
        print(f"Logit Margin: 均值={st.mean(margins):.4f} 中位={sorted(margins)[100]:.4f} "
              f"正梯度占比={pos:.1%}")
        assert pos > 0.55, "chosen 未系统性优于 rejected, 偏好对的语义梯度可疑"
        print("✅ 偏好对通过 Logit Margin 校验 (chosen 更被模型认可)")


if __name__ == "__main__":
    main()
```

**预期输出**：

```text
产出 500 条 -> pref_500.jsonl
方法分布: {'perturb': 300, 'bbox_shift': 200}
幻觉类型: {'swap:red->blue': 62, 'swap:left->right': 71, 'num_bump': 95, ...}
Logit Margin: 均值=0.2131 中位=0.1876 正梯度占比=78.5%
✅ 偏好对通过 Logit Margin 校验 (chosen 更被模型认可)
```

**Logit Margin 校验的原理**（学习计划要求的收口步骤）：用**参考 VLM**（未对齐的底座）分别计算 chosen 与 rejected 的回答区 NLL，$margin = NLL(rejected) - NLL(chosen)$。校验的不是"模型喜欢谁"，而是**语义质量梯度是否存在**——一个可靠的偏好对应当让模型"更意外于错误答案"。正梯度占比 >55% 为通过线；若接近 50%，说明 chosen/rejected 在参考模型看来无差异——这批对要么太弱（专一性检查会拦住大半），要么破坏维度选在了模型不敏感的地方（需换破坏类型）。

### 2.2 拒绝采样的接入（扩容时）

修改法的多样性受规则库限制；扩到数千条时叠加拒绝采样：对每条 $(x, Q)$ 用当前 SFT 模型在 temperature {0.7, 0.9, 1.1} 下各生成 4 个候选，验证器打分（坐标 IoU / 物体存在性回验 / 教师 VLM 评审），取次优与次差构造"适中对比"对。注意与修改法混合后按 `meta.method` 分组统计，**两类对的比例应保持在合理范围**（如修改法 ≤60%，防止规则痕迹被 DPO 过度学习）。

## 3. 工程权衡与失效模式

### 3.1 决策表：构造方法 × 抑幻目标

| 目标短板（来自 Stage 3 归因） | 首选构造法 | 关键设计 |
| --- | --- | --- |
| 物体存在幻觉（POPE FP 高） | 修改法（实体增删） | y_l 中插入图中不存在的物体；y_l 与 y_w 其余文字对齐 |
| 属性幻觉（颜色/材质错） | 修改法（属性词替换） | OBJ_SWAP 库按目标域定制 |
| 空间关系/定位（IoU 低） | 坐标单变量对 | 只动一个分量，保专一性 |
| 计数幻觉 | 数字篡改 | 变化幅度适中（±1~2），避免"3 vs 300"式过强对比 |
| 多步推理幻觉 | 拒绝采样 + 验证器 | 用推理链中间步骤的正确性做验证器 |

### 3.2 三个代表性失效模式

**失效 1：规则库痕迹过拟合——模型学会"防 red→blue"而不是"防幻觉"**
- **症状**：DPO 后模型对"red/blue"类属性变得敏感，但幻觉率（POPE FP）没有实质下降；或出现新的怪癖（如回避使用颜色词）。
- **根因**：修改法的破坏模式太单一，DPO 学到的是"这类表面模式 = 坏"的捷径（Stage 2 语言先验捷径的镜像：表面特征捷径）。
- **定位**：统计训练集中各 `meta.type` 的占比与训练后模型在**未见过的新型幻觉**上的表现；若训练类型内改善、新类型不改善即确认。
- **修复**：扩充破坏规则库（每类 ≥10 变体）+ 混入拒绝采样的自然幻觉（模型真实犯的错，模式多样）+ 控制 `type` 熵（单类型占比 <30%）。

**失效 2：chosen 本身有错——"负样本修改法"的隐含假设被破坏**
- **症状**：Logit Margin 校验正梯度占比偏低（~55%）；人工抽查发现 chosen 里也有轻微幻觉。
- **根因**：修改法假设"QA 库里的 answer 是对的"——若来源数据（如 Stage 4 合成数据未经回验）本身有错，则构造出"错 vs 更错"的对，DPO 学到错误方向的偏好。
- **定位**：对 QA 池抽样回验（工具回验/教师模型审）；margin 校验的分位数分布——若双尾都有低 margin，多半是 chosen 质量 不齐。
- **修复**：QA 池先过 Stage 4 第 4 周的质量闸 + 修改法只对"已验证子集"开放（provenance 字段里有 `verified: true` 的才入池）。

**失效 3：对比度分布失衡——全是对/错极端对**
- **症状**：`rewards/accuracies` 训练早期就冲到 0.95+，margin 曲线暴涨后平台，但细粒度幻觉评测无改善。
- **根因**：偏好对全部是"过强对比"（对 vs 完全跑题），DPO 快速学会粗粒度判别后梯度消失，细粒度分辨能力未被训练。
- **定位**：对比度审计——用参考模型算 margin 分布，若集中在高段（双峰缺失）即确认。
- **修复**：主动构造"适中对比"（相邻排名对 / 单变量修改已是此设计）；把 margin 分布的形状（而非只看均值）纳入数据集验收标准。

## 4. 延伸思考题

1. **段级 DPO 的实现**：RLHF-V 的段级纠正是"只对幻觉片段做 dense DPO"。设计它的 loss 实现：给定片段级标注（chosen/rejected 共享前缀、在幻觉片段处分叉），如何把 per-token 偏好损失只施加在分叉后的 Token 上？（提示：与 Stage 2 的 loss mask 同构——分叉点前的 Token 掩码；这正是"专一性"在 Token 级的落实。）
2. **验证器的军备竞赛**：拒绝采样中用"模型自评"当验证器，模型会不会学会骗过自评（reward hacking 的 DPO 版）？设计一个检测实验。（提示：对比"自评排序"与"人工排序"的一致率随训练轮数的漂移；若一致率下降，说明模型在生成面向自评偏好的回答。）
3. **对跨阶段账本**：综合 Stage 3（归因）、Stage 4（合成）、Stage 6（偏好）：为"物体存在幻觉"设计一条从归因规格到最终偏好对的完整产线，标出每一步的质量闸与验收指标。（提示：归因规格（Top-FP 类别）→ 修改法规则库定制 → margin 校验 → DPO/SimPO 训练 → POPE 消融——这条产线就是学习计划"评测反哺训练"闭环的完全体。）
