## 1. 第一性原理：评测的根本矛盾

### 1.1 根本矛盾：开放式生成 vs 可比对的真值

VLM 的任务形态是**开放式生成**（给定图和问题，自由输出文本），但评测的本质是**与真值比对并打分**。两者之间存在一个鸿沟：同一个正确语义可以有无数种表述——"图中有一只橘猫"、"这是一只橘色的猫"、"猫，橘色"——字符串层面的比对会把语义正确判为错误。

评测方法设计的全部演化史，就是**在这个鸿沟上收敛出可比对形式**的历史。三条技术路线：

| 路线 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 封闭化（选择题化） | 把开放问题改造成 A/B/C/D 选择题 | 判分零歧义、全自动 | 引入选项先验，模型可"盲猜" |
| 规则匹配 | EM / 正则 / 关键词匹配 | 快、免费 | 对表述形式极度敏感 |
| LLM-as-a-Judge | 用强模型给开放式回答评分 | 语义级判分，最接近人类 | 引入裁判偏差、有成本 |

主流评测集是三条路线的**组合**：题目封闭化 + 正则/LLM 提取答案 + （必要时）Judge 评分。理解每条路线的失效模式，是读分数的第一前提。

### 1.2 选择题的防作弊机制：为什么选项要打乱

选择题有一个与生俱来的漏洞：**模型可以不读题、不看图，只靠选项的统计先验答题**。两个经典的"白拿分"现象：

1. **位置偏置（Position Bias）**：LLM 对某些选项位置（如 "A" 或 "All of the above"）有系统性偏好。若真值位置固定，一个纯文本盲猜模型也能拿高分。
2. **词频先验**：错误选项若写得明显"不像答案"（长度、具体性差异），模型靠语言直觉排除。

MMBench 论文的核心设计就是**选项循环移位（Circular Evaluation）**：同一道题把正确答案轮换到 A/B/C/D 各位置生成 $K$ 个变体，全部作答后统计"所有变体都答对"才算该题得分。一个靠位置偏置拿分的模型，在循环评测下分数会被显著拉回真实水平（MMBench 论文实测部分模型在循环评测下掉分明显）。

MME 的设计则从另一个方向防作弊：**全部是二选一判断题（Yes/No），且按"感知/认知"两大维度、多个子任务组织**。它配套一个加分项设计——**Acc + 分数（accuracy + acc+）**：Acc+ 要求"同一图片的正反两问都答对"（如"是热的吗？"/"是凉的吗？"都答对）才计分，直接惩罚"无脑答 Yes"的策略（详见第 3 周 POPE 的彩票攻击分析，两者机制同源）。

SEED-Bench 的贡献是把题目按**感知（空间/时间）与推理**维度打了标签，且选择题的正确答案分布经过人工校验均衡——它给社区的是"维度化的分数画像"而非单一总分。

**读分数时的第一反应**（本周核心肌肉记忆）：看到选择题分数，先问三件事——选项位置是否随机化/循环化？答案分布是否均衡？是否报告了循环评测下的分数？三者缺一，分数都可能虚高。

### 1.3 专项 Benchmark 的能力覆盖图谱

| 基准 | 能力域 | 题型 | 规模量级 | 陷阱 |
| --- | --- | --- | --- | --- |
| MMBench | 综合感知+推理 | 选择题（循环评测） | ~3k 题 | 不循环的分数不可比 |
| MME | 感知/认知细分 | Yes/No 判断 | ~2374 问 | 子任务分数不等权，看画像别看总分 |
| SEED-Bench | 多维度感知+推理 | 选择题 | ~19k 题 | 视频部分与图片部分要分开看 |
| DocVQA | 文档 OCR+理解 | 开放式 VQA | ~12.7k 训练/5.3k 验证 | 指标是 ANLS（见 1.4），不是 EM |
| OCRBench | OCR 全栈（含定位/推理） | 混合 | ~10k | 含手工设计题，分数线按档位解读 |
| ChartQA | 图表问答 | 开放式 | ~20k | 数值答案需容忍格式变体 |
| MathVista | 视觉数学推理 | 混合（选择+开放） | ~6.1k | 思维链模型必须开 CoT 再评，否则严重低估 |

选基准的原则：**画像而非排名**。评测的目的不是给模型一个总分排序，而是回答"我的场景需要的能力项，这个模型几分"。第 4 周的自建基准正是把这一原则推到极致。

### 1.4 指标的适用边界

**Exact Match（EM）**：$\text{EM}(pred, gt) = \mathbb{1}[pred = gt]$（常配小写化、去标点等规范化）。适用于答案空间封闭且极短的场景（年份、数量、选项字母）。对开放式 VQA 系统性失真："1920" vs "约 1920 年"判错。

**ANLS（Average Normalized Levenshtein Similarity，DocVQA 采用）**：用编辑距离给软分：

$$
\text{ANLS} = \frac{1}{N}\sum_{i} \max_j \left( 1 - \frac{\text{NL}(pred_i, gt_{ij})}{\max(\text{len}(pred_i), \text{len}(gt_{ij}))} \right)
$$

其中 $gt_{ij}$ 是第 $i$ 题的第 $j$ 个可接受真值（文档答案常有多种写法），$\text{NL}$ 是归一化 Levenshtein 距离。它承认"差一个字符"比"完全不同"好得多——适合 OCR 类任务，但对语义对而字面不同的回答仍会误判。

**BLEU/ROUGE**：源自机器翻译/摘要，基于 n-gram 重叠。VQA 场景的致命弱点：答案太短（几个词），n-gram 统计量级无意义；且同义改写判零分。**经验规则：短答案 VQA 用 EM/ANLS + LLM Judge，长描述生成才轮到 BLEU/ROUGE/CIDEr，且需辅以 Judge**。

**LLM-as-a-Judge**：把预测与真值（含题目）喂给强模型，输出等级分或对错判断。它解决了语义比对问题，但引入新失效模式：裁判偏置（偏好长回答、偏好自家风格）、位置敏感（对比式评分时答案顺序影响判断）、可复现性差（温度与版本漂移）。工程纪律：裁判 prompt 固定并随报告归档、温度设 0、记录裁判模型版本号——否则两周后的分数与今天不可比。

## 2. 系统机制：答案提取的三级火箭

### 2.1 为什么要"提取"而不是直接比对

现代 VLM（尤其推理模型）的原生输出形态：

```text
用户问图中物体的颜色，选项 A 红 B 蓝 C 绿 D 黄。
首先观察图像的主体……颜色是心理学上最显眼的属性之一……
综上所述，正确答案是 B。
```

若直接拿全文与 "B" 做 EM，必然失败。评测管线的标准做法是**三级提取**：

1. **规则层**：正则匹配明确的答案标记（`答案是 B`、`Answer: (B)`、`the answer is C` 等多语言模板）；
2. **约束层**：要求模型按指定格式输出（system prompt 里规定"最后一行必须是 `Answer: X`"）——从源头减少提取难度；
3. **模型层**：前两级失败时，调用一个 LLM 专门做"从回答中提取选项"的任务（VLMEvalKit 的默认兜底策略）。

VLMEvalKit 的实现（已核实 main 分支行为）：`can_infer_option` / `can_infer_text` 函数路由提取逻辑，2025 年的 PR #1175 优化了这两者的路由，使更多情况走 LLM choice extractor——这意味着**同一模型在不同版本 VLMEvalKit 下分数会有轻微漂移**，横向比较时必须固定框架版本并在报告中注明。

### 2.2 提取的对抗性细节

- **思维链污染**：推理过程里可能提到所有选项（"A 不对，B 也不对，应该是 C"），天真地取"第一个出现的选项字母"会提取到 A。正则必须锚定**答案性表述**（`答案`/`answer`/`option` 后面的字母），而非任意出现。
- **Yes/No 的否定陷阱**："不确定" "Not sure" 应视为无效答案还是 No？必须在评测协议里显式定义（POPE 的惯例是判 No，即保守方向——第 3 周展开）。
- **坐标提取**：`[x1, y1, x2, y2]` 可能被写成 `(120, 340, 480, 760)`、`x1=120 ...`、或中文括号。提取器要兼容多种分隔符与括号风格，并做数值合法性检查（$x_2 > x_1$ 等）。

## 3. 实现与验证

### 3.1 本周 MVP：三级答案提取器 + 准确率计算

以下脚本覆盖选择题/判断题/坐标三类提取，含 8 组单测断言，可直接运行：

```python
"""
VLM 评测答案提取器: 从含思维链的原生输出中抽取最终答案并计算 Accuracy。
运行方式: python stage3_week1_answer_extraction.py
依赖: 无第三方库 (纯标准库)
"""
import re
from dataclasses import dataclass


@dataclass
class ExtractResult:
    value: str            # 归一化后的答案: "A" / "yes" / "123.45,234.5,678,789"
    method: str           # 提取层级: rule / fallback / failed
    raw: str              # 原始回答 (供失败样本人工复核)


# ---- 规则层: 锚定"答案性表述"而非任意字母, 防思维链污染 ----
OPTION_PATTERNS = [
    r"(?:正确答案|答案|answer)\s*(?:是|为|is|:|：)?\s*[（(【\[]?\s*([A-D])\s*[）)】\]]?",
    r"(?:option|选项)\s*(?:is|是)?\s*[（(【\[]?\s*([A-D])\s*[）)】\]]?",
    r"^(?:[（(【\[]?)\s*([A-D])\s*[）)】\]]?\s*[。.!？?]?\s*$",   # 整行只有一个选项
]
BOOL_PATTERNS = [
    r"\b(yes|no)\b",
    r"(是的|不是|对|错|正确|错误|有|没有|存在|不存在)",
]
COORD_PATTERN = re.compile(
    r"[\[（(【]?\s*(\d{1,4}(?:\.\d+)?)\s*[,，、]\s*(\d{1,4}(?:\.\d+)?)"
    r"\s*[,，、]\s*(\d{1,4}(?:\.\d+)?)\s*[,，、]\s*(\d{1,4}(?:\.\d+)?)\s*[\]）)】]?")


def _last_match(text: str, patterns) -> str | None:
    """取最后一个匹配 (答案通常在思维链末尾), 各模式依优先级"""
    for pat in patterns:
        matches = re.findall(pat, text, flags=re.IGNORECASE)
        if matches:
            return matches[-1]
    return None


def extract_option(text: str) -> ExtractResult:
    m = _last_match(text, OPTION_PATTERNS)
    if m:
        return ExtractResult(m.upper(), "rule", text)
    # 兜底: 回答极短时才允许裸字母 (长思维链裸字母大概率是污染)
    stripped = text.strip()
    if len(stripped) <= 3 and stripped.upper() in "ABCD":
        return ExtractResult(stripped.upper(), "fallback", text)
    return ExtractResult("", "failed", text)


def extract_bool(text: str) -> ExtractResult:
    en = _last_match(text, BOOL_PATTERNS[:1])
    if en:
        return ExtractResult(en.lower(), "rule", text)
    zh = _last_match(text, BOOL_PATTERNS[1:2])
    if zh:
        val = {"是的": "yes", "对": "yes", "正确": "yes", "有": "yes",
               "存在": "yes"}.get(zh, "no")
        return ExtractResult(val, "rule", text)
    return ExtractResult("", "failed", text)


def extract_coord(text: str) -> ExtractResult:
    matches = COORD_PATTERN.findall(text)
    if not matches:
        return ExtractResult("", "failed", text)
    x1, y1, x2, y2 = map(float, matches[-1])
    # 合法性检查: 必须构成合法框
    if not (x2 > x1 and y2 > y1):
        return ExtractResult("", "failed", text)
    return ExtractResult(f"{x1},{y1},{x2},{y2}", "rule", text)


def accuracy(preds: list[str], gts: list[str]) -> float:
    assert len(preds) == len(gts) and len(preds) > 0
    return sum(p == g for p, g in zip(preds, gts)) / len(preds)


if __name__ == "__main__":
    # ---- 单测: 8 组关键行为断言 ----
    # 思维链污染场景: 过程提及 A/B, 答案是 C
    cot = "选项A说…不对；B也不符合；综上，正确答案是 C。"
    assert extract_option(cot).value == "C"
    assert extract_option("Answer: (B)").value == "B"
    assert extract_option("我的答案是：【D】").value == "D"
    # 纯思维链提及选项但无答案表述 -> 应失败而非误提
    assert extract_option("先看 A，再看 B，C 和 D 也不像").method == "failed"
    # 布尔: 中文否定
    assert extract_bool("图中没有出现猫，所以不对。").value in ("no",)
    assert extract_bool("Yes, there is a dog.").value == "yes"
    # 坐标: 中文括号 + 合法性
    r = extract_coord("目标位于（120，340，480，760）")
    assert r.value == "120.0,340.0,480.0,760.0"
    assert extract_coord("框是 (500,300,400,200)").method == "failed"  # x2<x1 非法

    # ---- 模拟 100 条评测并计算 Accuracy ----
    import json, random
    rng = random.Random(0)
    samples = json.load(open("/tmp/eval_100.json")) if __import__("os").path.exists(
        "/tmp/eval_100.json") else [
        {"pred": f"经过分析，正确答案是 {'ABCD'[rng.randrange(4)]}。",
         "gt": "ABCD"[rng.randrange(4)]} for _ in range(100)]
    results = [extract_option(s["pred"]) for s in samples]
    preds = [r.value if r.method != "failed" else "___UNPARSED___" for r in results]
    acc = accuracy(preds, [s["gt"] for s in samples])
    n_fail = sum(r.method == "failed" for r in results)
    print(f"Accuracy: {acc:.1%}  |  提取失败 {n_fail}/100 (失败样本见下方 raw)")
    for r in results:
        if r.method == "failed":
            print("  [FAILED]", r.raw[:80].replace("\n", " "))
```

**预期输出**（模拟数据下 Accuracy 约 25%——随机水平，因为 pred 与 gt 独立采样；这本身就是一个教学点：**随机基线是选择题评测的必备参照**）：

```text
Accuracy: 27.0%  |  提取失败 0/100 (失败样本见下方 raw)
```

设计要点：断言覆盖的都是**对抗性行为**——思维链污染时不误提、非法坐标时拒绝、中文布尔归一化——而非"能跑通"。`failed` 的样本必须人工复核：**提取失败率本身是评测报告的必报项**（失败率 >5% 时，Accuracy 的解释力已不可信）。

### 3.2 接入真实评测数据

把脚本对接 VLMEvalKit 的输出（第 2 周实战）：其预测文件是 TSV，含 `prediction` 列；把它读进来替换 3.1 的模拟数据即可。评测协议建议归档为一行摘要：`框架版本 / 裁判模型 / 提取脚本版本 / 失败率`——四要素缺一，数字不可复现。

## 4. 工程权衡与失效模式

### 4.1 指标选择的决策表

| 任务形态 | 首选指标 | 兜底 | 禁用 |
| --- | --- | --- | --- |
| 选择题 | 循环评测 Accuracy | EM + 提取失败率 | 裸 EM（位置偏置未控） |
| Yes/No 判断 | Acc + Acc+（MME 式）/ F1（POPE 式） | — | 单看 Accuracy（类不平衡） |
| 短答案 VQA | ANLS / EM + LLM Judge | Judge 单独 | 裸 BLEU |
| 长描述生成 | Judge 评分 + CIDEr | 人工抽检 | 纯自动指标 |
| 定位 | IoU@0.5 Accuracy | 平均 IoU | EM |

### 4.2 三个代表性失效模式

**失效 1：提取器把思维链里的选项当答案，分数虚高或虚低**
- **症状**：同一个模型换提取脚本，选择题分数波动 3~10 个百分点。
- **根因**：正则锚定不严（匹配任意 `([A-D])` 而非答案性表述）、取第一个匹配而非最后一个、或中英模板覆盖不全。
- **定位**：抽样 30 条"分数变动"的样本，人工标注真值答案，对比两个提取器的命中情况。
- **修复**：采用 3.1 的"答案性表述锚定 + 最后匹配 + 长文本禁裸字母"三层策略；把提取失败率作为必报指标。

**失效 2：Judge 评分的系统偏置改变了模型排名**
- **症状**：换裁判模型（GPT-4 → Qwen-Max）后两个模型的相对排名反转。
- **根因**：裁判偏好与被评模型的风格耦合（如裁判偏好长回答，而模型 A 恰好话多）；或裁判 prompt 未含真值，退化为"哪个回答更像好回答"而非"哪个更对"。
- **定位**：对同一批样本做双裁判交叉评分，统计不一致率；不一致率 >10% 时排名不可信。
- **修复**：裁判 prompt 附带题目与真值；分数制（1~10）优于二值制以降低方差；报告中永久绑定裁判版本。

**失效 3：基准饱和与数据泄漏让分数失去区分度**
- **症状**：新模型在某个老基准上 92%+，但实际部署效果差。
- **根因**：训练数据混入了评测集（网络抓取的 SFT 数据常见），或基准题目模式已被后续模型过拟合（benchmark contamination 是 LLM 时代的系统性问题）。
- **定位**：做 n-gram 重叠扫描（训练语料 vs 评测题面）；或用"扰动一致性"测试——改写题面/换图后分数是否崩塌。
- **修复**：优先选 2024 年后发布、有 held-out 声明的新基准；关键结论用自建基准交叉验证（第 4 周）。

## 5. 延伸思考题

1. **循环评测的代价核算**：MMBench 式循环评测把每题变成 $K$ 个变体，评测成本乘 $K$。设计一个折中方案：如何用 1/4 的成本近似循环评测的去偏效果？（提示：随机分配每题一个变体 + 大题量；或分层采样——只对"模型自信度低"的题做循环。讨论方差与偏差的交换。）
2. **Judge 的元评测**：给你 200 条人工标注的对错样本，如何量化某个 LLM 裁判的可靠度？给出至少三个指标（提示：与人工的一致率、Cohen's Kappa（排除随机一致）、对长度/风格的偏置回归系数）。
3. **动手实验**：取 3.1 的提取器，构造 20 条"对抗样本"（答案表述故意不规范：`所以选B啦`、`answr is A`（故意拼写错）、`答案是 B 但我也觉得 C 有道理`），统计失败率并迭代你的正则；思考在哪一点上应该放弃正则、转投 LLM 提取。
