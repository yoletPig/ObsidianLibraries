### 阶段八：大模型与多模态训练系统及推理工程（3 - 5 周）

**阶段核心目标**：实现从“算法使用者”到“高性能 AI 系统工程师”的跨越。深刻理解大模型在训练与推理阶段的显存瓶颈（Memory Wall）、计算瓶颈与 I/O 瓶颈，掌握分布式并行训练架构（ZeRO 1/2/3、FSDP、张量/流水线并行）以及高吞吐推理服务引擎（vLLM、SGLang、PagedAttention、RadixAttention），能够对训练与推理系统进行极限显存优化与吞吐量调优。

### 📅 逐周学习路线与 MVP 交付

#### 第 1 周：显存瓶颈剖析与 PyTorch 分布式并行基础

* **学习重点**：
* **大模型显存开销精确计算**：
* **模型权重（Weights）**：16-bit (FP16/BF16) 下每 1B 参数占用 $2\text{ GB}$ 显存。
* **优化器状态（Optimizer States）**：标准 AdamW (FP32) 每 1B 参数占用 $8\text{ GB}$（一阶动量 $m$ + 二阶动量 $v$）；开启 FP16/BF16 混合精度训练时，优化器备份权重额外占用 $4\text{ GB}$，合计 $12\text{ GB/1B}$。
* **梯度（Gradients）**：16-bit 下每 1B 参数占用 $2\text{ GB}$。
* **激活显存（Activation Memory）与 KV Cache**：长上下文（Context Length）下的显存增长曲线。


* **PyTorch 分布式通信原语 (Distributed Primitives)**：
* 理解 `all_reduce`、`all_gather`、`reduce_scatter`、`broadcast` 等底层 NCCL 通信原语。
* 理解 DDP (Distributed Data Parallel) 的梯度 Bucketing 与通信重叠（Communication Overlapping）机制。




* **💡 第 1 周 MVP 交付**：
> 编写一个 PyTorch 显存监控与分析脚本：使用 `torch.cuda.memory_allocated()` 和 `torch.cuda.max_memory_allocated()`，精确测算并打印出 7B VLM 模型在前向传播（Forward）、反向传播（Backward）以及优化器 Update 阶段的显存占用，画出显存瀑布图，推导出模型权重、梯度与激活显存的具体比例。



---

#### 第 2 周：分布式训练引擎：DeepSpeed ZeRO 与 FlashAttention 机制

* **学习重点**：
* **DeepSpeed ZeRO (Zero Redundancy Optimizer) 深度拆解**：
* **ZeRO-1**：对优化器状态（Optimizer States）切片，减少 4x 显存开销。
* **ZeRO-2**：对优化器状态 + 梯度（Gradients）切片，通信量与 DDP 相同。
* **ZeRO-3**：对优化器状态 + 梯度 + 模型参数（Parameters）全切片，虽然显著降低显存，但引入额外的参数 `all_gather` 通信开销。
* **Offload 机制**：ZeRO-Offload / ZeRO-Infinity 将状态切片 offload 到 CPU RAM / NVMe SSD。


* **FlashAttention-1 / 2 / 3 底层原理**：
* **传统的 Attention 瓶颈**：显存读写瓶颈（Memory-Bound），需要频繁将大小为 $O(N^2)$ 的 Intermediate Attention Matrix 写入 HBM（GPU 高带宽显存）。
* **FlashAttention 的核心突破**：利用 GPU 片上高速 SRAM，进行 **Tiling（分块计算）** 与 **Online Softmax 重计算**，将显存复杂度降至 $O(N)$，实现 2~4 倍的计算加速。




* **推荐论文**：
* ZeRO: *ZeRO: Memory Optimizations Toward Training Trillion Parameter Models*
* FlashAttention: *FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness*


* **💡 第 2 周 MVP 交付**：
> 编写 DeepSpeed 配置文件（`ds_config.json`），在多 GPU 环境下运行一个 7B+ VLM 的 ZeRO-3 + FlashAttention-2 训练脚本。在 8k+ 上下文长度下对比开启与关闭 FlashAttention-2 时的 TFLOPS 计算吞吐量与显存峰值差异。

#### 第 3 周：高吞吐推理引擎核心：vLLM & PagedAttention

* **学习重点**：
* **推理阶段的 KV Cache 内存痛点**：
* 自回归生成（Autoregressive Decoding）中 KV Cache 造成的内存碎片化（Memory Fragmentation）与过度预分配（Over-reservation）问题。


* **PagedAttention 原理（vLLM 的基石）**：
* 借鉴操作系统虚拟内存（Virtual Memory）与分页（Paging）思想，将 KV Cache 划分为固定大小的物理 Block，允许不连续的显存存储。


* **连续批处理（Continuous Batching）**：
* 替代传统 Static Batching，实现 Request 级别的 Iteration-level 动态调度，大幅提升 GPU 利用率。


* **多头注意力变体（Attention Variants）对推理显存的影响**：
* MHA (Multi-Head Attention) vs MQA (Multi-Query Attention) vs GQA (Grouped-Query Attention)。




* **推荐论文**：
* vLLM: *Efficient Memory Management for Large Language Model Serving with PagedAttention* (SOSP 2023)


* **💡 第 3 周 MVP 交付**：
> 1. 部署 `vLLM` 推理服务，加载 Qwen2.5-VL 或 LLaVA 模型。
> 2. 编写 Python 压力测试脚本（基于 `aiohttp` / `asyncio`），发起 50 个高并发请求，统计并对比传统 Hugging Face `generate()` 与 vLLM 的 **QPS (Queries Per Second)**、**TTFT (Time To First Token)** 以及 **ITL (Inter-Token Latency)** 指标。

#### 第 4 周：前沿推理系统与高效 Prefill：SGLang 与 Prefix Caching

* **学习重点**：
* **SGLang (Structured Generation Language) 架构解析**：
* **RadixAttention 机制**：在 LRU Cache 中使用 Radix Tree（基数树）管理 KV Cache，实现跨请求、跨多轮对话以及复杂多模态 Prompt 的自动 KV Cache 共享（Prefix Caching）。


* **Chunked Prefill 与 Piggybacking 优化**：
* 将计算密集型（Compute-Bound）的 Prefill 阶段与显存带宽密集型（Memory-Bound）的 Decode 阶段在同一个 Batch 中混合调度，降低延迟空闲。


* **VLM 动态图像 Token 批处理（VLM Inference Optimization）**：
* 应对多模态模型中不同图片分辨率导致 Vision Token 长度剧烈波动时的动态 Batching 处理策略。




* **推荐开源仓库**：
* `sgl-project/sglang`
* `vllm-project/vllm`


* **💡 第 4 周 MVP 交付**：
> 部署 `SGLang` 推理后端，在一个包含长 System Prompt 或重复图像输入的 Benchmark 任务上运行测试，测量 RadixAttention 的 **Prefix Cache Hit Rate（前缀缓存命中率）**，证明在多轮对话或高重复 Prompt 场景下，SGLang 相比传统推理引擎能带来 2 倍以上的 Prefill 延迟缩减。

#### 第 5 周：性能诊断 Profiling 与量化/内核加速实战

* **学习重点**：
* **GPU 性能分析工具链（Profiling Tools）**：
* 使用 **PyTorch Profiler** 与 **NVIDIA Nsight Systems (Nsys)** 抓取 CUDA Kernel 执行时间线，识别算力受限（Compute-Bound）与带宽受限（Memory-Bound）的瓶颈节点。


* **推理量化技术（Quantization）**：
* **Weight-Only 量化**：AWQ、GPTQ (INT4/INT8)。
* **Weight-Activation 量化**：FP8 (W8A8)、INT8 (SmoothQuant)。
* **KV Cache 量化**：FP8 KV Cache 降低推理过程中的显存占用。




* **💡 第 5 周 MVP 交付**：
