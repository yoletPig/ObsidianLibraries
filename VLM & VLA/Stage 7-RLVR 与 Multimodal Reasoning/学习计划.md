### 📅 逐周学习路线与 MVP 交付

#### 第 1 周：RL 基础、PPO 痛点与 GRPO 算法推导

* **学习重点**：
* **大模型 RL 基础**：
* 状态（State = Prompt + Generated Tokens）、动作（Action = Token）、策略（Policy $\pi_\theta$）、奖励（Reward $R$）。


* **PPO 算法局限与显存卡点**：
* PPO 需要 Actor、Critic、Reference、Reward 4 个模型同时在显存中运行，计算开销与显存瓶颈极大。


* **GRPO (Group Relative Policy Optimization) 深度推导**：
* **无需 Critic 模型**：针对同一个 Prompt $q$，Actor 采样一组输出（Group of Completions, 数量为 $G$），生成响应 $\{o_1, o_2, \dots, o_G\}$。
* **组内相对优势计算 (Group Relative Advantage)**：

$$A_i = \frac{r_i - \text{mean}(\mathbf{r})}{\text{std}(\mathbf{r}) + \epsilon}$$


* **GRPO 损失函数**：

$$\mathcal{L}_{\text{GRPO}}(\theta) = -\frac{1}{G}\sum_{i=1}^{G} \min \left( \frac{\pi_\theta(o_i \mid q)}{\pi_{\text{old}}(o_i \mid q)} A_i, \text{clip}\left(\frac{\pi_\theta(o_i \mid q)}{\pi_{\text{old}}(o_i \mid q)}, 1-\epsilon, 1+\epsilon\right) A_i \right) + \beta D_{\text{KL}}(\pi_\theta \parallel \pi_{\text{ref}})$$






* **推荐论文**：
* DeepSeek-Math: *DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models*
* DeepSeek-R1: *DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning*


* **💡 第 1 周 MVP 交付**：
> 不借助任何 RL 库，**用纯 NumPy / PyTorch 实现一个独立的 `GRPO Advantage & Loss Calculator` 函数**：输入一组假定模型产出的 Logits、5 个 Rollout 样本的奖励得分（如 `[1.0, 0.0, 0.0, 1.0, 0.5]`），推导组内 Advantage 并计算 gradients，验证 KL 惩罚项的截断效果。

#### 第 2 周：RLVR 可验证奖励与 Reward / Verifier Engine 设计

* **学习重点**：
* **RLVR 核心理念**：抛弃主观、不可靠且容易被 Hack 的神经网络 Reward Model（如 Pairwise RM），改用**客观、可执行、基于规则/代码的确定性验证器（Verifier）**。
* **多模态可验证场景与 Rule-based Reward 设计**：
* **格式奖励 (Format Reward)**：强制要求模型将思考过程包裹在 `<think>...</think>` 中，最终答案写在 `<answer>...</answer>` 中。
* **空间定位/Grounding 奖励**：计算预测 Bounding Box `[ymin, xmin, ymax, xmax]` 与 Ground Truth 的 **IoU**。若 $\text{IoU} \ge 0.5$ 给予高分，否则 0 分。
* **几何与数学推理奖励**：提取 `<answer>` 中的数值/公式，调用 Python SymPy 或 Python Interpreter 执行校验。
* **JSON Schema / Tool Call 校验**：验证生成的工具调用或 API 参数结构合法性。


* **防止 Reward Hacking (奖励作弊)**：
* 预防模型通过“疯狂重复冗长文本”套取长度奖励，或通过“滥用格式符号”骗取 Format Reward 的应对策略。




* **💡 第 2 周 MVP 交付**：
> 编写一个**模块化的 Python Verifier Engine**，包含：
> 1. 正则解析器（抽取 `<think>` 与 `<answer>`）；
> 2. Bounding Box IoU 计算器；
> 3. 复合 Reward 汇总逻辑（$\text{Total Reward} = \text{Reward}_{\text{format}} + \text{Reward}_{\text{IoU/Accuracy}}$）。对 100 条模拟输出进行单元测试，确保高质量回答得 1.0，低质量/格式错误回答得 0 或负分。

#### 第 3 周：`verl` 强化学习框架架构与分布式 Rollout

* **学习重点**：
* **`verl` 核心架构 (Volcano Engine RL)**：
* 理解 3D-Parallel 支撑的 **HybridEngine**（在 Training 模式与 Generation 模式间高效转换，消除 Actor 与 Rollout 引擎间的权重切换开销）。
* 理解基于 **Ray** 的分布式集群资源调度（Actor worker, Rollout worker, Ref worker, Reward worker）。


* **高吞吐并发 Rollout 采样**：
* 整合 `vLLM` / `SGLang` 作为 RL 训练中的 Rollout 推理引擎，大幅提升采样速度。


* **`verl` 配置文件（YAML）解析与运行**：
* 掌握 `verl` 中 `actor_rollout_ref`、`critic`（GRPO 下关闭）、`data` 与 `reward_model` 节点的配置参数。




* **推荐开源仓库**：
* `verl-project/verl` (ByteDance 官方开源大模型 RL 框架)


* **💡 第 3 周 MVP 交付**：
> 搭建 `verl` 训练环境，在单卡或多卡 GPU 上成功运行 `verl` 官方提供的 GRPO 最小 Demo（如基于 Qwen2.5-Math / Qwen-0.5B 在 GSM8K 数据集上微调），在 WandB 中成功监控到 `actor/kl_divergence`、`reward/mean` 以及 `response_length` 的实时变化。

#### 第 4 - 5 周：多模态 Visual CoT 与 Vision-Language RLVR 实战

* **学习重点**：
* **VLM 结合 GRPO 的数据构造**：
* 构建 Prompt 结构：`System: You are a visual reasoning assistant. Please think step by step inside <think> and provide the final precise answer in <answer>.\nImage: <image>\nQuestion: {question}`。


* **视觉慢思考（Visual Deep Thinking）现象观察**：
* 观察模型在经过 GRPO 训练后，`<think>` 内部是否产生自主的视觉推理行为（如“先观察左下角物体，再计算相对距离，最后得出坐标”）。


* **显存与计算优化（针对多模态）**：
* 多模态图像输入在前向传播与 Rollout 采样中的 Prefix Cache 与 Vision Feature 缓存优化，解决多 Rollout 导致的 GPU 显存溢出（OOM）问题。




* **💡 第 4-5 周 MVP 交付**：
> 1. 准备一个包含 500~1,000 条**空间推理/几何定位**的图像数据集。
> 2. 使用 `verl` 框架，以 **Qwen2-VL** 或 **LLaVA** 为策略模型（Actor），结合第 2 周实现的 Verifier 运行 GRPO 训练。
> 3. **记录并呈现 RL 训练过程中模型的“推理演变”**：展示第 0 步、第 100 步与第 500 步时，模型在回答同一张图片问题时 `<think>` 思考链长度与准确率的变化过程。

#### 第 6 - 7 周：轨迹过滤、Multi-Rollout 采样与多方案消融对比

* **学习重点**：
* **轨迹过滤与异常样本处理 (Sanity Check & Trajectory Filtering)**：
* 如果一个 Group 中的 $G$ 个样本得分全为 0 或全为 1，则 Advantage 方差为 0，对梯度更新无贡献。学习如何动态剔除或重新采样此类无效 Group（Advantage Masking）。


* **SFT vs. DPO vs. GRPO 端到端对比（Ablation Study）**：
* 在相同基座模型与相同目标任务（如 Spatial Reasoning / POPE / MathVista）上，量化对比三种 Post-training 路线的性能差异。


* **分析典型失败模式（Failure Cases）**：
* 分析 RLVR 训练中出现的模式坍塌（Mode Collapse）、过早收敛、死循环重复生成等问题。




* **💡 第 6-7 周 MVP 交付**：
> 撰写一份完整的 **Post-Training 强化学习实验消融报告**，在同一 Task/Benchmark 上提供以下对比数据表与图表：
> * **Model 1**: Baseline (SFT Model)
> * **Model 2**: DPO / SimPO 对齐模型
> * **Model 3**: GRPO (RLVR) 推理增强模型
> 对比三者在准确率（Accuracy）、回答平均 Token 长度、幻觉发生率（Hallucination Rate）方面的差异，并剖析 GRPO 带来的性能提升收益点。
