## 1. 第一性原理：重复数据的危害与两类去重的分工

### 1.1 根本矛盾：训练的梯度视角看重复

重复数据不是"浪费空间"的问题，而是**扭曲梯度分布**的问题。设某条（或近似某条的）数据在训练集中出现 $k$ 次，等效于该样本的损失权重放大 $k$ 倍——模型会为此样本的模式付出不成比例的拟合容量。三种可观测后果：

1. **记忆效应**：模型逐字背诵高频样本（生成时复述训练例），泛化差。合成数据的模板坍缩（第 1 周失效 1）与爬取数据的近重复会急剧放大这一点。
2. **评测泄漏**：重复样本里若混有评测集的近邻，分数虚高（Stage 3 失效 3 的机制）。
3. **分布偏移**：重复不是均匀的——高频模式通常是"容易批量生成"的模式（如某种问答模板），重复放大的是分布里最平庸的部分。

### 1.2 两类去重的数学本质与分工

**字面去重（MinHash + LSH）**回答："这两条文本是不是**同一篇东西的改写**？"

Jaccard 相似度 $J(A, B) = |A \cap B| / |A \cup B|$（按 shingle/n-gram 集合计算）。直接两两比较是 $O(n^2)$——百万级数据不可行。MinHash 的洞见：**用"最小哈希值是否相等"作为 Jaccard 的无偏估计**：

$$
P[\min_{x \in A} h(x) = \min_{x \in B} h(x)] = J(A, B)
$$

**这个公式在干什么**：对全集做一次随机排序，两集合各自取"排序后最先出现的元素"——两集合越相似，这个"头名元素"越可能是同一个。于是"头名相等的概率"就等于交集占比 $J$。用 $k$ 个独立哈希函数得到 $k$ 维签名，签名相同比例 $\approx J$。再配合 **LSH 分桶**（把 $k$ 维签名切成 $b$ 段（band），每段 $r = k/b$ 行哈希到桶，**任一段全行碰撞即候选对**）：

$$
P[\text{成为候选对}] = 1 - (1 - J^{\,r})^{\,b}
$$

（读法：一段内 $r$ 行全部相等的概率是 $J^r$；$b$ 段里至少一段撞上就是 $1-(1-J^r)^b$。调 $b$/$r$ 就能把这个 S 曲线的陡峭位置挪到想要的工作点。）总复杂度降到近线性 $O(n \cdot k)$——这是"海量"两个字的工程前提。

**语义去重（Embedding + 余弦）**回答："这两条数据是不是**教了模型同一件事**？"

两条字面完全不同的句子（"图中有一只橘猫在沙发上睡觉" vs "沙发上的橘猫正打盹"）Jaccard 可以很低，但对模型是同一监督信号——重复的判定单位是**语义**而非字符。用 Sentence-Transformers（文本）或 CLIP（图文）编码，余弦相似度：

$$
\cos(u, v) = \frac{u \cdot v}{\|u\| \|v\|}
$$

**这个公式在干什么**：两个 Embedding 向量的点积除以各自长度——消掉向量长短的影响，只留"方向是否一致"。方向越一致（语义越像）值越接近 1，正交（无关）趋近 0，相反为负。结果拿来当**语义重复判据**：配 **FAISS** 做近邻检索（百万级向量毫秒级 query），相似度超过阈值（0.92 是学习计划指定的起点）判为语义重复。

**分工总结**：字面去重便宜、快、适合第一道闸（处理完全/近完全重复）；语义去重较贵、适合第二道闸（处理改写与模板变体）。**只做字面去重的清洗是不完整的**——这正是自测清单第 3 题的核心：合成数据的大敌恰恰是"字面不同、语义雷同"的模板坍缩样本，它们大量逃过精确匹配与 MinHash（shingle 重叠低于阈值），只有语义层能抓住。

> **一句话总结**：MinHash 用"最小哈希相等概率 = Jaccard"把 $O(n^2)$ 的两两比较变成近线性的签名比对，抓"字面像"的重复；Embedding 余弦抓"教的是同一件事"的重复——两道闸串联，阈值永远要按自己的数据分布人工校准。

阈值 0.92 的语义直觉：CLIP/Sentence 空间中不相关文本的余弦通常在 0.3~0.6，同义改写在 0.9+，同一模板换实体在 0.95+。0.92 大致卡在"同义改写"与"相关但不同"之间。**阈值是分布相关的**——接入自己的数据后应抽样人工核对阈值两侧的样本对再定稿，不要迷信任何论文数字。

## 2. 系统架构：四道闸的清洗流水线

```text
原始合成数据 (2000 条, 混噪声)
   │
   ▼
┌─ 闸1: Schema 校验 (程序, 毫秒级) ─────────────┐
│ JSON 可解析 / 必填字段 / 长度界限 / 格式断言     │  -> 丢弃率通常 2~8%
└──────────────────────────────────────────────┘
   ▼
┌─ 闸2: 规则过滤 (正则, 秒级) ──────────────────┐
│ 乱码字符 / 重复句式 / 答案为空或复读 / 占位符泄漏 │
└──────────────────────────────────────────────┘
   ▼
┌─ 闸3: 字面去重 (MinHash+LSH, 分钟级) ─────────┐
│ Jaccard > 0.8 的近重复对, 保留质量分高者        │
└──────────────────────────────────────────────┘
   ▼
┌─ 闸4: 语义去重 (Embedding+FAISS, 分钟级) ─────┐
│ 余弦 > 0.92 的语义重复, 保留排序靠前/信息量大者  │
└──────────────────────────────────────────────┘
   ▼
┌─ 闸5: 质量打分 (LLM Judge 或启发式, 小时级) ───┐
│ 事实性/连贯性/指令遵循 1~5 分 -> 取 Top 40%     │
└──────────────────────────────────────────────┘
   ▼
高质量数据集 (含每条的过滤审计记录)
```

顺序设计的经济学：**便宜的闸放前面**。闸1/2 是纯 CPU 规则，闸3 是哈希计算，闸4 要跑 Embedding 模型，闸5 要调 LLM——每过一道闸，后续闸的量就少一批，最贵的 LLM 打分只对幸存者执行。若倒置（先 LLM 打分再去重），重复样本会白烧几倍打分预算。

保留策略细节：语义重复簇内**保留哪一条**？经验做法是保留"答案更长/信息熵更高/质量分更高"的一条——去重不是扔，是**簇内择优**。

## 3. 实现与验证

### 3.1 本周 MVP：五闸清洗 Pipeline

闸1/2/3（MinHash 手写实现）与启发式打分零重依赖可运行；闸4 给出 FAISS/Embedding 接入点，离线用字符 n-gram 向量近似演示。

```python
"""
数据清洗 Pipeline: Schema -> 规则 -> MinHash 去重 -> 语义去重 -> 质量打分 (Top 40%)。
运行方式: python stage4_week4_clean.py --raw raw.jsonl --out clean.jsonl [--use_faiss]
依赖: datasketch(可选), faiss-cpu + sentence-transformers(可选)
"""
import argparse
import hashlib
import json
import re
from collections import defaultdict


# ---------- 闸1+2: Schema 与规则 ----------
PLACEHOLDER = re.compile(r"\{\{|\}\}|XXX|TODO|<image>\s*<image>")
REPEAT_RUN = re.compile(r"(.)\1{8,}")          # 同字符连跑 9+ 次

def rule_check(rec):
    if not isinstance(rec, dict) or not all(rec.get(k) for k in ("question", "answer")):
        return "schema"
    q, a = rec["question"], rec["answer"]
    if not (5 <= len(q) <= 500 and 10 <= len(a) <= 4000):
        return "length"
    if PLACEHOLDER.search(q + a) or REPEAT_RUN.search(q + a):
        return "garbage"
    if len(set(a)) < 8 and len(a) > 30:        # 答案字符多样性过低 -> 复读
        return "repeat"
    return None


# ---------- 闸3: MinHash + LSH (手写核心, 与 datasketch 同构) ----------
def shingles(text, k=3):
    """字符级 n-gram 集合 (中文无分词歧义; 英文同理适用)"""
    text = re.sub(r"\s+", "", text.lower())
    return {text[i:i + k] for i in range(max(1, len(text) - k + 1))}


def minhash_sig(sh, num_perm=128, seed=0):
    sig = []
    for i in range(num_perm):
        # 第 i 个哈希函数: key 参数注入 perm 序号, 数据从构造器传入
        m = min(int.from_bytes(
            hashlib.blake2b(str(s).encode(), digest_size=8,
                            key=i.to_bytes(4, "big") + seed.to_bytes(4, "big")).digest(),
            "big") for s in sh)
        sig.append(m)
    return sig


def est_jaccard(s1, s2):
    same = sum(a == b for a, b in zip(s1, s2))
    return same / len(s1)


def lsh_pairs(sigs, bands=32, rows=4):
    """签名分桶: bands*rows = num_perm; 返回疑似重复对 (近似 O(n))"""
    buckets = defaultdict(list)
    for idx, sig in sigs.items():
        for b in range(bands):
            key = (b, tuple(sig[b * rows:(b + 1) * rows]))
            buckets[key].append(idx)
    pairs = set()
    for members in buckets.values():
        if len(members) > 1:
            members = sorted(members)
            for i in range(len(members)):
                for j in range(i + 1, len(members)):
                    pairs.add((members[i], members[j]))
    return pairs


def dedup_literal(records, thr=0.8):
    sigs = {i: minhash_sig(shingles(r["question"] + " " + r["answer"]))
            for i, r in enumerate(records)}
    drop = set()
    for i, j in lsh_pairs(sigs):
        if est_jaccard(sigs[i], sigs[j]) >= thr:
            # 簇内择优: 保留答案更长者
            drop.add(j if len(records[j]["answer"]) >= len(records[i]["answer"]) else i)
    return drop


# ---------- 闸4: 语义去重 ----------
def dedup_semantic(records, thr=0.92, use_faiss=False):
    if use_faiss:
        from sentence_transformers import SentenceTransformer
        import faiss, numpy as np
        model = SentenceTransformer("sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2")
        emb = model.encode([r["question"] for r in records],
                           normalize_embeddings=True, show_progress_bar=False)
        index = faiss.IndexFlatIP(emb.shape[1])          # 内积 = 归一化向量的余弦
        index.add(np.array(emb))
        sims, ids = index.search(np.array(emb), 2)       # 最近邻(含自身)取 k=2
        drop = set()
        for i, (s, j) in enumerate(zip(sims[:, 1], ids[:, 1])):
            if s > thr and j not in drop:                # 保留先出现的
                drop.add(int(j))
        return drop
    # 离线近似: 字符 2-gram 集合的 Jaccard 当伪语义 (仅演示流程)
    import itertools
    vecs = [shingles(r["question"], 2) for r in records]
    drop = set()
    for (i, j), (va, vb) in zip(itertools.combinations(range(len(records)), 2),
                                itertools.combinations(vecs, 2)):
        if va | vb and len(va & vb) / len(va | vb) > 0.55:   # 演示阈值, 非余弦
            drop.add(j)
    return drop


# ---------- 闸5: 质量打分 (启发式; LLM Judge 接口留出) ----------
def quality_score(rec):
    """0~1 启发式分: 有 CoT 结构 + 答案信息量 + 问题具体度"""
    s = 0.0
    a = rec["answer"]
    if any(k in a for k in ("观察", "推断", "结论", "首先", "因此")):
        s += 0.35                                        # 有推理结构
    s += min(len(a) / 300, 0.35)                          # 答案信息量 (封顶)
    s += min(len(re.findall(r"[\u4e00-\u9fa5\w]{2,}", rec["question"])) / 15, 0.3)
    return s


def llm_judge_scores(records, api_base, model):
    """真实模式: 调 LLM 按 1~5 打分 (事实性/连贯性/指令遵循), 归一化到 0~1"""
    from openai import OpenAI
    client = OpenAI(base_url=api_base, api_key="EMPTY")
    out = []
    for r in records:
        prompt = (f"按事实性与连贯性给这条问答打 1~5 分, 只输出数字。\n"
                  f"Q: {r['question'][:300]}\nA: {r['answer'][:600]}")
        rsp = client.chat.completions.create(model=model, temperature=0,
                                             messages=[{"role": "user", "content": prompt}])
        try:
            out.append(min(int(rsp.choices[0].message.content.strip()[0]), 5) / 5)
        except Exception:
            out.append(0.5)                              # 解析失败给中性分并人工复核
    return out


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--raw", default="raw.jsonl"); ap.add_argument("--out", default="clean.jsonl")
    ap.add_argument("--top", type=float, default=0.4)
    ap.add_argument("--use_faiss", action="store_true")
    ap.add_argument("--judge-api"); ap.add_argument("--judge-model")
    args = ap.parse_args()

    raw = [json.loads(l) for l in open(args.raw)]
    n0 = len(raw)
    # 闸1+2
    kept, rejected = [], {}
    for r in raw:
        why = rule_check(r)
        if why is None:
            kept.append(r)
        else:
            rejected[why] = rejected.get(why, 0) + 1
    # 闸3
    drop_lit = dedup_literal(kept)
    kept = [r for i, r in enumerate(kept) if i not in drop_lit]
    n_lit = len(kept)
    # 闸4
    drop_sem = dedup_semantic(kept, use_faiss=args.use_faiss)
    kept = [r for i, r in enumerate(kept) if i not in drop_sem]
    n_sem = len(kept)
    # 闸5
    scores = (llm_judge_scores(kept, args.judge_api, args.judge_model)
              if args.judge_api else [quality_score(r) for r in kept])
    for r, s in zip(kept, scores):
        r["quality"] = round(s, 3)
    kept.sort(key=lambda r: -r["quality"])
    final = kept[: int(n0 * args.top)]                  # Top 40% 按原始总量计

    with open(args.out, "w") as f:
        f.writelines(json.dumps(r, ensure_ascii=False) + "\n" for r in final)

    # ---- 断言与审计报告 ----
    # 演示数据模板占比高, 模板族会被闸3/4 大幅塌缩; 真实混合数据幸存率更高
    assert n_sem >= int(n0 * args.top * 0.4), "清洗后幸存量不足, 无法支撑 Top 40% 目标"
    print(f"原始 {n0} | 规则剔除 {rejected} | 字面去重剩 {n_lit} | "
          f"语义去重剩 {n_sem} | 最终 Top40% {len(final)} 条 -> {args.out}")


if __name__ == "__main__":
    main()
```

## 4. 工程权衡与失效模式

### 4.1 决策表：去重与打分的参数

| 参数 | 起点 | 说明 |
| --- | --- | --- |
| MinHash shingle k | 3（字符级 n-gram，中英文通用） | k 越大对改写越敏感、对小文本越粗糙 |
| LSH bands/rows | 128 签名 = 32 bands × 4 rows | 检出 J≈0.8 的概率 = 1-(1-0.8⁴)³² ≈ 1.0（0.5904³²≈5×10⁻⁸，几乎必检出）；J≈0.5 时降至 ≈0.87 |
| 语义阈值（文本） | 0.90~0.94 | 分布相关，人工抽检定稿 |
| 语义阈值（CLIP 图文） | 0.92+ | CLIP 相似度整体偏高，阈值略升 |
| Top-K 比例 | 30%~50% | 打分置信度低时保守（更大 K），高时激进 |

### 4.2 三个代表性失效模式

**失效 1：语义去重误杀"教学必要"的相似样本**
- **症状**：清洗后模型在某一维度（如计数 2~5 的区分）明显变弱。
- **根因**：计数教学本来就需要"同模板换数字"的样本族——语义去重把这条"族"当重复删到只剩 1 条，梯度信号不足以学会规则泛化。
- **定位**：按维度统计清洗前后样本量，找骤降维度；抽 0.92 两侧样本对人工判。
- **修复**：**去重键问题分层**——教学必需的参数化模板族（答案不同）豁免；只对"答案也雷同"的样本判重（把 answer 拼进相似度输入，或按维度设阈值）。

**失效 2：MinHash 阈值过松，近重复漏网**
- **症状**：训练后模型仍有复读倾向，检查发现大量"仅换实体词"的样本存活。
- **根因**：shingle 重叠率因实体替换而低于 0.8 阈值，字面闸放行；而语义闸若没接（或阈值过松）就漏了。
- **定位**：对存活样本跑一次高阈值（0.85）MinHash 复查，统计漏网率。
- **修复**：字面/语义双闸的阈值联动——字面闸收紧到 0.7 做保守第一刀，语义闸兜底。

**失效 3：LLM Judge 打分的系统性偏置污染 Top-K**
- **症状**：Top 40% 数据里长答案占比异常高，微调后模型输出冗长。
- **根因**：Judge（或启发式）对"长=信息量大"的相关性赋予过高权重——本 MVP 的 `quality_score` 里 `len(a)/300` 项就可能诱发此偏置。
- **定位**：对打分与答案长度做相关性分析（相关系数 >0.7 即偏置）；抽长短答案同题对评估。
- **修复**：打分维度去相关（长度归一化后按"单位长度信息量"计分）；LLM Judge 的 prompt 显式声明"长度不影响评分"；最终数据做长度分布监控并回配平。

## 5. 延伸思考题

1. **阈值的理论视角**：0.92 这个数在不同 Embedding 模型间不可迁移（不同模型的相似度分布不同）。设计一个"自动定阈值"流程：不依赖固定值，而是从数据分布本身（如相似度直方图的双峰谷点）推导阈值，并讨论其失效场景（单峰分布时怎么办）。
2. **规模推演**：1 亿条数据的语义去重，FAISS IndexFlatIP（精确检索）内存放不下时有哪些降级路径？（提示：IVF/HNSW 近似索引、聚类后簇内去重、两阶段——先 MinHash 粗筛再 Embedding 细查；每条给出精度/速度/内存的定性代价。）
3. **闭环实验**：用第 4 节失效 1 的"分层去重"改造本 MVP，在同一条 SFT 流程上对比"全局去重"与"分层去重"数据的计数维度评测分（Stage 3 mini-Bench），验证清洗策略对能力维度的实际影响——这是把 Stage 3 评测与 Stage 4 清洗真正闭环的练习。
