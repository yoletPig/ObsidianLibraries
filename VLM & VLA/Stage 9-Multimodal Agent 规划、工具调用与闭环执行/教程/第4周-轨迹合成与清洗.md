## 1. 第一性原理：轨迹数据的"噪声放大器"效应

### 1.1 根本矛盾：Agent 的失败轨迹比 SFT 错标更毒

第 6 阶段第 3 周已论证"偏好数据是 DPO 的裁判"；本阶段的轨迹是 SFT/RL 的**行为示范**，噪声的危害机制不同且更隐蔽：

1. **SFT 的行为模仿是全过程的**：模型不只学"最终答对"，还模仿**每一步的风格与节奏**。若轨迹里充满试错（调用→失败→重试），模型学会的不是"如何排错"，而是**"先随便试、失败很正常"的行为先验**——低效试错被当成了标准动作（学习计划达成标准的原文：剪枝确保模型学习最短最优路径）。
2. **死循环轨迹 teaches 循环**：重复同一动作的轨迹若混入训练，模型在推理时遇到相似状态就会进入同样的循环——这是部署期死循环的重要来源之一。
3. **伪成功比失败更毒**：最终答对但过程有错的轨迹（错误中间量被后续巧合纠正）教模型"过程不必严谨"。

因此 Agent 轨迹的清洗标准必须**严于**一般 SFT 数据：不只查"对不对"，还要查"过程是否高效、每步是否有依据"。

### 1.2 TaskCraft 的合成机制（正确版）

TaskCraft 的合成流程（已核实 arXiv:2506.10055 v2）：

```text
原子任务 (atomic: 单工具、单跳、可验证)
   │  depth 扩展: 在其上叠加子任务链 -> 多跳推理深度
   │  width 扩展: 增加所需工具种类/交互广度
   ▼
任务树: 难度可扩展、多工具、可验证
   │  在真实工具环境中执行 (agent + tool)
   ▼
执行轨迹 (含成功验证) + 任务层级标注
```

关键设计：**任务与验证器原子绑定**（Stage 4 的纪律）、**难度由扩展算子参数化**（可控地生成难例课程）、**轨迹来自真实工具环境执行**（Observation 不许编造）。这套"算子化合成"比人工标注可扩展得多——3.6 万条任务，且 depth/width 两个轴天然支持课程化采样（Stage 7 的动态难度）。

### 1.3 三类清洗的判定算法

**① 死循环检测（Loop Detection）**：

- **精确重复**：相邻 $k$ 步的 (tool, args) 完全相同且无 intervening 成功信号；
- **语义重复**：动作参数略变但目标相同（连续 3 次对同一区域 Crop）——用动作嵌入相似度或"同一元素+同类动作"判定；
- **状态不前进**：连续 N 步的环境状态指纹（页面 URL+关键元素哈希/文件哈希）无变化。

判定不是"有重复就删"：**带进展的合法重试**（每次参数不同且逐步逼近，如二分查找式的尝试）是有价值的纠错示范。判定核心是"**重复且无信息增量**"。

**② 逻辑断层检测（Thought-Action 因果一致性）**：

- Thought 声称"先搜索价格"而 Action 却调用了 OCR——语言与行为脱节；
- 判定手段：(a) 规则版——Thought 中的动词/宾语与工具功能词表匹配；(b) 模型版——用 LLM 判"该 Thought 是否支持该 Action"（Stage 3 的 Judge 纪律：固定 prompt、报一致率）；
- 最强信号仍是**执行验证**（Stage 4 第 3 周）：Observation 与 Action 语义不符的步就是断层证据。

**③ Trajectory Pruning（轨迹剪枝）**：

- 目标：从"10 步试错轨迹"提取"4 步最优直线轨迹"；
- 前提：**只有成功轨迹可剪**（失败轨迹要么整条剔除、要么只保留到失败点并标注失败原因作负样本）；
- 剪枝准则：删除"对最终结果无贡献"的步——判定方式是**消融回放**：把候选步从轨迹中移除后重放，若最终结果与工具状态不变则该步冗余（严格版）；近似版用"该步的 Observation 是否被后续步引用"（引用图分析）判定；
- 剪枝后必须**重新校验**：剪枝轨迹重放成功（环境有状态时，剪枝可能破坏前置条件——只有无副作用/可重放的轨迹才能激进剪枝）。

## 2. 实现与验证

### 2.1 本周 MVP：Trajectory Filter

```python
"""
Agent 轨迹校验器: 死循环检测 + 逻辑断层检测 + 剪枝, 产出可训练 JSONL。
运行方式: python stage9_week4_traj_filter.py --in traces.jsonl --out clean_trajs.jsonl
依赖: 标准库 (断层判定的模型版需 openai)
"""
import argparse
import hashlib
import json
import re
from collections import Counter


# ---------- ① 死循环检测 ----------
def detect_loop(steps: list[dict], window: int = 3, min_gain: int = 1) -> str | None:
    """steps: [{tool, args, obs, ok}]; 返回死循环类型或 None"""
    if len(steps) < window:
        return None
    # a) 精确重复: 最近 window 步 (tool, args) 完全相同
    keys = [json.dumps({"t": s.get("tool"), "a": s.get("args")}, sort_keys=True)
            for s in steps[-window:]]
    if len(set(keys)) == 1:
        return "exact_loop"
    # b) 状态不前进: 连续 window 步状态指纹无变化
    fps = [hashlib.md5(str(s.get("state", "")).encode()).hexdigest()
           for s in steps[-window:]]
    if len(set(fps)) == 1:
        return "stalled_state"
    # c) 无信息增量的重复工具调用 (同工具连续 >=3 次且 Observation 雷同)
    tools = [s.get("tool") for s in steps[-window:]]
    if len(set(tools)) == 1 and len({hashlib.md5(str(s.get("obs", ""))[:64].encode()).hexdigest()
                                     for s in steps[-window:]}) == 1:
        return "same_obs_loop"
    return None


# ---------- ② 逻辑断层检测 ----------
TOOL_VERBS = {  # 工具功能词表 (规则版; 模型版用 LLM Judge)
    "search": {"搜索", "查找", "find", "search"},
    "ocr": {"识别", "读取", "文字", "ocr"},
    "crop": {"裁剪", "放大", "区域", "crop"},
    "python": {"计算", "执行", "求", "运行", "python"},
}

def detect_gap(thought: str, tool: str) -> bool:
    """Thought 是否为该 Action 提供了依据 (规则近似: 动词/宾语词表交集)"""
    verbs = TOOL_VERBS.get(tool, set())
    if not verbs:
        return False                       # 未知工具跳过规则判定
    th = thought.lower()
    return not any(v in th for v in verbs) # 无任何相关词 -> 疑似断层


# ---------- ③ 轨迹剪枝 ----------
def prune(steps: list[dict], final_key: str = "answer") -> list[dict]:
    """引用图剪枝: 保留 被 final/后续步引用 或 标记 essential 的步"""
    final = steps[-1].get(final_key, "")
    refs_final = {s for s in steps if s.get("obs") and s["obs"][:40] in final}
    keep = []
    for i, s in enumerate(steps[:-1]):
        obs40 = (s.get("obs") or "")[:40]
        used_later = any(obs40 and obs40 in (later.get("thought", "") + later.get("args_str", ""))
                         for later in steps[i + 1:])
        essential = s.get("essential", False)       # 环境状态变更类动作 (写文件/提交) 不可剪
        if s in refs_final or used_later or essential or s.get("ok") is False:
            keep.append(s)                          # 失败步保留为纠错示范 (可选策略)
    if not keep or keep[-1] is not steps[-1]:
        keep.append(steps[-1])                      # final 步必须保留
    return keep


def audit_trace(traj: dict) -> tuple[bool, str]:
    """单条轨迹审计: 返回 (是否可用于训练, 原因)"""
    steps = traj["steps"]
    if len(steps) < 2:
        return False, "too_short"
    # 全程失败且无反思价值的剔除
    if not any(s.get("ok") for s in steps) and traj.get("status") != "success":
        return False, "failed_trajectory"
    loop = detect_loop(steps)
    if loop:
        return False, f"loop:{loop}"
    # 断层检测: 抽样判定 (全量判定成本高; 断层 >=2 处才剔除)
    gaps = sum(detect_gap(s.get("thought", ""), s.get("tool", ""))
               for s in steps if s.get("thought"))
    if gaps >= 2:
        return False, f"logic_gaps:{gaps}"
    return True, "ok"


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--in", dest="inp", default="traces.jsonl")
    ap.add_argument("--out", default="clean_trajs.jsonl")
    ap.add_argument("--prune", action="store_true")
    args = ap.parse_args()

    traces = [json.loads(l) for l in open(args.inp)]
    kept, reasons = [], Counter()
    for t in traces:
        ok, why = audit_trace(t)
        if ok:
            if args.prune:
                n0 = len(t["steps"])
                t["steps"] = prune(t["steps"])
                t["pruned_from"] = n0
            kept.append(t)
        reasons[why] += 1

    # 训练格式: 多模态 SFT (thought 为监督目标, observation 掩码——Stage 2/7 的规则)
    out_rows = []
    for t in kept:
        msgs = [{"role": "user", "content": t["task"]}]
        for s in t["steps"]:
            msgs.append({"role": "assistant", "content":
                         f"Thought: {s.get('thought','')}\nAction: {json.dumps({'tool': s['tool'], 'args': s.get('args', {})})}"})
            msgs.append({"role": "environment", "content": s.get("obs", "")})
        out_rows.append({"messages": msgs, "status": t.get("status")})
    with open(args.out, "w") as f:
        f.writelines(json.dumps(r, ensure_ascii=False) + "\n" for r in out_rows)

    # ---- 审计报告 ----
    total, n_ok = len(traces), len(kept)
    assert n_ok > 0, "全部轨迹被剔除, 检查过滤器阈值"
    print(f"输入 {total} 条 -> 保留 {n_ok} 条 ({n_ok/total:.0%})")
    print("剔除原因分布:", dict(reasons))
    if args.prune:
        pruned = [t for t in kept if t.get("pruned_from")]
        avg_cut = (sum(t["pruned_from"] - len(t["steps"]) for t in pruned) /
                   max(1, len(pruned)))
        print(f"剪枝: {len(pruned)} 条被剪, 平均去除 {avg_cut:.1f} 步")
    # 健康度断言: 保留率异常 (过高=过滤器失效, 过低=数据源有问题)
    assert 0.15 < n_ok / total <= 1.0, "保留率异常, 复核过滤器或数据源质量"


if __name__ == "__main__":
    main()
```

### 2.2 断层检测的模型版（LLM Judge）

规则版词表覆盖有限；模型版把 `(thought, action)` 对交给 LLM 判定"该 Thought 是否为该 Action 提供依据"，输出 yes/no + 理由。纪律沿用 Stage 3 第 1 周：裁判 prompt 固定、温度 0、抽样人工校准一致率（Kappa >0.6 才可用）。**规则版与模型版混跑取交集**（两者都判断层才剔）可显著降误杀。

## 3. 工程权衡与失效模式

### 3.1 决策表：过滤与剪枝的阈值

| 决策点 | 保守 | 激进 | 说明 |
| --- | --- | --- | --- |
| 死循环窗口 | 3 步全同 | 2 步全同 | 窗口小易误杀合法短重试 |
| 断层判定 | 规则+模型双确认、≥2 处才剔 | 单处即剔 | 误杀好轨迹的代价 > 漏放差轨迹（SFT 噪声不对称） |
| 失败轨迹处理 | 全部剔除 | 带标注保留（纠错示范/RL 负样本） | 取决于下游用途（SFT 剔、偏好训练留） |
| 剪枝强度 | 只删"确认无引用"步 | 消融回放严格验证 | 有状态环境必须保守 |

### 3.2 三个代表性失效模式

**失效 1：过度剪枝破坏了环境前置条件**
- **症状**：剪枝后的轨迹重放失败（如删掉了"登录"步，后续"下单"步失去前置状态）。
- **根因**：引用图分析只看了文本引用，没看**环境状态依赖**（登录/建目录/加购物车这类状态变更步是隐式前置条件）。
- **定位**：剪枝轨迹抽样重放，统计失败率。
- **修复**：状态变更类动作标记 `essential=True` 不可剪（本 MVP 已内置字段）；有条件时以重放验证为剪枝准绳。

**失效 2：断层检测的误杀——工具语义与用词不匹配**
- **症状**：合理的轨迹被大量剔除（保留率异常低）。
- **根因**：规则词表覆盖不足（Thought 写"提取文本"而词表只有"识别"，工具是 OCR）——语义相关但词面不匹配被判断层。
- **定位**：抽样被剔除的"断层"轨迹人工复核，误杀率 >20% 即确认。
- **修复**：模型版 Judge 兜底（规则判断层的再过一道 LLM 确认）；词表按实际工具描述对齐扩充。

**失效 3：剪枝剪掉了"有价值的纠错示范"**
- **症状**：清洗后的模型在真实环境遇错就卡死（训练数据里全是直线轨迹，没见过失败）。
- **根因**：把失败步全剪成"完美轨迹"，模型没有习得"从 Observation 中的错误信号恢复"的行为（第 2 周 Reflection 的能力没有数据支撑）。
- **定位**：对比清洗前后模型在"含错误注入的任务"上的恢复率。
- **修复**：**分池策略**——SFT 主池用剪枝直线轨迹，另设 10~20% "带一次纠错"的轨迹池（保留一次失败+反思+修正），与 Stage 4 第 3 周的负样本注入比例一致。

## 4. 延伸思考题

1. **剪枝与探索的辩证**：Stage 7 的 RL 需要探索（奖励会强化成功路径，探索由采样机制保证），而 SFT 的轨迹剪枝消灭探索痕迹。论证：为什么"SFT 用最优轨迹 + RL 用原始轨迹"是正确分工？（提示：SFT 是行为克隆——克隆什么就成为什么；RL 的优势加权天然会放大好轨迹、稀释差轨迹，原始轨迹反而提供必要的探索分布。）
2. **断层检测的边界**：Thought 与 Action 的"因果一致性"真的可判定吗？构造一个"Thought 与 Action 字面不相关但行为合理"的反例（如 Thought 决定"先确认页面状态"而 Action 是无操作等待）。（提示：状态检查类/等待类动作天然"无依据"——断层检测必须带工具语义知识或跳过白名单，纯文本判定有天花板。）
3. **跨阶段审计链**：把 Stage 4（合成）、Stage 7（RL 轨迹）、本阶段（清洗剪枝）的轨迹流水线写成一张"质量闸门图"：每一环的输入/输出/质量闸/失败流向。检查点：Stage 7 的"全同组无梯度"与本阶段"死循环剔除"的判定逻辑同构（信号为零的数据没有训练价值）。
