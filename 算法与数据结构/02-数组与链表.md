# 02 - 数组与链表

## 本篇目标

1. 从内存视角理解数组与链表的本质区别：**连续内存 vs 分散节点 + 指针**；
2. 手写简化版动态数组，吃透倍增扩容与均摊 O(1)（承接 01 篇）；
3. 掌握链表两大变体（双向、哨兵）与高频题型：原地操作、快慢指针判环；
4. 弄清"数组 vs 链表"的真实答案——不是教科书上的插入删除快慢，而是**缓存友好性**。

## 1. 内存视角：两种截然不同的布局

**数组**是一块连续内存，元素等长排列。按下标访问的地址是一次乘法：

```
addr(a[i]) = addr(a[0]) + i × 元素大小
```

所以随机访问 O(1)。**链表**是散落在堆上的节点，每个节点存"数据 + 下一个节点的地址"，访问第 i 个必须从头走 i 步，O(i)。

| 操作 | 数组 | 链表 |
| --- | --- | --- |
| 按下标访问 | O(1) | O(n) |
| 头部插入/删除 | O(n)（整体搬移） | O(1) |
| 尾部插入 | 均摊 O(1) | O(1)（持有尾指针时） |
| 已知位置插入/删除 | O(n)（搬移） | O(1)（找到位置后；**找到**本身要 O(n)） |
| 内存开销 | 只存数据 | 每节点多 1~2 个指针（64 位下每个 8 字节） |

Python 的 `list` 是动态数组（不是链表——它存的是 PyObject 指针的连续数组）；`collections.deque` 是分块双向链表。链表在 Python 里没有内置，需要自己用类定义。

## 2. 手写简化版动态数组

01 篇分析了倍增为什么均摊 O(1)，这里把完整实现写出来（面试手写题原型）：

```python
class ArrayList:
    """简化版动态数组：只支持 int，突出扩容机制。"""

    def __init__(self) -> None:
        self._cap = 2                      # 初始容量
        self._size = 0                     # 实际元素数
        self._data = [0] * self._cap       # 用 list 模拟一块定长内存

    def __len__(self) -> int:
        return self._size

    def _resize(self, new_cap: int) -> None:
        """扩容：申请新内存 + 整体搬迁，代价 O(n)。"""
        new_data = [0] * new_cap
        for i in range(self._size):
            new_data[i] = self._data[i]
        self._data = new_data
        self._cap = new_cap

    def append(self, x: int) -> None:
        if self._size == self._cap:        # 满了：倍增（01 篇证明均摊 O(1)）
            self._resize(self._cap * 2)
        self._data[self._size] = x
        self._size += 1

    def get(self, i: int) -> int:
        if not 0 <= i < self._size:
            raise IndexError(i)
        return self._data[i]               # 一次"乘加"直达，O(1)

    def pop_back(self) -> int:
        if self._size == 0:
            raise IndexError("pop from empty")
        self._size -= 1
        val = self._data[self._size]
        # 缩容策略：元素少于容量 1/4 时减半（用 1/4 而不是 1/2，见下陷阱）
        if 0 < self._size <= self._cap // 4 and self._cap > 2:
            self._resize(self._cap // 2)
        return val

    def insert(self, i: int, x: int) -> None:
        """在第 i 位插入：后面元素整体右移，O(n)。"""
        if not 0 <= i <= self._size:
            raise IndexError(i)
        if self._size == self._cap:
            self._resize(self._cap * 2)
        for j in range(self._size, i, -1): # 从后往前挪，避免覆盖
            self._data[j] = self._data[j - 1]
        self._data[i] = x
        self._size += 1

arr = ArrayList()
for x in [3, 1, 4, 1, 5, 9, 2, 6]:
    arr.append(x)
arr.insert(2, 99)
print([arr.get(i) for i in range(len(arr))])   # [3, 1, 99, 4, 1, 5, 9, 2, 6]
```

> **陷阱**：缩容阈值取"少于一半就减半"会在临界点抖动——在 size = cap/2 处反复插入删除会触发反复扩缩容，每次都是 O(n) 搬迁。标准对策（Sedgewick《算法（第 4 版）》的 ResizingArrayStack）：**size ≤ cap/4 才减半到 cap/2**，中间留出缓冲带。

## 3. 链表：定义与三大变体

```python
class ListNode:
    __slots__ = ("val", "next")        # 固定属性集合：省内存、禁动态加属性
    def __init__(self, val: int = 0, next: "ListNode | None" = None) -> None:
        self.val = val
        self.next = next

def build(values: list[int]) -> ListNode | None:
    """辅助函数：按 values 建链表，返回头节点。"""
    dummy = ListNode()
    cur = dummy
    for v in values:
        cur.next = ListNode(v)
        cur = cur.next
    return dummy.next

def to_list(head: ListNode | None) -> list[int]:
    out = []
    while head:
        out.append(head.val)
        head = head.next
    return out
```

三个变体，各自解决什么问题：

1. **单向链表**：最省内存，但只能从头向后走——"删除节点"需要先找到前驱，O(n)；
2. **双向链表**（`prev` + `next`）：已知节点即可 O(1) 自删。LRU 缓存（LC 146）的标准底座；Linux 内核 `list_head` 是纯双向环形的经典工业实现；
3. **哨兵节点（dummy）**：在真实头节点前放一个空壳，**头插、头删与中间操作代码完全一致**，消灭"改头指针"特判。写链表题的第一件事就是加哨兵。

```python
def delete_val(head: ListNode | None, target: int) -> ListNode | None:
    """删除第一个值为 target 的节点：哨兵让边界统一。"""
    dummy = ListNode(next=head)        # 哨兵
    prev = dummy
    while prev.next and prev.next.val != target:
        prev = prev.next
    if prev.next:                      # 摘除：prev.next 跨过被删节点
        prev.next = prev.next.next
    return dummy.next                  # 返回真实头（可能是 None）
```

## 4. 高频题型一：原地操作（双指针同向）

链表题的考点集中在"**不用额外数组、在原链表上改指针**"。两道代表：

```python
def reverse_list(head: ListNode | None) -> ListNode | None:
    """反转链表（LC 206）：三指针滚动，O(n) 时间 O(1) 空间。"""
    prev, cur = None, head
    while cur:
        nxt = cur.next     # 先存后继
        cur.next = prev    # 掉头
        prev = cur         # prev 前进
        cur = nxt          # cur 前进
    return prev

# 关键一次：删除倒数第 k 个节点（LC 19 的核心动作），两指针间距 k：
def remove_nth_from_end(head: ListNode | None, k: int) -> ListNode | None:
    dummy = ListNode(next=head)
    fast = slow = dummy
    for _ in range(k):                 # fast 先走 k 步
        fast = fast.next
    while fast.next:                   # 两个指针同步走，fast 到尾时
        fast = fast.next               # slow 正好在倒数第 k+1 个（前驱）
        slow = slow.next
    slow.next = slow.next.next         # 删除
    return dummy.next
```

原地操作在数组上同样高频（LC 27 移除元素、LC 283 移动零）：维护"下一个可写位置"的写入指针，读指针扫全数组，读到的有效元素写入写指针位置。

## 5. 高频题型二：快慢指针判环（Floyd 判圈）

经典问题：链表可能成环，O(1) 空间怎么检测？

**Floyd 判圈算法**（Floyd's cycle detection，又名龟兔赛跑，出处：Robert Floyd, 1967；CLRS 习题 10.2-5 相关）：慢指针每次走 1 步、快指针每次走 2 步。若无环，快指针先到 None；若有环，快指针会追上慢指针。

```python
def has_cycle(head: ListNode | None) -> bool:
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:               # is 判同一节点，不是 ==
            return True
    return False                       # fast 走到头：无环

def detect_cycle_entry(head: ListNode | None) -> ListNode | None:
    """进一步找环入口（LC 142）。数学证明：
    设头到入口 a 步，入口到相遇点 b 步，环长 c。
    相遇时慢指针走了 a+b，快指针走了 a+b+k·c，且快=2×慢，
    得 a = k·c - b。=> 慢指针再走 a 步（= 走 b 步到入口再绕 k-1 圈）
    恰好到入口。于是让第三个指针从头与慢指针同速前进，相遇即入口。"""
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
        if slow is fast:
            p = head
            while p is not slow:       # 同速前进，必在入口相遇
                p, slow = p.next, slow.next
            return p
    return None
```

> **陷阱**：判环必须用 `is`（同一对象）而不是 `==`（值相等）。若链表允许多个节点同值，`==` 会误判。快指针每次**先检查 `fast.next` 再跳两步**，否则在空指针上崩。

快慢指针的另一用途是找链表中点（LC 876）：快指针到尾时慢指针在中点，归并排序的链表版（07 篇）靠它实现 O(1) 空间切分。

## 6. 数组 vs 链表：真实答案是缓存

教科书答案是"插入删除用链表"。但工程上，**绝大多数场景数组完胜**，原因在内存层级：

- CPU 访问内存以**缓存行（cache line，通常 64 字节）**为单位。数组遍历时相邻元素一起被载入缓存（空间局部性），一次主存访问服务多次元素访问；
- 链表节点散落堆上，访问 `node.next` 大概率缓存未命中，每次跳跃都可能是一次主存访问（延迟 ~100ns 量级，比 L1 慢 1~2 个数量级）；
- 链表每节点多 1~2 个指针还增加内存占用与分配器压力。

一个可跑的实验（经验做法，具体倍数随机器浮动）：

```python
import time

def cache_friendliness_experiment() -> None:
    n = 1_000_000
    arr = list(range(n))                       # 连续的指针数组
    # 建一条同样长的链表
    head = ListNode(0)
    cur = head
    for i in range(1, n):
        cur.next = ListNode(i)
        cur = cur.next

    t0 = time.perf_counter()
    s = 0
    for v in arr:                              # 数组顺序遍历
        s += v
    t_arr = time.perf_counter() - t0

    t0 = time.perf_counter()
    s2 = 0
    node = head
    while node:                                # 链表逐节点跳
        s2 += node.val
        node = node.next
    t_list = time.perf_counter() - t0
    print(f"数组 {t_arr:.3f}s vs 链表 {t_list:.3f}s（指针跳转版本通常慢数倍）")

cache_friendliness_experiment()
```

工程结论（经验做法，与 C++ 社区共识一致，如 Bjarne Stroustrup 在多次演讲中的表态）：**默认用数组（vector/list），只有"已知节点句柄后要 O(1) 增删、且频繁增删"时才考虑链表**。模型推理框架中数据布局优先 SoA/连续张量，也是同一思想（衔接模型性能优化系列）。

## 本篇小结

1. 数组 O(1) 随机访问来自"基地址 + 乘加"的地址计算；链表的一切操作绕不开指针追走；
2. 动态数组 = 定长数组 + 倍增扩容，append 均摊 O(1)；缩容阈值留缓冲带防抖动；
3. 写链表题第一件事：加哨兵节点，消灭头部特判；
4. 快慢指针判环（Floyd 判圈）：相遇即有环；找入口用"a = k·c − b"的同速第二阶段；
5. 数组 vs 链表的真实胜负手是缓存局部性——默认数组，链表留给"句柄已知的 O(1) 增删"场景。
