3. 掌握本章最值钱的方法论：**状态定义与转移方程怎么"找"**——不是背题，是推导；
4. 建立"循环顺序由依赖关系决定"的意识（为 13 篇背包一维化铺路）。

## 1. DP 在解决什么问题

**动态规划（Dynamic Programming）**适用于同时满足两个条件的优化问题（Bellman 1950 年代提出，"dynamic"是当时的营销词，出处见 Bellman 自传 Eyewitness Account）：

1. **最优子结构**：原问题的最优解由子问题的最优解构成——子问题答案不依赖"怎么来的"；
2. **重叠子问题**：暴力递归会反复解同一个子问题——缓存它们就有收益（01 篇空间换时间的严格版）。

反面对照：斐波那契 `f(n)=f(n-1)+f(n-2)` 两条件都满足；归并排序的子问题**不重叠**（每半边只算一次），所以它是分治不是 DP；最短路有最优子结构，但"最长简单路径"没有（子路径的最长解不能拼出原问题的解）。

## 2. 爬楼梯：从 O(2^n) 到 O(n) 的完整进化

```python
from functools import lru_cache

def climb_stairs_v0(n: int) -> int:
    """版本 0：暴力递归。f(n) = f(n-1) + f(n-2)。O(2^n)——重叠子问题大量重复。"""
    if n <= 2:
        return n
    return climb_stairs_v0(n - 1) + climb_stairs_v0(n - 2)

def climb_stairs_v1(n: int) -> int:
    """版本 1：记忆化（自顶向下）。缓存已解子问题，每个 f(k) 只算一次。O(n)"""
    @lru_cache(maxsize=None)
    def f(k: int) -> int:
        if k <= 2:
            return k
        return f(k - 1) + f(k - 2)
    return f(n)

def climb_stairs_v2(n: int) -> int:
    """版本 2：递推表格（自底向上）。dp[i] = 到第 i 阶的方案数。O(n) 时间 O(n) 空间。
    依赖方向：dp[i] 只依赖 dp[i-1]、dp[i-2] → 从小到大扫。"""
    if n <= 2:
        return n
    dp = [0] * (n + 1)
    dp[1], dp[2] = 1, 2
    for i in range(3, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

def climb_stairs_v3(n: int) -> int:
    """版本 3：滚动变量。dp[i] 只依赖前两项 → 只留两个变量。O(n) 时间 O(1) 空间。"""
    if n <= 2:
        return n
    a, b = 1, 2                      # a=dp[i-2], b=dp[i-1]
    for _ in range(3, n + 1):
        a, b = b, a + b
    return b

assert all(fn(10) == 89 for fn in (climb_stairs_v0, climb_stairs_v1,
                                   climb_stairs_v2, climb_stairs_v3))
```

四个版本是**同一个状态定义**（f(i) = 到第 i 阶的方案数）的三种执行方式。记忆化与递推的取舍：

| | 记忆化（自顶向下） | 递推（自底向上） |
| --- | --- | --- |
| 思考方式 | 直接翻译递归定义，好写 | 要自己排好计算顺序 |
| 空间 | 哈希表/数组 + 调用栈 | 纯数组（可滚动压缩） |
| 适合 | 状态稀疏（不会全用到）、树形/记忆化搜索 | 状态稠密、要求 O(1) 空间优化 |

面试建议（经验做法）：**先用记忆化写对，再视要求压成递推**——两步都展示，比一步到位的"天降 dp 表"更能体现思考过程。

## 3. 打家劫舍：第一次"做决策"的 DP

```python
def rob(nums: list[int]) -> int:
    """LC 198 打家劫舍：不能偷相邻两家，求最大金额。O(n)
    状态定义：dp[i] = 考虑前 i+1 家（下标 0..i）能偷到的最大金额。
    决策：第 i 家 偷 or 不偷 ——
      偷：dp[i] = dp[i-2] + nums[i]   （i-1 必须不偷）
      不偷：dp[i] = dp[i-1]           （利益保留到 i-1）
    转移：dp[i] = max(dp[i-1], dp[i-2] + nums[i])"""
    if not nums:
        return 0
    n = len(nums)
    if n == 1:
        return nums[0]
    dp = [0] * n
    dp[0] = nums[0]
    dp[1] = max(nums[0], nums[1])
    for i in range(2, n):
        dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])
    return dp[n - 1]

def rob_circular(nums: list[int]) -> int:
    """LC 213 环形版：首尾相邻。拆成两个线性子问题取 max——
    不偷第一家（考虑 1..n-1）或 不偷最后一家（考虑 0..n-2）。"""
    if len(nums) == 1:
        return nums[0]
    return max(rob(nums[1:]), rob(nums[:-1]))

assert rob([2, 7, 9, 3, 1]) == 12          # 2 + 9 + 1
assert rob_circular([2, 3, 2]) == 3        # 首尾冲突，只能偷一家
```

对比爬楼梯，本题多了**决策**（偷/不偷）——这正是大多数 DP 的真实形态：**状态定义给出"子问题问什么"，转移方程枚举"当前这一步的决策"**。把决策枚举全、每个决策的代价与后续写对，转移方程就是水到渠成的加法/取 max。

> **提示**：写转移前先回答三个问题（经验做法，本章方法论的核心）：① 状态里必须有哪几个量才能唯一刻画"局面"？（位置、已用资源、上一个决策……）② 状态的"边界"（最小的几个）是什么？③ 当前状态能从哪些"更小的状态 + 一个决策"到达？

## 4. 最长上升子序列：O(n²) 与 O(n log n)

```python
def length_of_lis(nums: list[int]) -> int:
    """LC 300 LIS 之 O(n²) DP。
    状态：dp[i] = 以 nums[i] 结尾的 LIS 长度（必须以 i 结尾——决策落在 i 上）。
    转移：dp[i] = max(dp[j] + 1)，j < i 且 nums[j] < nums[i]。"""
    n = len(nums)
    dp = [1] * n                          # 边界：单独一个元素长 1
    for i in range(1, n):
        for j in range(i):
            if nums[j] < nums[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp) if dp else 0

def length_of_lis_fast(nums: list[int]) -> int:
    """LC 300 LIS 之 O(n log n)：贪心 + 二分（06 篇）。
    tails[k] = 长度为 k+1 的上升子序列的"最小可能结尾"——它单调递增。
    每个新元素二分找它应放的位置：替换（延长末尾或压低某长度的结尾）。"""
    tails: list[int] = []
    for x in nums:
        lo, hi = 0, len(tails)
        while lo < hi:                    # bisect_left 语义：第一个 >= x 的位置
            mid = (lo + hi) // 2
            if tails[mid] < x:
                lo = mid + 1
            else:
                hi = mid
        if lo == len(tails):
            tails.append(x)               # x 比所有结尾都大：LIS 变长
        else:
            tails[lo] = x                 # 压低该长度的结尾（未来更易接上）
    return len(tails)

assert length_of_lis([10, 9, 2, 5, 3, 7, 101, 18]) == 4
assert length_of_lis_fast([10, 9, 2, 5, 3, 7, 101, 18]) == 4
assert length_of_lis([7, 7, 7, 7]) == 1        # 严格上升
```

**为什么状态定义是"以 i 结尾"**：如果定义成"前 i 个元素中的 LIS"，转移时不知道选中的子序列结尾在哪，没法判断 nums[i] 能否接上——**状态必须携带足够信息让决策可判定**。这就是"怎么找状态"的第一个实例：从"转移需要什么信息"倒推状态要包含什么。

O(n log n) 版的正确性论证：`tails` 单调递增（归纳：替换或追加都保持有序）；每个 x 的放置用 lower_bound 保证"能延长就延长，否则把某长度结尾压得更小"。注意 tails 本身**不是**某条 LIS，只是长度等价的压缩表示（常见误解）。

## 5. 状态定义方法论：从"子问题长什么样"倒推

把前三题的推导过程提炼成可复用的流程（经验做法，综合自竞赛与面试社区共识）：

1. **写暴力递归**：用最自然的方式定义"解原问题需要解决什么子问题"（哪怕 O(2^n)）；
2. **找重叠**：把递归调用画成树，找重复出现的参数组合——重复的就是状态；
3. **检查最优子结构**：子问题的最优解拼起来确实是最优吗？决策是否影响后续可行集？（打家劫舍"偷了 i-1"影响"i 能不能偷"——所以状态是"前 i 家的最大"而非"偷到第 i 家为止"）；
4. **定转移**：枚举"最后一步的决策"，写 `dp[状态] = f(更小状态)`；
5. **定边界与循环顺序**：依赖谁就先算谁（下一节）；
6. **验证**：小例子手算 dp 表（13 篇的调试技巧）。

**两个易错信号**：① 转移时发现"缺信息"（比如不知道上一个选了什么）→ 加维度（13 篇状态机 DP 就是加"上一次交易状态"维度）；② "当前决策影响未来可选集"→ 把"未来受影响的那个量"纳入状态。

## 6. 循环顺序：依赖关系决定扫描方向

DP 表格的循环顺序不是玄学，是**拓扑序**（10 篇的呼应）：`dp[i]` 依赖 `dp[i-1]` 就正着扫；二维里 `dp[i][j]` 依赖上、左就双层正扫；背包的"倒序"是反直觉特例（13 篇详述）。用一道二维题演示：

```python
def unique_paths(m: int, n: int) -> int:
    """LC 62 不同路径：机器人只能右/下，从左上到右下几条路。O(mn)。
    状态：dp[i][j] = 到 (i,j) 的路径数。转移：dp[i][j] = dp[i-1][j] + dp[i][j-1]
    （从上方来 or 从左方来）。依赖"上与左" → 双层正序扫。"""
    dp = [[1] * n for _ in range(m)]      # 边界：第一行/列各 1 条
    for i in range(1, m):
        for j in range(1, n):
            dp[i][j] = dp[i - 1][j] + dp[i][j - 1]
    return dp[m - 1][n - 1]

def min_path_sum(grid: list[list[int]]) -> int:
    """LC 64 最小路径和：同构题，把"+"换 min、路径数换路径代价。O(mn)"""
    m, n = len(grid), len(grid[0])
    dp = [[0] * n for _ in range(m)]
    dp[0][0] = grid[0][0]
    for j in range(1, n):
        dp[0][j] = dp[0][j - 1] + grid[0][j]
    for i in range(1, m):
        dp[i][0] = dp[i - 1][0] + grid[i][0]
    for i in range(1, m):
        for j in range(1, n):
            dp[i][j] = min(dp[i - 1][j], dp[i][j - 1]) + grid[i][j]
    return dp[m - 1][n - 1]

assert unique_paths(3, 7) == 28
assert min_path_sum([[1, 3, 1], [1, 5, 1], [4, 2, 1]]) == 7
```

滚动数组压缩（01 篇空间换时间的反向运用——**时间不变、空间降维**）：`dp[i][j]` 只依赖上一行 → 用一维数组原地更新（LC 63/120 练习）。

## 7. 常见误区

1. **状态定义含糊**：dp[i] 到底"以 i 结尾"还是"前 i 个里最优"？两者转移完全不同（LIS 两版都可定义但只有前者能转移）。写代码前用一句话把 dp[i] 的语义说完整；
2. **边界初始化错**：dp[0] 是"空集"的答案还是"第一个元素"的答案？用小例子（n=1）验证边界；
3. **把贪心当 DP**：贪心要求"局部最优全局最优"（14 篇交换论证），DP 是枚举所有决策——能用贪心的问题用 DP 也对（只是慢），反之不成立。拿不准就先写 DP 保正确性；
4. **重叠子问题没找对就硬套模板**：先暴力递归确认重叠，再上表格；不重叠的递归（分治）套 DP 是无效功。

## 本篇小结

1. DP = 重叠子问题 + 最优子结构；进化链：暴力递归 → 记忆化（缓存）→ 递推表格（排好计算顺序）→ 滚动压缩（省空间）；
2. 决策型 DP（打家劫舍）：转移 = 枚举"最后一步的决策"再取最优；环形拆解为两个线性子问题是常用手法；
3. LIS："以 i 结尾"的状态定义由"转移需要什么信息"倒推；O(n²) DP 与 O(n log n) 贪心+二分两版都要会；
4. 状态定义六步法：暴力递归 → 找重叠 → 验最优子结构 → 定转移 → 定边界与顺序 → 小例验证；
5. 循环顺序 = 状态依赖关系的拓扑序；二维依赖上/左就正序双层扫。
