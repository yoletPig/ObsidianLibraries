4. 建立"什么时候哈希表是对的选择"的判断力（对比有序结构）。

## 1. 哈希表在解决什么问题

数组查找要 O(n)，有序数组二分查找 O(log n)（06 篇）。哈希表的目标更激进：**平均 O(1) 完成插入、删除、查找**。原理一句话：用一个函数把 key 映射到数组下标，把"查找"变成"算一次下标再直接访问"（思想可追溯至 1953 年 Hans Luhn 的备忘录；系统论述见 CLRS 第 11 章、Knuth《计算机程序设计艺术》第 3 卷第 6.4 节）。

```
key ──hash()──→ 哈希值 ──取模──→ 桶下标 ──→ [桶 0][桶 1][桶 2]...
```

两个绕不开的问题：**不同的 key 映到同一个桶（哈希冲突）**怎么办；**桶数组满了/太挤了**怎么办。这两问的答案就是本篇的骨架。

## 2. 手写拉链法哈希表

拉链法（separate chaining）：每个桶挂一条链，冲突的元素串在同一条链上。

```python
class MyHashMap:
    """拉链法哈希表（简化教学版）：支持 int -> int。"""

    def __init__(self, init_cap: int = 8) -> None:
        self._cap = init_cap
        self._size = 0
        self._buckets = [[] for _ in range(self._cap)]   # 每个桶是一条链(list 模拟)

    def _index(self, key: int) -> int:
        # 哈希函数：乘法散列的简化版 + 取模。负数 key 也能正确取模（Python % 恒非负）
        return (key * 2654435769) % self._cap            # 黄金比例常数 2^32/φ

    def put(self, key: int, value: int) -> None:
        if self._size >= self._cap:                      # 负载因子达到 1：扩容
            self._resize(self._cap * 2)
        idx = self._index(key)
        chain = self._buckets[idx]
        for pair in chain:                               # 已存在则更新
            if pair[0] == key:
                pair[1] = value
                return
        chain.append([key, value])                       # 不存在则追加
        self._size += 1

    def get(self, key: int) -> int:
        idx = self._index(key)
        for pair in self._buckets[idx]:
            if pair[0] == key:
                return pair[1]
        raise KeyError(key)

    def remove(self, key: int) -> None:
        idx = self._index(key)
        chain = self._buckets[idx]
        for i, pair in enumerate(chain):
            if pair[0] == key:
                chain[i] = chain[-1]                     # 与末尾交换后弹出：O(1) 删除
                chain.pop()
                self._size -= 1
                return
        raise KeyError(key)

    def _resize(self, new_cap: int) -> None:
        """扩容 = 再哈希（rehash）：所有元素重新计算桶下标。"""
        old_buckets = self._buckets
        self._cap = new_cap
        self._buckets = [[] for _ in range(new_cap)]
        self._size = 0
        for chain in old_buckets:
            for key, value in chain:
                self.put(key, value)                     # 逐个重插（不会再触发扩容）

m = MyHashMap()
for i in range(100):
    m.put(i, i * i)
assert m.get(7) == 49 and m.get(99) == 9801
print(f"100 个 key，桶数组大小 {m._cap}（自动扩容过了）")
```

复杂度分析：只要负载因子 α = size/cap 是常数，链平均长度 O(α)，所有操作**期望 O(1)**（假设哈希函数把 key 均匀打散，即"简单均匀散列假设"，CLRS 11.2）；最坏情况所有 key 挤进一个桶，退化为 O(n)。扩容单次 O(n)，均摊 O(1)（01 篇同样的几何级数论证）。

## 3. 开放寻址与 Python dict 的底层

拉链法的替代方案：**开放寻址（open addressing）**——不用链，冲突了就按规则探测下一个空位。常见探测序列：

- **线性探测**：`idx, idx+1, idx+2, ...`。缓存最友好（探测都在邻近内存），但会产生"一次聚集"（连续占用越长，插入越容易继续延长它）；
- **平方探测**：`idx, idx+1², idx+2², ...`，缓解聚集；
- **双重散列**：用第二个哈希函数定步长，聚集最轻但缓存一般。

```python
def linear_probe_demo() -> None:
    cap = 8
    table: list[tuple[int, int] | None] = [None] * cap

    def index(key: int) -> int:
        return key % cap

    # 插入：从目标桶开始找第一个空位
    def insert(key: int, val: int) -> None:
        i = index(key)
        while table[i] is not None:      # 被占就往右挪一格（环形）
            i = (i + 1) % cap
        table[i] = (key, val)

    # 查找：沿同样路径找，遇到空位说明不存在
    def find(key: int) -> int | None:
        i = index(key)
        while table[i] is not None:
            if table[i][0] == key:
                return table[i][1]
            i = (i + 1) % cap
        return None

    for k in (10, 18, 26):               # 三者同余 2，依次向后挤
        insert(k, k * 10)
    print(table)                          # (10,..)在桶2，(18,..)在桶3，(26,..)在桶4
    assert find(26) == 260
```

**Python dict 的底层**（CPython 源码 `Objects/dictobject.c`）：开放寻址 + **扰动**（把哈希值高位异或到低位再取模）+ 自定义探测序列；负载因子超过约 2/3 就扩容。set 用同一套机制（`Objects/setobject.c`）。这就是为什么：

1. dict 的 key 必须可哈希（`__hash__` 稳定且 `__eq__` 一致）——`list`、`dict`、`set` 不能做 key，`tuple`/`frozenset`/数值/字符串可以；
2. dict 遍历顺序 = 插入顺序（3.7+ 语言规范保证）：实现里有一个紧凑的 entries 数组按插入序记录，哈希表只做索引；
3. **哈希碰撞攻击**：攻击者构造大量同桶 key 把 dict 打成 O(n) 每操作（HTTP 头解析 DoS 曾是真实案例，CVE-2011-3412 是 .NET 侧同类问题）。CPython 对 str 哈希做了随机化（PYTHONHASHSEED）——面试聊到"哈希表最坏情况"时提这个是加分项。

## 4. 哈希函数常识

不需要会造密码学哈希，但要懂"好哈希"的标准：**确定性**（同 key 同值）、**均匀性**（尽量把 key 打散）、**雪崩效应**（key 变一点，哈希值大变）。

```python
def hash_function_examples() -> None:
    # 常识 1：整数哈希常用"乘法散列"——乘一个奇数/黄金比例常数再取高位
    x = 1234567
    print((x * 2654435769) & 0xFFFFFFFF)     # Knuth 推荐的黄金比例常数

    # 常识 2：字符串哈希 = 多项式累加（Java、多数教材的做法）
    def str_hash(s: str, base: int = 131, mod: int = 10**9 + 7) -> int:
        h = 0
        for ch in s:
            h = (h * base + ord(ch)) % mod   # 逐字符滚进
        return h

    print(str_hash("hello"), str_hash("hellp"))  # 相邻字符串哈希差很远

    # 常识 3：自定义对象做 dict key，必须同时定义 __hash__ 与 __eq__
    # 铁律：a == b 则 hash(a) == hash(b)；反之不必成立（撞了由冲突机制兜底）

hash_function_examples()
```

> **陷阱**：可变对象做了 key 之后又改值，`__eq__` 变了而哈希桶没变——这个 key 再也找不到了。所以"key 必须不可变"不是语法规定，是**一致性要求**。

## 5. 应用模式一：两数之和（查存在/查配对）

```python
def two_sum(nums: list[int], target: int) -> list[int]:
    """LC 1 两数之和：一遍哈希。O(n) 时间 O(n) 空间。"""
    seen: dict[int, int] = {}               # 值 -> 下标
    for i, x in enumerate(nums):
        if target - x in seen:              # 需要"配对值"以前出现过吗？
            return [seen[target - x], i]
        seen[x] = i                         # 先查后插，避免用同一元素两次
    return []

assert two_sum([2, 7, 11, 15], 9) == [0, 1]
```

模式抽象：**遍历时向哈希表问一个 O(1) 的问题**——"我需要的另一半见过没有"。同型题：LC 128 最长连续序列（问 x-1 存在吗？其实还用哈希做 O(n) 起点筛选）、LC 560 和为 K 的子数组（配对值是"前缀和 − k"，见模式三）。

## 6. 应用模式二：分组（同构、异位词、按特征归类）

```python
from collections import defaultdict

def group_anagrams(strs: list[str]) -> list[list[str]]:
    """LC 49 异位词分组：设计"特征键"，同组必有同一键。O(n·k log k)"""
    groups: defaultdict[tuple, list[str]] = defaultdict(list)
    for s in strs:
        key = tuple(sorted(s))          # 排序后的字符序列 = 异位词的规范形
        groups[key].append(s)           # tuple 可哈希，list 不行
    return list(groups.values())

result = group_anagrams(["eat", "tea", "tan", "ate", "nat", "bat"])
assert sorted(sorted(g) for g in result) == [["ate", "eat", "tea"], ["bat"], ["nat", "tan"]]
```

模式抽象：**给每个元素算一个"等价类特征"当 key**，哈希表自动完成分组。特征可以是排序串、字符计数 tuple（`tuple(Counter(s).values())` 配合固定 26 位）、或任何"同组同值"的函数。`defaultdict(list)` 是这里的标准搭档，省去"key 不存在先初始化"的样板。

## 7. 应用模式三：前缀和 + 哈希

```python
def subarray_sum(nums: list[int], k: int) -> int:
    """LC 560 和为 k 的子数组个数。前缀和 + 哈希，O(n)。
    核心：区间 [j+1, i] 的和 = P[i] - P[j]，要它等于 k，
    即 j 处的前缀和 = P[i] - k —— 又变回"查存在性"模式。"""
    count = 0
    prefix = 0
    seen: dict[int, int] = {0: 1}       # 空前缀和为 0，出现 1 次
    for x in nums:
        prefix += x
        count += seen.get(prefix - k, 0)  # 有多少个 j 的前缀和恰好差 k
        seen[prefix] = seen.get(prefix, 0) + 1
    return count

assert subarray_sum([1, 1, 1], 2) == 2
assert subarray_sum([1, 2, 3], 3) == 2
```

这是三大模式里最"值钱"的一个：把"找区间"化归为"找前缀和之差"，再用哈希查差值出现次数。同型题：LC 523 连续的子数组和（前缀和取模 + 首次出现位置）、LC 974 和可被 K 整除的子数组（模哈希）。

> **提示**：三个模式可以叠用——LC 560 同时用了"前缀和"（化区间为差）和"两数之和"（查差值存在）。遇到子数组/子串问题先想前缀和，想到前缀和再想能不能配哈希。

## 8. 什么时候不该用哈希表

1. **要有序遍历/区间查询/前驱后继**：哈希表不支持。需要"最小的大于 x 的元素"就用有序结构（BST/平衡树，08 篇；Python 里用 `bisect` 模块维护有序数组，06 篇）；
2. **要最坏情况保证**：实时/安全敏感场景哈希最坏 O(n)。理想是 C++ `std::map`（红黑树，O(log n) 恒定）；Python 生态里可用 `sortedcontainers.SortedDict`（三方库，经验做法）；
3. **数据量小**：n < 20 时线性扫描数组常比哈希快（缓存 + 无哈希计算开销，经验做法）。

## 本篇小结

1. 哈希表 = 哈希函数 + 桶数组 + 冲突解决；拉链法好写好懂，开放寻址缓存更友好（Python dict 的路线）；
2. 负载因子是性能命门：α 太大链条变长，Python 约在 2/3 扩容；扩容 = 全量再哈希，单次 O(n) 均摊 O(1)；
3. key 的铁律：`==` 与 `__hash__` 一致；可变对象不可做 key；
4. 三大应用模式：查存在（两数之和）、按特征分组（异位词）、前缀和+哈希（和为 k 的子数组）；
5. 需要有序、区间、最坏保证时，换有序结构——数据结构选型永远是"问题需要什么操作，就找支持这些操作最便宜的结构"。
