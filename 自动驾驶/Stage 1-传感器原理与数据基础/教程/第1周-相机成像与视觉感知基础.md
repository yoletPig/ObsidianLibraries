## 1. 第一性原理：相机在做什么

### 1.1 从光子到像素的一句话流水线

相机成像的本质是**记录到达每个感光单元的光子数量**。完整流水线（本节只建立直觉，一句话版本）：

```
场景光 → 镜头聚焦 → 快门/曝光（累计光子）→ CMOS 传感器（光电转换）
      → ISP 图像信号处理：去马赛克 Demosaic → 白平衡 → 伽马校正 → 压缩
      → 你看到的 RGB 图像
```

- **曝光（exposure）**：传感器在一段时间内累计光子。时间越长（慢快门）或光圈越大，图越亮——但运动目标会更模糊。这就是夜间路侧相机拖影的来源。
- **ISP（Image Signal Processing）**：传感器原始输出是 Bayer 格式（每个像素只感知 R/G/B 之一），ISP 负责插值出全彩、校色、调 gamma。对你来说它是个黑盒，但要知道：**你拿到的 8-bit RGB 图已经被非线性处理过**，做光度标定时要意识到这一点。
- 对感知算法而言，相机输出的图像是**带颜色纹理的 2D 投影**——语义信息最丰富（认得出红绿灯、车道线、文字），但**没有距离**。

### 1.2 针孔相机模型：3D 到 2D 的投影

针孔相机模型（Pinhole Camera Model）把复杂镜头理想化为一个小孔：所有光线沿直线穿过孔，投到像平面上。设相机坐标系（Camera Frame）约定为 **x 右、y 下、z 沿光轴向前**（计算机视觉标准约定），空间一点 $P$ 在相机系下为 $(X, Y, Z)$，则它的像素坐标：

$$
u = f_x \frac{X}{Z} + c_x, \qquad v = f_y \frac{Y}{Z} + c_y
$$

**这个公式在干什么**：把 3D 空间中的一点，按"光线直线传播"的规律压到 2D 图像平面上，再把物理单位换算成像素编号。

逐符号拆解：

| 符号 | 物理含义 | 大白话 |
| --- | --- | --- |
| $X, Y, Z$ | 点在相机坐标系下的坐标（米） | 物体在你右前方多远、偏多少、多高 |
| $Z$ | 点沿光轴的深度 | **只有这个决定缩放**：越远越小 |
| $X/Z, \; Y/Z$ | 归一化平面坐标 | 先忘掉距离，只看"方向"：视角偏了多少 |
| $f_x, f_y$ | 焦距（以像素为单位） | 焦距越长，同样的角度偏移在图上占的像素越多（放大倍率） |
| $c_x, c_y$ | 主点（principal point），像素单位 | 图像中心的光轴落点，通常是图像宽高的一半附近 |
| $u, v$ | 像素坐标（列，行） | 最终查图像数组时用的下标 |

**为什么除以 $Z$？** 这是整个公式最关键、也最容易背了就忘的一步。针孔模型里，同一个方向上的两个物体（一个 5m 外、一个 10m 外），穿过小孔的光线是**同一条**——投影只保留"方向"，丢掉"距离"。数学上表达"只留方向"就是把 $(X,Y,Z)$ 除以深度 $Z$，得到归一化平面上的 $(X/Z, Y/Z)$。这也意味着：**深度信息在投影这一步物理性丢失了，事后无法从单张图恢复**——这就是自动驾驶需要激光雷达/雷达补测距的根本原因，也是"单目测距不可靠"的第一性解释。

**$Z = 0$ 会怎样？** 除零，公式无意义——物体正好在光轴垂直的平面上时不存在有限投影。工程上投影前都断言 `Z > eps`。

> **动手验证**：见第 4 节代码例 2——同一个物体放在 5m、10m、20m，u 坐标从 1280 → 1120 → 1040，越远越靠近图像中心（越远越小）。

### 1.3 内参矩阵 K：相机的"指纹"

把上面两个公式写成矩阵形式，就是**内参矩阵（Intrinsic Matrix）**：

$$
\begin{bmatrix} u \\ v \\ 1 \end{bmatrix} = \frac{1}{Z} \begin{bmatrix} f_x & 0 & c_x \\ 0 & f_y & c_y \\ 0 & 0 & 1 \end{bmatrix} \begin{bmatrix} X \\ Y \\ Z \end{bmatrix} = \frac{1}{Z} K \begin{bmatrix} X \\ Y \\ Z \end{bmatrix}
$$

**这个矩阵在干什么**：一行代码完成"从相机系 3D 方向到像素"的换算，其中 $K$ 只与相机本身有关（焦距、像素间距、主点），与拍什么场景无关——所以叫"内"参。齐次坐标（最后一维填 1）纯粹是为了让平移和投影都能写成矩阵乘法。

几个工程事实：

- $f_x = f / d_x$，其中 $f$ 是物理焦距（毫米），$d_x$ 是单个像素的物理宽度（微米级）。**换传感器分辨率，$f_x$ 就变**——所以 K 是"镜头 + 传感器"组合的属性。
- $f_x \approx f_y$ 一般成立；若差很多，说明像素不是正方形（罕见）或标定有误。
- 内参通过**张正友标定法**（Zhang's method，拍多角度棋盘格）得到。`cv2.calibrateCamera` 干的就是这件事，输出 K 和畸变系数。

## 2. 镜头畸变：理想模型的现实修正

针孔模型假设直线成像后仍是直线。真实镜头（尤其广角）不满足：**径向畸变（radial distortion）**让直线弯成曲线，**切向畸变（tangential distortion）**来自镜头与传感器没装正。

### 2.1 OpenCV 畸变模型（k1, k2, p1, p2）

畸变在**归一化平面**上施加（先除以 Z，再扭曲），OpenCV 约定：

$$
r^2 = x^2 + y^2
$$
$$
x_d = x(1 + k_1 r^2 + k_2 r^4) + 2p_1xy + p_2(r^2 + 2x^2)
$$
$$
y_d = y(1 + k_1 r^2 + k_2 r^4) + p_1(r^2 + 2y^2) + 2p_2xy
$$

**这组公式在干什么**：每个点的归一化坐标 $(x,y)$ 被按"离图像中心多远"（$r^2$）做非线性的拉伸/挤压，模拟真实镜头的光学缺陷。

逐符号拆解：

| 符号 | 物理含义 | 大白话 |
| --- | --- | --- |
| $r^2 = x^2 + y^2$ | 归一化坐标下到中心的距离平方 | "你离图像中心多远" |
| $k_1$ | 径向畸变低阶项 | 负值 = 桶形畸变（广角镜头常见，中间鼓）；正值 = 枕形 |
| $k_2$ | 径向畸变高阶项 | 修正广角边缘更剧烈的弯曲；普通镜头可近似为 0 |
| $p_1, p_2$ | 切向畸变 | 镜头装配歪了，图像整体有个小的"剪切"偏移 |
| $(x_d, y_d)$ | 畸变后的坐标 | 再乘 $f_x, f_y$ 加 $c_x, c_y$ 才是真实像素 |

**关键性质：畸变随 $r$ 增长**——图像中心几乎无畸变，边角最严重。所以广角（短焦距）相机必须做去畸变才能把像素反投影回 3D 方向。

代码验证（第 4 节例 3）：取 $k_1=-0.15$ 的典型广角镜头，归一化坐标 $(0.2, 0.1)$ 处像素偏移仅 1.33 像素，坐标缩到一半时偏移缩到 0.17 像素——"越靠中心越干净"的定量证据。

### 2.2 路侧工程含义

- 路侧枪机多为定焦广角（看全路口），标定后保存 K + 畸变系数，检测/测速前先去畸变。
- 长焦镜头（看远）畸变小但视场窄——第 5 节的选型权衡。
- **坑**：拿到别人的标定文件先确认畸变模型（OpenCV 的 k1k2p1p2 与 MATLAB 的顺序不同），用错了畸变方向，反投影的 3D 点会系统性偏移几米。

## 3. 四个坐标系：从世界到像素的完整链

自动驾驶里一个 3D 点要经过**四个坐标系**才能和图像对上：

```
世界坐标系 (World)  --外参[R|t]-->  相机坐标系 (Camera)  --K 投影-->  图像坐标系 (Image)  --量化-->  像素坐标系 (Pixel)
    (米，场景固定原点)                (米，x右y下z前)                 (毫米级物理平面)                 (u,v，无单位)
```

**为什么要四个**：世界系是"地图/路侧杆"的公共参照；相机系是"相机自己眼中的米"；图像系是物理像平面（还带单位）；像素系是数组下标。每一步只干一件小事，合起来才是完整投影。

完整公式（用齐次坐标一行写完）：

$$
\tilde{p} = \frac{1}{Z_c} K \begin{bmatrix} R \mid t \end{bmatrix} \tilde{P}_w
$$

**这个公式在干什么**：先用外参 $[R \mid t]$ 把世界系的点搬到相机系（R 旋转、t 平移，都是"相机安装在哪里、朝哪个方向"的描述），再除以相机系深度 $Z_c$ 投影，再乘 K 变成像素。

> **外参的两种读法**（新手最容易绕晕的点）：$T_{w \to c}$ 的旋转 R 描述"世界系到相机系"的变换，它的直观理解是"相机的姿态"的逆。工程惯例是存 $T_{cam \to world}$（相机在世界里的位姿），用时取逆。**写代码时永远显式标注矩阵方向**（如 `T_velo_to_cam`），方向搞反是最常见的标定 bug。

### 3.1 数值手算例（面试与调试都够用）

设相机无旋转、位于世界原点；内参 $f_x = f_y = 800$ 像素，$c_x = 960, c_y = 540$（1920×1080 图像）。世界系下有一个路牌：偏右 2 m、高 1 m、正前方 10 m，即 $P_w = (2, 1, 10)$。

1. **世界 → 相机**：外参为恒等，$P_c = (2, 1, 10)$。
2. **相机 → 图像**：$x_n = X/Z = 2/10 = 0.2$，$y_n = Y/Z = 1/10 = 0.1$（归一化平面，单位是无量纲的方向比）。
3. **图像 → 像素**：$u = 800 \times 0.2 + 960 = 1120$，$v = 800 \times 0.1 + 540 = 620$。

结论：路牌落在第 1120 列、第 620 行。把 $Z$ 改成 20，$u$ 变成 $800 \times 0.1 + 960 = 1040$——同一块牌子往后退 10 m，像素坐标向图像中心收缩。**这个三步手算建议背下来**：调试任何"点云投影到图像不重合"的问题，第一步都是拿一个已知点人工走一遍这条链。

## 4. 可运行代码：投影链 + 畸变 + 视场角

```python
# w1_camera.py —— 针孔投影、畸变、FOV 数值验证
import numpy as np

# ---------- 例1：世界-相机-图像-像素 四坐标系变换链 ----------
P_w = np.array([2.0, 1.0, 10.0, 1.0])          # 世界系齐次坐标 (x, y, z, 1)

T_wc = np.eye(4)                               # 相机位于世界原点、无旋转
T_cw = np.linalg.inv(T_wc)                     # 外参：世界 -> 相机
P_c = T_cw @ P_w                               # 相机坐标系下
print("P_c =", P_c[:3])

# 内参矩阵 K：fx=fy=800 像素, 主点 (960, 540) —— 1920x1080 图像
fx = fy = 800.0
cx, cy = 960.0, 540.0
K = np.array([[fx,  0, cx],
              [ 0, fy, cy],
              [ 0,  0,  1]])
p_img = K @ P_c[:3]
u, v = p_img[0] / p_img[2], p_img[1] / p_img[2]   # 除以 Z（深度）才是像素
print(f"像素坐标 u={u:.1f}, v={v:.1f}")
assert abs(u - (fx * P_c[0] / P_c[2] + cx)) < 1e-9   # 与手算一致

# ---------- 例2：Z 越远，像素越靠中心（物体越小）----------
for Z in [5.0, 10.0, 20.0]:
    u = fx * 2.0 / Z + cx
    print(f"Z={Z:5.1f} m -> 同一物体落在 u={u:.1f}")

# ---------- 例3：镜头畸变（径向 k1,k2 + 切向 p1,p2）----------
def distort(xn, yn, k1, k2, p1, p2):
    """OpenCV 约定：在归一化平面 (x=X/Z, y=Y/Z) 上施加畸变。"""
    r2 = xn**2 + yn**2
    radial = 1 + k1 * r2 + k2 * r2**2
    xd = xn * radial + 2 * p1 * xn * yn + p2 * (r2 + 2 * xn**2)
    yd = yn * radial + p1 * (r2 + 2 * yn**2) + 2 * p2 * xn * yn
    return xd, yd

k1, k2, p1, p2 = -0.15, 0.02, 1e-4, -5e-5      # 典型广角镜头量级
xn, yn = 0.2, 0.1
xd, yd = distort(xn, yn, k1, k2, p1, p2)
u0, v0 = fx * xn + cx, fy * yn + cy            # 无畸变像素
u1, v1 = fx * xd + cx, fy * yd + cy            # 有畸变像素
print(f"无畸变像素: ({u0:.2f}, {v0:.2f})")
print(f"有畸变像素: ({u1:.2f}, {v1:.2f})")
print(f"偏移量    : ({u1-u0:+.2f}, {v1-v0:+.2f}) 像素")

# 验证：越靠图像中心畸变越小
for scale in [0.1, 0.5, 1.0]:
    xn, yn = 0.2 * scale, 0.1 * scale
    xd, yd = distort(xn, yn, k1, k2, p1, p2)
    off = np.hypot(fx*(xd-xn), fy*(yd-yn))
    print(f"归一化坐标缩放 {scale:.1f}: 距中心偏移 {off:.3f} 像素")

# ---------- 例4：视场角（FOV）与焦距的关系 ----------
# 以 1/1.8" 传感器（感光面宽约 7.2 mm）为例
for f in [4.0, 8.0, 16.0]:                     # 物理焦距 mm
    hfov = 2 * np.degrees(np.arctan(7.2 / 2 / f))
    print(f"焦距≈{f}mm -> 水平 FOV ≈ {hfov:.1f}°")
```

**预期输出**（Python 3.12 + numpy 1.26 实测）：

```
P_c = [ 2.  1. 10.]
像素坐标 u=1120.0, v=620.0
Z=  5.0 m -> 同一物体落在 u=1280.0
Z= 10.0 m -> 同一物体落在 u=1120.0
Z= 20.0 m -> 同一物体落在 u=1040.0
无畸变像素: (1120.00, 620.00)
有畸变像素: (1118.81, 619.41)
偏移量    : (-1.19, -0.59) 像素
归一化坐标缩放 0.1: 距中心偏移 0.001 像素
归一化坐标缩放 0.5: 距中心偏移 0.167 像素
归一化坐标缩放 1.0: 距中心偏移 1.333 像素
焦距≈4.0mm -> 水平 FOV ≈ 84.0°
焦距≈8.0mm -> 水平 FOV ≈ 48.5°
焦距≈16.0mm -> 水平 FOV ≈ 25.4°
```

> **动手验证**：
> 1. 把例 1 的 $P_w$ 改成 $(0, 0, 10)$，投影应精确落在主点 $(960, 540)$——光轴上的点投影在图像中心。
> 2. 若装了 `opencv-python-headless`，用 `cv2.undistortPoints` 对例 3 的 $(x_d, y_d)$ 做去畸变（传入同样的 k1k2p1p2），应还原出 $(0.2, 0.1)$——验证你的畸变公式方向与 OpenCV 一致。

## 5. 相机选型与路侧常见配置

### 5.1 参数间的制约关系

三个参数互相"拉扯"，选型就是权衡：

- **分辨率 × 视场角 → 角分辨率**。像素密度（像素/度）≈ 图像宽 ÷ FOV。1920 像素 ÷ 84° ≈ 23 像素/度；要看得清远处行人（0.2 m 细节 @ 60 m ≈ 0.19°），需要至少 ~5 像素覆盖——宽 FOV 和远距离识别不可兼得，所以路侧常"一杆多相机"（广角看全场景 + 长焦看远）。
- **帧率**：路侧交通监控常见 25 fps（PAL 制传统）；追拍违章/测速的抓拍相机会用更高快门速度而不是更高帧率。帧率翻倍，码流/算力也翻倍。
- **曝光时间**：上限约为 1/帧率。高速场景目标运动模糊（motion blur）≈ 车速 × 曝光时间，120 km/h 在 1 ms 曝光下模糊 3.3 cm——通常是可接受的，但夜间拉长曝光后车牌就糊了。
- **动态范围（dynamic range）**：一帧内最亮与最暗可分辨之比。逆光路口（天空亮、车底暗）超出普通传感器能力，出现"天空过曝、阴影全黑"。路侧相机靠 WDR（宽动态，多帧合成）缓解，但 WDR 帧有额外延迟——做高速检测时要留意。

### 5.2 典型路侧产品参数（查证过的实例）

以海康威视 DS-2CD3T46(D)WDV3-I3 等主流 400 万像素筒型/枪机为例（官方 Datasheet）：

| 参数 | 典型值 | 说明 |
| --- | --- | --- |
| 分辨率 | 2688×1520（400 万像素） | 路侧交通监控的常见起步配置 |
| 帧率 | 最高 25 fps | 交通监控标准帧率 |
| 焦距选项 | 2.8 / 4 / 6 / 8 mm | 定焦多档；2.8mm 水平 FOV 约 97°（1/3" 传感器） |
| 传感器 | 1/3" CMOS + ICR 红外 | 夜间红外补光 |

**路侧 vs 车端的差异**：车端前视相机常见 800 万像素、120° FOV、8MP@30fps 量级（如各量产智驾方案），强调宽动态与低延迟；路侧则固定安装、供电无忧，常用 400 万～4K 定焦枪机长期观测，标定一次长期有效。**注意**：具体型号参数以厂商最新 Datasheet 为准，上表是量级参考。

## 6. 工程权衡与失效模式

### 6.1 权衡速查

- **焦距**：短焦广角看得全但远处像素少；长焦看得远但视野窄。路侧"一杆多机"正是为绕开这个不可兼得。
- **分辨率**：越高看得越细，但带宽、存储、推理算力线性上升。400 万像素是路侧精度/成本甜点。
- **帧率**：跟踪需要 ≥ 25 fps（帧间位移小于目标尺寸）；融合系统里相机通常还是频率最高的那个。

### 6.2 典型失效模式

1. **逆光/夜间失效**：相机是所有传感器中最依赖光照的。**症状**：夜图噪声大、逆光剪影；**缓解**：宽动态（WDR）、红外补光、与雷达互补。
2. **未去畸变就做几何计算**：用广角原图直接反投影测距/测速，边角目标系统性偏差。**定位**：误差随目标离图像中心距离增大；**修复**：先 `cv2.undistort` 或在投影链里显式加畸变模型。
3. **标定文件与镜头不匹配**：换焦距/换镜头后沿用旧 K。**症状**：投影重合在中心附近还行、越往外越歪；**修复**：任何硬件变动后重新标定。
4. **混用内外参方向**：`T_w2c` 当 `T_c2w` 用。**症状**：投影整体错位，像"从背后看世界"；**修复**：显式命名 + 拿第 3 节手算例当单元测试。

## 7. 延伸思考题（含解析）

**Q1**：为什么单张图像无法测距，双目相机就可以？
**A**：单张图投影已丢失 $Z$（1.2 节），恢复深度需要额外信息。双目利用同一物体在两个视角下的视差（disparity）：深度 $Z = f \cdot B / d$（B 为基线距离，d 为视差）——本质是用"已知基线的两次针孔投影"几何三角化。距离越远视差越小，所以双目的远距精度差，这也解释了车端为什么还需要激光雷达。

**Q2**：$f_x$ 和物理焦距 $f$（mm）是什么关系？为什么 K 里用 $f_x$ 而不用 $f$？
**A**：$f_x = f / d_x$（$d_x$ 为像素物理宽度）。投影公式最终输出像素下标，用像素单位的焦距可以一步到位，不用再关心传感器尺寸。同一镜头换 1080p/4K 传感器，$f$ 不变但 $f_x$ 翻倍。

**Q3**：k1 为负是什么畸变？怎么肉眼判断？
**A**：桶形畸变（barrel），广角镜头常见。肉眼判断：拍一张带规则网格（如瓷砖墙）的照片，若直线向外弯成"桶边"即为桶形。标定后 $k_1 < 0$ 与之对应。

**Q4**：路侧相机标定一次能用多久？什么情况下必须重标？
**A**：固定安装、温度形变小的场景可数月甚至更久。但任何机械扰动（杆体被撞、镜头变焦、强台风后）都必须重标。工程实践：用车道线、停止线等已知地面标记做定期自动校验，偏移超阈值告警。

**Q5**：为什么本篇投影代码把点写成齐次坐标 (x, y, z, 1)？
**A**：纯技巧性的工程选择：齐次坐标让"3D 平移"也能写成 4×4 矩阵乘法（非齐次下平移是加法，无法与旋转连乘）。于是从雷达到像素的整条链可以合成**一个**矩阵（第 4 周展开），推理时一次乘法完成全部空间变换。
