## 1. tracking-by-detection：范式全流程

现代多目标跟踪（Multiple Object Tracking, MOT）的主流范式是 **tracking-by-detection**：不做"从像素里找目标再连线"的传统跟踪，而是**每一帧都用检测器独立检测，然后把跨帧的检测"缝"成轨迹**。检测器（Stage 2）负责"这一帧有什么"，跟踪器只负责"哪帧的哪个和哪帧的哪个是同一个"。

每帧流水线四步，职责边界清晰：

```
检测 (detections + scores)
  ↓  ① 关联前置：所有轨迹 KF 预测到当前帧（第 2 周）
  ↓  ② 关联：门控 + 匈牙利，检测配轨迹（第 3 周）
  ↓  ③ 滤波更新：配上的检测修正轨迹状态
  ↓  ④ 轨迹管理：未配上的检测/轨迹进入生死裁决
输出 (confirmed tracks: id, pos, vel, 类别, 置信度)
```

为什么要"先预测再关联"（① 在 ② 前）？因为关联的代价矩阵用的是**预测位置**：KF 把每条轨迹外推到本帧时刻（顺带解决多传感器的时延差——外推到统一时间戳），再用预测点去和检测算距离。预测把第 2 周的"跟得住"变成了第 3 周"分得清"的前提。

## 2. track 状态机：杂波的第一道闸门

### 2.1 三态设计

| 状态 | 含义 | 转入条件 | 转出条件 |
| --- | --- | --- | --- |
| **tentative（候选）** | 疑似新目标，还不对外输出 | 有未匹配检测认领 | 累计命中 ≥ min_hits → confirmed；连续丢失 → deleted |
| **confirmed（确认）** | 可信轨迹，对外输出 | hits ≥ min_hits（典型 3） | 连续丢失 > max_age → deleted |
| **deleted（删除）** | 释放 ID 与内存 | — | 不可恢复（新目标 = 新 ID） |

状态流转一图流：

```
            未匹配检测
                │ 新建
                ▼
          ┌───────────┐  hits >= min_hits   ┌───────────┐  misses > max_age
          │ tentative │ ──────────────────► │ confirmed │ ─────────────────►
          └───────────┘                     └───────────┘                   ┌─────────┐
                │ misses > max_age（教学版与 confirmed 共用；            │ deleted │
                └── 量产常给 tentative 更短的超时，如 1~2 帧） ◄──────────┘（misses 归零则续命）
```

### 2.2 为什么这样设计

- **tentative 挡杂波**：真实检测器每帧都有几十个误检，若每个都直接建 confirmed 轨迹，轨迹池瞬间爆炸。杂波是空间随机、时间不持续的——"连续 3 帧出现在可预测位置"对杂波是极小概率事件（本周实验会量化：197 个 tentative 只有 3 个真目标转正；而不做防护时会有 7 条杂波轨迹幸存成 confirmed）。
- **max_age 挡漏检**：目标被树荫/车辆遮挡 0.5 s，检测消失但目标还在。KF 纯预测滑行（速度照推、协方差按 Q 膨胀），门控顺带放宽（椭圆大了，马氏距离反而更容易通过），检测一恢复就续上——**同一 ID 存活**。没有 max_age 的跟踪器，一次遮挡 = 一次 ID 重生。
- **与 NMS 的配合**：检测端 NMS（非极大值抑制，Stage 2）可能把紧邻的两个目标压成一个框（双目标合并漏检），track 会经历"1 条轨迹接 1 个检测 → 突然 2 个检测"的时刻——状态机允许把多余检测开成新 tentative，避免误并入旧轨迹。反过来检测分数低的目标被 NMS 后端滤掉造成漏检，由 max_age 兜底。

## 3. MOT 指标：怎么量化"跟得好"

多目标跟踪评测的标准指标族来自 **CLEAR MOT**（Bernardin & Stiefelhagen, 2008），加上身份保持的 **IDF1**（Ristani et al., ECCV 2016）。逐个看：

### 3.1 MOTA（Multi-Object Tracking Accuracy）

$$
MOTA = 1 - \frac{FN + FP + IDSW}{\sum_t g_t}
$$

**这个公式在干什么**：数三种错误占真值总量的比例，一次扣完。逐符号拆解：

| 符号 | 物理含义 | 大白话 |
| --- | --- | --- |
| $FN$（false negative） | 漏检：真值目标没有对应输出 | 该报没报 |
| $FP$（false positive） | 误报：输出没有对应真值 | 不该报乱报 |
| $IDSW$ | 身份切换次数：同一真值目标先后被两条不同轨迹认领 | 认错人 |
| $\sum_t g_t$ | 全部帧的真值目标总数 | 分母，错误率的基准 |

**为什么可以是负数**：输出离谱地多（FP 巨大）时，$FN+FP+IDSW$ 可以超过分母，MOTA < 0——指标用线性惩罚明确告诉你"宁可少报不可乱报"。MOTA 主要惩罚检测质量与身份切换，**不衡量位置准不准**——那是 MOTP 的事。

### 3.2 MOTP（Multi-Object Tracking Precision）

**所有匹配对（真值目标 ↔ 输出轨迹）的平均位置误差**（2D 用 IoU 阈值下匹配框的重叠度，3D/点目标用平均距离）。MOTA 高、MOTP 低 = "目标都找对了但框得歪"。注意它衡量的是**已配对目标的定位精度**，与 MOTA 互补。

### 3.3 IDF1（Identity F1 Score）

**基于身份保持的匹配**：把"整条真值轨迹"与"整条预测轨迹"做全局二部匹配（而非逐帧匹配），统计"身份正确识别的检测数 ÷ (真值检测数 + 预测检测数)"。一句话：**IDF1 高 = 一条轨迹从头到尾认的是同一个人/车**。MOTA 高但 IDF1 低 = "每帧都报到了，但一会儿叫 A 一会儿叫 B"——这正是第 1 周说的 ID 漂移，也是路侧 V2X 最怕的指标组合。

> 指标工程实现对照 `py-motmetrics`（其结果与 MOTChallenge 基准对齐）；本周 mini-MOT 按同一口径实现 MOTA/MOTP/IDSW（IDF1 需要轨迹级全局匹配，作为思考题）。更新的 **HOTA**（Higher Order Tracking Accuracy, Luiten et al., IJCV 2022）把"检测"与"关联"解耦成两个可分别打分的乘法子项，正在成为新基准——概念上记住"MOTA 偏检测、IDF1 偏身份、HOTA 两者都管"即可。

## 4. 可运行实验：mini-MOT（exp5）

**场景**：10 秒 @10 Hz，3 个目标——T0 向右、T1 向下（与 T0 空间交叉）、T2 斜线穿过同一区域；每帧 90% 检出、位置噪声 0.5 m、平均 2 个均匀分布杂波。**跟踪器**：CV 模型 KF + 马氏门控（99%，9.21）+ `linear_sum_assignment` + 三态状态机（min_hits=3，max_age=10）。脚本约 170 行，核心部分节选如下（完整见 `实验脚本/exp5_mini_mot.py`）：

```python
# exp5_mini_mot.py —— KF + 匈牙利 + 轨迹状态机的 mini-MOT（节选核心）
# 用法：python3 exp5_mini_mot.py on|off   （on=年轻轨迹欧氏门控，默认）
class Track:
    _next = 1
    def __init__(self, z):
        self.id = Track._next; Track._next += 1
        self.x = np.array([z[0], z[1], 0.0, 0.0])       # [x, y, vx, vy]
        self.P = np.diag([SIG_Z**2, SIG_Z**2, 25.0, 25.0])
        self.hits, self.misses = 1, 0
        self.confirmed = False
    def predict(self):                                   # CV 预测（第 2 周）
        self.x = F @ self.x
        self.P = F @ self.P @ F.T + Q
    def update(self, z):                                 # KF 更新 + 计数
        y = z - H @ self.x
        S = H @ self.P @ H.T + R
        K = self.P @ H.T @ np.linalg.inv(S)
        self.x = self.x + K @ y
        self.P = (np.eye(4) - K @ H) @ self.P
        self.hits += 1; self.misses = 0
        if self.hits >= MIN_HITS: self.confirmed = True
    def mahalanobis2(self, z):                           # 门控距离（第 3 周）
        S = H @ self.P @ H.T + R
        d = z - H @ self.x
        return d @ np.linalg.inv(S) @ d

tracks, output = [], []                  # output: (frame, track_id, pos)
for k in range(N):
    for tr in tracks: tr.predict()
    # ---- 关联：马氏门控 + 匈牙利 ----
    cost = np.full((len(tracks), len(dets_by_frame[k])), 1e6)
    for i, tr in enumerate(tracks):
        for j, z in enumerate(dets_by_frame[k]):
            d2 = tr.mahalanobis2(z)
            if d2 <= GATE:
                if (USE_YOUNG_GATE and tr.hits < MIN_HITS
                        and np.linalg.norm(z - tr.x[:2]) > YOUNG_GATE_M):
                    continue   # 年轻轨迹只信 3m 内观测，防"速度乱飞、门控罩全场"
                cost[i, j] = d2
    ri, ci = linear_sum_assignment(cost)
    matched_t, matched_d = set(), set()
    for i, j in zip(ri, ci):
        if cost[i, j] < 1e6:
            tracks[i].update(dets_by_frame[k][j])
            matched_t.add(i); matched_d.add(j)
    # ---- 未匹配轨迹 miss 计数 / 未匹配检测建 tentative ----
    alive = []
    for i, tr in enumerate(tracks):
        if i not in matched_t: tr.misses += 1
        if tr.misses <= MAX_AGE: alive.append(tr)
    for j, z in enumerate(dets_by_frame[k]):
        if j not in matched_d: alive.append(Track(z))
    tracks = alive
    for tr in tracks:
        if tr.confirmed: output.append((k, tr.id, tr.x[:2].copy()))

# ---- 评估：逐帧把 confirmed 输出与真值做 2m 门限匹配，数 FN/FP/IDSW ----
MOTA = 1 - (FN + FP + IDSW) / total_gt
MOTP = np.mean(dists)    # 匹配对平均位置误差
```

评估部分的完整逻辑（脚本后半，节选）：

```python
# exp5_mini_mot.py 评估节选 —— MOTA/MOTP/IDSW 的逐帧统计
EVAL_GATE = 2.0
gt2track = {i: None for i in gt_state}    # GT 身份 -> 上一次匹配的 track id
FN = FP = IDSW = 0; dists = []
for k in range(N):
    hyp = [(tid, pos) for (f, tid, pos) in output if f == k]     # 本帧输出
    gts = [(i, gt_pos(k, i)) for i in gt_state]                  # 本帧真值
    cost = np.full((len(gts), len(hyp)), 1e6)
    for a, (gi, gp) in enumerate(gts):
        for b, (tid, hp) in enumerate(hyp):
            d = np.linalg.norm(gp - hp)
            if d <= EVAL_GATE: cost[a, b] = d                    # 2m 内才可配
    ri, ci = linear_sum_assignment(cost)
    matched_g, matched_h = set(), set()
    for a, b in zip(ri, ci):
        if cost[a, b] < 1e6:
            gi, tid = gts[a][0], hyp[b][0]
            dists.append(cost[a, b])                             # 供 MOTP
            matched_g.add(a); matched_h.add(b)
            if gt2track[gi] is not None and gt2track[gi] != tid:
                IDSW += 1                                        # 身份换手
            gt2track[gi] = tid
    FN += len(gts) - len(matched_g)      # 真值没被任何 confirmed 覆盖
    FP += len(hyp) - len(matched_h)      # confirmed 没对应任何真值
total_gt = N * len(gt_state)
```

注意评估口径的三个决定（对不上开源结果时先查这里）：输出**只计 confirmed**（tentative 不算 FP 也不算 FN）；真值-输出匹配用 2 m 门限的匈牙利（与 CLEAR MOT 的逐帧匹配同思路）；IDSW 按"同一真值身份先后绑定的轨迹 ID 变化"计。口径不同，同一份轨迹能差出十几个百分点——先对齐口径再谈调参。

## 5. SORT 与 DeepSORT：两句话与一条演进线

- **SORT**（Simple Online and Realtime Tracking；Bewley et al., arXiv:1602.00763）：本周 mini-MOT 的"官方同款"——强检测器 + KF（状态为框位置尺寸及速度）+ 匈牙利 IoU 匹配，2D MOT 上 260+ Hz，凭这套极简组合就逼近当年的复杂方法。它证明了：**tracking-by-detection 时代，检测质量比跟踪算法的精巧更值钱**。
- **DeepSORT**（Wojke et al., arXiv:1703.07402）：在 SORT 上加一条**外观关联**——用一个带 ReID（re-identification，重识别）损失的 CNN 从检测框里提出外观向量，级联匹配时"外观近 + 运动近"才算同一目标。专治几何关联治不了的病：遮挡后重现的目标 ID 不换、交叉行人的身份不错乱。

演进线到今天：SORT → DeepSORT（+外观）→ ByteTrack（ECCV 2022，低分检测框二轮关联，不用外观就上台阶）→ 跟踪与检测联合的端到端方案。但骨架全是本周这四步。

## 6. 轨迹输出怎么喂给下游

mini-MOT 的 `output` 列表（frame, track_id, pos）在真实系统里长成这样：

| 下游 | 拿什么 | 拿去干什么 |
| --- | --- | --- |
| **预测补帧** | confirmed 轨迹的 KF 状态 | 检测 10 Hz、规控 100 Hz：中间的帧由 KF 纯预测补齐，下游看到平滑连续的目标流（这就是第 1 周时延对齐的续集：输出也统一到下游时间戳） |
| **历史平滑** | 滑动窗口内的轨迹历史 | 反推目标意图（变道、刹车）、剔除检测毛刺；输出给 V2X 的轨迹要再做一段历史平滑，避免广播的位置跳变 |
| **V2X 广播** | TrackID + 状态 + 类别 | 车端拿 TrackID 对应自己看到的目标——**ID 漂移 = 车端全部对不上**（第 1 周难点五的闭环） |
| **路侧事件检测** | 轨迹级统计 | 逆行、违停、行人闯入都是"轨迹级"模式，不是单帧检测能判断的 |

**一条工程铁律**：对下游输出的轨迹，宁可滞后几帧输出"确认过的平滑状态"，不要输出"最新但抖动"的状态——下游（尤其规划）对位置突变的容忍度远低于对延迟的容忍度。这也是 confirmed 态才对外输出、tentative 不输出的原因。

## 7. 工程权衡与失效模式

1. **min_hits 太大**：轨迹出生延迟长，短命目标（窜出的行人）全程没有输出。**症状**：FN 集中在目标出生帧；**修复**：min_hits 降为 2，或对高置信检测（score > 0.9）出生即 confirmed。
2. **max_age 太大**：杂波轨迹在死亡前多活几十帧（FP 上升），两条并行旧轨迹在目标重现时抢 ID。**症状**：FP 与 IDSW 同时涨；**修复**：max_age 与场景遮挡时长匹配（路侧开阔场景 5 帧够，城区 10~30 帧）。
3. **共线目标误并**：前后同车道两车距离近、速度接近，检测合并/交替，轨迹"吞并"了另一个目标。**症状**：一条轨迹尺寸/速度中途跳变；**修复**：轨迹尺寸一致性校验 + 外观特征。
4. **评估口径不对齐**：自己算的 MOTA 与 `py-motmetrics` 对不上，通常是匹配阈值（IoU 0.5 或距离门限）、confirmed 才计入输出、distractor 处理三处口径差异。**修复**：对照 `py-motmetrics` 的 CLEAR MOT 实现逐项核对。

## 8. 延伸思考题（含解析）

**Q1**：为什么 MOTA 的分母是"真值总数"而不是"输出总数"？
**A**：MOTA 是"错误率"口径：三类错误都相对"世界上实际发生了多少"来计。若分母是输出数，多输出反而摊薄错误率，会鼓励 FP——与指标的设计意图相反。

**Q2**：一个跟踪器 MOTA 0.9、IDF1 0.6，说明什么？
**A**：检测与定位基本到位（每帧都报对了），但身份保持差——轨迹频繁断裂重生或交叉互换。优先查关联（门控/代价）与遮挡处理（max_age/外观），而不是检测。

**Q3**：本周实验里 IDSW = 0，什么条件下它会变成非零？
**A**：让两目标交叉时刻更贴近（预测点距离小于门控半径）或加大检测噪声，交叉瞬间马氏距离矩阵出现"互换更优"的格局，全局指派就会换手。可以亲手改 `gt_state` 验证——这也是面试题"什么参数会影响 ID switch"的实证答案。

**Q4**：tentative 期间 KF 也在预测和更新，这与 confirmed 后有什么不同待遇？
**A**：状态更新一样，但 (a) 不对外输出；(b) 门控更紧（本实验的 3 m 欧氏门控）；(c) 没有宽限红利——本教学版给 tentative 与 confirmed 相同的 max_age，但量产系统通常让 tentative 连丢 1~2 帧即删（confirmed 才享受 max_age 宽限），本实验里杂波 tentative 是被"再吸不到就死"的统计规律自然淘汰的。差别共同保证"杂波进不来、真目标不冤死"。

**Q5**：为什么预测补帧用 KF 预测而不是"上帧位置直接外发"？
**A**：直接外发是零阶保持（目标看着一顿一顿），且丢掉了速度信息；KF 预测带速度与加速度趋势，且协方差告知下游"这个预测有多可信"，下游可按不确定度调整代价地图膨胀。

**Q6**：为什么评估时"tentative 不算 FP"是合理口径？
**A**：tentative 未对外输出、下游根本看不到；把它算 FP 会惩罚"该有的确认机制"本身，导致调参方向错误（为了压 FP 把 min_hits 调大，反而伤短命目标）。口径必须与"下游真实收到什么"对齐——评估口径是系统接口的一部分。
