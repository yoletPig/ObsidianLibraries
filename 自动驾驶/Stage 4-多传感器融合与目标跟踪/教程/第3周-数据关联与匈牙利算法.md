## 1. 为什么需要数据关联：多出来的难题是什么

第 2 周的滤波器只面对一个问题：**观测已给定**，怎么把它的信息融进状态。多目标场景多出一个前置问题：这一帧检测器吐出 5 个框，画面里已有 4 条轨迹，**哪个框属于哪条轨迹**？这就是数据关联（data association）。

它难在组合爆炸与歧义：

- **组合爆炸**：$n$ 条轨迹对 $m$ 个检测，可能指派方案是 $n!$ 量级；真实路口几十条轨迹、上百个检测时不可能穷举。
- **交叉歧义**：两个行人交叉走过，预测位置短暂贴近甚至重叠。此时若用"就近配"，很可能把两条轨迹**互换身份**——A 的轨迹从此跟着 B 走。这就是 ID switch（身份切换）的最大来源。
- **杂波与漏检**：检测器还可能多报（杂波，clutter）或少报（漏检，miss）。关联算法必须同时回答"这是新目标吗""这条轨迹断了吗"。

关联错误的代价是**灾难性且不可逆的**：滤波器再好，喂错了观测也只会把错误精致地平滑掉。所以工程上数据关联的优先级高于滤波精度——先配对，再谈准。

## 2. 匹配度量之一：IoU 匹配

对 2D 检测框（SORT 的做法），最直观的代价是**交并比（IoU, intersection over union）**：

$$
IoU(A, B) = \frac{|A \cap B|}{|A \cup B|}, \qquad c = 1 - IoU
$$

**这个公式在干什么**：两个框的交集面积除以并集面积（1=完全重合，0=不相交），取 $1-IoU$ 变成"越小越好"的代价。逐符号拆解：

| 符号 | 物理含义 | 大白话 |
| --- | --- | --- |
| $A$ | 轨迹预测出的检测框（KF 把上一帧框推到本帧） | "我猜它这个框在这" |
| $B$ | 检测器本帧输出的框 | "检测器说它在这" |
| $\|A \cap B\|$ | 交集面积 | 重叠了多少 |
| $\|A \cup B\|$ | 并集面积 | 合起来占多大 |

**IoU 匹配的优点**：不依赖任何噪声统计、对框大小自适应（大框允许大位移），SORT 用它做到 260+ Hz。**缺点**：目标重叠（遮挡）时 IoU 全线下降、互相混淆；不适用于点目标（雷达航迹）或 3D 中心距场景。它回答的是"框重叠不重叠"，不回答"在预测不确定度意义上合不合理"——这就要请出马氏距离。

## 3. 匹配度量之二：马氏距离门控

### 3.1 公式

第 2 周已算出预测的残差协方差 $S = H P^- H^\top + R$（"预测与测量差多少算正常"）。把残差 $\mathbf{y} = \mathbf{z} - H\hat{\mathbf{x}}^-$ 代入**马氏距离（Mahalanobis distance）**：

$$
d_M^2 = \mathbf{y}^\top S^{-1} \mathbf{y}
$$

**这个公式在干什么**：把普通距离除以"正常波动范围"，得到一个无量纲的"这个偏差有多反常"分数。逐符号拆解：

| 符号 | 物理含义 | 大白话 |
| --- | --- | --- |
| $\mathbf{y}$ | 残差向量 | 预测与测量的分歧 |
| $S$ | 残差协方差 | 分歧的"正常尺度"，且含各方向的相关性 |
| $S^{-1}$ | 按正常尺度归一 | 越不确定的方向，同样的偏差越"不算事" |
| $d_M^2$ | 归一化偏差平方 | 无量纲"反常度"分数 |

**和欧氏距离的关键区别**：欧氏距离把所有方向一视同仁；马氏距离知道"沿路方向预测误差大（速度不确定）、横向误差小"这类各向异性——一个 8 m 的纵向偏差可能正常，一个 3 m 的横向偏差就异常。第 2 周的协方差椭圆在这里直接兑现价值：**椭圆就是马氏距离的等值线**。

### 3.3 手算一个 2D IoU（30 秒建立量感）

轨迹预测框 $A$：4 m × 2 m（轿车），中心 (10, 0)；检测框 $B$：4 m × 2 m，中心 (11.5, 0)。沿 x 方向重叠 $10 + 2 - 11.5 = 0.5$ m，y 方向完全重叠 2 m：

$$
IoU = \frac{0.5 \times 2}{4 \times 2 + 4 \times 2 - 0.5 \times 2} = \frac{1.0}{15.0} \approx 0.067
$$

中心只偏了 1.5 m（不足半个车位），IoU 已掉到 0.07——**IoU 对平移的敏感度是米级 × 米级平方的**，这就是第 1 周难点四"中心 0.5 m + 朝向 5° 让 3D IoU 崩掉"的量感来源，也是高速目标（帧间位移 1 m 量级）必须"先预测后匹配"的原因：拿上一帧的框直接算 IoU，几乎全部为零。

### 3.2 为什么必须门控（gating）

**门控 = 事先给 $d_M^2$ 设上限，超限的配对直接禁止参与指派。** 两个理由：

1. **防污染**：一个 50 m 外的杂波若不被门控拦住，会以"最反常但唯一"的姿态参与指派，甚至被强行配给某条轨迹，把它的速度状态带崩。门控是杂波的第一道闸门。
2. **降复杂度与防错配**：匈牙利算法对全矩阵运作 $O(n^3)$；门控把绝大多数格子置为不可用后，可行指派空间骤减，也避免"全局最优解里出现荒谬配对"。

**阈值从哪来**：高斯假设下 $d_M^2$ 服从自由度为观测维数的卡方分布（chi-square, $\chi^2$）。设置信水平（如 99%），超限概率 1%，查表得阈值：

| 自由度（观测维数） | 95% 阈值 | 99% 阈值 |
| --- | --- | --- |
| 2 | 5.991 | 9.210 |
| 3 | 7.815 | 11.345 |
| 4 | 9.488 | 13.277 |

2D 位置观测（自由度 2）常用 9.21（99%）：允许 1% 的真观测被误拒，换取 99% 的杂波被拒。**阈值调紧**→漏配增多、轨迹易断；**调松**→杂波混入。第 6 节思考题会让你亲手试出这种权衡。

## 4. 匈牙利算法：全局最优指派

### 4.1 问题定义

$n$ 条轨迹、$m$ 个检测，代价矩阵 $C$（$C_{ij}$ = 轨迹 $i$ 配检测 $j$ 的代价，可以是 $1-IoU$、$d_M^2$ 或两者组合）。**指派问题（assignment problem）**：每行最多配一列、每列最多配一行，使总代价最小。

**贪心（就近配）**：每次挑当前全局最小代价的格子，划掉该行该列，重复。它快（$O(nm\log)$），但**局部最优不等于全局最优**——先抢了小代价格子可能逼得剩下的行去配代价巨大的格子。

**匈牙利算法（Hungarian algorithm）**：Kuhn 1955 年提出（方法基于匈牙利数学家 König 与 Egerváry 的工作，故名），保证**多项式时间 $O(n^3)$ 内给出全局最优解**。思想一句话：反复"增广"——若当前指派不是最优，沿代价结构找到一条可交换的交替路径，把一个已配对改成另一组配对，总代价严格不增；直到无法再改进，即为全局最优。你不需要会证明，只需要**永远用 `scipy.optimize.linear_sum_assignment`**（Munkres 1957 算法的实现），并知道它返回的指派总代价**不劣于任何贪心方案**。

**2×2 手算走一遍算法要解决的问题**：代价矩阵 $\begin{bmatrix} 1 & 2 \\ 2 & 4 \end{bmatrix}$。贪心拿最小格 (0,0)=1，剩下 (1,1)=4，总代价 5；而 (0,1)+(1,0)=2+2=4。差就出在"行差"上——第 0 行换成 (0,1) 多花 1，第 1 行换成 (1,0) 省下 2，净赚 1。匈牙利算法的所有复杂机制（行列约减、增广路径）本质上就是在系统化地寻找这种"换手净赚"的机会，直到无利可图。

### 4.2 可运行实验（exp4）

一个 3×3 交叉场景：3 条轨迹的预测位置、3 个检测，代价=欧氏距离；然后是经典的贪心反例；最后是门控+匈牙利完整流程（含一个 90 m 外的杂波）。

```python
# exp4_hungarian.py —— 匈牙利算法 vs 贪心、马氏距离门控（固定种子）
import numpy as np
from scipy.optimize import linear_sum_assignment

np.random.seed(3)

# ---------- 实验1：3x3 交叉场景的全局最优指派 ----------
tracks = np.array([[50.0, 100.0],      # track A 预测在 (50,100)
                   [60.0, 102.0],      # track B
                   [52.0, 105.0]])     # track C
dets = np.array([[51.5, 101.0],        # det 0
                 [61.0, 103.0],        # det 1
                 [49.0, 99.0]])        # det 2
cost = np.linalg.norm(tracks[:, None, :] - dets[None, :, :], axis=2)

print("==== 代价矩阵（行=轨迹，列=检测，单位 m）====")
print(np.array2string(cost, precision=2, suppress_small=True))
r, c = linear_sum_assignment(cost)
total = cost[r, c].sum()
print("\n匈牙利算法全局最优指派：")
for i, j in zip(r, c):
    print(f"  track {i}  <->  det {j}   (代价 {cost[i, j]:.2f} m)")
print(f"总代价 = {total:.2f} m")

# ---------- 实验2：贪心反例（经典代价矩阵）----------
print("\n==== 贪心 vs 全局最优 反例 ====")
cost2 = np.array([[1.0, 2.0, 5.0],
                  [2.0, 4.0, 5.0],
                  [5.0, 5.0, 5.0]])
greedy = []
rows, cols = set(), set()
c2 = cost2.copy()
while len(greedy) < 3:
    i, j = np.unravel_index(np.argmin(c2), c2.shape)
    greedy.append((int(i), int(j), c2[i, j]))
    rows.add(i); cols.add(j)
    c2[sorted(rows), :] = np.inf
    c2[:, sorted(cols)] = np.inf
gt = sum(v for _, _, v in greedy)
r2, cidx = linear_sum_assignment(cost2)
opt = cost2[r2, cidx].sum()
print(f"贪心指派 {[(i, j) for i, j, _ in greedy]}  总代价 = {gt:.0f}")
print(f"匈牙利指派 {list(zip(r2, cidx))}  总代价 = {opt:.0f}")
print(f"贪心比最优差 {gt - opt:.0f}")

# ---------- 实验3：马氏距离门控 ----------
P = np.diag([4.0, 1.0])               # x 方向 2σ=4m，y 方向 2σ=1m（沿路方向不确定度大）
x_pred = np.array([50.0, 100.0])
S_inv = np.linalg.inv(P)
dets3 = np.array([[52.0, 100.5], [58.0, 101.0], [51.0, 110.0]])
GATE = 5.991
for d in dets3:
    diff = d - x_pred
    d2 = diff @ S_inv @ diff
    eu = np.linalg.norm(diff)
    verdict = "通过" if d2 <= GATE else "拒绝"
    print(f"det {d}: 欧氏距离 = {eu:5.2f} m, 马氏距离^2 = {d2:7.2f} -> {verdict}")

# ---------- 实验4：门控 + 匈牙利完整关联 ----------
tracks4 = np.array([[50.0, 100.0], [60.0, 102.0]])
P4 = [np.diag([4.0, 1.0]), np.diag([4.0, 1.0])]
dets4 = np.array([[51.5, 101.0], [61.0, 103.0], [90.0, 90.0]])   # 第3个是远处杂波
BIG = 1e6
cost4 = np.zeros((2, 3))
for i in range(2):
    Si = np.linalg.inv(P4[i])
    for j in range(3):
        diff = dets4[j] - tracks4[i]
        d2 = diff @ Si @ diff
        cost4[i, j] = d2 if d2 <= GATE else BIG        # 超门控 -> 代价置无穷
r4, c4_ = linear_sum_assignment(cost4)
matched_cols = set(c4_[cost4[r4, c4_] < BIG])
for i, j in zip(r4, c4_):
    if cost4[i, j] < BIG:
        print(f"track {i} <-> det {j}  (马氏^2 = {cost4[i, j]:.2f})")
    else:
        print(f"track {i}: 无通过门控的检测 -> 本帧未匹配（进入 miss 计数）")
for j in range(3):
    if j not in matched_cols:
        print(f"det {j}: 未被任何轨迹认领 -> 候选杂波或新目标")
```

**预期输出**（固定种子实测）：

```
==== 代价矩阵（行=轨迹，列=检测，单位 m）====
[[ 1.8  11.4   1.41]
 [ 8.56  1.41 11.4 ]
 [ 4.03  9.22  6.71]]

匈牙利算法全局最优指派：
  track 0  <->  det 2   (代价 1.41 m)
  track 1  <->  det 1   (代价 1.41 m)
  track 2  <->  det 0   (代价 4.03 m)
总代价 = 6.86 m
```

注意这个解的性质：track 0 拿到它本行的最小代价 det 2（1.41 m）、track 1 拿到 det 1（1.41 m）、track 2 拿到 det 0（4.03 m）——每一行恰好都拿到自己的行最小值，且列不冲突，总代价 6.86 m。可以逐一手算验证：3×3 指派总共只有 $3! = 6$ 种方案，6.86 m 确实最小。这个例子无冲突，说明匈牙利算法"至少不比肉眼差"；**真正考验它的是行最小值互相冲突的场景**——比如两条轨迹都想认领同一个检测。这正是下一个反例要展示的。

**贪心反例**：

```
==== 贪心 vs 全局最优 反例 ====
贪心指派 [(0, 0), (1, 1), (2, 2)]  总代价 = 10
匈牙利指派 [(0, 1), (1, 0), (2, 2)]  总代价 = 9
贪心比最优差 1
```

贪心每步都拿"当前最小"（1 → 4 → 5），却被 (0,0) 这格小代价绑架；全局最优让 track 0、1 **交叉互换**，总和反而更小。把这个 3×3 的小矩阵记在脑子里——面试被问"为什么不用贪心"时，画出来 30 秒讲清。真实路口几十条轨迹时，贪心的错误会成串出现（一条错配引发连锁）。

**马氏门控**（注意各向异性）：

```
det [ 52.  100.5]: 欧氏距离 =  2.06 m, 马氏距离^2 =    1.25 -> 通过
det [ 58. 101.]: 欧氏距离 =  8.06 m, 马氏距离^2 =   17.00 -> 拒绝
det [ 51. 110.]: 欧氏距离 = 10.05 m, 马氏距离^2 =  100.25 -> 拒绝
```

第三个检测横向偏 10 m 被坚决拒绝（$d_M^2=100$）——因为 y 方向的 $S$ 只有 1 m²，横向偏差"极不正常"；若是纯欧氏距离，10 m 和第一个 2 m 只是差 5 倍，没有"正常/反常"的概念。

**门控 + 匈牙利完整流程**：

```
track 0 <-> det 0  (马氏^2 = 1.56)
track 1 <-> det 1  (马氏^2 = 1.25)
det 2: 未被任何轨迹认领 -> 候选杂波或新目标
```

90 m 外的杂波在指派前就被门控拦掉（代价置 1e6），两条轨迹各自配到合理检测，杂波悬空——交给第 4 周的"新生/杂波裁决"处理。

## 5. 贪心 vs 全局最优速查

| 维度 | 贪心（最近邻逐个配） | 匈牙利（全局最优） |
| --- | --- | --- |
| 复杂度 | $O(nm)$ ~ $O(nm\log n)$ | $O(n^3)$ |
| 结果 | 局部最优，可被小代价格子绑架 | 全局最优 |
| 交叉场景 | 易连锁错配 → ID switch | 稳定 |
| 何时可用 | 目标稀疏、几乎无交叉、算力极限（如嵌入式逐帧降级模式） | 默认选择 |
| 反例 | 3×3 矩阵总代价 10 vs 9 | — |

## 6. 关联失败怎么办：新生与消亡

指派结束后，总有一批行和列没配上。它们是跟踪器"生死逻辑"的输入：

- **未匹配检测（unmatched detection）**：可能是杂波，也可能是新进入视野的目标。**不能立刻建轨迹**——真实检测器每帧都会吐几十个误检，直接建轨迹会让轨迹池爆炸。标准做法：先建 **tentative（候选）轨迹**，连续/累计命中若干帧（min_hits，典型 3）才转正——杂波是随机的，连续 3 帧出现在可预测位置上的概率极低。这就是第 4 周状态机的主题。
- **未匹配轨迹（unmatched track）**：可能是目标被遮挡/漏检，也可能真的驶出视野。**不能立刻删除**——删了，遮挡结束的目标会以新 ID 重生（ID switch）。标准做法：容忍若干帧漏检（max_age，典型 5~10 帧），期间靠 KF 纯预测"惯性滑行"，门控放宽一点等它回来；超过 max_age 才删除。
- **双向失败的极端情况**：目标急转弯导致预测完全偏离，所有检测都被门控拒绝。此时轨迹会滑行到 max_age 死亡，目标以新 ID 重生。这是几何关联的固有局限——外观特征（ReID，第 4 周）就是为它准备的补丁。

> **动手验证**：把 exp4 实验 3 的门控阈值从 5.991 收紧到 3.0，第一个合理检测（$d_M^2=1.25$）仍通过；再把 $P$ 的 y 方向方差从 1 改成 0.04（自信过头），合理检测（横向偏 0.5 m）的 $d_M^2 = 2^2/4 + 0.5^2/0.04 = 7.25$，超过 5.991 被拒——亲眼看到"协方差太自信会把好观测拒之门外"。门控是概率承诺，不是物理墙。

## 7. 工程权衡与失效模式

1. **代价矩阵量纲混搭**：把马氏距离²（量级 0~10）与 $1-IoU$（0~1）直接相加，前者淹没后者。**症状**：某类代价完全不起作用；**修复**：分别归一化再加权，或两阶段匹配（先 IoU 后马氏，SORT/DeepSORT 的做法）。
2. **门控过紧**：Q 调小后椭圆变小，正常机动目标被拒。**症状**：高速/机动目标 ID 频繁重生；**修复**：门控阈值随目标速度/状态维数查表，或对 $\chi^2$ 阈值做在线一致性监控。
3. **轨迹池不清理**：tentative 轨迹只进不出，匈牙利矩阵越来越大。**症状**：帧耗时随时间上涨；**修复**：max_age + tentative 超时即删（第 4 周实现）。
4. **全矩阵指派的遮挡崩塌**：多目标深度遮挡时一坨检测对应一坨预测，IoU 全体下降，最优指派也开始互换。**修复**：外观特征、运动方向约束，或分块关联。

## 8. 延伸思考题（含解析）

**Q1**：为什么 $d_M^2$（而不是 $d_M$）直接和 $\chi^2$ 分位数比较？
**A**：高斯残差 $\mathbf{y} \sim \mathcal{N}(0, S)$ 时，二次型 $\mathbf{y}^\top S^{-1}\mathbf{y}$ 严格服从 $\chi^2_k$ 分布（$k$ = 观测维数），平方量直接查表。用 $d_M$ 还得开方变换分布，多此一举。

**Q2**：IoU 匹配和马氏门控各自的失效场景？
**A**：IoU 挂在遮挡（框重叠互相混淆）与点目标（无框可言）；马氏挂在 Q/R 统计失真（协方差不反映真实误差，门控形同虚设）。量产常用级联：先 IoU 粗配（便宜、尺度自适应），再马氏细配。

**Q3**：检测数比轨迹数多很多时，匈牙利算法会怎么处理多出来的列？
**A**：`linear_sum_assignment` 对非方阵自动处理（配 min(n,m) 对）。多余的检测天然"未匹配"，进入新生裁决。工程上也可以把代价矩阵补成方阵并填大数，效果等价。

**Q4**：为什么说"关联错了，滤波器救不回来"？
**A**：KF 假设观测来自同一目标。把 B 车的观测喂给 A 车的滤波器，残差被按"正常波动"吸收，A 的速度状态被拉向 B 的运动——错误被平滑地合法化，且 ID 已换，历史不可追溯。这是关联优先级高于滤波的根本原因。

**Q5**：什么场景下匈牙利算法的全局最优反而有害？
**A**：当"没有合理指派"时它仍会强行配出 min(n,m) 对（总代价再大也配）。所以**门控必须先行**——先剪掉荒谬格子，匈牙利只在"合理格子"里做全局权衡。这正是本实验流程"门控→指派→裁决"顺序的原因。

**Q6**：代价矩阵里 IoU（0~1）和马氏距离²（0~几十）怎么组合到一起？
**A**：不能直接相加。常规做法有三种：(1) 归一化后加权：$c = \alpha(1-IoU) + (1-\alpha)\, d_M^2/d_{gate}^2$；(2) 级联匹配：先 IoU 粗配，配不上的再用马氏细配（SORT/DeepSORT 的模式）；(3) 门控为"与"、代价取其一：两道门都过，代价用马氏。任何组合都要先各自归一，否则量级大的那个会独自决定指派。
