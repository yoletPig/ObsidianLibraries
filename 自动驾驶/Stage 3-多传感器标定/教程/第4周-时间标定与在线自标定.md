## 1. 时间偏移：最容易被低估的误差源

### 1.1 先算账

车辆 120 km/h 行驶：

$$
v = \frac{120\ \text{km/h}}{3.6} = 33.3\ \text{m/s}
$$

两个传感器时间戳差 $\Delta t$，同一物理目标在两帧数据中的纵向位置差：

$$
\Delta s = v \cdot \Delta t
$$

| $\Delta t$ | $\Delta s$ @ 33.3 m/s | 直观后果 |
| --- | --- | --- |
| 1 ms | 3.3 cm | 无害 |
| 5 ms | 16.7 cm | 接近车道线宽度的一半 |
| **10 ms** | **33.3 cm** | **半个车身宽度的错位；目标级关联开始出错** |
| 20 ms | 66.7 cm | 相机看到的目标与 LiDAR 团簇对不上号 |
| 33 ms | 1.10 m | 一整帧@30fps 的错位 |

真实运行输出（实验脚本末尾打印）：

```
120 km/h (33.3 m/s) 下时间偏移的空间代价：
   1 ms  ->   0.03 m
   5 ms  ->   0.17 m
  10 ms  ->   0.33 m
  20 ms  ->   0.67 m
  33 ms  ->   1.10 m
  50 ms  ->   1.67 m
```

对比：第 2、3 周辛苦把外参标到 0.1°（100 m 外 17 cm），一个 10 ms 的时间戳偏差在同样距离上贡献 3.3 m 的**纵向**错位——高一个数量级。时间标定不做好，空间标定白做。

### 1.2 时间偏移从哪来

1. **时钟不同源**：各传感器有自己的晶振，漂移率典型 20~100 ppm（每天差 2~10 秒的百万分之几，但 accumulating）；没有统一授时（GPS PPS/PTP）时偏差可以到毫秒级；
2. **时间戳打在哪里**："曝光中心时刻"与"时间戳生成时刻"之间隔着曝光积分（rolling shutter 相机逐行曝光可达数 ms）、ISP 流水线、驱动处理、驱动序列化——每段都贡献延迟，且这些延迟**固定部分是常偏，可标定**；
3. **传输延迟**：CAN/以太网队列、USB 缓冲，抖动部分（jitter）不可标定，只能靠硬件触发或打双时间戳统计。

工程结论：**硬件同步（同一时钟源 + 硬触发）是第一选择**；做不到的部分留给软件时间标定去估计**常偏**（本节主角）。

### 1.3 一个相机帧的时间戳流水线剖析

以 rolling shutter 相机为例，从"光子到达"到"时间戳落盘"的延迟链：

| 环节 | 典型量级 | 性质 |
| --- | --- | --- |
| 曝光积分（rolling shutter 逐行） | 5~15 ms（整幅） | 固定 + 与内容相关的行间延迟 |
| 曝光中心 → 帧读出完成 | 1~5 ms | 固定（可标定进常偏） |
| ISP 流水线（去马赛克/降噪/压缩） | 5~30 ms | 固定 |
| 驱动收包、打时间戳 | 0.1~2 ms | 固定 + 少量抖动 |
| 队列/序列化/网络传输 | 0.1~10 ms | 抖动为主，不可标定只能统计 |

前四段的固定部分加起来就是标定要估计的**常偏**；最后一段的抖动决定时间戳的**不确定度下界**。所以时间标定的完整输出是两个数：常偏 $\Delta t$ 和它的置信区间——只报一个均值不报区间的标定是不完整的。

## 2. 时间标定方法

### 2.1 软同步对齐：先让时钟同源

- **NTP**（毫秒级）、**PTP/IEEE 1588**（亚毫秒级）：以太网域内所有设备对齐到同一时钟。车载以太网 + PTP 是当前主流方案；
- **GPS PPS**（秒脉冲）：户外直接用卫星秒脉冲做硬件级对齐，配合 PTP 授时室内外无缝；
- 硬件触发：同一个触发信号同时启动相机曝光与 LiDAR 旋转，从根上消除触发偏差。

软同步做完，剩下的常偏通常在个位数毫秒——数据驱动标定的活。

### 2.2 数据驱动：互相关对齐（最小可工作实现）

**思想**：两个传感器观测同一个随时间变化的物理量（例如：IMU 的 yaw 角速度 vs 相机序列特征推算的 yaw 角速度）。若相机时钟比 IMU 慢 $\Delta t$，把相机信号在时间轴上平移 $\Delta t$ 后两条曲线重合度最高。于是——**网格搜索候选偏移，选残差最小的**：

$$
\hat{\Delta t} = \arg\min_{\Delta t} \sum_{t} \big(w_{imu}(t) - \hat{w}_{cam}(t + \Delta t)\big)^2
$$

**这个公式在干什么**：对每个候选 $\Delta t$，把相机信号插值到 IMU 时间轴上，算残差平方和；最优偏移让两条曲线最贴合。这就是一维互相关的连续版（插值代替离散平移）。

```python
# exp7_timeoffset.py —— IMU 100Hz + 相机派生信号 20Hz，真偏移 37 ms
import numpy as np
rng = np.random.default_rng(6)

def yaw_rate(t):   # 模拟转弯过程的真实角速度（几个正弦叠加）
    return 0.08*np.sin(2*np.pi*0.5*t) + 0.05*np.sin(2*np.pi*0.23*t + 1.0) \
           + 0.02*np.sin(2*np.pi*1.1*t + 2.0)

T_END = 20.0
t_imu = np.arange(0, T_END, 0.01)
w_imu = yaw_rate(t_imu) + rng.normal(0, 0.002, len(t_imu))
DT_TRUE = 0.037
t_cam = np.arange(0, T_END, 0.05)
w_cam = yaw_rate(t_cam + DT_TRUE) + rng.normal(0, 0.006, len(t_cam))
# 含义：t_cam 标签下的 w_cam 实际是 (t_cam + DT_TRUE) 时刻的物理量

grid = np.arange(-0.10, 0.1001, 0.001)                # 候选偏移，1 ms 步进
rmse = np.array([np.sqrt(np.mean((np.interp(t_imu, t_cam + dt, w_cam) - w_imu) ** 2))
                 for dt in grid])
i = int(np.argmin(rmse))
dt_est, rmse_best = grid[i], rmse[i]
```

真实输出：

```
真实时间偏移  : 37 ms
估计时间偏移  : 37.0 ms  (对齐后 RMSE = 0.00523 rad/s)
120 km/h 下 37 ms 错位 = 1.23 m 的空间错位
残余错位 0.0 ms = 0.0 cm

不校时间 RMSE = 0.00949 rad/s, 校准后 = 0.00523 rad/s (降到 55%)
```

**读数**：20 Hz 的低频信号、6e-3 的噪声，1 ms 网格搜索把 37 ms 偏移恢复到 1 ms 以内（网格分辨率内）。精度上限由三样东西决定：**信号带宽**（恒速直线上偏移不可观测——没有变化就没有相位可对）、**采样率**、**噪声**。想更准：加密搜索网格 + 抛物线插值细化峰值，或用运动物理量（角速度、加加速度）而非位置。

> **动手验证**：把 `DT_TRUE` 改成 0、`yaw_rate` 改成常数——你会发现估计退化（RMSE 对 dt 平坦）。**可观测性永远来自变化**，这是所有数据驱动标定的元规则。

### 2.2.1 精化：抛物线插值细化谷底，以及它的诚实局限

网格搜索的分辨率就是搜索步长（1 ms）。想更快，在 RMSE 曲线谷底取相邻三点 $(y_0, y_1, y_2)$ 拟合抛物线、解析求谷底偏移 $\delta = \frac{1}{2}\frac{y_0 - y_2}{y_0 - 2y_1 + y_2}$。完整脚本的后续输出：

```
抛物线细化: dt = 36.59 ms (真值 37.00 ms, 残差 0.41 ms)
5 个噪声种子的细化估计 (ms): [35.91 35.12 36.35 37.01 36.5 ]
均值 36.18 ms, 标准差 0.64 ms
```

**诚实读数**：抛物线细化并没有"必然更准"——本例主种子上反而引入 0.41 ms 残差，5 个噪声种子的均值为 36.18 ms（系统偏差 -0.8 ms）、标准差 0.64 ms。原因：插值方法假设谷底附近对称，而噪声让 RMSE 曲线不对称。教训有三条：(1) 亚毫秒精度要靠**更多数据/更高信噪比**，不能只靠数值技巧；(2) 时间标定必须报**多数据段的均值与方差**（本实验的 5 种子统计就是最小版）；(3) 存在约 1 ms 量级的系统偏差时，120 km/h 下相当于 3.3 cm——通常可接受，但必须在验收报告里写明。

### 2.3 连续时间批量优化：学术界的标准答案

互相关法一次只能对一对传感器、一个物理量。完整方案是**连续时间轨迹批量优化**：

- 把自运动轨迹表示成**连续时间函数**（B 样条或高斯过程），而不是离散位姿序列；
- 每个传感器的每次观测，按"名义时间 + 待估时间偏移"到连续轨迹上**取值**，构造重投影/运动残差；
- 空间外参与时间偏移在**一个大目标函数**里联合优化。

奠基工作：Furgale, Rehder, Siegwart, *Unified Temporal and Spatial Calibration for Multi-Sensor Systems*, IROS 2013（B 样条 + 批量最大似然，空间与时间统一估计）。实现：ETH 的 **Kalibr** 工具箱（`ethz-asl/kalibr`），camera-IMU 时空联合标定的事实标准。后续扩展：Peršić et al.（arXiv:1904.04187，T-RO 2020）用高斯过程替代 B 样条做雷达/相机/LiDAR 的时空标定。

**B 样条直觉一句话**：用一串带时间节点的控制点定义一条光滑曲线，任意时刻的位姿 = 相邻几个控制点的加权组合——于是"某时刻 + Δt 的位姿"就是对同一批控制点换一组权重，对 Δt 的导数有解析式。这就是它对时间偏移友好的原因：Δt 进入残差是**光滑可导**的，LM 优化器可以直接联合调"控制点 + 外参 + Δt"。离散位姿序列做不到这一点（Δt 一变，最近邻位姿就跳变，残差不连续）。

一句话理解它与互相关法的关系：互相关是"两路信号对齐"，连续时间批量优化是"所有传感器的所有观测都对齐到同一条连续轨迹"，因此能利用全部信息、处理任意采样率组合、并给出不确定度。工程上：标定间用 Kalibr 系工具做一次性精细标定，路测数据用互相关/滑窗简化版做在线监测。

## 3. 在线自标定：外参会漂移

### 3.1 为什么要在线

标定间里 0.1° 的外参，装车后面对的现实：

1. **振动**：几万公里路面激励，支架预紧力松弛、螺栓微动磨损——外参缓慢漂移；
2. **碰撞与剐蹭**：哪怕只碰了传感器支架，外参直接跳变（可能毫米级位移 + 十分之一角度级旋转，肉眼不可见但融合可感）；
3. **温度形变**：金属支架热胀冷缩，白天暴晒 vs 冬夜，机身形变可到零点几毫米——对长焦相机等效于主点/外参漂移；
4. **维修保养**：拆装过保险杠/挡风玻璃/传感器支架 = 外参作废，但维修工单和标定状态经常不同步。

### 3.2 在线自标定的两层含义

**健康监测（必做）**：不主动改参数，只持续计算弱约束指标并监控趋势——

- 结构化场景的**地面一致性**：LiDAR 地面点拟合出的地面平面，投到图像后应与图像语义分割/边缘的地面区域重合；偏差趋势 = 外参/内参漂移趋势；
- 多传感器**静止段互检**：停车时各传感器对同一静态目标的观测量做一致性检验；
- 时间偏移在线估计：运行数据持续跑 2.2 节的互相关（滑窗），输出偏移随时间曲线。

地面一致性监测的最小实现（伪代码，指标可直接进看板）：

```python
# 每个滑窗（如 10 s）执行一次，输出一个标量指标 + 趋势斜率
pts_ground = lidar_ground_segment(window)          # 地面点分割（高度+法向过滤）
n_l, d_l = fit_plane(pts_ground)                  # LiDAR 侧地面平面（ego 系）
d_img = image_ground_boundary(window)             # 图像侧：分割/边缘给出的地平线行号
n_cam = T_cam_ego[:3, :3] @ n_l                   # 外参把法向转到相机系
d_pred = d_l - T_cam_ego[:3, 3] @ n_cam           # 平面在相机系的偏距
rows = project_ground_plane_rows(K, n_cam, d_pred) # 预测的地面区域行号
score = mean(|rows - d_img|)                      # 像素级偏差 = 漂移指标
```

指标设计要点：(1) `score` 对不同外参分量的灵敏度不同（pitch/yaw 旋转在远地面处放大，z 平移在近处放大），看板应分距离段统计；(2) 只看**趋势**（周环比斜率）而非绝对值——图像地面边界本身受相机俯仰姿态影响，绝对值有车辆载荷/姿态干扰；(3) 阈值 = 功能验收容差折算到像素，而不是拍脑袋。

**在线重标（谨慎）**：用无目标方法（第 2 周 3.2 节：边缘对齐/强度投影/MI）在行驶数据上滑窗估计外参修正量。关键工程约束：**修正量必须设阈值与置信度门限**——无目标估计在低纹理场景会跑飞，宁可报警进标定间，不可让一个坏估计污染融合。业界常见做法是"在线只监测，超阈值触发进标定间/触发安全降级"。

### 3.3 标定质量管理（工程视角）

一个量产团队的最小标定质量体系：

**（一）产线/标定间精度验收流程**

1. 静态靶标复检：标定完成后，用**独立**的靶标位姿（不是标定用的那些）复测重投影/点面残差，通过与标定内残差的差值暴露过拟合；
2. 多距离段验证：近（3 m）、中（30 m）、远（100 m+）各设检查项——旋转误差只在远距离暴露，平移误差在近距离暴露（第 2 周实验的结论直接搬过来用）；
3. 物理常识自检：地面投影在下半画面、天空无点云、左右不镜像。

**（二）重投影误差看板**

每台车每次标定记录：内参 K、畸变、外参、时间偏移、各自的验证残差与不确定度，进数据库、画趋势图。看板回答三个问题：这台车历史上标了几次？指标在退化吗？同车型分布里它是离群点吗？

**（三）定期标定与事件触发**

- 周期性：按里程/时间重进标定间（频率凭实车漂移数据定，无硬性标准）；
- 事件触发：碰撞维修、传感器更换、在线监测超阈值——立即重标；
- 版本管理：外参与标定数据集、软件版本绑定；外参文件没有版本号等于没有外参。

## 4. 误差预算：从功能容差倒推标定需求

在清单之前，先给一个经常被跳过、但决定标定方案设计的步骤：**误差预算（error budget）分配**。做法是从下游功能的容差倒推每个误差源允许的上限——有了这张表，才能回答"外参标到多准才够、时间同步做到什么级别才够"。

**示例：高速 NOA 场景，要求 100 m 外目标横向/纵向关联错位 < 0.5 m（总预算）**

| 误差源 | 100 m 处影响 | 预算分配 | 对标定/同步的要求 |
| --- | --- | --- | --- |
| 外参旋转误差（按需方） | $d\cdot\delta\theta$ | 0.20 m | $\delta\theta < 0.11°$（靶标法可达） |
| LiDAR 测距系统差 | 直接计入深度 | 0.05 m | 出厂标定 + 温度补偿 |
| 时间偏移（常偏）@ 33.3 m/s | $v\Delta t$ | 0.15 m | $\Delta t < 4.5$ ms（PTP + 互相关标定可达） |
| 时间戳抖动 | $v\sigma_t$ | 0.10 m | $\sigma_t < 3$ ms（硬触发/双时间戳） |
| 车辆动力学补偿残差（位姿外推） | 与融合频率相关 | 按余量 | 不归标定管，但要在预算表里占位 |

**读法**：预算分配是"标定需求 ↔ 功能需求"的翻译器。反向使用它还能做验收裁决——当在线监测发现时间偏移涨到 8 ms，查表可知预算超支 0.11 m，触发重标是**有依据的工程决策**，而不是拍脑袋。

## 5. Cheesy Summary：标定-验证-上线清单

可以直接抄进工程文档的 checklist（按执行顺序）：

**标定前**

- [ ] 传感器热机 ≥ 15 min（晶振/机械稳定）
- [ ] 确认内参已标且在有效期；确认标定板平面度证书
- [ ] 确认时间同步链路（PTP 主钟在线 / PPS 有效 / 硬触发接线）
- [ ] 记录环境温度与传感器温度（漂移追溯用）

**标定执行**

- [ ] 相机内参：≥15 张、满幅覆盖（四角必须出现）、姿态多样、锁定对焦
- [ ] 相机-LiDAR：≥3 块法向 >30° 的板位；板面点云剔除边缘混合回波
- [ ] 手眼/雷达间：8~10 组大角度多方向运动；无合成数据自检不上真实数据
- [ ] 时间偏移：运动激励数据（转弯/加减速），互相关或连续时间批量估计
- [ ] 全程数据落盘（原始数据 + 中间结果），可复跑

**验证（全部通过才允许出厂）**

- [ ] 独立数据重投影误差达标（相机 < 0.5 px；外参投影个位数像素）
- [ ] 近/中/远三距离段目视 + 量化检查（板点落入率等）
- [ ] 地面/天空物理常识自检通过
- [ ] 参数不确定度有界（畸变系数、时间偏移的置信区间）
- [ ] 结果写入看板，附标定数据集 ID 与软件版本

**上线与运行**

- [ ] 外参/时间偏移文件带版本号与校验和
- [ ] 在线健康监测开启（地面一致性、静止段互检、时间偏移滑窗估计）
- [ ] 事件触发重标流程就绪（碰撞/维修/超阈值）

## 6. 小结

- 时间偏移的空间代价 = $v \cdot \Delta t$：120 km/h 下 10 ms = 33 cm，比典型外参误差高一个数量级。空间标定的价值建立在时间标定之上。
- 方法梯度：硬同步/PTP（消除源头）→ 互相关对齐（单对传感器、最小实现、可观测性来自运动变化）→ 连续时间批量优化（Furgale IROS 2013 / Kalibr / Peršić GP，全量信息联合估计）。
- 在线自标定：先监测后重标；无目标方法用于漂移补偿必须带阈值与置信度门限，宁可报警不可带病修正。
- 质量管理三板斧：独立数据验收（近中远三段）、误差看板与趋势、定期 + 事件触发的重标策略。
- 外参没有版本号 = 没有外参。

## 7. 自测题（带答案）

**Q1：120 km/h、相机 30 fps、LiDAR 10 Hz，都不做时间标定。最坏纵向错位多大？**
A：帧周期 33.3 ms（相机）与 100 ms（LiDAR）。两个时间戳完全不同源时，最坏常偏可达约半个周期量级：相机侧 ~17 ms（0.56 m）、LiDAR 侧 ~50 ms（1.67 m），两者叠加最坏近 2 m。就算时钟同源，曝光中心与时间戳生成时刻的固定延迟（rolling shutter 相机可达数 ms）仍贡献 10+ cm。这就是"软同步做完还要标常偏"的原因。

**Q2：互相关时间标定在匀速直行的数据上为什么失效？什么数据才有效？**
A：恒定物理量对时间平移不敏感——任何偏移下两条平直曲线都"对齐"。可观测性来自**变化**：转弯（角速度变化）、加减速（纵向加速度变化）、颠簸（垂直振动）。采集激励数据是时间标定的前提，正如姿态多样是空间标定的前提。

**Q3：连续时间批量优化比互相关强在哪？为什么说它"天然处理异步多传感器"？**
A：它把轨迹表示为时间的连续函数（B 样条/高斯过程），每个传感器每次观测按各自时间戳（加待估偏移）到轨迹上取值构造残差——采样率不同的传感器只是"在连续函数上取点的位置不同"，无需重采样对齐；且全部观测进同一个最大似然目标，信息不浪费，还能输出不确定度。互相关是它的单对、单物理量特例。

**Q4：在线无目标重标和进标定间重标，各用在什么场景？为什么在线修正要设门限？**
A：在线无目标（边缘/强度对齐）用于日常漂移监测与小量修正——它不需要停产进标定间，但精度受场景纹理与点云分辨率限制，低纹理场景可能跑飞。标定间（靶标法）用于首次标定、碰撞维修后、在线监测报警时的权威重标。设门限是因为：一个坏的无目标估计会直接污染融合输入，比"不修正"危害更大；超阈值应触发报警与安全策略，而不是静默采纳。

**Q5：某车在线监测显示"外参漂移趋势 0.02°/千公里"。距离下次周期性重标还有 2 万公里。该不该提前重标？**
A：算账：2 万公里累计 0.4°，100 m 外横向错位 0.7 m——若该感知功能依赖远距离融合（如高速 NOA），这个量级已接近或超过目标关联容差，应提前触发重标；若功能运行域以近距离为主且监测余量充足，可缩短监测周期、维持原排期。答案取决于功能对精度的需求（由下游验收指标倒推），而不是漂移数字本身——这是"标定服务于功能"的工程视角。
