## 1. 第一性原理：协同感知的三个层级

第 1 周定位了 V2X 对感知的三件事（补盲、校验、预告），本周回答"传**什么粒度**的信息"。所有方案都在同一条光谱上：

| 层级 | 传什么 | 典型带宽 | 信息损失 | 工程难度 |
| --- | --- | --- | --- | --- |
| **早期数据级**（data-level / early fusion） | 原始点云/图像 | 激光雷达 1 帧 ~MB 级（10 Hz 下数十 Mbps/目标） | 无 | 双方传感器/标定完全一致，几乎不可工程化 |
| **特征级**（feature-level / intermediate fusion） | 中间特征图（如 BEV 特征） | 百 KB~MB 级/帧 | 中（特征已压缩但未语义化） | 需要联合训练、统一的特征空间与位姿 |
| **目标级结果级**（object-level / late fusion） | 目标列表（TrackID/类别/位置/速度/尺寸/置信度） | **KB 级/帧** | 大（视野外的一切细节丢失） | 最低——就是 Stage 4 的融合器换个数据源 |

**这个表在说什么**：带宽与信息量是一对不可兼得的交换，而且差得不是 20%，是**三个数量级**。目标级方案每帧只传几千字节（上周 w2 的消息编码就是它的形状），能塞进任何 V2X 链路；代价是"只传结论不传证据"——遮挡判断、类别细分、形状细节全部丢失。**工程现实**：当前量产与路侧示范项目跑的是目标级（RSM/CPM 的目标容器就是为此设计）；学术前沿在特征级（见第 4 节）；数据级主要用于同构实体验证实验（如 DAIR-V2X 论文里的 early fusion 基线）。

一句话决策口诀：**带宽预算够、模型统一、位姿准 → 特征级上限高；跨厂商、跨制式、今天就要上线 → 目标级是唯一现实解**。

## 2. 路侧-车端对齐：坐标变换 + 时延补偿

收到一条 RSM/CPM 类消息后，车端融合器在用它之前必须回答两个问题：**这是哪里的坐标？这是什么时候的状态？**

### 2.1 坐标对齐：外参变换（Stage 3 在这里兑现）

路侧感知在**路侧世界系**（world frame，通常以 RSU 或路口为原点的东北天/东 北京 坐标）下输出目标；车端融合器工作在 **ego 系**（自车坐标系，x 前 y 左，随车移动旋转）。两者之间是一个刚体变换：

$$
\mathbf{p}_{\text{ego}} = R(-\psi)\,\big(\mathbf{p}_{\text{world}} - \mathbf{t}_{\text{veh}}\big)
$$

**这个公式在干什么**：先平移（把世界原点搬到自车脚下），再旋转（把坐标轴掰到车头方向）。逐符号拆解：

| 符号 | 物理含义 | 大白话 |
| --- | --- | --- |
| $\mathbf{p}_{\text{world}}$ | 目标在路侧世界系的位置 $(x, y)$ | 路侧消息里报的数 |
| $\mathbf{t}_{\text{veh}}$ | 自车在路侧世界系中的位置 | 需要通过 GNSS/地图或 V2X 位姿共享得知 |
| $\psi$ | 自车航向角（世界系中车头指向） | 决定旋转量 |
| $R(-\psi)$ | 2D 旋转矩阵 $\begin{bmatrix}\cos\psi & \sin\psi\\ -\sin\psi & \cos\psi\end{bmatrix}$ | 把"东北方向"重述成"前左方向" |
| $\mathbf{p}_{\text{ego}}$ | 目标在 ego 系的位置 $(x_{\text{前}}, y_{\text{左}})$ | 车端融合器能用的数 |

**谁来标定这个变换**：$\mathbf{t}_{\text{veh}}$ 与 $\psi$ 本质上是"车在路侧坐标系里的外参"——它的标定思想与 Stage 3 完全一致（已知对应点求刚体变换），只是这次"传感器"是会动的车。工程上有两条路：① 双方都在同一 GNSS/地图时基下各自定位（本教程 demo 采用）；② 消息里直接携带发送方的位姿，接收方现算相对变换。

### 2.2 时间对齐：时延补偿公式

消息报的是 $t_{\text{msg}}$ 时刻的状态，到达并被使用时已是 $t_{\text{now}}$。匀速假设下外推：

$$
\mathbf{p}(t_{\text{now}}) = \mathbf{p}_{\text{msg}} + \mathbf{v}_{\text{msg}}\cdot(t_{\text{now}} - t_{\text{msg}})
$$

**这个公式在干什么**：让旧消息"先走完这一路时延"。逐符号拆解：

| 符号 | 物理含义 | 大白话 |
| --- | --- | --- |
| $\mathbf{p}_{\text{msg}}$ | 消息里报的位置（$t_{\text{msg}}$ 时刻） | 第 2 周 roundtrip 解码出来的数 |
| $\mathbf{v}_{\text{msg}}$ | 消息里报的速度矢量（由 speed+heading 重建） | **没有这个字段补偿就无从谈起**——第 1 周埋的伏笔 |
| $\Delta t = t_{\text{now}} - t_{\text{msg}}$ | 消息年龄（age） | 由 secMark/时间戳算出，第 1 周 100 ms 预算在这里落地 |
| $\mathbf{v}\Delta t$ | 时延期间目标走过的位移 | 120 km/h × 100 ms = 3.33 m |

两个公式的先后顺序：**先补偿、后变换**或**先变换、后补偿**在数学上都可（都是线性/仿射运算可交换），工程惯例是先把位置补偿到 $t_{\text{now}}$ 的世界系状态，再一次性变换到 ego 系——w3 脚本就是这样写的。

### 2.3 对齐误差从哪来：一张误差预算表

两个对齐公式各有自己的输入，每个输入都带误差。把 w3 场景的误差来源列全（量化用第 2 周结论，其余为典型量级）：

| 误差源 | 量级 | 性质 | 对策 |
| --- | --- | --- | --- |
| 消息定点量化 | ≤0.55 cm（位置）/ ≤1 cm（速度） | 随机、有界 | 可忽略（第 2 周 roundtrip 已证） |
| 路侧感知噪声 | 0.3~0.5 m | 随机 | 逆方差加权/KF 更新吸收 |
| 速度噪声 × 时延 | 0.3 m/s × 0.1 s ≈ 3 cm | 随机、随时延放大 | 控制时延 + 速度质量标记 |
| 路侧标定/安装误差 | 5~20 cm（固定偏差） | **系统性** | 定期标定（Stage 3 流程） |
| 时钟不同步 | 时钟差 × 速度（50 ms × 11 m/s ≈ 0.55 m） | **系统性** | GNSS 授时 + 年龄漂移监控 |
| 自车位姿误差 | 0.1~1 m（GNSS 级） | 慢变 | RTK/地图匹配；车端融合自身也要吃这个误差 |

读表要点：**最危险的恰好都是系统性误差**（标定、时钟）——随机误差会被融合平均掉，系统偏差不会，它会伪装成"这个 RSU 报的目标总是偏右 0.5 m"。工程上把这叫"RSU 一致性检查"：同一目标被多台 RSU 同时看到时，交叉比对定位偏差源。

## 3. 目标级协同融合：把路侧当"另一个传感器"

### 3.1 方法论：Stage 4 的全套工具原样复用

这是本阶段最重要的一句话：**在车端融合器眼里，"路侧发来的目标列表"和"本车激光雷达输出的检测列表"没有本质区别——都是某个视角下的观测，都带噪声、都可能有漏检**。于是协同融合 = Stage 4 的老三样换个数据源：

1. **对齐**（第 2 节：坐标 + 时间）——相当于多传感器融合里的"时空同步"；
2. **关联**（门控 + 匈牙利）——ego 现有轨迹 vs 对齐后的路侧目标，距离/马氏门控剪枝，匈牙利指派；
3. **融合更新**（KF / 逆方差加权）——配上的目标做观测更新（路侧观测噪声小，就给它的 R 小一点——Q/R 调参思想原样适用）；没配上的路侧目标**新建轨迹**（这就是补盲！）；没配上的本地轨迹照常走预测。

### 3.2 可运行实验：车端 1 目标 + 路侧 2 目标的跨视角融合（w3）

场景：十字路口，路侧单元上帝视角；车端在 (60, 0) 朝北行驶。目标 A 在车端正前方但被货车完全遮挡（**盲区**），只有路侧看得见；目标 B 双方都看得见。路侧消息时延 100 ms。

```python
# w3_coop_fusion.py —— 第 3 周：路侧目标跨视角关联与融合（目标级协同，复用 Stage 4 门控+匈牙利+KF 思路）
# 场景：十字路口。路侧单元 RSU 在世界系原点上帝视角；车端在 (60,0) 朝北(+y)行驶。
#   目标 A：(60, 20) 朝北 8 m/s —— 车端被前方货车完全遮挡（盲区），只有路侧能看到
#   目标 B：(52,  8) 朝北 8 m/s —— 双方都能看到（用于展示"1+1 融合更准"）
# 坐标约定：世界系 x 东 y 北；ego 系 x 前 y 左。GT 记的是消息感知时刻 t_msg 的位置；
#   统一到"当前时刻 t_now = t_msg + 100ms"后再比较（B 的 ego 系真值 = (8.8, 8)）。
import numpy as np
from scipy.optimize import linear_sum_assignment

np.random.seed(33)

GT = {
    "A": {"p": np.array([60.0, 20.0]), "v": np.array([0.0, 8.0])},   # 盲区目标
    "B": {"p": np.array([52.0,  8.0]), "v": np.array([0.0, 8.0])},
}
VEH_POS = np.array([60.0, 0.0]); VEH_YAW = np.radians(90.0)          # 朝北
LATENCY = 0.10                                                        # 路侧消息时延 100 ms

def world2ego(p):
    """世界系 -> ego 系：p_ego = R(-yaw) (p_world - t)，ego x=前，y=左"""
    d = p - VEH_POS
    R = np.array([[ np.cos(VEH_YAW), np.sin(VEH_YAW)],
                  [-np.sin(VEH_YAW), np.cos(VEH_YAW)]])
    return R @ d

EGO_B_TRUE = world2ego(GT["B"]["p"] + GT["B"]["v"] * LATENCY)         # t_now 时刻真值 (8.8, 8)
EGO_A_TRUE = world2ego(GT["A"]["p"] + GT["A"]["v"] * LATENCY)         # (20.8, 0)

# ---- 2. 双方感知输出（车端在 ego 系，路侧在世界系；噪声固定种子）----
# 车端在 t_now 检测到 B：ego 真值 (8.8, 8) + 噪声 σ≈0.8 m；A 在盲区，车端无输出
ego_det = [world2ego(GT["B"]["p"] + GT["B"]["v"] * LATENCY) + np.array([ 0.6, -0.5])]
rsu_det = [GT["A"]["p"] + np.array([ 0.4, -0.3]),                     # 路侧 A、B 都检测到（σ≈0.4 m）
           GT["B"]["p"] + np.array([ 0.2,  0.3])]
rsu_v   = [GT["A"]["v"] + np.array([ 0.1,  0.1]),
           GT["B"]["v"] + np.array([-0.1,  0.1])]

# ---- 3. 路侧目标 -> ego 系：外参变换 + 时延补偿 ----
print("==== 路侧目标对齐到 ego 系（外参变换 + 时延补偿）====")
rsu_in_ego = []
for (p, v) in zip(rsu_det, rsu_v):
    p_comp = p + v * LATENCY                    # 时延补偿：p(t_now) = p_msg + v * (t_now - t_msg)
    e = world2ego(p_comp)
    rsu_in_ego.append(e)
    print(f"路侧目标 世界系 {np.round(p,2)} -> 补偿后 {np.round(p_comp,2)} -> ego 系 {np.round(e,2)}")
print(f"ego 系 t_now 真值：B {np.round(EGO_B_TRUE,2)}，A {np.round(EGO_A_TRUE,2)}")

# ---- 4. 关联：距离门控 + 匈牙利（Stage 4 第 3 周套路）----
GATE = 4.0                                        # 教学版硬门限（生产用马氏门控）
n, m = len(ego_det), len(rsu_in_ego)
C = np.full((n, m), GATE + 1.0)                   # 超门限填大代价（不允许配）
for i, pe in enumerate(ego_det):
    for j, pr in enumerate(rsu_in_ego):
        d = np.linalg.norm(pe - pr)
        if d < GATE:
            C[i, j] = d
ri, ci = linear_sum_assignment(C)
pairs = [(i, j) for i, j in zip(ri, ci) if C[i, j] <= GATE]
print("\n==== 门控+匈牙利关联 ====")
print(f"车端检测 {n} 个，路侧对齐后 {m} 个；关联成功对（ego行,路侧列）: {pairs}")

# ---- 5. 结果级融合：重复目标逆方差加权；路侧独有目标 -> 新建 ego 轨迹 ----
print("\n==== 融合输出（ego 系）====")
fused = []
for i, j in pairs:
    se, sr = 0.8**2, 0.4**2                              # 双方位置方差（车端 σ0.8m，路侧 σ0.4m）
    w = (1/se) / ((1/se) + (1/sr))                       # 逆方差权重（Stage 4 第 1 周公式）
    fused.append(w * np.array(ego_det[i]) + (1-w) * np.array(rsu_in_ego[j]))
    print(f"重复目标: ego {np.round(ego_det[i],2)} + 路侧 {np.round(rsu_in_ego[j],2)}"
          f" -> 融合 {np.round(fused[-1],2)} (ego 权重 {w:.2f})")
matched_rs = {j for _, j in pairs}
for j, pr in enumerate(rsu_in_ego):
    if j not in matched_rs:
        fused.append(np.array(pr))
        print(f"路侧独有目标（盲区!）-> 直接纳入 ego 列表: {np.round(pr,2)}")

# ---- 6. 验收：盲区目标是否被补上 + 融合精度 ----
print("\n==== 验收 ====")
ego_only_err = np.linalg.norm(ego_det[0] - EGO_B_TRUE)
fusedB_err   = np.linalg.norm(fused[0] - EGO_B_TRUE)
blind_added  = len(fused) == 2 and np.linalg.norm(fused[1] - EGO_A_TRUE) < 1.5
print(f"目标 B：仅车端误差 {ego_only_err:.2f} m -> 融合后 {fusedB_err:.2f} m")
print(f"盲区目标 A：{'已补上' if blind_added else '丢失'}，ego 系位置 {np.round(fused[1],2)}"
      f"（真值 {np.round(EGO_A_TRUE,2)}，误差 {np.linalg.norm(fused[1]-EGO_A_TRUE):.2f} m）")

# ---- 7. 时延外推误差：不做补偿会怎样 ----
print("\n==== 时延外推误差（不做补偿的教训）====")
for v_kmh, lat in [(50, 0.10), (120, 0.10), (120, 0.50)]:
    v = v_kmh / 3.6
    print(f"{v_kmh:3d} km/h x {lat*1000:3.0f} ms 时延 x 不补偿 = 位置偏移 {v*lat:5.2f} m")
```

**预期输出**（固定种子实测）：

```
==== 路侧目标对齐到 ego 系（外参变换 + 时延补偿）====
路侧目标 世界系 [60.4 19.7] -> 补偿后 [60.41 20.51] -> ego 系 [20.51 -0.41]
路侧目标 世界系 [52.2  8.3] -> 补偿后 [52.19  9.11] -> ego 系 [9.11 7.81]
ego 系 t_now 真值：B [8.8 8. ]，A [20.8  0. ]

==== 门控+匈牙利关联 ====
车端检测 1 个，路侧对齐后 2 个；关联成功对（ego行,路侧列）: [(0, 1)]

==== 融合输出（ego 系）====
重复目标: ego [9.4 7.5] + 路侧 [9.11 7.81] -> 融合 [9.17 7.75] (ego 权重 0.20)
路侧独有目标（盲区!）-> 直接纳入 ego 列表: [20.51 -0.41]

==== 验收 ====
目标 B：仅车端误差 0.78 m -> 融合后 0.45 m
盲区目标 A：已补上，ego 系位置 [20.51 -0.41]（真值 [20.8  0. ]，误差 0.50 m）

==== 时延外推误差（不做补偿的教训）====
 50 km/h x 100 ms 时延 x 不补偿 = 位置偏移  1.39 m
120 km/h x 100 ms 时延 x 不补偿 = 位置偏移  3.33 m
120 km/h x 500 ms 时延 x 不补偿 = 位置偏移 16.67 m
```

逐段解读这份输出——它就是目标级协同感知的全部流程缩影：

- **对齐段**：A 补偿后从 19.7 走到 20.51（它 8 m/s 朝北走了 100 ms ≈ 0.8 m，速度噪声 0.1 m/s 贡献了 ±0.01 m）；ego 系里 A 出现在 $y = -0.41$（**右侧 0.4 m**）而真值 0——这 0.5 m 就是路侧观测噪声，可接受。
- **关联段**：B 的车端观测 (9.4, 7.5) 与路侧对齐后 (9.11, 7.81) 距离 0.43 m << 门限 4 m，配上；A 车端根本没有观测，自然配不上。
- **融合段**：逆方差权重给路侧 0.80（它 σ=0.4 m，比车端 σ=0.8 m 准），B 的误差从 0.78 m 降到 0.45 m——**双方都看见时，融合必然不差于任一方**（Stage 4 第 1 周的结论）；A 被直接纳入——**鬼探头问题的目标级解法就这四行代码**。
- **教训段**：120 km/h 下不补偿 3.33 m；若链路劣化到 500 ms（比如消息在处理队列里排队），错位 16.67 m——比"根本没收到"更危险，因为这是一个**自信的错**。第 4 周仿真会看到不补偿对 RMSE 的真实伤害。

> **动手验证**：把 `LATENCY` 改成 0.5 且**注释掉补偿行**（`p_comp = p`），重跑——B 的路侧观测停在 ego 系 (8.3, 7.8)，与车端观测 (12.6, 7.5) 相距 4.31 m，**超过 4 m 门限，关联直接失败**：验收行变成"融合后 11.40 m"（那其实是拿 A 的路侧观测去和 B 的真值比距离的假象），B 被拆成两个互不相认的目标——这就是**幽灵目标**（Stage 4 讲过的 ID 分裂在通信场景的变体）。500 ms 时延不补偿，协同从"补盲神器"劣化成"目标分裂器"。

## 4. 特征级协同：三篇代表作一句话

理解目标级的"信息损失"具体损失了什么，看特征级路线在补什么：

- **F-Cooper**（Chen et al., ACM/IEEE Symposium on Edge Computing **SEC 2019**）：点云特征图直接做 maxout 融合——证明"传特征比传结果好，比传点云省"，特征级协同的开山之作。
- **DiscoNet**（Li et al., **NeurIPS 2021**，arXiv:2111.00643）：用知识蒸馏训练带位姿感知边的协同图——早融合性能 + 晚融合带宽的折中，训练时教、推理时省。
- **V2X-ViT**（Xu et al., **ECCV 2022**，arXiv:2203.10638）：多尺度窗口注意力做 V2X 特征融合，同时显著提升对位姿误差与异步时延的**鲁棒性**——正面回应了本章的对齐误差问题。

三篇共同的前提：参与方跑**同一套网络、共享同一特征空间**——这正是它们短期难以进量产的原因（车厂之间网络权重都无法共享，更别说路侧设备型号五花八门）。

## 5. 公开数据集：协同感知研究的"靶场"

| 数据集 | 出处 | 规模（论文/官方自报） | 特点 |
| --- | --- | --- | --- |
| **DAIR-V2X** | Yu et al., CVPR 2022 | 共 71,254 帧点云 + 71,254 帧图像（真实采集，北京约 28 个路口）；其中车路协同子集 **DAIR-V2X-C 含 19,966 帧**配对数据 | **首个真实场景车-路协同数据集**，真车+真路侧双视角，VIC3D 基线（官方数据：LiDAR early fusion AP-3D 62.61 vs 仅车端 48.06） |

## 6. 本周小结

- 协同感知三层级的本质是**带宽与信息量的交换**：数据级 MB 级（无损失）、特征级百 KB~MB 级（可学习）、目标级 KB 级（结论级）——量产现状与跨厂商互操作性决定了目标级是现实主流。
- 对齐两公式：外参变换 $\mathbf{p}_{\text{ego}} = R(-\psi)(\mathbf{p}_{\text{world}} - \mathbf{t}_{\text{veh}})$（先平移后旋转）+ 时延补偿 $\mathbf{p}(t_{\text{now}}) = \mathbf{p}_{\text{msg}} + \mathbf{v}\cdot\Delta t$（120 km/h × 100 ms = 3.33 m 不补偿即错一个车道）。
- 目标级协同融合 = **把路侧目标当另一个传感器**：门控+匈牙利做跨视角认亲，KF/逆方差加权做更新，独有目标进确认态补盲——Stage 4 全套工具零修改迁移。
- w3 实测：重复目标 0.78→0.45 m（融合更准）、盲区目标补上（0.50 m）；不补偿 500 ms 时直接关联失败、幽灵目标诞生——**补偿是协同的前提，不是优化项**。
- 特征级三代表作（F-Cooper/DiscoNet/V2X-ViT）要解决的是"同一特征空间 + 位姿误差鲁棒性"；真实数据看 DAIR-V2X（VIC3D 基线协同增益 ~30% AP），可控实验看 OPV2V/V2X-Sim。

## 7. 工程权衡与失效模式

1. **时延不补偿就融合**：第 3.2 节教训段已量化（3.33 m @ 120 km/h×100 ms）。**症状**：高速路场景融合误差远大于城市；**修复**：强制消息携带时间戳+速度，补偿公式进融合入口，并设 age 上限（如 >300 ms 的消息降权或丢弃——宁可不用，不可误用）。
2. **路侧目标直接当"真值"用**：路侧也有噪声、漏检、误检（本库《后融合.md》列的五大难点在路侧同样成立）。**症状**：车端轨迹被路侧坏观测拉飞；**修复**：给路侧观测合理的 R（本例 σ=0.4 m），让 KF 的增益机制自动分配信任；加卡方一致性检查。
3. **门限一刀切**：4 m 硬门限在目标密集路口（车间距 < 4 m 排队）会错配。**症状**：相邻车道车辆轨迹互换（对端视角的 ID switch）；**修复**：马氏门控（把不确定度算进门限）+ 类别/尺寸一致性约束，Stage 4 第 3 周方案原样迁移。
4. **双份 TrackID 语义混淆**：路侧的 TrackID（如 "101"）与车端本地轨迹 ID 是两个独立命名空间。**症状**：日志里两个 "101" 指不同目标，排查灾难；**修复**：融合地图里显式维护 "本地 ID ↔ 路侧 ID" 映射表（这正是《后融合.md》"ID 漂移影响 V2X 通信"的落地对策）。
5. **只融合不仲裁类别**：路侧说 truck、车端说 car。**症状**：类别字段随消息频率抖动；**修复**：类别一致性约束进关联代价 + 时序多数投票（Stage 4 类别仲裁思想的复用）。

## 8. 延伸思考题（含解析）

**Q1**：目标级协同融合的"路侧独有目标直接新建轨迹"，会不会把路侧的误检变成车端的鬼目标？
**A**：会。这就是新建轨迹必须走 Stage 4 的确认机制（tentative→confirmed，连续 N 帧才确认）的原因：路侧误检通常不会连续多帧落在同一位置。若路侧消息带置信度，还应把它折算进观测方差——高置信的补盲目标确认更快。

**Q2**：为什么"先补偿后变换"和"先变换后补偿"等价？什么时候不等价？
**A**：两者都是线性运算：$R(\mathbf{p} + \mathbf{v}\Delta t - \mathbf{t}) = R(\mathbf{p}-\mathbf{t}) + R\mathbf{v}\Delta t$，只要速度矢量也做同样的旋转。**不等价的情形**：速度只在某个坐标系里有定义（如路侧给的是径向速度）、或自车在 Δt 内自身位姿变化大（高速+长时延）——那时 ego 系本身在动，补偿要在世界系完成后再变（本教程假设 Δt=100 ms 内 ego 位姿已知恒定，简化成立）。

**Q3**：特征级协同需要传位姿吗？它对位姿误差比目标级更敏感还是更迟钝？
**A**：要传（特征图要按相对位姿对齐到统一 BEV 空间）。**更敏感**：目标级错 0.5 m 只是框偏 0.5 m；特征级错 0.5 m，整张特征图错位，注意力/卷积在错误的像素上对齐，误差被放大。V2X-ViT 的贡献正是让网络学会容忍这种误差。

**Q4**：DAIR-V2X 论文里 early fusion AP-3D 62.61 vs 仅车端 48.06，能得出"特征级比目标级好"的结论吗？
**A**：不能直接得出。该对比是"early fusion vs 不协同"，对照组没有 late fusion 基线；且同实体验证（同型号设备、精确标定）是特征级最有利的场景。能得出的结论是：**协同本身**带来约 14.6 AP 的增益——这正是第 4 周"协同检测增益"指标的来源。

**Q5**：自车也在动，ego 系的"当前时刻真值"为什么不包含自车位移？
**A**：包含了，只是藏在位姿里：ego 系本身随自车平移旋转，$\mathbf{t}_{\text{veh}}(t)$ 与 $\psi(t)$ 用的都是当前时刻的值——补偿与变换等价于在"当前静止的自车"参考系里看世界。真正的坑在**自车位姿自身的时延**：若位姿滞后 100 ms，整个变换结果随自车速度整体错位（8 m/s 自车 × 100 ms = 0.8 m）——高等级系统会把"自车定位时延"也纳入误差预算表（2.3 节最后一行）。
