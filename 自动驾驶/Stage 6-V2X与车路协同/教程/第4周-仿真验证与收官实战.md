## 1. 第一性原理：为什么协同感知必须仿真

单车感知的验证可以靠实车路测（贵但可行）；协同感知的验证多了一个维度——**至少两端的时空一致性**：

- **设备三件套**：RSU（含路侧感知栈）、车载终端、通信链路，任何一端出问题都表现为"协同失效"，现场根本分不清是感知错、标定错还是通信错；
- **危险场景不可复现**：鬼探头、闯红灯、对向逆行——真机验证要么等运气、要么违法；
- **变量不可控**：想研究"时延 100 ms vs 300 ms 对 RMSE 的影响"，真实链路无法精确控制时延。

仿真把这三件事全部解决：**场景可构造、变量可控制、实验可复现**（固定种子的 numpy 仿真连"第 3 帧第 2 个目标的噪声是多少"都精确复现）。这也是为什么协同感知领域的公开数据集 OPV2V、V2X-Sim 全部基于仿真，或以仿真为主。

## 2. 仿真工具导览：一套工具链各管一段

| 工具 | 出身 | 管什么 |
| --- | --- | --- |
| **CARLA** | Intel/巴塞罗那 CVC 等开源驾驶仿真器 | 世界与传感器：渲染城市、车辆、摄像头/激光雷达仿真 |
| **SUMO** | 德国航天中心（DLR）开源交通流仿真 | 交通流：成百上千辆背景车的微观行为 |
| **OpenCDA** | UCLA Mobility Lab（论文 *OpenCDA: An Open Cooperative Driving Automation Framework*, IEEE ITSC 2021，arXiv:2107.06260；GitHub `ucla-mobility/OpenCDA`） | **全栈协同**：CARLA（世界）+ SUMO（交通流）联合仿真，内置感知/定位/规划/控制/V2X 模块，纯 Python |
| **OpenCOOD** | 同为 UCLA 出品（OPV2V 数据集的配套框架） | 协同 3D 检测基准：多种融合策略的统一评测 |

分工一句话：**CARLA 管"世界长什么样"，SUMO 管"路上有多少车怎么开"，OpenCDA 把两者拼起来并加上 V2X 协作逻辑，OpenCOOD 负责协同检测的统一评测**。本教程的 numpy 仿真就是 OpenCDA 工作流的"机制版微缩"——真实工具需要 GPU 与 CARLA 环境，这里用几百行 numpy 把**目标级协同融合的骨架**拆给你看，跑通后再去 OpenCDA 里对号入座。

## 3. 可运行实战：1 路侧 + 2 车端的目标级协同仿真（w4）

### 3.1 场景与架构设计

- **世界**：十字路口，6 个匀速目标（纵向穿行的车、横向车流、慢速行人、自车后方盲区车），10 Hz × 100 帧 = 10 秒；
- **三个观测源**（各带缺陷，这正是协同的意义）：

| 观测源 | 位置/视场 | 噪声 | 缺陷 |
| --- | --- | --- | --- |
| 车端 1（ego，朝东行驶） | 前视 ±35°、量程 80 m | σ=0.8 m | 背后、侧面全盲 |
| 车端 2（对向，朝西行驶） | 前视 ±35°、量程 80 m | σ=0.8 m | 视角互补于 ego，但同样有前向盲区 |
| 路侧 RSU（路口上方） | **360°、量程 150 m** | σ=0.4 m | 消息时延 100 ms + 5% 丢包 |

- **融合**：Stage 4 的 CV 模型 KF + 门控（4 m）+ 匈牙利 + 简易轨迹管理（连续 5 帧漏检删除）；
- **对比**：同一份真值与噪声流跑两种模式——"仅车端"（只用 ego 自身检测）vs "协同"（ego + 车端 2（经位姿共享变换）+ RSU（经时延补偿，丢包帧自动跳过））；
- **指标**：位置 RMSE（真值 3 m 内有轨迹匹配才计入）与漏检数（帧·目标级，6 目标 × 100 帧 = 600）。

### 3.2 完整代码

```python
# w4_coop_sim.py —— 第 4 周收官实战："1 路侧 + 2 车端"目标级协同感知仿真
# 三个观测源（各自带噪声/视场限制/时延/丢包），用 Stage 4 的 KF(CV)+匈牙利做目标级协同融合，
# 对比「仅车端」vs「协同后」的位置 RMSE 与漏检数。固定种子，CPU 秒级可复现。
import numpy as np
from scipy.optimize import linear_sum_assignment

np.random.seed(42)
DT, N = 0.1, 100                      # 10 Hz，10 秒
SIG_EGO, SIG_V2, SIG_RSU = 0.8, 0.8, 0.4   # 三源位置噪声 (m)
RSU_LAT = 0.10                        # 路侧消息时延 100 ms
RSU_DROP = 0.05                       # 路侧消息丢包率 5%
FOV_HALF, RNG_EGO = np.radians(35.0), 80.0 # 车端前视 ±35°，量程 80 m

# ---- 真值：6 个匀速目标（十字路口混合交通）----
GT0 = np.array([[50,15,0,7],[62,95,0,-9],[15,45,7.5,0],
                [46,47,1.4,0.6],[95,55,-6,0],[2,48,2,0]], float)  # [x,y,vx,vy]
def gt_at(f):
    t = f * DT
    gt = GT0.copy(); gt[:, :2] += gt[:, 2:] * t
    return gt

# ---- 传感器模型：FOV 内以检测概率出观测（世界系）----
def sensor_detect(gt_now, pose, yaw, p_det, sig, rng_max, fov_half):
    d = gt_now[:, :2] - pose
    rng = np.hypot(d[:, 0], d[:, 1])
    ang = np.abs(np.arctan2(d[:, 1], d[:, 0]) - yaw)   # 世界系 x 东 y 北，yaw 为朝向角
    ang = (ang + np.pi) % (2*np.pi) - np.pi
    vis = (rng < rng_max) & (np.abs(ang) < fov_half)
    out, vid = [], []
    for i in np.where(vis & (np.random.rand(len(gt_now)) < p_det))[0]:
        out.append(gt_now[i, :2] + sig * np.random.randn(2)); vid.append(i)
    return np.array(out), np.array(vid)

def world2ego(p, ego_pose, ego_yaw):
    d = np.atleast_2d(p) - ego_pose
    c, s = np.cos(ego_yaw), np.sin(ego_yaw)
    return d @ np.array([[c, s], [-s, c]])              # ego x=前, y=左

def ego2world(p, ego_pose, ego_yaw):
    c, s = np.cos(ego_yaw), np.sin(ego_yaw)
    return np.atleast_2d(p) @ np.array([[c, -s], [s, c]]) + ego_pose   # 逆变换

# ---- Stage 4 的 KF(CV)：状态 [x,y,vx,vy]，观测位置 ----
F = np.array([[1,0,DT,0],[0,1,0,DT],[0,0,1,0],[0,0,0,1]])
Q = np.diag([0.01,0.01,0.05,0.05]); H = np.array([[1,0,0,0],[0,1,0,0]])
class Track:
    _n = 0
    def __init__(self, z, sig):
        self.x = np.array([z[0], z[1], 0.0, 0.0]); self.P = np.diag([sig**2, sig**2, 25., 25.])
        self.miss = 0; self.id = Track._n; Track._n += 1
    def predict(self):
        self.x = F @ self.x; self.P = F @ self.P @ F.T + Q
    def update(self, z, sig):
        R = sig**2 * np.eye(2)
        y = z - H @ self.x; S = H @ self.P @ H.T + R
        K = self.P @ H.T @ np.linalg.inv(S)
        self.x += K @ y; self.P = (np.eye(4) - K @ H) @ self.P
        self.miss = 0

def step_tracks(tracks, dets, sig, gate=4.0):
    for tr in tracks: tr.predict(); tr.miss += 1
    if len(tracks) and len(dets):
        C = np.full((len(tracks), len(dets)), gate + 1.0)
        for i, tr in enumerate(tracks):
            for j, z in enumerate(dets):
                dd = np.linalg.norm(H @ tr.x - z)
                if dd < gate: C[i, j] = dd
        ri, ci = linear_sum_assignment(C)
        for i, j in zip(ri, ci):
            if C[i, j] <= gate: tracks[i].update(dets[j], sig)
    for z in dets:
        if not any(np.linalg.norm(H @ tr.x - z) < gate for tr in tracks):
            tracks.append(Track(z, sig))
    return [tr for tr in tracks if tr.miss <= 5]

def evaluate(est_w, gt_now, thr=3.0):
    """est_w：世界系轨迹估计（N,2）；返回匹配误差列表与漏检数"""
    errs, miss = [], 0
    if len(est_w):
        for g in gt_now[:, :2]:
            dmin = np.linalg.norm(est_w - g, axis=1).min()
            if dmin < thr:
                errs.append(dmin)
            else:
                miss += 1
    else:
        miss = len(gt_now)
    return errs, miss

# ---- 主循环：两种模式跑同一份真值与噪声流 ----
def run(coop):
    tracks, errs_all, miss_all = [], [], []
    for f in range(N):
        ego_pose = np.array([5 + 8*f*DT, 50.0]); ego_yaw = 0.0          # 车端1朝东
        v2_pose  = np.array([95 - 8*f*DT, 50.0]); v2_yaw = np.pi        # 车端2朝西
        gt_now = gt_at(f)
        d_ego, _ = sensor_detect(gt_now, ego_pose, ego_yaw, 0.90, SIG_EGO, RNG_EGO, FOV_HALF)
        det_ego_f = world2ego(d_ego, ego_pose, ego_yaw) if len(d_ego) else np.empty((0,2))
        if coop:
            d_v2, _ = sensor_detect(gt_now, v2_pose, v2_yaw, 0.90, SIG_V2, RNG_EGO, FOV_HALF)
            det_pool = [det_ego_f]
            if len(d_v2): det_pool.append(world2ego(d_v2, ego_pose, ego_yaw))   # V2V 共享位姿
            # 路侧：t-RSU_LAT 时刻感知，100 ms 后到达，自带速度可外推补偿；5% 丢包
            gt_prev = gt_at(f-1) if f >= 1 else gt_at(0)
            d_r, vid_r = sensor_detect(gt_prev, np.array([50.,50.]), 0.0, 0.95, SIG_RSU, 150.0, np.pi)
            if len(d_r) and np.random.rand() > RSU_DROP:
                v_est = gt_prev[vid_r, 2:] + 0.3*np.random.randn(len(vid_r), 2)
                comp = d_r + v_est * RSU_LAT                              # 时延外推补偿
                det_pool.append(world2ego(comp, ego_pose, ego_yaw))
            dets = np.vstack([d for d in det_pool if len(d)]) if any(len(d) for d in det_pool) \
                   else np.empty((0, 2))
        else:
            dets = det_ego_f
        tracks = step_tracks(tracks, dets, SIG_EGO)
        est_w = ego2world([H @ tr.x for tr in tracks], ego_pose, ego_yaw) if tracks else np.empty((0,2))
        errs, miss = evaluate(est_w, gt_now)
        errs_all += errs; miss_all.append(miss)
    rmse = np.sqrt(np.mean(np.array(errs_all)**2))
    return rmse, sum(miss_all), N*len(GT0)

for name, coop in [("仅车端(ego)", False), ("协同(2车+RSU)", True)]:
    rmse, miss, total = run(coop)
    print(f"{name:14s} 位置RMSE = {rmse:.3f} m   漏检 = {miss}/{total} 帧·目标 ({miss/total*100:.1f}%)")
```

### 3.3 预期输出与解读

**预期输出**（固定种子实测）：

```
仅车端(ego)       位置RMSE = 0.636 m   漏检 = 332/600 帧·目标 (55.3%)
协同(2车+RSU)     位置RMSE = 0.326 m   漏检 = 1/600 帧·目标 (0.2%)
```

两组数字各说各话：

- **漏检 55.3% → 0.2%**：这是协同最大的收益，且原因一目了然——ego 前视 ±35° 的视场把身后和侧面的目标（特别是那辆始终在 ego 后方的 6 号车）物理性排除，仅车端模式里它们是"结构性漏检"（约 1/3 的 600 直接来自视场外），再加上遮挡与 10% 检测概率失败。协同模式下 RSU 的 360°/150 m 视场兜底，唯一剩下的 1 个漏检是轨迹尚未确认的第 0 帧（冷启动），5% 丢包全被 KF 预测撑过去了——**上一周"丢包不重传、靠预测顶"的设计在这里得到验证**。
- **RMSE 0.636 → 0.326 m**：三源融合的方差收益。逆方差加权直觉版：三路 σ=0.8/0.8/0.4 的观测等价于一个 σ≈0.31 m 的传感器（$1/\sigma^2_{\text{合}} = \Sigma 1/\sigma_i^2$），再加上 RSU 时延补偿保留了它的精度红利——0.326 m 与理论值同量级。
- **两个数字的关系**：漏检是"有没有"，RMSE 是"准不准"。工程上**先看漏检（补盲率）再看 RMSE**——一个看不见的目标谈不上准不准，这正是第 1 周"补盲是 V2X 第一价值"的量化版。

> **动手验证（必做，这是收官作业）**：做三组消融，各改一行、记录两组指标的变化（以下数字均为固定种子实测）——
> ① **去掉时延补偿**：把 `comp = d_r + v_est * RSU_LAT` 改成 `comp = d_r`，协同 RMSE 0.326 → **0.661 m**——比不协同（0.636 m）还差：RSU 观测带着 100 ms 滞后和更小的噪声"自信地错"，把轨迹拉偏。**协同不是无条件更好，补偿是协同的前提**（第 3 周"3.33 m"论断的系统级实证）。
> ② **去掉 RSU**：把路侧分支注释掉，只剩 V2V——漏检 0.2% → **41.7%**（两台前视车拼不出 360° 视场，RSU 的上帝视角无可替代），RMSE 0.584 m（双车融合仍有精度收益）。
> ③ **时延加大到 500 ms（保留补偿）**：`RSU_LAT = 0.5`——RMSE 0.326 → **1.447 m**、漏检 0.2% → 14.3%：补偿公式还在工作，但速度噪声 × 0.5 s 被放大、目标滞后也更难对齐门限——**补偿能救 100 ms，救不了 500 ms**，时延预算（第 1 周）必须在链路层兑现。
> 每组把数字抄进表格，这就是一次完整的协同感知系统消融实验。

## 4. V2X 感知系统的评估指标

### 4.1 协同检测增益（Cooperative Perception Gain）

w4 用的 RMSE/漏检是机制版指标；规范化的协同检测评测沿用 Stage 2 的 AP 家族，定义**协同增益**：

$$
G = \frac{AP_{\text{协同}} - AP_{\text{仅单车}}}{AP_{\text{仅单车}}} \times 100\%
$$

**这个公式在干什么**：把"协同带来的相对提升"归一化。逐符号：$AP_{\text{仅单车}}$ 是只用自车传感器的基线（机会均等的对照）；$AP_{\text{协同}}$ 是加入 V2X 数据后的成绩；$G$ 是两者差值相对基线的百分比——DAIR-V2X 官方基线里 LiDAR early fusion 62.61 对仅车端 48.06，粗算 $G ≈ 30\%$。**注意口径**：AP 之外还要看距离分段（远处的增益远大于近处——路侧视角的真正价值在远方）与异步设置（VIC-Async 变体的成绩更接近真实通信条件）。

### 4.2 通信负载-精度权衡（Bandwidth-Accuracy Trade-off）

第 3 周三层级表的横轴与纵轴画在同一张图上就是这条曲线：

| 方案 | 负载量级/帧 | 精度上限 | 适用 |
| --- | --- | --- | --- |
| 数据级 | MB 级 | 最高（无损） | 同构实体实验 |
| 特征级 | 百 KB~MB 级 | 高（有损可学习） | 同网络权重的编队 |
| 目标级 | **KB 级** | 中（结论级） | 跨厂商量产（现状主流） |

评估一个协同方案时，标准做法是画"通信带宽（x 轴）- AP/RMSE（y 轴）"曲线看 Pareto 前沿：同样 1 KB 预算下谁的精度高、同样精度下谁的带宽省。第 3 周的三篇特征级论文的对比图全是这个画法。**另加两个协同特有指标**：补盲率（w4 的漏检下降即其微观版）与对时延/位姿误差的敏感度曲线（把仿真里的 `RSU_LAT` 和位姿噪声扫一遍——只有仿真扫得起）。

## 5. 全系列收官：六阶段知识地图

十个阶段（六个 Stage）下来，一条完整的路侧感知系统链路已经齐装。把它从数据流到通信流串起来：

```
【物理世界】十字路口：车辆、行人、信号灯、天气
     │
     ▼
① 传感器选型与数据基础（Stage 1）
   摄像头（语义强/测距弱）+ 毫米波雷达（测速强/分辨率低）+ 激光雷达（3D 精准/成本高）
   引出坐标系（世界系/传感器系/ego 系）与时间同步——Stage 6 的对齐问题在这里埋根
     │  点云 / 图像 / 目标列表
     ▼
② 目标检测（Stage 2）
   2D 检测（YOLO 系）→ 3D 检测（PointPillars 等）→ 类别/3D 框/置信度
   置信度的语义与校准，决定第 6 周消息里 conf 字段怎么被别人使用
     │  检测列表（每帧，异步、带噪声）
     ▼
③ 多传感器标定（Stage 3）
   内参（相机 K）+ 外参（传感器↔世界系）+ 时间偏移
   ——路侧安装的每台设备都要重做一遍；V2X 场景里"车在路侧系中的外参"是它的自然延伸
     │  统一坐标系与时基下的检测
     ▼
④ 融合与跟踪（Stage 4）
   前融合/后融合选型 → KF/EKF（滤波）→ 门控+匈牙利（关联）→ 轨迹管理（确认/删除）
   产出：稳定 TrackID + 位置/速度/尺寸/置信度 —— 修复《后融合.md》"ID 漂移"问题的地方
     │  融合目标列表（KB 级，这就是"感知系统的产品"）
     ▼
⑤ BEV 感知（Stage 5）
   视角转换（LSS/Transformer）→ 上帝视角特征 → 前融合的另一种打开方式
   在路侧：多相机 BEV 是目标级输出的质量放大器；在协同：BEV 特征是特征级协同的通货
     │  （可选）BEV 特征图 —— 特征级协同的数据源
     ▼
⑥ V2X 与车路协同（Stage 6，本阶段）
   通信（PC5 广播，时延预算 100 ms）→ 消息集（J2735 / T/CSAE 53：目标列表变标准消息）
   → 对齐（外参变换 + 时延补偿）→ 协同融合（路侧目标 = 另一个传感器）
   → 仿真验证（OpenCDA 工作流 / numpy 微缩版）
     │
     ▼
【产品】路口的"上帝视角"：每辆车的盲区被路侧补上，
        每个鬼探头在进入视线前 100 ms 已出现在车载屏幕与规划器的地图上
```

**收敔回三句话**（第 1 周 1.3 节的承诺，现在可以完整兑现）：

1. **补盲** = 第 3 周 w3 的"路侧独有目标直接纳入"那四行代码 + 第 4 周 w4 漏检 55.3%→0.2%；
2. **校验** = 逆方差加权/KF 更新，RMSE 0.636→0.326 m；
3. **预告** = 广播 + 时延补偿让 100 ms 前的远方目标以可计算的误差出现在当前时刻。

三个 Stage 4 的老朋友在 Stage 6 各自的新岗位：**KF 在撑丢包间隙，匈牙利在做跨视角认亲，TrackID 在当跨端身份证**——这就是"学完不会用"和"学完会设计"的分水岭。

## 6. 结课自测大题（附答案）

**大题一（消息链路，30 分）**
路侧感知栈在某帧输出：`track_id=207, cls=ped, pos_enu=(12.50, 30.00) m, vel=(0.0, 1.6) m/s, conf=0.81`，感知时刻 121.20 s（分钟内 1.20 s）。请：(a) 按第 2 周简化 BSM 格式写出 speed、secMark 两个编码值；(b) 该消息经 80 ms 到达车端，车端按速度外推补偿后的位置是多少？(c) 若车端时钟比路侧慢 50 ms，补偿后的位置误差是多少？

**答案**：(a) speed = 1.6/0.02 = 80；secMark = 1200 ms。(b) age=80 ms，外推 +v·Δt = (0, 0.128) → (12.50, 30.128) m。(c) 车端以为 age=30 ms，只补 (0, 0.048)，而真实位移 0.128 m，误差 |0.128−0.048| = **0.08 m = 1.6 m/s × 50 ms 时钟差**——时钟不同步按"速度 × 时间偏差"直接折算成空间误差，且是系统性偏差，呼应 Stage 1/第 2 周时间同步。

**大题二（对齐与关联，30 分）**
RSU 在世界系报目标 p=(30, 70)，v=(0, 10) m/s；ego 在 (30, 100) 朝北（yaw=90°）；消息时延 200 ms。(a) 补偿后世界系位置？(b) 变换到 ego 系（x 前 y 左）？(c) ego 本地轨迹在 (28.5, 1.2)，门限 4 m，能否关联？

**答案**：(a) p+v·0.2 = (30, 72)（目标朝北走了 2 m，靠近自车）。(b) d=p−t=(0,−28)，ego 系 = (d_y, −d_x) = (−28, 0)——**在正后方 28 m**（目标从后方接近）。(c) 距离 √(1.5²+1.2²)=1.92 m < 4 m，可关联——注意"负 x"不是错误，后视盲区目标正是靠协同被看见的。

**大题三（系统设计，40 分）**
某高速路口要部署一套"鬼探头预警"系统：路侧 1 台 RSU（感知栈用你 Stage 1-5 的产出），车端做目标级协同融合。请列出：(a) 端到端时延预算表（三段）；(b) 消息选型（走哪条标准消息、必带哪些字段）与理由；(c) 车端融合器收到消息后的五步处理；(d) 上线前在仿真里必须验证的三个变量。

**答案（要点）**：(a) 感知 50 + 处理 30 + 通信 20 = 100 ms 量级（3GPP TS 22.185 上限口径）；行人场景 100 ms 位移 0.14 m 可接受，但系统须为车辆目标（1.39 m）留补偿。(b) 目标级走 T/CSAE 53 的 RSM（或 ETSI CPM 思路的私有化简版），必带：时间戳（secMark 类）、位置、**速度+航向**（补偿必需）、尺寸、置信度、稳定 TrackID（跨端关联必需）——每个字段对应一个已知失效模式。(c) ① 时戳有效性检查（msgCnt 连续性/丢包统计）→ ② 时延外推补偿 → ③ 外参变换到 ego 系 → ④ 门控+匈牙利与本车轨迹关联 → ⑤ 匹配者 KF 更新（路侧 R 小）、独有者进确认态补盲、超龄消息丢弃。(d) 时延（100/300/500 ms 扫描，看 RMSE 与漏检退化）、丢包率（0~20%）、路侧位姿/标定误差（坐标变换噪声对补盲目标位置的影响）——w4 脚本里每个参数都是一个可扫描的旋钮。
