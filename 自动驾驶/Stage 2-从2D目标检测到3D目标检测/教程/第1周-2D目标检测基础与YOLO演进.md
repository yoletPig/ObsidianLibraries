## 1. 检测任务定义：从分类到定位

### 1.1 三级跳

图像理解的三个经典任务，输出一个比一个"重"：

| 任务 | 输入 | 输出 | 输出数量 |
| --- | --- | --- | --- |
| 分类（classification） | 图像 | 类别标签 | 固定 1 个 |
| 分类+定位（classification + localization） | 图像 | 类别 + **1 个**框 $(x, y, w, h)$ | 固定 |
| 目标检测（object detection） | 图像 | 未知数量个（框 + 类别 + 置信度） | **未知，0~N 个** |

检测的困难几乎全部来自最后一行：输出数量未知。分类网络最后接一个固定大小的全连接层就行；检测网络必须对"画面里到底有几辆车"这种问题给出答案，还要保证框得准、类别对、不重复报。整个检测领域 20 年的结构演进，本质上都在回答两个子问题：

1. **候选框从哪来**（region proposal → anchor → anchor-free）；
2. **重复的框怎么去掉、好坏怎么评**（NMS + IoU + mAP）。

### 1.2 一个预测的完整表示

一个 2D 检测器的每个输出是：

$$
(x_1,\ y_1,\ x_2,\ y_2,\ c,\ s)
$$

**这行式子在说什么**：每个预测框 = 6 元组。$(x_1,y_1)$ 是左上角、$(x_2,y_2)$ 是右下角（xyxy 格式；另有 cxcywh 格式，两者可以互转），$c$ 是类别（多类时是一个 one-hot/多类概率向量），$s$ 是置信度分数（score，0~1），表示"我有多确信这个框里真有个目标"。置信度是后面 NMS 排序和 mAP 分档的依据——记住，**检测器输出的是"一堆带分数的框"，分数意味着"宁可多报、让后面的指标体系去筛"**。

预览一下终点：到第 2 周，这 6 元组会变成 10 元组——3D 框 $(x, y, z, w, l, h, \text{yaw})$ + 类别 + 置信度。度量衡不变，维度升级。

## 2. IoU：两个框重合程度的唯一通用语言

### 2.1 定义

交并比（Intersection over Union, IoU）：

$$
\mathrm{IoU}(A, B) = \frac{|A \cap B|}{|A \cup B|} = \frac{|A \cap B|}{|A| + |B| - |A \cap B|}
$$

**这个公式在干什么**：分子是两个框的交集面积，分母是并集面积（两个框面积之和减去交集——因为交集被加了两遍，要减掉一遍）。取值 $[0, 1]$：

- IoU = 0：两个框不挨着；
- IoU = 1：完全重合；
- IoU = 0.5：业界常用的"算命中"门槛（预测框与某个真值框 IoU ≥ 0.5 才算检出了这个目标；车这类大目标在 KITTI 用 0.7 的更严门槛，第 4 周展开）。

**结果拿来做什么**：IoU 是整个检测体系的"度量衡"——NMS 用它判断两个框是否重复，mAP 用它判断预测是否命中真值，评测集用它划分难度。它只依赖几何形状，与置信度无关。

手算一个：$A = [0,0,4,4]$（面积 16），$B = [2,2,6,6]$（面积 16）。交集 $[2,2,4,4]$ 面积 4；并集 $16+16-4=28$；IoU $= 4/28 \approx 0.143$。下面用代码验证。

### 2.2 NumPy 实现

```python
def iou_xyxy(box_a, box_b):
    """计算两个 xyxy 框的 IoU（交并比）。"""
    # 交集的左右上下边界：取两个框各自边界的"较大左/上、较小右/下"
    x1 = max(box_a[0], box_b[0])
    y1 = max(box_a[1], box_b[1])
    x2 = min(box_a[2], box_b[2])
    y2 = min(box_a[3], box_b[3])
    # 没有重叠时，宽或高会算出负数，用 clamp(0) 归零
    inter_w = max(0.0, x2 - x1)
    inter_h = max(0.0, y2 - y1)
    inter = inter_w * inter_h
    area_a = (box_a[2] - box_a[0]) * (box_a[3] - box_a[1])
    area_b = (box_b[2] - box_b[0]) * (box_b[3] - box_b[1])
    union = area_a + area_b - inter
    return inter / union
```

### 2.3 NMS：同一辆车只留一个框

非极大值抑制（Non-Maximum Suppression, NMS）解决"重复框"问题。检测网络（尤其 anchor-based 的）天然会在同一目标上激活多个 anchor，输出三四个几乎一样的框。NMS 的流程：

1. 按置信度从高到低排序；
2. 取分数最高的框，**保留**；
3. 把它与剩余每个框算 IoU，删除所有 IoU > 阈值（典型 0.5）的"重复框"；
4. 在剩下的框里重复 2-3，直到处理完。

**直觉**：真目标只会被报告一次，而且最好的那次报告置信度最高——所以"分数最高的框"大概率是对的，跟它重叠严重的都是它的回声。

```python
import numpy as np

def nms_xyxy(boxes, scores, iou_thr=0.5):
    """非极大值抑制：按分数从高到低保留框，删掉与已保留框 IoU 超阈值的框。"""
    order = np.argsort(scores)[::-1]      # 分数降序的索引
    keep = []
    while order.size > 0:
        i = order[0]                      # 当前分数最高的框
        keep.append(i)
        # 剩余每个框与 i 的 IoU
        rest = order[1:]
        ious = np.array([iou_xyxy(boxes[i], boxes[j]) for j in rest])
        order = rest[ious <= iou_thr]     # 只留下重叠不大的
    return keep

# 5 个假框：0/1/3 是同一辆车的三重检测，2/4 是另外两个目标
boxes = np.array([
    [100, 100, 210, 210],   # 0: 车 A（最高分）
    [102, 103, 214, 208],   # 1: 车 A 的重复框
    [400, 120, 500, 300],   # 2: 行人 B
    [ 98,  97, 205, 212],   # 3: 车 A 的又一个重复框
    [700, 300, 780, 380],   # 4: 骑行者 C
], dtype=np.float64)
scores = np.array([0.92, 0.81, 0.77, 0.60, 0.55])

print("两两 IoU 矩阵：")
for i in range(5):
    row = " ".join(f"{iou_xyxy(boxes[i], boxes[j]):.2f}" for j in range(5))
    print(f"  框{i}: {row}")

keep = nms_xyxy(boxes, scores, iou_thr=0.5)
print("NMS 保留的框索引:", keep)
print("保留框分数    :", scores[keep])

# 验证：车 A 的三个框只留最高分的 0 号；行人 B 和骑行者 C 都保留
assert keep == [0, 2, 4], keep
print("验证通过：3 个目标，5 个预测框去重后剩 3 个（去掉 2 个重复框）")
```

**真实运行输出**：

```
两两 IoU 矩阵：
  框0: 1.00 0.91 0.00 0.90 0.00
  框1: 0.91 1.00 0.00 0.82 0.00
  框2: 0.00 0.00 1.00 0.00 0.00
  框3: 0.90 0.82 0.00 1.00 0.00
  框4: 0.00 0.00 0.00 0.00 1.00
NMS 保留的框索引: [0, 2, 4]
保留框分数    : [0.92 0.77 0.55]
验证通过：3 个目标，8 个重复框被去掉 2 个
```

读一下 IoU 矩阵：框 0/1/3 两两 IoU 在 0.82~0.91（同一辆车），框 2、框 4 与谁都是 0。NMS 保留 {0, 2, 4} 正好每目标一个。注意**框 3（分数 0.60）被删不是因为它差，而是因为它的信息已被框 0 覆盖**。

> **动手验证**：把 `iou_thr` 改成 0.95——重复框全被保留（阈值太严）；改成 0.6——结果不变，但若框 1 与框 0 只重叠 0.55 就会漏删。阈值是"宁删勿漏"与"宁漏勿删"的旋钮，行人密集场景常用更低的阈值或后面提到的 Soft-NMS。
>
> **一句话总结**：IoU 回答"重合多少"，NMS 用它回答"谁在重复报同一个目标"。

## 3. anchor 机制：为什么先猜再修

### 3.1 直接回归框难在哪

YOLOv1 最初没有 anchor：每个网格单元直接回归 $(x, y, w, h)$。问题出在 $w, h$——它们的变化范围横跨几个数量级（近处的车宽 300 像素，远处的 30 像素），网络要在一个输出神经元上覆盖这么大的动态范围，回归误差会被放大。另外画面里目标数量、位置任意，"每个格子只报一个"的约定在相邻目标场景会丢目标。

### 3.2 anchor 的想法：把"绝对回归"变"相对修正"

anchor（锚框/先验框）是在每个位置**预设一批不同长宽比的参考框**，网络不再直接报框，而是对每个 anchor 预测修正量：

$$
b_x = \sigma(t_x) + c_x, \quad b_y = \sigma(t_y) + c_y, \quad b_w = p_w e^{t_w}, \quad b_h = p_h e^{t_h}
$$

**这行式子在干什么**：把 anchor 中心所在网格坐标记为 $(c_x, c_y)$，anchor 的宽高记为 $(p_w, p_h)$，网络原始输出是 4 个无约束实数 $(t_x, t_y, t_w, t_h)$（YOLOv2 的约定）：

- $b_x = \sigma(t_x) + c_x$：$\sigma$ 是 sigmoid，把预测压到 (0,1)——框中心只会微微偏离所在格子，不会跑到画面另一头（v1 直接回归 $x,y$ 会预测出离格子很远的框，训练不稳定）；
- $b_w = p_w e^{t_w}$：宽 = anchor 宽 × 指数修正。$t_w=0$ 时框宽就是 anchor 宽；网络只需输出"大 30% / 小 50%"这类相对量，动态范围问题消失。

**结果拿来做什么**：anchor 把问题从"从零猜框"变成"在先验上微调"，收敛更快、召回更高。代价是引入一堆超参（几个 anchor、什么尺寸——YOLOv2 用 k-means 在训练集上聚类得到）。第 2 周会看到 PointPillars 在 BEV 空间放 anchor（0° 和 90° 两个朝向），第 3 周会看到 CenterPoint 如何干脆把 anchor 也扔掉（anchor-free）。

## 4. mAP：从一个个框到一个数字

### 4.1 precision 与 recall

把所有预测框按置信度降序排列，逐个与真值匹配（IoU ≥ 阈值且该真值未被占用的算命中 TP，否则算误报 FP），然后定义累计量：

$$
P = \frac{TP}{TP + FP} = \frac{\text{累计命中数}}{\text{累计预测数}}, \qquad R = \frac{TP}{N_{gt}} = \frac{\text{累计命中数}}{\text{真值总数}}
$$

**这两个公式在干什么**：精确率（precision）回答"我报出来的框里有多少是真的"——低 precision 意味着误报多（把货箱报成行人，刹车事故）；召回率（recall）回答"真目标里我找到了多少"——低 recall 意味着漏报（没看见行人，更糟）。两者随置信度阈值此消彼长：阈值抬高，报得少而准（P↑R↓）；阈值放低，报得多而杂（P↓R↑）。

### 4.2 AP：PR 曲线下面积

把每个置信度阈值下的 $(R, P)$ 画成 PR 曲线，平均精度（Average Precision, AP）定义为曲线下面积（带 precision 包络插值）：

$$
AP = \int_0^1 P_{\text{env}}(R)\, dR
$$

**这个公式在干什么**：$P_{\text{env}}(R)$ 是"包络"——在任意 recall 处取其右侧出现过的最大 precision（数值上从右往左扫一遍取 max）。加包络是因为 PR 曲线天然锯齿抖动（报错一个框 precision 会突然掉一下再爬回来），包络把锯齿抹平，只保留"在这个召回水平上曾经达到过的最佳精度"。AP ∈ [0,1]，越大越好；mAP 就是把每一类的 AP 平均。不同基准的插值细节不同（VOC 老版 11 点采样、2010 版全点 area、COCO 用 101 点并对多个 IoU 阈值平均），思想一致。

### 4.3 小规模手算演示：8 个预测框算 AP

单类、单图、3 个真值框、8 个预测（3 个真命中、5 个误报，命中判定已由 IoU ≥ 0.5 完成）：

```python
import numpy as np

# 每行 = [置信度, 是否命中]。"是否命中"是提前用 IoU>=0.5 匹配 GT 判定好的
# 8 个预测框：3 个真命中(TP)、5 个误报(FP)；图中共 3 个 GT
dets = np.array([
    [0.95, 1],   # TP
    [0.90, 0],   # FP
    [0.85, 1],   # TP
    [0.80, 1],   # TP
    [0.70, 0],   # FP
    [0.60, 0],   # FP
    [0.50, 0],   # FP
    [0.30, 0],   # FP
])
conf = dets[:, 0]
tp = dets[:, 1].astype(bool)
n_gt = 3

# 按置信度降序累计 TP/FP（本例已按降序排列）
tp_cum = np.cumsum(tp)
fp_cum = np.cumsum(~tp)
recall    = tp_cum / n_gt
precision = tp_cum / (tp_cum + fp_cum)

print(" 置信度  TP累计 FP累计  P      R    类型")
for c, t, f, p, r in zip(conf, tp_cum, fp_cum, precision, recall):
    print(f"  {c:.2f}    {t}      {f}     {p:.3f}  {r:.3f}   {'TP' if tp[list(conf).index(c)] else 'FP'}")

# AP = PR 曲线下面积：先从右往左取 precision 包络，再逐段积分
mrec = np.concatenate(([0.0], recall, [1.0]))
mpre = np.concatenate(([0.0], precision, [0.0]))
for i in range(len(mpre) - 2, -1, -1):        # 包络：任何 recall 处取右侧最大 precision
    mpre[i] = max(mpre[i], mpre[i + 1])
idx = np.where(mrec[1:] != mrec[:-1])[0]      # recall 发生变化的格点
ap = np.sum((mrec[idx + 1] - mrec[idx]) * mpre[idx + 1])
print(f"\n代码积分 AP = {ap:.4f}")

# 手工分段核对：包络在 R=1/3 处=1.0，在 R=2/3 与 R=1 处均为 0.75
ap_hand = (1/3 - 0) * 1.0 + (2/3 - 1/3) * 0.75 + (1 - 2/3) * 0.75
print(f"手工分段积分 AP = {ap_hand:.4f}")
assert abs(ap - ap_hand) < 1e-9
print("验证通过：AP = 1/3×1.0 + 1/3×0.75 + 1/3×0.75 = 0.8333")
```

**真实运行输出**：

```
 置信度  TP累计 FP累计  P      R    类型
  0.95    1      0     1.000  0.333   TP
  0.90    1      1     0.500  0.333   FP
  0.85    2      1     0.667  0.667   TP
  0.80    3      1     0.750  1.000   TP
  0.70    3      2     0.600  1.000   FP
  0.60    3      3     0.500  1.000   FP
  0.50    3      4     0.429  1.000   FP
  0.30    3      5     0.375  1.000   FP

代码积分 AP = 0.8333
手工分段积分 AP = 0.8333
验证通过：AP = 1/3×1.0 + 1/3×0.75 + 1/3×0.75 = 0.8333
```

**逐行读懂这张表**：

1. 前 4 个预测把 3 个真值全部命中（R 到 1.0），中途穿插了 1 个误报，所以 P 一路在 0.5~1.0 间抖动；
2. 第 5 个之后的预测全是 FP——recall 已经饱和在 1.0，只能往下拖 precision；
3. 包络抹掉抖动后只剩三个台阶：R∈[0, 1/3] 上 P=1.0，R∈[1/3, 2/3] 上 P=0.75（= max(2/3, 0.75)），R∈[2/3, 1] 上 P=0.75。分段积分 $\frac{1}{3}×1.0 + \frac{1}{3}×0.75 + \frac{1}{3}×0.75 = 0.8333$。

**注意**：那 5 个 FP 全部排在低置信度区间——这就是置信度的价值：**排序质量决定 AP**。同样的命中数，如果误报都排在前面，AP 会显著变差。AP 衡量的不是"报没报对"，而是"真目标是否总是排在假目标前面"。

## 5. YOLO 主线演进：每一代改了什么

YOLO（You Only Look Once）是把检测做成单次前向回归的开山系列，也是工程上最常被问到的一条主线。核心事实（均已对照论文/官方发布核实）：

| 版本 | 发表时间/出处 | 关键创新 | 一句话评价 |
| --- | --- | --- | --- |
| YOLOv1 | CVPR 2016（arXiv 2015-06） | 把检测统一成单网络回归：$7×7$ 网格，每格预测框+类别，一次前向出全部结果 | 速度起飞（45 FPS 级），但定位粗、相邻目标易丢 |
| YOLOv2 / YOLO9000 | CVPR 2017（arXiv 2016-12） | **引入 anchor**（k-means 聚类先验）+ 全卷积层 BatchNorm + 高分辨率微调（416²）+ 多尺度训练 | 上面 3.2 节那组公式的出处；精度大幅回升 |
| YOLOv3 | arXiv 技术报告 2018-04 | **3 尺度预测**（借助类似 FPN 的结构，9 个 anchor 分 3 组）+ Darknet-53（残差骨干）+ sigmoid 多标签分类 | 小目标显著改善；从此 YOLO 都是"多尺度单阶段"形态 |
| YOLOv5 | 2020，Ultralytics（GitHub 开源，**无论文**） | 首个原生 PyTorch 版；工程化（自动 anchor、Mosaic 增广、多种模型尺寸 n/s/m/l/x、易部署导出） | "工程化胜利"：没有论文却成为工业界最广泛使用的版本之一 |
| YOLOv8 | 2023-01，Ultralytics（**无论文**） | **anchor-free 解耦头**（分类与回归分家）+ C2f 模块 + 统一 API | 回答了 3.2 的伏笔：anchor 时代开始落幕 |

**FPN 一句话**：特征金字塔网络（Feature Pyramid Network, FPN，CVPR 2017）把骨干网络里"深而弱、空间粗"的低分辨率特征图上采样，与"浅而细、空间精"的高分辨率特征图逐级相加，让每个尺度都能同时拿到语义和细节——YOLOv3 起的"多尺度预测"就是它的直接应用。

**演进的内在逻辑**（面试考点）：v1 解决"能不能一次前向做检测"，v2 用 anchor 解决"回归不稳定"，v3 用多尺度解决"小目标"，v5 用工程解决"好不好用"，v8 用 anchor-free 解决"超参太多"。同一个"简化部署、保持精度"的主线，在第 3 周的 CenterPoint 上会原样重演一遍——2D 检测史就是 3D 检测史的预演。

## 6. 工程权衡与常见坑

1. **IoU 阈值与"Don't Care"区域**：0.5 门槛是惯例而非真理。小目标 IoU 对几个像素的偏移极其敏感（同一偏移量，小框 IoU 掉得多），所以小目标为主的场景要小心解释 AP 的波动。
2. **NMS 必须按类别分别做**：一辆车和一个行人可以重叠（车挡着人），跨类别去重会误删。所有框架的 NMS 默认 class-wise，自己实现时最容易漏。
3. **NMS 在置信度过滤之前还是之后**：正确姿势是先用低阈值（如 0.01）粗筛再 NMS（省计算），评测时再扫全部分数段算 AP。直接砍掉低分框会高估 precision。
4. **AP 插值口径不一致**：比较两个模型的 AP 前先确认是不是同一种插值（VOC11 点 / VOC2010 area / COCO 101 点结果不同）；KITTI 用 R40（第 4 周展开），写论文报数字要标注 R11 还是 R40。
5. **"召回 100% 但 AP 低"**：说明都报出来了但排序烂（误报混进了高分段），去查置信度校准而不是查召回。

## 7. 延伸思考题（含解析）

**Q1**：为什么 mAP 用"面积"而不用"某个固定阈值下的 precision"？
**A**：固定阈值只反映一个工作点；部署时阈值可调，不同场景要不同的 P/R 权衡。面积积分覆盖所有工作点，是对整个排序质量的综合评价。

**Q2**：NMS 的 IoU 阈值设 0.3 和 0.7 分别会怎样？
**A**：0.3 太激进，靠得近的两个真目标（如并排停车的两个车门区域）会被误删一个，recall 下降；0.7 太宽松，重复框留下来，precision 下降、下游跟踪可能出现同一个车两条轨迹。

**Q3**：YOLOv2 的 $b_w = p_w e^{t_w}$ 里为什么用 $e$ 而不是线性修正？
**A**：宽高恒为正，线性修正会预测出负宽；乘性（对数空间）修正既保证正性，又让"翻倍/减半"在数值上对称（$t_w=±\ln 2$），且大目标的修正量自然放大、小目标自然缩小，尺度自适应。

**Q4**：把 4.3 的例子改成"GT=3，预测 4 个全 TP"，AP 是多少？
**A**：R/P 序列 = (1/3, 1), (2/3, 1), (1, 1)，包络恒为 1，AP = 1.0。AP=1 只需要"真目标排在误报前面"，与报不报误报无关——误报全排在最后即可。
