## 1. 评测为什么重要：同一个模型，两张榜单两种人生

3D 检测领域的两大主流评测基准（benchmark）——KITTI 和 nuScenes——用了**完全不同**的匹配逻辑：

| 维度 | KITTI | nuScenes |
| --- | --- | --- |
| 匹配方式 | 3D IoU / BEV IoU ≥ 阈值（car 0.7，行人/骑行者 0.5） | BEV 中心距离 ≤ 0.5/1/2/4 m（**不用 IoU**） |
| 汇总指标 | AP@R40，难度分 Easy/Mod/Hard 三列 | mAP（四档距离平均）+ 5 项 TP 错误 → 合成 NDS |
| 数据形态 | 单帧（tracking 另有基准），城郊驾驶 | 1000 个 20 s 场景，城市驾驶（波士顿/新加坡），6 相机 + 1 雷达 + 5 毫米波 |
| 朝向怎么评 | 单独的 AOS 指标（cosine 相似度） | 并入 AOE（朝向误差，弧度） |

**这带来一个直接后果**：一个 IoU 偏低但中心很准的模型（常见于远处小目标），在 KITTI 上吃亏、在 nuScenes 上占便宜；反之朝向回归烂的模型，KITTI 的主指标看不见问题，nuScenes 的 AOE 直接补刀。**读懂评测协议是读懂论文数字的前提**——下面两节分别拆解。

## 2. KITTI 评测：IoU 门派

### 2.1 匹配与阈值

KITTI（cvlibs.net/datasets/kitti，Geiger et al. 2012）沿用 PASCAL VOC 思路：预测框与真值框按 IoU 匹配（一个真值只能被一个预测占用，剩余预测记 FP），但 IoU 从 2D 像素框升级为两种 3D 形态：

- **BEV IoU**：鸟瞰图（Bird's Eye View）上两个带朝向矩形的交并比——本周第 5 节手写的就是它；
- **3D IoU**：两个长方体的体积交并比，多乘一个 z 方向重叠（第 5.4 节说明两者关系）。

官方匹配阈值（KITTI 官方评测页查证）：

| 类别 | 3D/BEV IoU 阈值 |
| --- | --- |
| Car（汽车） | **0.7** |
| Pedestrian（行人）/ Cyclist（骑行者） | **0.5** |

**为什么 car 用 0.7 而行人只要 0.5**：车是大目标（约 1.6×3.9×1.5 m），朝向和尺寸标得很准，用严阈值能区分出"框得真好"和"大致框对"；行人目标小、姿态多变，0.7 阈值下随机抖动就能把对的框判成错的，指标失去区分度。**阈值是相对目标尺寸校准的，不是越严越好**。

### 2.2 Easy / Moderate / Hard：官方难度定义

KITTI 官方评测页给出的三档难度（按**最难条件**归档——一个真值只要触碰任何一条上限就被降到更难一档）：

| 难度 | 最小框高（Min. bounding box height） | 最大遮挡（Max. occlusion） | 最大截断（Max. truncation） |
| --- | --- | --- | --- |
| Easy | 40 px | 完全可见（Fully visible） | 15 % |
| Moderate | 25 px | 部分遮挡（Partly occluded） | 30 % |
| Hard | 25 px | 难以看清（Difficult to see） | 50 % |

**逐项解读**：

- **框高阈值**：标注框在**图像平面**上的像素高度。0.7 m 高的行人，框高 40 px 大约对应 13 m 内——这是用"图像上的大小"近似"距离"（远且小的目标点云只有十几个点，检出难度完全不同，第 1 周 Stage 1 的近密远疏在此回收）；
- **遮挡**：0 = 完全可见，1 = 部分遮挡，2 = 难以看清（ largely occluded 的大半被挡）。Easy 档只收遮挡级 0 的目标；
- **截断**：目标伸出图像边界的比例。截断 50% 的行人只剩半边，检出价值与难度都不同。

**榜单排名以 Moderate 列为准**（官方页面明说 "Methods are ranked on the moderately difficult results"）。所以论文摘要里那句 "our method achieves 82.63 AP on KITTI test" 几乎总是指 Car Moderate @R40。

### 2.3 R11 → R40：recall 采样点数

第 1 周的 AP 是 PR 曲线下面积，数值积分要在若干个 recall 采样点上取值：

- **R11**（老版）：仿 PASCAL VOC 2011 以前，在 recall = {0, 0.1, ..., 1.0} 共 11 个点取最大 precision 平均；
- **R40**（现行）：**2019-10-08 起**，KITTI 官方采用 40 个均匀 recall 采样点（官方说明此举参考 MonoDIS 论文的分析，"yields a more fair comparison"）。

R11 的 11 个点太稀，两个模型只在 11 个格点上比高下，偶然性大；R40 把采样密度提高近 4 倍，对 PR 曲线的刻画更细。**读旧论文（2019-10 前）的数字要注意口径**：R11 和 R40 的同一模型 AP 能差 1~3 个点，混着比就是耍流氓。

## 3. nuScenes 评测：中心距离门派

### 3.1 为什么不用 IoU

nuScenes（Motional，arXiv 1903.11027，CVPR 2020）的检测评测（官方 devkit 文档查证）不用 IoU 匹配，改用 **BEV 平面真值中心与预测中心的欧氏距离**：

$$
d_{\text{center}} = \left\| (x_{pred}, y_{pred}) - (x_{gt}, y_{gt}) \right\|_2
$$

**这个公式在干什么**：只看俯视平面上两个中心的直线距离（米），与尺寸、朝向、置信度无关。距离 ≤ 阈值即算命中。官方在 {**0.5, 1, 2, 4**} m 四档阈值下分别算 AP，再取平均得到 mAP。

**为什么放弃 IoU**（nuScenes 论文的理由）：① 旋转框 IoU 计算贵（本周第 5 节你会亲手体会到：角点+多边形裁剪一整套），评测数百万预测时成本高；② 更本质的是，IoU 匹配把"中心偏了一点"和"朝向差了 90°"混在一个数里——一个中心精准但朝向全错的框，IoU 可能仍然达标，问题被掩盖。中心距离把"定位"单独拎出来评，朝向、尺寸、速度各自有专门的指标（见 3.3）——**一个 IoU 拆成六个正交指标**。

另一个与 KITTI/COCO 的不同：mAP 是"对 recall、precision > 0.1 的 PR 曲线段积分"——曲线两端（recall 或 precision ≤ 0.1 的部分）不参与积分，避免"靠最后几个零散检出撑面积"的刷分方式。

### 3.2 mAP 与 KITTI 的三个不同

| | KITTI AP | nuScenes mAP |
| --- | --- | --- |
| 匹配 | IoU ≥ 单一阈值（每类固定） | 中心距离 ≤ 四档阈值平均 |
| 朝向/尺寸 | 隐含在 IoU 里 | 不参与匹配（另有 AOE/ASE） |
| recall 采样 | 40 点（R40） | PR 曲线积分（recall/precision > 0.1） |

### 3.3 五项 TP 错误（True Positive metrics）

在**中心距离 2 m 匹配**下（官方 devkit：TP metrics 用 2 m 阈值），对每个命中框计算五项"单属性"误差，再对类别取平均（m 前缀）。全部是**越小越好**的正数：

| 指标 | 全称 | 测什么 | 单位/定义 |
| --- | --- | --- | --- |
| **ATE** | Average Translation Error | 中心定位误差 | BEV 中心欧氏距离（米） |
| **ASE** | Average Scale Error | 尺寸误差 | **1 − IoU**（先把框的中心与朝向对齐后再算 IoU，纯看尺寸） |
| **AOE** | Average Orientation Error | 朝向误差 | 最小 yaw 差（弧度；barrier 类 180° 封顶） |
| **AVE** | Average Velocity Error | 速度误差 | 速度向量差的模（m/s） |
| **AAE** | Average Attribute Error | 属性分类误差 | 1 − 属性分类准确率 |

**注意两处"对齐"技巧**：ASE 先把中心朝向对齐再算 IoU，保证它只测"高宽长准不准"；AOE 取"最小 yaw 差"是因为车头朝向有 180° 对称性（一辆车头朝北和朝南的框，对检测而言可能都对）——这与第 3 周坑 1"sin/cos 解码丢 180°"呼应，但方向相反：**模型端要区分车头车尾（朝向 bin），评测端反而允许 180° 误差**。

### 3.4 NDS：一个数字合成公式

nuScenes 检测分数（nuScenes Detection Score, NDS）官方 devkit 公式：

$$
\text{NDS} = \frac{5 \cdot \text{mAP} + \sum_{i \in \{TP\}} \max(1 - \text{m}TP_i,\ 0)}{10}
$$

**这个公式在干什么**（逐项拆）：

- $\max(1 - \text{m}TP_i, 0)$：把五项"越小越好"的误差翻转成"越大越好"的得分——误差 0.2 m 的 ATE 得 0.8 分；误差超过 1 时得分钳到 0（否则会出现负分，一个烂指标倒扣其他指标的分）；
- **权重 5 : 1 : 1 : 1 : 1 : 1**：mAP 占总分的一半，五项 TP 错误合计占另一半——设计者认为"检出没有"仍然是最重要的事，但"检出了但朝向/速度/尺寸全烂"也必须能在总分里体现；
- 分母 10 = 5 + 5，归一到 [0, 1]。

**结果拿来做什么**：NDS 是"既能查漏检、又能查质量"的综合分。一个 mAP 高但 AOE 巨大的模型（典型的：没好好学朝向），KITTI 主指标看不见，NDS 会直接掉 10% 以上——这就是 nuScenes 榜单上 mAP 排名与 NDS 排名经常不一致的原因。

### 3.5 手算一个 NDS（代码验证）

```python
import numpy as np

# ---- 假设只有一个类别"car"，评测器给出四个匹配档下的 AP ----
aps = {"0.5m": 0.20, "1m": 0.40, "2m": 0.60, "4m": 0.80}
mAP = np.mean(list(aps.values()))
print(f"各中心距离阈值下的 AP: {aps}")
print(f"mAP = mean(0.2, 0.4, 0.6, 0.8) = {mAP:.4f}")

# ---- 5 类 TP 错误（各类平均后的均值），先换成得分 max(1 - err, 0) ----
errs = {"mATE": 0.30, "mASE": 0.20, "mAOE": 0.10, "mAVE": 0.20, "mAAE": 0.10}
scores = {k: max(1.0 - v, 0.0) for k, v in errs.items()}
for k in errs:
    print(f"{k}: 误差 {errs[k]:.2f} -> 得分 1-err = {scores[k]:.2f}")

# ---- NDS = (5*mAP + sum(TP scores)) / 10 ----
nds = (5 * mAP + sum(scores.values())) / 10
print(f"NDS = (5 x {mAP:.1f} + {sum(scores.values()):.2f}) / 10 = {nds:.4f}")
assert abs(nds - 0.66) < 1e-9
print("验证通过：NDS = (5x0.5 + 0.7+0.8+0.9+0.8+0.9)/10 = (2.5+4.1)/10 = 0.66")
```

**真实运行输出**：

```
各中心距离阈值下的 AP: {'0.5m': 0.2, '1m': 0.4, '2m': 0.6, '4m': 0.8}
mAP = mean(0.2, 0.4, 0.6, 0.8) = 0.5000
mATE: 误差 0.30 -> 得分 0.70
mASE: 误差 0.20 -> 得分 0.80
mAOE: 误差 0.10 -> 得分 0.90
mAVE: 误差 0.20 -> 得分 0.80
mAAE: 误差 0.10 -> 得分 0.90
NDS = (5 x 0.5 + 4.10) / 10 = 0.6600
验证通过：NDS = (5x0.5 + 0.7+0.8+0.9+0.8+0.9)/10 = (2.5+4.1)/10 = 0.66
```

读一遍：这个假想模型 mAP 只有 0.5，但五项误差都小，NDS 拿到 0.66——**TP 错误项贡献了 (4.1/10) ≈ 62% 的总分**（4.1 ÷ 6.6）。反过来若 mAP = 0.6 而 AOE = 1.2（超 1 钳 0），NDS 掉到 (3.0 + 3.2)/10 = 0.62。这就是"nuScenes 更宽容匹配 + TP 补刀"的定量感受。

> **动手验证**：把 `errs` 里的 mAOE 改成 1.5（朝向彻底没学），NDS 变成多少？再想想为什么 nuScenes 榜单上 CenterPoint 论文报告两阶段 65.5 NDS，而某些 mAP 更高的方法 NDS 反而更低。

## 5. 手写 BEV 旋转框 IoU（本周核心交付）

### 5.1 问题：矩形一转，"最大最小值"就失效了

第 1 周的 IoU 对轴对齐框只要四个 max/min 就能算交集；框一旦带朝向，交集变成**两个凸多边形的交**——不能用坐标夹逼，要走计算几何：

1. **角点展开**：7 自由度框 $(x, y, w, l, \text{yaw})$ → BEV 平面 4 个角点；
2. **凸多边形裁剪**：用其中一个矩形（凸）逐边裁剪另一个矩形，得到交集多边形——经典算法是 **Sutherland–Hodgman**；
3. **鞋带公式（shoelace）**：算交集多边形面积，代回 IoU 定义。

### 5.2 完整实现 + 5 组验证

```python
# exp5_bev_rotated_iou.py（归档于 实验脚本/）—— BEV 旋转框 IoU（角点展开 + Sutherland–Hodgman 裁剪 + 鞋带公式）
import numpy as np


def box2corners(x, y, w, l, yaw):
    """BEV 旋转框 (x,y,w,l,yaw) -> 4 个角点，逆时针顺序，shape (4,2)。
    约定：l 沿朝向 yaw 方向，w 垂直朝向。"""
    # 本体坐标系（车头朝 +x_local）：沿 l 的半长、沿 w 的半宽，按逆时针排列
    local = np.array([
        [ l/2, -w/2],
        [ l/2,  w/2],
        [-l/2,  w/2],
        [-l/2, -w/2],
    ])
    c, s = np.cos(yaw), np.sin(yaw)
    R = np.array([[c, -s], [s, c]])
    return local @ R.T + np.array([x, y])


def poly_area(poly):
    """鞋带公式（shoelace）计算多边形面积，输入 (K,2)。"""
    x, y = poly[:, 0], poly[:, 1]
    return 0.5 * abs(np.dot(x, np.roll(y, -1)) - np.dot(y, np.roll(x, -1)))


def clip_convex(subject, clip):
    """Sutherland–Hodgman：用凸多边形 clip 裁剪 subject，返回裁剪后顶点。
    两个多边形都须是逆时针。"""
    output = subject
    n = len(clip)
    for i in range(n):
        a, b = clip[i], clip[(i + 1) % n]
        # 边 a->b 的"内侧" = 叉积 >= 0（左侧）
        edge = b - a
        inputs = output
        output = []
        if len(inputs) == 0:
            break
        def inside(p):
            return np.cross(edge, p - a) >= -1e-12
        p_prev = inputs[-1]
        prev_in = inside(p_prev)
        for p in inputs:
            cur_in = inside(p)
            if cur_in != prev_in:
                # 线段 p_prev->p 与直线 a->b 求交
                t = np.cross(a - p_prev, edge) / np.cross(p - p_prev, edge)
                output.append(p_prev + t * (p - p_prev))
            if cur_in:
                output.append(p)
            p_prev, prev_in = p, cur_in
    return np.array(output)


def bev_rotated_iou(box_a, box_b):
    """两个 BEV 旋转框的 IoU。输入 (x, y, w, l, yaw)。"""
    ca = box2corners(*box_a)
    cb = box2corners(*box_b)
    area_a = poly_area(ca)
    area_b = poly_area(cb)
    inter_poly = clip_convex(ca, cb) if area_a > 0 and area_b > 0 else []
    inter = poly_area(inter_poly) if len(inter_poly) >= 3 else 0.0
    union = area_a + area_b - inter
    return inter / union if union > 0 else 0.0


def point_in_box(p, box):
    """蒙特卡洛用：判断点是否在旋转框内（转到本体坐标判 |lx|,|ly|）。"""
    x, y, w, l, yaw = box
    c, s = np.cos(yaw), np.sin(yaw)
    dx, dy = p[:, 0] - x, p[:, 1] - y
    lx = c * dx + s * dy          # R^T @ d 的第一行
    ly = -s * dx + c * dy
    return (np.abs(lx) <= l/2) & (np.abs(ly) <= w/2)


def iou_monte_carlo(box_a, box_b, n=200_000, rng=None):
    """蒙特卡洛撒点估计 IoU（用于交叉验证解析值）。"""
    rng = rng or np.random.default_rng(7)
    corners = np.vstack([box2corners(*box_a), box2corners(*box_b)])
    lo, hi = corners.min(0) - 0.5, corners.max(0) + 0.5
    pts = rng.uniform(lo, hi, size=(n, 2))
    ina = point_in_box(pts, box_a)
    inb = point_in_box(pts, box_b)
    area_rect = np.prod(hi - lo)
    inter = (ina & inb).mean() * area_rect
    union = (ina | inb).mean() * area_rect
    return inter / union


if __name__ == "__main__":
```

### 5.3 逐模块解读

- **box2corners**：本体坐标里按逆时针排 4 个角（沿车头 ±l/2、沿车宽 ±w/2），旋转矩阵 $R$ 转到世界系再加中心。**逆时针顺序是后面一切的前提**——Sutherland–Hodgman 的"内侧"判定（叉积 ≥ 0）依赖顶点顺序一致；
- **clip_convex**：对裁剪多边形的每条边，把被裁多边形的顶点序列走一遍：出界进界的过渡点求交插入，界内点保留。两矩形相交时交集最多 8 个顶点（两个"十字"交点 × 各边）；
- **蒙特卡洛交叉验证**：在一个包围盒里撒 20 万个均匀点，落在"两框交"与"两框并"里的频率 × 包围盒面积 = 交/并面积的估计。撒点估计的统计误差 ∝ $1/\sqrt{N}$，20 万点在 IoU ≈ 0.3 量级下误差约千分之几，足以确认解析实现没有大错。

**工程建议**：真实评测/训练代码用 `shapely`（`box(...).intersection(...)`）或框架自带的旋转 IoU CUDA 核；手写版的价值在于让你理解"旋转 IoU 到底在算什么"，以及面试时能白板推出来。

### 5.4 BEV IoU 与 3D IoU 的关系

BEV IoU 是**近似**：只看俯视图，忽略 z 方向。设两框 z 区间分别为 $[z_1, z_1+h_1]$、$[z_2, z_2+h_2]$，则：

$$
\text{IoU}_{3D} = \text{IoU}_{BEV} \times \frac{\text{z 方向重叠高度}}{\text{z 方向并集高度}}
$$

**这个公式在干什么**：3D 交集体积 = BEV 交集面积 × z 重叠高度；3D 并集体积不是简单的乘积展开，但上式给出了正确的分解思路——BEV 完全重合（IoU_BEV = 1）的两框，若一辆在桥上、一辆在桥下（z 重叠为 0），3D IoU 仍是 0。KITTI 的 car 目标高度相似且贴地，BEV IoU 与 3D IoU 差别不大，所以工程上常用更便宜的 BEV IoU 做训练时的匹配；但**悬空/多层场景两者会系统性背离**。nuScenes 干脆绕开两者用中心距离，也是规避旋转 IoU 计算成本的一种选择。

- **OpenPCDet**（open-mmlab 团队主导的 PCDet 体系，GitHub 4k+ star）：点云 3D 检测的"参考实现"库，PointPillars/SECOND/CenterPoint/PV-RCNN 全都有官方配置，代码结构清晰（dataloader → 模型 → 头 分层），**第 5 周机动周推荐用它跑预训练 PointPillars**，把第 2 周的 shape 链逐项对照；

两库的关系像"专题精装房 vs 大型精装商城"：学原理、改结构用 OpenPCDet 顺手；比模型、找 baseline 用 MMDetection3D 全。

## 7. 工程权衡与常见坑

1. **R11/R40 口径混用**：复现 2019 年以前的论文时，他们报的是 R11 数字，与现行榜单直接对比会"虚低"。看 KITTI 论文表先找脚注有没有说明 recall 位置。
2. **3D IoU 的中心锚点歧义**：KITTI 标注锚点是**框底部中心**，nuScenes 是**几何中心**（第 2 周 1 节提过）——评测脚本里 z 锚点不一致会把所有框"平移半个车高"，3D IoU 全线下降，BEV IoU 却看不出来（z 不参与）——这是"BEV IoU 达标但 3D 指标离奇低"的头号原因。
3. **nuScenes mAP 的 >0.1 截断**：复现评测时漏掉"recall/precision > 0.1 才积分"的条件，mAP 会系统性偏高（把长尾的零面积段算了进去）。
4. **TP 错误的"忽略类"**：barrier 不评 AOE/AVE/AAE，锥桶不评 AVE/AAE——自己写 NDS 汇总时若不按类屏蔽，会把无效误差平均进去拉低分数。
5. **蒙特卡洛验证的包围盒**：撒点包围盒若不含两框并集的边缘，估计偏大；代码里 `±0.5` 的余量别删。
6. **评估时的置信度 filtering**：与第 1 周坑 3 相同——先卡阈值再算 AP 会低估；评测协议要求把所有预测按分数排序参与计算。

## 8. 延伸思考题（含解析）

**Q1**：为什么 KITTI 用图像上的框高（40/25 px）划分难度，而不是直接用距离？
**A**：KITTI 没有给出"每个目标距离"的官方字段吗？其实有（点云可算），但 2012 年设计时想沿用 PASCAL 传统且框高与"点云里有多少点"单调相关（近→大→点多）。框高是"目标在两个模态里共同可见的大小"代理，图像/点云都受它约束。副作用：同一难度档内实际距离范围很宽。

**Q2**：一个模型朝向回归全错（都差 90°），KITTI car AP@0.7 和 nuScenes mAP、NDS 各会怎么变？
**A**：KITTI：旋转 90° 的框 IoU 大幅下降（长宽互换），AP@0.7 崩；nuScenes：mAP 几乎不变（匹配只看中心距离），但 AOE ≈ 1.57 → TP 得分 0 → NDS 掉约 10 个点。这就是 3.4 节"NDS 补刀"的具象化。

**Q3**：nuScenes 为什么匹配阈值给到 4 m 那么宽？
**A**：四档平均等价于"对定位误差的积分"——0.5 m 档筛精定位，4 m 档保底粗糙检出。城市路口场景下，远处行人的中心误差普遍在 1~2 m，若只用 0.5 m 一档，mAP 会低到失去区分度。多档平均让"检出"与"定位好"分档计分。

**Q4**：手写的 `bev_rotated_iou` 在什么输入下会出错或变慢？
**A**：① 顶点顺序若被改成顺时针，叉积"内侧"判定反转，交集算成 0——顺序是隐式契约；② 大量框两两算 IoU（NMS/匹配）时 Python 循环是瓶颈，生产用向量化角点 + shapely 批量或 CUDA 核；③ 数值上 `1e-12` 的容差防浮点抖动，去掉后共点边界情况会闪断。

**Q5**：同一个模型在 KITTI 上 Car Moderate AP = 0.85，在 nuScenes 上 car mAP 只有 0.6，模型是不是退步了？
**A**：不能直接比。场景难度（城市 vs 城郊）、类别数（3 类 vs 10 类）、匹配协议（IoU 0.7 vs 中心距离四档平均）全都不同。跨数据集比较的唯一合法方式是"同一数据集内的相对排名"，或者把模型在两个集上都跑一遍看各自的相对提升。
