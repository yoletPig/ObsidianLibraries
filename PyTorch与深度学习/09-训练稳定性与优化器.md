## 1. 权重初始化

### 1.1 为什么需要它

前向传播是矩阵乘的串联：$h_{l+1} = W_l h_l + b_l$。若 $W$ 的元素方差是 $\mathrm{Var}(W)$，则输出方差大致为（以独立零均值元素近似推导）：

$$\mathrm{Var}(h_{l+1,j}) = \sum_{i=1}^{n_{in}} \mathrm{Var}(W_{ji})\,\mathrm{Var}(h_{l,i}) = n_{in}\,\mathrm{Var}(W)\,\mathrm{Var}(h_{l,i})$$

**每过一层，方差被乘上 $n_{in} \cdot \mathrm{Var}(W)$**。默认 `nn.Linear` 的初始化是 $U[-1/\sqrt{n_{in}}, 1/\sqrt{n_{in}}]$（方差 $= \frac{1}{3n_{in}}$），网络一深激活逐层收缩；反过来初始化过大则逐层爆炸。5 章的连乘在**前向**的镜像。

### 1.2 Xavier 初始化（tanh/sigmoid 网络）

目标：前向**方差守恒**——令 $n_{in}\,\mathrm{Var}(W) = 1$。同时考虑反向传播的方差守恒（用 $n_{out}$），取折中（Glorot & Bengio, *Understanding the difficulty of training deep feedforward neural networks*, AISTATS 2010）：

$$\mathrm{Var}(W) = \frac{2}{n_{in} + n_{out}} \qquad \text{(Glorot normal: } W \sim N(0, 2/(n_{in}+n_{out}))\text{)}$$

### 1.3 Kaiming 初始化（ReLU 网络）

ReLU 会把一半激活置零，**方差被砍半**——同样 $n_{in}\mathrm{Var}(W)$ 的增益下输出方差只剩一半，深层连乘照样衰减（He et al., *Delving Deep into Rectifiers*, ICCV 2015，ResNet 同作者）。补偿一半的损失：

$$\mathrm{Var}(W) = \frac{2}{n_{in}} \qquad \text{(Kaiming normal: } W \sim N(0, 2/n_{in})\text{)}$$

直觉总结：**Xavier 保 tanh 世界的方差，Kaiming 为 ReLU 的"减半"加倍**。卷积层的 $n_{in}$ = `in_channels × kH × kW`。

```python
import torch, math
import torch.nn as nn

conv = nn.Conv2d(64, 128, 3)         # n_in = 64*3*3 = 576, n_out = 128*3*3 = 1152
print(math.sqrt(2 / (576 + 1152)))   # Xavier std  ≈ 0.0340
print(math.sqrt(2 / 576))            # Kaiming std ≈ 0.0589
nn.init.kaiming_normal_(conv.weight, nonlinearity="relu")
nn.init.zeros_(conv.bias)            # 偏置一律 0(无争议的惯例)

# 8 章 miniGPT 用的 normal(0, 0.02) 不是推出来的, 是 GPT-2 论文的工程设定:
# 模型够深时按层数缩放(残差流方差随深度累积), 0.02 是实践出来的稳定值(经验做法)
```

## 2. 归一化家族：BN / LN / RMSNorm

6 章讲过 BN（沿 $(N,H,W)$ 每通道归一化，依赖 batch 统计量）。补齐另外两位：

$$\text{LayerNorm: } \hat{x} = \frac{x - \mu_{\text{特征维}}}{\sqrt{\sigma^2_{\text{特征维}} + \epsilon}} \odot \gamma + \beta \qquad \text{RMSNorm: } \hat{x} = \frac{x}{\sqrt{\tfrac{1}{d}\sum_i x_i^2 + \epsilon}} \odot \gamma$$

| | BatchNorm | LayerNorm | RMSNorm |
| --- | --- | --- | --- |
| 统计维度 | 每通道, 跨 $(N,H,W)$ | 每样本, 跨特征维 | 每样本, 跨特征维 |
| 依赖 batch | **是**(小 batch 失效) | 否 | 否 |
| train/eval 行为不同 | 是(running stats) | 否 | 否 |
| 中心化(减均值) | 是 | 是 | **否**(只除 RMS) |
| 缩放/平移参数 | γ, β | γ, β | 仅 γ |
| 典型战场 | CNN 视觉 | Transformer(原版) | LLaMA/Mistral 等现代 LLM |

RMSNorm（Zhang & Sennrich, *Root Mean Square Layer Normalization*, NeurIPS 2019）去掉均值中心化和偏置，少一次统计、少一组参数，效果不降——LLaMA 系全线采用。**为什么 Transformer 不用 BN**：变长序列上"每通道跨 batch"的统计会被 padding 污染，且小 batch（大模型训练常态）统计噪声大；LN 按样本算，与 batch 无关。

```python
x = torch.randn(2, 3, 4)          # (B, T, C)
ln = nn.LayerNorm(4)              # 对最后一维归一化
print(ln(x).mean(dim=-1))         # 每个位置均值 ≈ 0, 方差 ≈ 1
```

## 3. warmup 与学习率调度

### 3.1 为什么需要 warmup

两个互相印证的理由：

1. **Adam 的二阶矩冷启动**：$v$ 从 0 开始指数平均，前期 $\hat v$ 偏小、$\hat m/\sqrt{\hat v}$ 的步长被放大，梯度估计又最不可靠（参数乱）——**开局最容易一步迈飞**。RAdam（Liu et al., *On the Variance of the Adaptive Learning Rate and Beyond*, ICLR 2020）从方差角度论证了这一不稳定性。
2. **Transformer 的实践证据**：原论文用 4000 步线性 warmup（公式 $\text{lr} = d^{-0.5}\cdot\min(step^{-0.5},\ step\cdot w^{-1.5})$），不加 warmup 的深层 Transformer 训练发散或卡在高 loss（Vaswani et al. 2017 §5.3）。

策略：前 $w$ 步从 0 线性升到峰值，之后按调度衰减。

### 3.2 cosine 衰减与 one-cycle

- **Cosine**（Transformer 时代事实标准，SGDR 论文引入 cos 周期重启：Loshchilov & Hutter, ICLR 2017）：

$$\eta_t = \eta_{\min} + \frac{1}{2}(\eta_{\max} - \eta_{\min})\left(1 + \cos\frac{\pi \, t}{T}\right)$$

- **one-cycle**（Smith, *A Disciplined Approach to Neural Network Hyper-Parameters*, 2018）：升-降一个周期，且**momentum 反向**（lr 升时 momentum 降），配合 LR range test 找峰值。

```python
import math, torch

def lr_cosine(step, total, warmup, peak=3e-4, min_lr=3e-5):
    if step < warmup:                       # 线性 warmup
        return peak * (step + 1) / warmup
    t = (step - warmup) / max(1, total - warmup)
    return min_lr + 0.5 * (peak - min_lr) * (1 + math.cos(math.pi * t))

# 手算验证: warmup=100, total=1000
print(lr_cosine(50, 1000, 100))    # 0.000153 —— warmup 中点, 约峰值一半
print(lr_cosine(100, 1000, 100))   # 0.0003   —— 峰值
print(lr_cosine(550, 1000, 100))   # 0.000165 —— 半山腰(余弦中点恰为峰谷中值)
print(lr_cosine(999, 1000, 100))   # 3e-05    —— 谷底

# PyTorch 内置等价写法:
model = torch.nn.Linear(8, 2)
opt = torch.optim.AdamW(model.parameters(), lr=3e-4)
sched = torch.optim.lr_scheduler.OneCycleLR(
    opt, max_lr=3e-4, total_steps=1000, pct_start=0.1)   # 10% 步数用于 warmup
# 训练循环里每步: opt.step(); sched.step()
```

经验做法速记：Transformer 系 **AdamW + peak 3e-4（小模型）~ 1e-4 及以下（大模型）+ 总步数 5-10% 的 warmup + cosine 到峰值 10%**；CNN 分类常用 **SGD momentum 0.9 + 0.1 × batch/256**（见 10 章线性缩放）起步。

## 4. 优化器谱系：SGD → momentum → Adam → AdamW

3 章已建立直觉，本篇补全公式与"解耦权重衰减"。

### 4.1 谱系逻辑

每一代解决上一代的一个具体痛点：

```text
SGD:        θ ← θ - η·g                  痛点: 方向抖动
momentum:   v ← βv + g; θ ← θ - η·v      痛点: 所有参数共用一个步长尺度
Adam:       m,v 双矩 + 偏差修正           痛点: 权重衰减被 m,v 搅浑
AdamW:      衰减从梯度里拆出来直接作用     → 现代 LLM 标配
```

### 4.2 AdamW：权重衰减的解耦

传统 L2 正则把 $\lambda\theta$ **加进梯度**再交给 Adam：梯度经过 $m, v$ 的滑动平均"稀释"后，正则强度对每个参数变得不均——大梯度参数几乎不受正则，小梯度参数被过度衰减。AdamW（Loshchilov & Hutter, *Decoupled Weight Decay Regularization*, ICLR 2019）把衰减从梯度通路里拆出来，**直接作用在参数上**：

$$\theta \leftarrow \theta - \eta\left(\frac{\hat m}{\sqrt{\hat v}+\epsilon} + \lambda\theta\right)$$

工程含义：`AdamW(weight_decay=0.1)` 中 0.1 的语义与 `Adam(weight_decay=0.1)` **完全不同**；从 Adam 迁移到 AdamW 时衰减系数通常要**加大**一个量级（经验做法：Transformer 常用 0.01~0.1）。另一个细节：**bias 与 LayerNorm 参数一般不衰减**（衰减它们只会扰乱尺度，无正则收益——GPT-2/nanoGPT 的参数分组实践）：

```python
decay, no_decay = [], []
for name, p in model.named_parameters():
    if p.ndim >= 2:          # 矩阵权重衰减; 向量(bias/LN 的 γ β)不衰减
        decay.append(p)
    else:
        no_decay.append(p)
opt = torch.optim.AdamW([
    {"params": decay, "weight_decay": 0.1},
    {"params": no_decay, "weight_decay": 0.0},
], lr=3e-4)
```

## 5. 梯度裁剪

### 5.1 公式与代码

按全局范数裁剪（RNN/Transformer 训练标配，5 章已述动机）：

```python
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
# 若 ||g|| > 1.0: g ← g * 1.0 / ||g||;  返回值是裁剪前的全局范数(拿去记录!)
```

使用守则：放在 `loss.backward()` 之后、`optimizer.step()` 之前；**记录返回的范数**——它是"训练健康度"的核心指标（TensorBoard 上该值长期贴着 1.0 说明每步都在裁剪，lr 或模型有问题；偶发尖峰属于正常，10 章的 loss spike 排查会用到）。

## 6. 混合精度训练（fp16 / bf16 / GradScaler）

### 6.1 为什么需要它

fp32（1 符号 + 8 指数 + 23 尾数）对训练安全但贵。半精度把显存/带宽省一半、（有 Tensor Core 的卡上）计算翻倍——大模型训练的必修件。两种半精度的位分配决定性格：

| 类型 | 位分配(符号/指数/尾数) | 数值范围 | 最大值 | 精度 |
| --- | --- | --- | --- | --- |
| fp32 | 1/8/23 | ±3.4e38 | 巨大 | 高 |
| fp16 | 1/5/10 | ±65504 | 小 | 中 |
| bf16 | 1/8/7 | 与 fp32 同量级 | 巨大 | 低 |

**fp16 的两个坑**：上界 65504，梯度大就溢出成 inf；下界附近（最小正规数约 6e-5），梯度小就整体下溢成 0。**bf16 把尾数位拿去换指数位**——范围和 fp32 一样宽，永远不会溢出/下溢，代价是精度粗（约 3 位十进制有效数字）。

### 6.2 GradScaler：给 fp16 梯度"整体放大"

混合精度（Micikevicius et al., *Mixed-Precision Training*, ICLR 2018）的分工：**前向/多数计算用半精度，权重主副本与敏感计算（如 loss、归约）保持 fp32**。fp16 的下溢问题用 loss scaling 解决：

```python
scaler = torch.cuda.amp.GradScaler()          # PyTorch 2.x 新写法: torch.amp.GradScaler("cuda")

for x, y in loader:
    optimizer.zero_grad()
    with torch.autocast(device_type="cuda", dtype=torch.float16):   # [GPU] autocast 只在 CUDA 生效意义完整
        logits = model(x)
        loss = loss_fn(logits, y)
    S = scaler.get_scale()
    scaler.scale(loss).backward()             # 反传的是 S*loss, 梯度整体放大 S 倍
    scaler.unscale_(optimizer)                # 先还原梯度, 再做(真)范数裁剪
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    scaler.step(optimizer)                    # 内部检查 inf/nan: 有则跳过本步
    scaler.update()                           # 连续无溢出则调大 S, 有溢出则减半
```

机制三句话：loss 乘放大系数 $S$（初始 65536）→ 梯度整体上移避开下溢区 → optimizer.step 前检查 inf/nan，**有则跳过该步并缩小 $S$**。**bf16 不需要 scaler**（不会下溢），直接 `autocast(dtype=torch.bfloat16)`——这是 A100/H100 时代大模型训练默认 fp32 主副本 + bf16 计算的原因。

**CPU 注记**：`torch.autocast("cpu", dtype=torch.bfloat16)` 在较新 PyTorch + 支持 bf16 的 CPU 上可用但收益有限；本系列示例一律 fp32 跑通，混合精度只标记为 [GPU] 技能。数值感受：`torch.finfo(torch.float16).max` → 65504；`torch.finfo(torch.bfloat16)` 的指数位与 fp32 相同。

## 7. 常见陷阱

1. **Xavier 用在 ReLU 网络上**：不报错，但深层激活逐层衰减，训练慢。按激活函数选初始化（1.2/1.3）。
2. **Transformer 里用 BN**：小 batch + 变长 + padding 三连击，统计量失真；用 LN/RMSNorm。
3. **warmup 步数设 0** 还疑惑"为什么前几百步 loss 横盘甚至上升"。
4. **AdamW 的 weight_decay 沿用 Adam 的 0.01 甚至 1e-4**：解耦后强度语义变了，正则名存实亡（4.2）。
5. **fp16 手动 `model.half()` 全模型转**：BN 统计量、loss、optimizer 状态全变 fp16，数值灾难；正确姿势永远是 autocast（6.2）。
6. **unscale 前做梯度裁剪**：裁的是放大 $S$ 倍后的梯度，`max_norm` 语义错乱——先 `scaler.unscale_(opt)` 再裁（6.2 顺序）。
7. **以为 GradScaler 能救 bf16**：bf16 没有下溢问题，加 scaler 白白引入跳步逻辑。

## 本篇小结

- 初始化的本质是方差守恒：Xavier $2/(n_{in}+n_{out})$ 保 tanh 世界的方差；Kaiming $2/n_{in}$ 为 ReLU 的方差减半补偿。GPT 的 0.02 是工程约定。
- 归一化选型：CNN 用 BN（batch 充足时最强），Transformer 用 LN，现代 LLM 用 RMSNorm（更简更稳）。
- warmup 防"开局一步迈飞"（Adam 冷启动 + 深层 Transformer 实证）；cosine 衰减到 10% 峰值是默认收尾。
- AdamW = Adam + 解耦权重衰减；bias/LN 参数不衰减；迁移时衰减系数要重调。
- 梯度裁剪按全局范数、记录返回值当健康指标；混合精度用 autocast，fp16 配 GradScaler（跳步+缩放），bf16 免 scaler。
