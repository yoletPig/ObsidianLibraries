# 01 - 张量与自动微分

## 本篇目标

读完本篇，你应该能做到：

1. 熟练创建张量，说清楚一个张量的三要素：**shape、dtype、device**。
2. 不需要运行代码就能判断两个形状的张量相加/相乘后广播成什么形状、会不会报错。
3. 理解 autograd 的计算图原理：`requires_grad`、`backward`、`.grad` 之间到底发生了什么。
4. 分清叶节点与非叶节点，以及 `torch.no_grad()` 和 `detach()` 这两个"长得像"的东西的本质区别。

自动微分是 PyTorch 存在的理由——神经网络训练的本质就是"对某个标量 loss 求所有参数的梯度"，后面 13 章全建立在本篇之上。

## 1. 张量：带类型和形状的多维数组

### 1.1 为什么需要它

NumPy 的 ndarray 已经能表示多维数组了，PyTorch 的 tensor 比 it 多两样东西：**可以放到 GPU 上算**，以及**可以记录"我是怎么被算出来的"从而自动求导**。前者解决速度，后者解决训练。

### 1.2 创建与三要素

```python
import torch
import numpy as np

# 从数据创建
a = torch.tensor([[1.0, 2.0], [3.0, 4.0]])   # 注意:传入 Python float 才是 float32
print(a.shape, a.dtype, a.device)
# torch.Size([2, 2]) torch.float32 cpu

# 常用工厂函数
b = torch.zeros(2, 3)            # 全 0, shape (2, 3)
c = torch.ones(2, 2)             # 全 1
d = torch.arange(6)              # [0,1,2,3,4,5], 整数, shape (6,)
e = torch.arange(6.0)            # 浮点版
f = torch.randn(2, 3)            # 标准正态分布 N(0,1), 训练中最常用的初始化
g = torch.rand(2, 2)             # [0,1) 均匀分布

# 与 NumPy 互转（共享内存！改动一边另一边会变）
n = np.ones((2, 2), dtype=np.float32)
t = torch.from_numpy(n)          # 共享内存
t2 = torch.tensor(n)             # 复制一份，不共享
s = t.numpy()                    # tensor -> numpy（仅 CPU 张量）
```

**三要素逐个看：**

- **shape**：每一维的长度。`a.shape` 返回 `torch.Size([2, 2])`，它就是个元组，支持 `a.size(0)` 按维取。
- **dtype**：元素类型。深度学习里最常见的是 `torch.float32`（默认浮点）与 `torch.int64`（标签的默认类型）。9 章会讲半精度 `float16/bfloat16`。
- **device**：数据在哪台设备上。CPU 张量和 GPU 张量**不能直接运算**，必须先 `.to()` 到同一设备。

```python
# [GPU] 仅在有 CUDA 的机器上可用，CPU 环境跳过
# gpu = torch.randn(2, 2, device="cuda")
# cpu = torch.ones(2, 2)
# gpu + cpu          # RuntimeError: 期望所有张量在同一设备
# (cpu.to("cuda") + gpu).device   # cuda:0 —— 正确做法

# dtype 转换
x = torch.arange(3)              # int64
x.float()                        # float32
x.to(torch.float16)              # 显式指定
```

常见陷阱：**整数张量参与除法会做整除**。`torch.tensor([1, 2, 3]) / 2` 得到 `[0.5, 1.0, 1.5]`（PyTorch 的 `/` 对整型做了真除法并转 float），但 `torch.div` 配合 `rounding_mode` 时行为不同；最稳妥的做法是先把数据转成 float 再运算。另外 `torch.tensor([1, 2])` 是 int64，喂给只吃 float 的 `nn.Linear` 会直接报错 `expected scalar type Float`——这是新手报错榜第一名。

## 2. 形状操作与索引

```python
x = torch.arange(6)              # shape (6,)
A = x.reshape(2, 3)              # (2, 3)  reshape 总元素数必须不变
B = x.view(3, 2)                 # (3, 2)  view 要求内存连续（contiguous）
C = x.reshape(1, 6).squeeze(0)   # squeeze 去掉长度为 1 的维
D = x.unsqueeze(0)               # (1, 6)  插入一个新维 —— 广播和 batch 维常用
E = A.permute(1, 0)              # (3, 2)  调换维度顺序（8 章注意力里天天用）
F = A.T                          # 转置，等价于 permute(1, 0)（二维时）

print(A)
# tensor([[0, 1, 2],
#         [3, 4, 5]])
print(A[1, 2])                   # tensor(5)  按下标取
print(A[:, 1])                   # tensor([1, 4])  第 1 列（注意结果是 (2,) 不是 (2,1)）
print(A[None].shape)             # torch.Size([1, 2, 3])  None 等价 unsqueeze(0)
```

`view` 与 `reshape` 的区别值得单独记：`view` 不会复制数据、速度更快，但要求张量内存连续；`reshape` 能复制也能不复制，永远成功。经验做法：明确知道连续时用 `view`（还能借它发现隐藏的非连续问题），不确定时用 `reshape`。

## 3. 广播规则（broadcasting）

### 3.1 为什么需要它

给一个 batch 的向量统一加一个偏置时，你不想写 for 循环，也不想 `expand` 一份大内存。广播让 PyTorch **逻辑上**复制、**物理上**不复制地完成这种运算。

### 3.2 规则（两条）

把两个形状**从最后一维开始向左对齐**，逐维比较，每一维满足以下之一即可广播：

1. 两个维度相等；或
2. 其中一个维度是 1（此时该维被"拉伸"到另一个的长度）；或
3. 某个张量缺少这个维（把它当作 1）。

任何一维不满足（两个都大于 1 且不相等）→ 报错。

### 3.3 真实形状示例

```python
# 例 1： (3, 1) + (4,) -> (3, 4)
a = torch.arange(3.0).reshape(3, 1)   # [[0],[1],[2]]
b = torch.arange(4.0)                 # [0, 1, 2, 3]
print(a + b)
# tensor([[0., 1., 2., 3.],
#         [1., 2., 3., 4.],
#         [2., 3., 4., 5.]])
# b 从右对齐: (4,) 对 (1,*)，第 0 维缺失当作 1，拉伸为 3；第 1 维 1 -> 4

# 例 2：批量向量加偏置 —— 神经网络里最常见的广播
x = torch.randn(32, 10)               # batch=32 个 10 维样本
bias = torch.randn(10)                # (10,)
y = x + bias                          # (32, 10)，bias 被广播 32 份

# 例 3：会报错的情况
# (2, 3) + (4, 3)：从右对齐 3==3 通过，但 2 和 4 都大于 1 且不等 -> RuntimeError
m = torch.zeros(2, 3); n = torch.zeros(4, 3)
try:
    m + n
except RuntimeError as err:
    print(err)   # The size of tensor a (2) must match the size of tensor b (4) at non-singleton dimension 0
```

3 章会看到：`nn.Linear` 内部就是 `x @ W.T + b`，其中 `+ b` 依赖的正是例 2 这种广播。

## 4. 自动微分：计算图

### 4.1 为什么需要它

训练神经网络 = 最小化 loss。最小化需要梯度。手工对百万参数求导不现实，于是框架在**你做前向计算的同时**把每一步运算记录成一张有向无环图（计算图），`backward()` 时沿图反向应用链式法则（5 章细讲数学），自动算出所有叶子（参数）的梯度。

### 4.2 最小示例

```python
x = torch.tensor(2.0, requires_grad=True)   # 告诉 PyTorch：请跟踪我
y = x ** 3                                   # y = 8，同时记录了 "y 是 x 的立方"
y.backward()                                 # 从 y 沿图反向传播（y 必须是标量）
print(x.grad)                                # tensor(12.) —— dy/dx = 3x^2 = 3*4 = 12
```

三步铁律：**建图（前向）→ backward → 读 .grad**。`.grad` 会**累加**，不清零就会越加越大——这是 2/3 章训练循环里 `optimizer.zero_grad()` 存在的原因。

多个数据时对向量求导，结果是对每个分量的偏导：

```python
v = torch.tensor([1.0, 2.0, 3.0], requires_grad=True)
out = (v * v).sum()          # out = 1+4+9 = 14
out.backward()
print(v.grad)                # tensor([2., 4., 6.]) —— dout/dv_i = 2*v_i
```

### 4.3 grad 是"存回叶子"的设计

`backward()` 默认只把梯度存到 **requires_grad=True 的叶节点**的 `.grad` 上，中间变量的梯度算完就用完即弃（省内存）。想保留中间梯度要用 `retain_grad()` 或钩子（见 4.4）。

## 5. 叶节点与非叶节点

### 5.1 概念

- **叶节点（leaf）**：不是任何运算的结果，即由用户直接创建的张量（`torch.tensor(...)`、`nn.Parameter`）。`x.is_leaf` 为 True。
- **非叶节点（non-leaf）**：由叶节点经过运算得到的中间结果。

只有叶节点默认保留 `.grad`，因为训练要更新的是参数（叶节点）；中间量（激活值）的梯度没人消费。

```python
x = torch.randn(3, requires_grad=True)   # leaf
y = x * 2                                # non-leaf, y.is_leaf == False
z = y.mean()                             # 标量
z.backward()
print(x.grad)        # tensor([0.6667, 0.6667, 0.6667])  dz/dx_i = (1/3)*2
print(y.grad)        # None —— 非叶节点默认不保留（并伴随一条 UserWarning）
```

验证过：`x.grad` 是 `0.6667`，`y.grad` 是 `None`（PyTorch 2.14 会给出上面提到的警告）。

### 5.2 什么时候需要非叶节点的梯度

调试中间层时（"梯度是不是在这层断了？"）。两种办法：

```python
y = x * 2
y.retain_grad()          # 让 backward 顺手把梯度存在 y.grad 上
z = y.mean()
z.backward()
print(y.grad)            # tensor([0.3333, 0.3333, 0.3333])

# 或者用 hook：不需要提前声明，适合 print-only
y2 = x * 2
y2.register_hook(lambda g: print("y2 的梯度:", g))
z2 = y2.mean(); z2.backward()
```

### 5.3 常见陷阱：对非叶节点手动置 requires_grad

```python
a = torch.randn(3, requires_grad=True)
b = a * 2
# b.requires_grad_()      # RuntimeError: 不允许对非叶节点改 requires_grad
b.detach().requires_grad_(True)   # 正确：先切断历史，再把它当新的叶子
```

## 6. torch.no_grad() 与 detach() 的区别

两者都会"切断梯度"，但作用对象不同——这是面试高频题，也是写推理代码绕不开的点。

### 6.1 本质区别

- **`torch.no_grad()`**：一个**上下文**，作用于"上下文里发生的运算"——里面的运算不建图，产出 `requires_grad=False` 的结果。它不改变任何已有张量的属性。
- **`t.detach()`**：作用于**这一个张量**——返回一个与 `t` **共享存储**但切断计算图历史的新张量（`requires_grad=False`）。上下文之外、之后对它的运算默认也不建图（因为它是新叶子）。

一句话：`no_grad` 管"接下来的运算"，`detach` 管"这一个张量的出身"。

```python
w = torch.randn(2, requires_grad=True)

# no_grad：块内运算不建图；w 本身还是原来的叶子
with torch.no_grad():
    a = w * 3          # a.requires_grad == False
    print(w.requires_grad)   # True —— 注意：w 的属性没被改
b = w * 3              # 块外运算照常建图, b.requires_grad == True

# detach：得到一个"没有历史"的孪生张量
c = w.detach()         # c 与 w 共享数据, c.requires_grad == False, c.is_leaf == True
c.add_(1.0)            # 就地修改 c —— 会连 w 的数据一起改！共享存储
print(w)               # w 的数值也变了
```

### 6.2 各自的典型用途

| 场景 | 用哪个 | 原因 |
| --- | --- | --- |
| 推理/评估（3 章的 eval 循环） | `torch.no_grad()` 或 `torch.inference_mode()` | 一整段代码都不需要梯度 |
| 把网络输出当"输入特征"喂给另一个网络 | `y.detach()` | 只切这一个张量，别处还要继续训练 |
| 参数更新 `w -= lr * w.grad` | `with torch.no_grad():` | 更新操作绝不能被记进图里 |
| 假数据/标签常量 | `torch.randn(..., requires_grad=False)`（默认就是） | 根本不需要切 |

`torch.inference_mode()` 是 PyTorch 1.9+ 引入的更强版本：不仅不建图，还把张量标记为"推理张量"，禁用版本计数器，比 `no_grad` 更快更省（官方推荐推理时优先用它，出处见 PyTorch 官方文档 *Autograd mechanics*）。代价是推理张量之后不能再参与需要梯度的计算——12 章部署时会再用到。

### 6.3 经典坑：用 no_grad 包了更新却忘了它包不住"赋值"

```python
for p in model.parameters():
    p.data -= 0.01 * p.grad      # 老写法：.data 等价于 detach 的就地通道（不推荐）
# 现代写法：optimizer.step() 内部就是在 no_grad 下完成的 —— 见 03 章
```

`.data` 是历史遗留写法，它绕过所有安全检查，能隐藏"就地修改破坏计算图正确性"的 bug。现代代码一律用 `detach()` 或交给 optimizer。

## 7. 常见陷阱清单

1. **梯度累加不清理**：连续两次 `loss.backward()` 中间不清零，`.grad` 是两次之和。默认一次 backward 后图被释放，再次 backward 会报 `Trying to backward through the graph a second time`；确实要复用图需 `loss.backward(retain_graph=True)`（7 章 seq2seq 有正当用途）。
2. **标量判断**：`backward()` 只能从标量调用。`y` 是向量时要 `y.sum().backward()` 或 `y.backward(torch.ones_like(y))`（等价于对每个分量梯度求和，5 章会解释这就是 JVP）。
3. **`.item()` 拿 Python 数**：打印 loss 用 `loss.item()`，否则打印的是整个张量对象且梯度图被引用，训练久了内存涨。
4. **in-place 运算破坏建图**：`x += 1`（in-place）在 autograd 需要原值做反向时（如 `tanh` 的反向需要输出值）会报错；用 `x = x + 1`（新建张量）。PyTorch 用版本号检测这种情况。
5. **detach 共享内存**（见 6.1 的 `c.add_` 例子）：想独立复制请用 `t.detach().clone()`。

## 本篇小结

- 张量三要素 shape/dtype/device；dtype 不匹配与 device 不匹配是两大高频报错。
- 广播从右对齐，逐维满足"相等 / 有一个为 1 / 缺失"三者之一，否则报错。
- autograd 在前向时建图，`backward()` 沿图反向把梯度写回叶节点的 `.grad`；`.grad` 累加，需手动清零。
- 叶节点才默认保留梯度；`retain_grad()`/hook 用于调试中间梯度。
- `no_grad` 管上下文内的运算，`detach` 切单个张量的历史且共享存储，`inference_mode` 是更强的推理专用版。
