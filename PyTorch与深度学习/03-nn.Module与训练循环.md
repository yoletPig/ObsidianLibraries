## 1. nn.Module：PyTorch 的一切模型基类

### 1.1 为什么需要它

2 章的线性回归只有两个参数 `w, b`，我们手动创建、手动更新、手动清零。一个网络有几百个参数张量时，这种手工管理不可维护。`nn.Module` 提供三件事：

1. **自动注册**：赋值给 `self` 的子模块和 `nn.Parameter` 会被记录；
2. **统一视图**：`parameters()` 一次拿到全部可训练张量；
3. **统一接口**：`forward()` 定义前向，`train()/eval()` 切换模式，`to()` 搬设备。

### 1.2 最小示例与机制

```python
import torch
import torch.nn as nn

class MLP(nn.Module):
    def __init__(self, in_dim, hidden, out_dim):
        super().__init__()                       # 必须第一行：注册机制依赖父类
        self.fc1 = nn.Linear(in_dim, hidden)     # 子模块 -> 自动注册
        self.act = nn.ReLU()                     # 无参数的层也要注册（state_dict 一致性）
        self.fc2 = nn.Linear(hidden, out_dim)

    def forward(self, x):                        # 定义"数据怎么流"
        return self.fc2(self.act(self.fc1(x)))

model = MLP(784, 256, 10)
print(model)                     # 打印结构
for name, p in model.named_parameters():
    print(name, tuple(p.shape), p.requires_grad)
# fc1.weight (256, 784) True
# fc1.bias   (256,)     True
# fc2.weight (10, 256)  True
# fc2.bias   (10,)      True
print(sum(p.numel() for p in model.parameters()))   # 784*256+256 + 256*10+10 = 203530
```

**注册机制的原理**（读源码前的心智模型）：`nn.Module.__setattr__` 被覆写过——当你给 `self.fc1 = nn.Linear(...)` 赋值时，父类发现值是 Module，就把它登记进 `self._modules` 这个有序字典；发现值是 `nn.Parameter` 就登记进 `self._parameters`。`parameters()` 就是递归遍历这棵"模块树"。

由此推出三条推论：

1. **参数放进 Python list/dict 不注册**：`self.layers = [nn.Linear(64, 64) for _ in range(3)]` 里的层不会被 `parameters()` 找到。正确做法是用 `nn.ModuleList` / `nn.ModuleDict`（8 章 miniGPT 用 `nn.ModuleList` 堆 Transformer block）。
2. **forward 里现算的张量不是参数**：`self.tmp = x * 2`（普通张量）不进 `_parameters`，不参与训练。
3. **一个张量是 Parameter 才默认 requires_grad=True**：普通 `nn.Linear` 的 weight/bias 内部就是 `nn.Parameter`。

### 1.3 Parameter 与 buffer

`nn.Parameter` 是"要训练的张量"；还有一类"跟着模型走但不训练"的张量叫 **buffer**，用 `self.register_buffer('mean', torch.zeros(5))` 注册——6 章 BatchNorm 的 `running_mean/running_var` 就是 buffer：推理要用（所以必须在 `state_dict` 里），但梯度不更新它们（由滑动平均维护，见 6.5）。

## 2. optimizer：怎么"下山"

### 2.1 为什么需要它

2 章我们手写 `w -= lr * dw`。optimizer 把"用什么策略更新"封装成对象，好处：换策略不用改训练循环、能保存/恢复自身状态、能对整组参数统一操作。

### 2.2 SGD：最朴素的下山

$$\theta \leftarrow \theta - \eta \cdot g$$

用当前 batch 估计的梯度 $g$ 直接走。问题：梯度方向抖动大（尤其各方向陡缓差异大时），像一个人在峡谷里下山，每步都被两侧坡面弹来弹去，沿谷底方向却走得很慢。

### 2.3 momentum：给下山的"滚一个球"

$$v \leftarrow \beta v + g, \qquad \theta \leftarrow \theta - \eta \cdot v$$

$\beta$ 通常取 0.9，$v$ 是梯度的**指数加权平均**（近 10 步左右的平均，因为 $(1-0.9)\approx 1/10$）。直觉：震荡方向来回抵消、平均后变小；一致方向不断累加、平均后变大。等效于"滚动的小球带着惯性冲过小坑"。

### 2.4 Adam：每个参数自己配步长

$$m \leftarrow \beta_1 m + (1-\beta_1) g \qquad \text{（一阶矩：梯度的平均，≈momentum）}$$
$$v \leftarrow \beta_2 v + (1-\beta_2) g^2 \qquad \text{（二阶矩：梯度平方的平均，≈各方向陡峭度）}$$
$$\theta \leftarrow \theta - \eta \cdot \frac{\hat m}{\sqrt{\hat v}+\epsilon}$$

$\hat m, \hat v$ 是修正了"从 0 冷启动偏小"问题的版本（**偏差修正**，9 章推导）。直觉：哪个参数的梯度一直很大，$\sqrt{\hat v}$ 就大，等效步长自动缩小；梯度小的参数步长相对放大——**每个参数自带自适应步长**，所以对学习率不如 SGD 敏感，是深度学习默认起步选择。

论文出处：Kingma & Ba, *Adam: A Method for Stochastic Optimization*, ICLR 2015（正式版标注 2014 年 12 月首次挂 arXiv）。

### 2.5 三者对比速查

| | SGD | SGD+momentum | Adam |
| --- | --- | --- | --- |
| 更新依据 | 当前梯度 | 梯度平均 | 梯度平均 + 二阶矩自适应 |
| 对 lr 敏感度 | 高 | 中 | 低 |
| 收敛速度（小网络） | 慢 | 中 | 快 |
| 最终泛化（视觉大任务） | 常更好 | 常更好 | 视任务 |
| 典型用途 | 调参精修、CNN 基线 | ResNet 类训练 | Transformer/NLP/快速实验 |

"SGD 在某些视觉任务上泛化更好"有实证支持（如 Wilson et al., *The Marginal Value of Adaptive Gradient Methods*, ICML 2017），但并非普遍规律——标注为**经验做法**级别的共识，具体任务以实验为准。

```python
optimizer = torch.optim.SGD(model.parameters(), lr=0.1, momentum=0.9)
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)   # 3 大 1e-3 是 Adam 社区默认
```

## 3. 标准训练循环模板（背下来）

```python
def train_one_epoch(model, loader, loss_fn, optimizer, device):
    model.train()                          # ① 切训练模式（影响 BN/Dropout，见下）
    for x, y in loader:                    # ② 拿一个 batch
        x, y = x.to(device), y.to(device)  # ③ 数据搬设备
        optimizer.zero_grad()              # ④ 清梯度（01 章：grad 是累加的）
        logits = model(x)                  # ⑤ 前向（自动建图）
        loss = loss_fn(logits, y)          # ⑥ 算损失
        loss.backward()                    # ⑦ 反向：填所有 .grad
        optimizer.step()                   # ⑧ 用梯度更新参数
    return loss.item()

@torch.no_grad()                           # 评估不建图：省内存 + 提速（01 章）
def evaluate(model, loader, loss_fn, device):
    model.eval()                           # 切评估模式
    total_loss, correct, total = 0.0, 0, 0
    for x, y in loader:
        x, y = x.to(device), y.to(device)
        logits = model(x)
        total_loss += loss_fn(logits, y).item() * len(y)
        correct += (logits.argmax(dim=1) == y).sum().item()
        total += len(y)
    return total_loss / total, correct / total
```

逐条说明：

- **`model.train()` / `model.eval()`**：不是"开训练/关训练"，而是切换模块内部行为。只影响两类层：**Dropout**（train 随机置零，eval 全开）与 **BatchNorm**（train 用当前 batch 统计量并更新滑动平均，eval 用历史统计量，6 章详述）。忘了 `eval()` 是"测试精度异常抖动"的头号病因。
- **四步顺序**：`zero_grad → forward → backward → step`。backward 必须在 step 之前，zero_grad 在 backward 之前——顺序错了梯度就是脏的。
- **`@torch.no_grad()`**：评估时不需要梯度，不建图可省下整张计算图的内存；另外 `argmax` 只在 eval 分支出现——训练精度要用 train 分支单独统计。

### 3.1 交叉熵损失：分类任务的标配

```python
loss_fn = nn.CrossEntropyLoss()
logits = model(x)            # (B, 10)，注意：网络最后一层不要加 Softmax！
loss = loss_fn(logits, y)    # y 是 (B,) 的 int64 类别标签
```

**最大的陷阱**：`nn.CrossEntropyLoss` 内部 = `LogSoftmax + NLLLoss`，它吃的是**原始 logits**。如果你在 `forward` 末尾加了 `nn.Softmax`，等于做了两次 softmax，训练会变得又慢又差，而且**不报错**——极其隐蔽。规则一句话：**CrossEntropyLoss 配 logits，手动概率才配 NLLLoss**。

数学定义（多类交叉熵，$z$ 为 logits，$t$ 为 one-hot 真值）：

$$L = -\sum_{k} t_k \log \frac{e^{z_k}}{\sum_j e^{z_j}}$$

幸运的性质：对 logits 的梯度恰好是 $\text{softmax}(z) - t$（可自行推导），干净且数值稳定（内部用 log-sum-exp 技巧防溢出）。

## 4. 完整可运行示例：MNIST 手写数字分类

数据：MNIST，7 万张 28×28 灰度手写数字，10 类。首次运行会自动下载约 12MB 到 `./data`（需要网络；离线机器可手动下载后放到该目录）。

```python
import torch
import torch.nn as nn
from torch.utils.data import DataLoader
from torchvision import datasets, transforms

torch.manual_seed(42)
device = "cuda" if torch.cuda.is_available() else "cpu"   # [GPU] 有卡自动用；无卡 CPU 可跑

transform = transforms.ToTensor()          # PIL 图 (28,28) -> 张量 (1,28,28)，像素缩放到 [0,1]
train_set = datasets.MNIST("./data", train=True,  download=True, transform=transform)
test_set  = datasets.MNIST("./data", train=False, download=True, transform=transform)
train_loader = DataLoader(train_set, batch_size=128, shuffle=True)    # 4 章细讲
test_loader  = DataLoader(test_set,  batch_size=256, shuffle=False)

class MLP(nn.Module):
    """784 -> 256 -> 10 的两层全连接网络"""
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(
            nn.Flatten(),              # (B, 1, 28, 28) -> (B, 784)
            nn.Linear(784, 256), nn.ReLU(),
            nn.Linear(256, 10),        # 输出 logits，不加 Softmax！
        )
    def forward(self, x):
        return self.net(x)

model = MLP().to(device)
print("参数量:", sum(p.numel() for p in model.parameters()))   # 203530
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)
loss_fn = nn.CrossEntropyLoss()

for epoch in range(1, 6):
    model.train()
    for x, y in train_loader:
        x, y = x.to(device), y.to(device)
        optimizer.zero_grad()
        loss = loss_fn(model(x), y)
        loss.backward()
        optimizer.step()
    # 每个 epoch 评估一次
    model.eval()
    correct = total = 0
    with torch.no_grad():
        for x, y in test_loader:
            x, y = x.to(device), y.to(device)
            pred = model(x).argmax(dim=1)
            correct += (pred == y).sum().item()
            total += len(y)
    print(f"epoch {epoch}  test_acc = {correct/total:.4f}")

# 典型输出（CPU 约每 epoch 20-40 秒，机器不同略有差异）:
# epoch 1  test_acc = 0.9529
# epoch 2  test_acc = 0.9660
# epoch 3  test_acc = 0.9724
# epoch 5  test_acc = 0.9780 左右
```

**阅读这份代码时问自己四个问题**（都能在前文找到答案）：

1. 为什么 `forward` 末尾没有 Softmax？（3.1 节）
2. 为什么评估要包 `torch.no_grad()`？（01 章 + 3 节）
3. 为什么每个 epoch 都要 `model.train()`/`model.eval()` 切换？（本例的 MLP 其实没有 BN/Dropout，切换是"礼貌性"的；一旦网络里加了这两类层，不切就出 bug——6/10 章）
4. `zero_grad/backward/step` 顺序为什么不能乱？（3 节）

## 5. 常见陷阱

1. **忘记 `zero_grad()`**：2 章手写过 `.grad.zero_()`，框架版换成了 `optimizer.zero_grad()`，忘掉的后果一模一样：loss 震荡甚至发散。新版 PyTorch 可用 `set_to_none=True`（默认）把 `.grad` 置 None 而不是清零，稍省内存。
2. **在 `nn.CrossEntropyLoss` 前加了 Softmax**：不报错、精度低，最阴险的 bug（3.1 节）。
3. **optimizer 在 `.to(device)` 之前创建**：`optimizer = Adam(model.parameters())` 之后又 `model.to("cuda")`，`parameters()` 返回的张量对象不变（`.to` 是就地语义），一般没事；但**反过来**"先 to 再重建 optimizer"则更稳。真正会翻车的场景是 `model.half()`/重新赋值 weight——经验做法：**先把模型放好设备、定好 dtype，最后再建 optimizer**。
4. **把 `.argmax` 用在 softmax 后**：softmax 是单调的，先 softmax 再 argmax 结果一样，但白算一次；直接对 logits argmax。
5. **评估时也调 `loss_fn` 却忘了 `eval()`**：带 Dropout 的网络评估 loss 异常高、精度抖动。
6. **train/eval 忘切换** 与 **`optimizer.zero_grad()` 忘调**并列为两大"代码看着对、结果就是不对"的经典。

## 本篇小结

- `nn.Module` 靠覆写 `__setattr__` 自动注册子模块与 `nn.Parameter`；放进 Python list 不会注册，要用 `nn.ModuleList`。
- optimizer 封装更新策略：SGD 是朴素下山，momentum 加惯性（梯度指数加权平均），Adam 给每个参数自适应步长（一阶/二阶矩 + 偏差修正）。
- 标准训练循环：`train()` → `zero_grad → forward → backward → step`；评估：`eval()` + `no_grad()`。这个模板全书通用。
- `CrossEntropyLoss` 吃 logits，网络末尾不要加 Softmax。
- MNIST + 两层 MLP，CPU 几分钟就能跑到 97%+ 测试精度——你的第一个完整深度学习模型。
