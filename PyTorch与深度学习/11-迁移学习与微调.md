## 1. 预训练-微调范式

### 1.1 为什么需要它

从零训练需要与模型容量匹配的数据量；但多数任务只有几千~几万标注样本。解法是**两阶段**：

```text
阶段一 预训练: 超大数据(无标注/弱标注) + 大算力 → 学通用表征(边缘/纹理/语法/世界知识)
阶段二 微调:   你的小数据 + 小算力 → 把通用表征适配到具体任务
```

为什么成立：视觉网络底层的 Gabor/边缘检测器（6 章的 Sobel 核，网络自己也能学出）、语言模型底层的语法特征，几乎与具体任务无关——它们在 ImageNet/全网语料上已经学好了。特征可视化证据见 Zeiler & Fergus, *Visualizing and Understanding Convolutional Networks*, ECCV 2014（第一层学边缘颜色、高层学物体部件）。

### 1.2 迁移的两种形态

- **特征提取**（frozen backbone）：冻结整个骨干，只训最后的分类头。骨干当"特征计算器"，最稳最省。
- **微调**（fine-tuning）：骨干参数也在小 lr 下更新。效果上限更高，但小数据可能把预训练知识"冲掉"（灾难性遗忘）。

经验做法：小数据（<1 万样本）从特征提取/轻微调起步；数据多再放开更多层。

## 2. 冻结层与差分学习率

### 2.1 冻结的实现：requires_grad=False

```python
import torch, torchvision

model = torchvision.models.resnet18(weights="IMAGENET1K_V1")

# 冻结全部, 只留分类头
for p in model.parameters():
    p.requires_grad = False
model.fc = torch.nn.Linear(model.fc.in_features, 10)   # 换头: 新参数默认 requires_grad=True

trainable = [p for p in model.parameters() if p.requires_grad]
print(sum(p.numel() for p in trainable))     # 51210 —— 只训练最后一层
```

要点：

1. **冻结 = 前向照跑、反向不建梯度**：`requires_grad=False` 的参数不进 autograd 图（01 章），省显存也省算力；
2. **必须"先冻结、后换头"**：新赋值的 `nn.Linear` 参数默认可训练；
3. optimizer 只应拿到可训练参数：`Adam(model.parameters())` 也能跑（梯度为 None 的参数 Adam 会跳过），但**显式过滤**更清晰省内存（经验做法）。

### 2.2 差分学习率（discriminative learning rates）

直觉：底层特征接近通用（几乎别动），顶层特征接近任务（可以大改）。给不同深度配不同 lr（ULMFiT 首次系统化：Howard & Ruder, *Universal Language Model Fine-tuning for Text Classification*, ACL 2018）：

```python
backbone = [p for n, p in model.named_parameters() if not n.startswith("fc")]
head = [p for n, p in model.named_parameters() if n.startswith("fc")]
optimizer = torch.optim.AdamW([
    {"params": backbone, "lr": 1e-5},   # 骨干: 小步微调
    {"params": head,     "lr": 1e-3},   # 头: 正常学习率
])
```

经验法则：相邻组 lr 差一个数量级（×0.1 逐层向下）；这是"既保留预训练知识又适配任务"的折中旋钮。

## 3. BatchNorm 在微调中的统计量陷阱

### 3.1 陷阱机制（全系列伏笔在此收网）

BN 有两类量：**可训练参数** γ/β（受 `requires_grad` 控制）与**缓冲统计量** running_mean/running_var（不受 `requires_grad` 控制，由前向更新，见 6 章 4.3）。于是微调时出现一个隐蔽错误：

```python
# 错误做法: 只设 requires_grad=False 就以为"冻结"了 BN
for p in model.parameters():
    p.requires_grad = False
# BN 的 running_mean/var 依然在每次前向(train 模式)被新数据刷新!
# 你的"冻结骨干"的统计量正在被 10 张目标域图片悄悄改写
```

后果：小 batch 的脏统计污染了 ImageNet 上精心积累的全局统计，eval 时表现异常。

### 3.2 正确做法：把 BN 模块整体置 eval

```python
model.train()                                # 全模型进训练模式
for m in model.modules():
    if isinstance(m, torch.nn.BatchNorm2d):
        m.eval()                             # BN 模块单独 eval: 统计量冻结, γ β 仍可训练(若未冻结)

# 更常见的组合(特征提取): γ β 也冻结 —— requires_grad=False + m.eval() 双保险
```

原理回顾（6 章表）：`module.eval()` 才控制"统计量用不用 batch 的/更不更新"；`requires_grad` 只控制梯度。**两个开关管两件不同的事**。这一陷阱是《模型性能优化》里"微调掉点排查清单"的常客，也影响量化（统计量失真会让量化校准漂移——衔接《模型性能优化 Stage 1》）。

## 4. LoRA：低秩适配

### 4.1 思想与公式

全量微调一个 7B 模型需要显存存参数+梯度+优化器状态（约 7B × 16 字节 ≈ 112GB，AdamW fp32 状态口径）——单卡不可能。LoRA（Hu et al., *LoRA: Low-Rank Adaptation of Large Language Models*, ICLR 2022）的观察：

1. 微调时权重的**变化量** $\Delta W$ 是低秩的（任务适配不需要全维度自由度）；
2. 于是不更新 $W$，改学一个低秩分解：

$$W' = W + \Delta W = W + \frac{\alpha}{r} B A, \qquad A \in \mathbb{R}^{r \times k},\ B \in \mathbb{R}^{d \times r},\ r \ll \min(d, k)$$

$h = Wx + \frac{\alpha}{r}BAx$：前向时原权重照用（推理零额外延迟的关键——部署时 $BA$ 可合并进 $W$），可训练的只有 $A, B$。初始化 $A$ 用高斯、$B$ 全零 → 训练起点 $\Delta W = 0$，从预训练状态平滑出发。$\alpha/r$ 是缩放（调 r 时不用重调 lr）。

### 4.2 参数账（背下这个算法）

全量：$d \times k$；LoRA：$r(d + k)$。以 LLM 的 $d=k=4096$、$r=8$ 为例：

$$\text{全量 } 4096^2 = 16{,}777{,}216 \quad \text{vs} \quad \text{LoRA } 8 \times (4096+4096) = 65{,}536 \quad \Rightarrow \ \textbf{256 倍压缩}$$

显存收益不止参数本身：可训练参数少了，**梯度与 Adam 状态同比消失**，大头在优化器状态上。

### 4.3 最小实现（30 行，含注入）

```python
import math
import torch
import torch.nn as nn

class LoRALinear(nn.Module):
    """在冻结的原 Linear 旁挂一个低秩旁路。前向: y = W_frozen x + (alpha/r) B(A x)"""
    def __init__(self, base: nn.Linear, r: int = 8, alpha: int = 16):
        super().__init__()
        self.base = base
        for p in self.base.parameters():
            p.requires_grad = False                    # 冻结原权重
        d_out, d_in = base.weight.shape
        self.A = nn.Parameter(torch.randn(r, d_in) * (1 / math.sqrt(d_in)))  # 高斯
        self.B = nn.Parameter(torch.zeros(d_out, r))                        # 全零 -> 起点恒等
        self.scale = alpha / r

    def forward(self, x):
        return self.base(x) + self.scale * (x @ self.A.T @ self.B.T)

# 注入: 把模型里所有 nn.Linear 换成 LoRALinear(实战只换注意力 q,k,v —— LoRA 论文的默认)
def inject_lora(model, r=8, alpha=16):
    for name, module in model.named_children():
        if isinstance(module, nn.Linear):
            setattr(model, name, LoRALinear(module, r, alpha))
        else:
            inject_lora(module, r, alpha)              # 递归进子模块
    return model

model = nn.Sequential(nn.Linear(4096, 4096), nn.GELU(), nn.Linear(4096, 4096))
model = inject_lora(model, r=8)
n_train = sum(p.numel() for p in model.parameters() if p.requires_grad)
print(n_train)    # 131072 = 2 × 65536 (两个 Linear 各挂一对 A,B)
x = torch.randn(2, 4096)
print(model(x).shape)    # torch.Size([2, 4096]) —— 接口不变
```

生产环境用 [huggingface/peft](https://github.com/huggingface/peft) 的 `get_peft_model`，还支持 QLoRA（4bit 量化骨干 + LoRA，衔接《模型性能优化》）。LoRA 默认只挂在注意力的投影矩阵上（论文消融显示性价比最高）。

### 4.4 为什么这是多模态微调的前置

VLM 的典型结构 = 视觉编码器（ViT）+ 连接层 + LLM（见《VLM & VLA Stage 1》）。其微调几乎总是：

1. **冻结/轻调**视觉编码器（ImageNet 级预训练特征已够用，小数据微调反而伤）——本篇 2.1；
2. 冻结 LLM 主干，**LoRA 挂在 LLM 的注意力投影上**学"如何利用视觉 token"——本篇 4.3；
3. BatchNorm/LN 统计量处理（ViT 用 LN 无此坑，CNN 骨干就有）——本篇 3 节。

VLA（视觉-语言-动作模型）在 VLM 之上再挂动作头，微调模式相同。**不掌握"冻结哪些、训哪些、用什么强度训"，多模态实战寸步难行**——这就是本篇被列为前置的原因。

## 5. 微调检查清单（经验做法汇总）

1. 训练前打印：总参数量 / 可训练参数量 / 二者之比（LoRA 通常 <1%）；
2. CNN 骨干：BN 模块 `m.eval()` 或重算统计量（3 节）；
3. lr 比从零训练小 1~2 个数量级；骨干/头用差分 lr（2.2）；
4. 数据少时先特征提取跑通基线，再逐步放开层；
5. 监控"预训练任务"的代理指标（如通用文本的困惑度）防灾难性遗忘；
6. 微调 lr 也需要 warmup（幅度可以小，9 章）。

## 6. 常见陷阱

1. **只设 `requires_grad=False` 当作冻结了 BN**（3.1，最高频）。
2. **换头后忘同步修改预处理**：预训练模型自带专属的 mean/std、分辨率、tokenize 方式——用 ImageNet 权重就配 ImageNet 的归一化常数，用 LLM 就用它的 tokenizer。错配的信号是"loss 从一开始就异常高"。
3. **LoRA 的 α 与 r 混为一谈**：缩放是 α/r；改变 r 而不同步 α 会改变有效强度。
4. **微调 lr 用从零训练的 lr**：预训练知识被大步长冲掉，表现为 train loss 快速下降但 val 不动（10 章形态 C 的变体）。
5. **以为 LoRA 推理有额外延迟**：合并 $W' = W + \frac{\alpha}{r}BA$ 后与原模型同构、零延迟（PEFT 的 `merge_and_unload()`）。

## 本篇小结

- 迁移学习的合法性来自"底层特征通用"；实现上三档强度：特征提取（全冻）→ 冻结+差分 lr → LoRA。
- 冻结的完整语义 = `requires_grad=False`（梯度）**加** BN 模块 `eval()`（统计量），两个开关各管一件事。
- LoRA 把 $\Delta W$ 参数化为低秩 $BA$，4096×4096 权重 r=8 时参数减少 256 倍，合并后推理零延迟；是多模态微调的事实标准。
- 微调的本质是"用最小干预适配任务"——这个哲学贯穿 VLM/VLA 的训练系统。
