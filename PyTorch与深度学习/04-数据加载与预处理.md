## 1. Dataset 与 DataLoader 的分工

### 1.1 为什么需要两层抽象

- **Dataset** 回答"第 i 个样本长什么样"：一条数据的读取 + 单条预处理。
- **DataLoader** 回答"怎么高效喂给模型"：批量、打乱、多进程预取、与训练循环解耦。

```python
from torch.utils.data import Dataset, DataLoader

class MyDataset(Dataset):
    """最小契约: __init__(读元信息) + __len__(总数) + __getitem__(单条)"""
    def __init__(self, xs, ys):
        self.xs, self.ys = xs, ys

    def __len__(self):
        return len(self.xs)

    def __getitem__(self, idx):
        x = self.xs[idx]
        y = self.ys[idx]
        return x, y          # 返回"单条"，不是 batch —— 批处理是 DataLoader 的事
```

**核心分工原则**：`__getitem__` 只管单条，绝不自己拼 batch。拼 batch 的逻辑在 `collate_fn`（见第 2 节）。

### 1.2 一个真实感的自定义 Dataset

模拟"图片文件夹 + CSV 标签表"的常见结构（把数据换成内存数组以便无依赖运行）：

```python
import torch
import numpy as np

class ToyImageDataset(Dataset):
    """模拟: 数据在磁盘上按 idx 存文件, 标签在 CSV 里"""
    def __init__(self, n_samples, transform=None):
        self.n = n_samples
        self.transform = transform              # 单条预处理挂在 Dataset 上（见第 4 节）
        # 真实场景: self.labels = pd.read_csv("labels.csv"); self.root = "./images"
        self.labels = torch.randint(0, 10, (n_samples,))

    def __len__(self):
        return self.n

    def __getitem__(self, idx):
        # 真实场景: img = Image.open(f"{self.root}/{idx}.png")
        img = torch.rand(1, 28, 28)             # (C, H, W) float32
        if self.transform is not None:
            img = self.transform(img)
        return img, int(self.labels[idx])       # 返回 python int/float，利于 collate

ds = ToyImageDataset(1000)
print(len(ds))          # 1000
img, label = ds[0]      # 单条访问
print(img.shape, label) # torch.Size([1, 28, 28]) 标签值
```

注意 `__getitem__` 支持任何整数索引方式，DataLoader 的 `shuffle=True` 就是靠**随机打乱索引顺序**再逐个调用 `__getitem__` 实现的——所以自定义 Dataset 不需要关心打乱。

## 2. collate_fn：batch 是怎么拼出来的

### 2.1 默认行为

DataLoader 取出 batch_size 个 `(x, y)` 后，用默认 `collate_fn` 拼批：对张量/数组沿新第 0 维堆叠（`torch.stack`），对 int/float 收集成张量：

```python
loader = DataLoader(ds, batch_size=4, shuffle=False)
x, y = next(iter(loader))
print(x.shape)   # torch.Size([4, 1, 28, 28])  —— 多了 batch 维
print(y)         # tensor([7, 0, 4, ...], dtype=torch.int64) —— int 列表被收成张量
```

### 2.2 什么时候必须自定义：变长数据

文本、音频、点云的样本长度不一，`torch.stack` 要求形状一致会直接报错。方案：自定义 `collate_fn` 做 **padding**（补齐到批内最长）。这正是 7 章 seq2seq、8 章 minibatch 文本训练的基础：

```python
from torch.nn.utils.rnn import pad_sequence

class VaryLenDataset(Dataset):
    def __init__(self, n=16):
        self.data = [torch.randn(torch.randint(3, 8, ()).item(), 4) for _ in range(n)]

    def __len__(self): return len(self.data)
    def __getitem__(self, i): return self.data[i]

def collate_fn(batch):
    """batch: [(seq_i, ...), ...] 每条 shape (L_i, 4)，长度不等"""
    seqs = [b for b in batch]                       # 各 (L_i, 4)
    lengths = torch.tensor([len(s) for s in seqs])  # 记录真实长度，pad 部分以后要被 mask
    padded = pad_sequence(seqs, batch_first=True)   # (B, L_max, 4)，用 0 补齐
    return padded, lengths

loader = DataLoader(VaryLenDataset(), batch_size=4, collate_fn=collate_fn)
x, lengths = next(iter(loader))
print(x.shape)      # torch.Size([4, L_max, 4])，L_max 是本批最长序列
print(lengths)      # tensor([5, 3, 7, 4]) 之类的真实长度
```

padding 带来的新责任：**pad 位置不能参与计算**。RNN 用 `pack_padded_sequence` 或按 `lengths` 截断，注意力用 mask（8 章）——数据层负责"补齐+记录长度"，模型层负责"屏蔽"。

### 2.3 collate_fn 的其他用途

- 在这里把 `(img, label, meta)` 打包成 dict；
- 做批级别的增强（如 mixup：把两条样本按比例混合，10 章）；
- 数值类型整理：把 PIL 图转张量等（通常放 transform 更好，见第 4 节）。

## 3. num_workers：多进程加载与它的坑

### 3.1 为什么需要它

GPU 算一步只要 1ms，`__getitem__` 读盘+解码一张图要 10ms——GPU 90% 时间在等数据。`num_workers=k` 让 k 个子进程并行做数据准备，主进程只管训练：

```python
loader = DataLoader(ds, batch_size=64, num_workers=4, pin_memory=True)
```

`pin_memory=True` 把数据先放进"锁页内存"，加速 CPU→GPU 拷贝（仅 GPU 训练有意义，CPU 环境可省）。判断瓶颈的方法（经验做法）：把 `num_workers` 从 0 逐级加到 4/8，观察每 epoch 时间；不再下降说明瓶颈在计算而非数据。

### 3.2 坑一：每个 worker 是"复制"出来的，随机数状态一样

多进程用 fork（Linux 默认）时，worker 继承主进程的随机状态。如果 Dataset/transform 里用了 Python `random` 或 NumPy 的全局随机（典型：随机数据增强），**每个 worker 产出完全相同的增强序列**——4 个 worker 等效于 1 个 worker 的多样性，甚至一个 batch 内样本高度相关。PyTorch 的 `torch` 随机源已被 DataLoader 自动区分（它给每个 worker 设了不同的 base seed），但 **Python `random` 和 NumPy 不会**，要手动 `worker_init_fn`（见第 5 节）。

### 3.3 坑二：lambda 和闭包不能跨进程

```python
DataLoader(ds, batch_size=4, collate_fn=lambda b: b)   # num_workers>0 时报错！
# PicklingError: Can't pickle <function <lambda>>
```

多进程要把 `collate_fn`（以及 Dataset 本身）pickle 给子进程，**lambda、局部闭包、实例属性里挂的 lambda 都不可 pickle**。修复：定义成模块顶层函数。同理，Windows/macOS 默认 spawn 启动方式还会重新 import 你的模块——**Dataset/collate 必须定义在 `if __name__ == "__main__":` 保护之外**。

### 3.4 坑三：主进程与 worker 的状态不同步

worker 里的 Dataset 是**复制**的：训练中你在主进程改了 `self.some_flag`，worker 不会感知。要动态传信息给 worker，用共享内存或每 epoch 重建 loader（经验做法）。

### 3.5 坑四：内存翻倍与"最后一尾"

- 每个 worker 复制 Dataset（fork 时写时复制，通常还好；但 Dataset 里有大数组且后续被改写时会真复制，内存 ×worker 数）。
- `drop_last=True` 丢掉不满一个 batch 的尾巴：训练时常开（避免 BN 遇到 batch=1，见 6 章），评估必须 `False`（否则少算样本）。
- `persistent_workers=True`（num_workers>0 时可用）避免每 epoch 重启进程，能省启动开销。

## 4. transforms：预处理写在哪、怎么写

### 4.1 原则：训练/验证的不对称

- **训练**：随机增强（RandomCrop/RandomFlip/颜色抖动）——同一张图每个 epoch 长得不一样，等效扩充数据（10 章）。
- **验证/测试**：只用确定性变换（Resize/CenterCrop/ToTensor）——评估必须可复现。

```python
from torchvision import transforms

train_tf = transforms.Compose([
    transforms.RandomCrop(28, padding=4),    # 随机位置裁剪
    transforms.RandomHorizontalFlip(),       # 随机水平翻转
    transforms.ToTensor(),                   # PIL (H,W,C) uint8 0-255 -> (C,H,W) float32 0-1
    transforms.Normalize((0.1307,), (0.3081,)),  # MNIST 的全局均值/标准差（官方常引数值）
])
eval_tf = transforms.Compose([
    transforms.ToTensor(),
    transforms.Normalize((0.1307,), (0.3081,)),
])
```

`ToTensor` 做了两件事值得记住：**维度重排 HWC→CHW**（PyTorch 卷积要求通道在前）与**缩放 0-255 → 0-1**。`Normalize` 是减均值除标准差，让输入分布居中——数值稳定性（9 章）的一部分。这两个常数 (0.1307, 0.3081) 是对整个 MNIST 训练集预先统计的全局值，**不是你自己 batch 的统计值**；用自己数据集时要用训练集重新统计（不要用测试集统计——数据泄漏）。

### 4.2 自定义 transform

任何"输入样本、输出样本"的可调用对象都行：

```python
class AddGaussianNoise:
    """给张量加噪声: 一种数据增强"""
    def __init__(self, sigma=0.1):
        self.sigma = sigma
    def __call__(self, img):
        return img + torch.randn_like(img) * self.sigma
```

## 5. 可复现的数据管道

### 5.1 为什么要专门配

打乱顺序、随机增强、多 worker 的随机流，三者叠起来让"两次运行精度差 1%"成为常态，而消融实验（13 章）要求**唯一变量是实验设置本身**。可复现需要把三层随机源全部钉住。

### 5.2 标准三件套（模板直接抄）

```python
import random
import numpy as np
import torch
from torch.utils.data import DataLoader

def seed_everything(seed=42):
    random.seed(seed)                 # Python 随机源（augmentation 里常用）
    np.random.seed(seed)              # NumPy 随机源
    torch.manual_seed(seed)           # torch CPU 随机源（也影响 DataLoader 的 shuffle）
    torch.cuda.manual_seed_all(seed)  # [GPU] 所有 GPU 种子

def seed_worker(worker_id):
    """DataLoader 的每个 worker 调一次: 钉住 Python/NumPy 的 worker 级随机源"""
    worker_seed = torch.initial_seed() % 2**32   # DataLoader 已为每个 worker 派生不同种子
    np.random.seed(worker_seed)
    random.seed(worker_seed)

g = torch.Generator()                     # 独立的 shuffle 随机源
g.manual_seed(42)

seed_everything(42)
train_loader = DataLoader(
    train_set, batch_size=64, shuffle=True,
    num_workers=4, worker_init_fn=seed_worker,
    generator=g,                          # 固定 shuffle 顺序
    persistent_workers=True,
)
```

逐项说明职责：

| 设置 | 管住什么 |
| --- | --- |
| `torch.manual_seed` | 模型初始化、dropout mask、torch 系随机增强 |
| `torch.Generator` 传给 loader | 每个 epoch 的样本顺序 |
| `worker_init_fn` | 每个 worker 里的 Python/NumPy 随机流（否则各 worker 相同） |
| `np.random.seed`/`random.seed` | 主进程里这两家的随机调用 |

### 5.3 划分训练/验证集的正确姿势

```python
from torch.utils.data import random_split, Subset

n = len(train_set)
n_train, n_val = int(n * 0.9), n - int(n * 0.9)
gen = torch.Generator().manual_seed(42)             # 固定划分！否则每次 split 不同
train_subset, val_subset = random_split(train_set, [n_train, n_val], generator=gen)
# random_split 返回 Subset，内部保存索引；原始数据只读，无泄漏
```

陷阱：`random_split` 不传 `generator` 时每次运行划分不同——如果验证集也因此变化，调参就是在"对着噪声调"。划分本身也要可复现。数据有分组结构（同一病人的多张图）时要用**分组划分**（如 sklearn 的 GroupShuffleSplit），否则同一对象的样本同时出现在训练与验证集，指标虚高——这是医学/工业数据集最常见的泄漏方式（经验做法：先检查样本间是否独立）。

## 6. 常见陷阱清单

1. **在 `__getitem__` 里拼 batch**：职责错位，改到 `collate_fn` 去。
2. **归一化统计量用错来源**：用了自己拍脑袋的常数或测试集统计；应从**训练集**统计。
3. **验证集也开了随机增强**：val 指标每次评估都不同，无法判断模型是否变好。
4. **num_workers>0 + lambda collate**：PicklingError（3.3 节）。
5. **Windows 上忘加 `if __name__ == "__main__"`**：spawn 重新 import 模块时无限递归开进程。
6. **`shuffle=False` 用于训练集**：固定顺序会让 SGD 带系统性偏差（每个 epoch 内相关样本扎堆），训练集必须打乱。
7. **评估集 `drop_last=True`**：测试指标系统性偏差（少了尾巴上的样本）。
8. **忘记 `worker_init_fn`**：训练"能跑"，但增强多样性悄然缩水、且不可复现——最无害也最隐蔽的一个。

## 本篇小结

- Dataset 管"单条"，DataLoader 管"成批+打乱+并行"；collate_fn 管拼接，变长数据必须自定义并配套 mask。
- `num_workers` 提速明显但有四个坑：worker 随机流复制（Python/NumPy 需 `worker_init_fn`）、lambda 不可 pickle、spawn 需 main 保护、内存随 worker 数增长。
- transform 遵循"训练随机、评估确定"；`ToTensor` = HWC→CHW + 缩放；`Normalize` 用训练集统计。
- 可复现三件套：全局 `seed_everything` + loader 的 `generator` + `worker_init_fn`；数据划分也必须传固定 `generator`。
