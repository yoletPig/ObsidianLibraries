### 阶段七：结课项目——端侧离线语音助手全链路（6 - 8 周）

**阶段核心目标**：把前六个 Stage 的全部技能焊成一台**完全离线、跑在 RK3588 上**的语音助手：麦克风前端（AEC+NS+AGC+VAD）→ 流式 ASR（SenseVoice/Paraformer-Small）→ 端侧 LLM（量化后，性能优化方向的成果）→ TTS（CosyVoice/GPT-SoVITS 蒸馏小模型）。这是你两个方向学习计划的交汇点，也是求职作品集的头号项目。

> 🔗 本 Stage 与性能优化方向的 Stage 4（RKNN 部署）、Stage 8（端侧量化）强耦合。若按「先语音后性能」的顺序执行，本 Stage 中 LLM/模型的量化部署部分会在性能优化阶段完成后**回填升级**。

---

### 📅 逐周学习路线与 MVP 交付

#### 第 1-2 周：系统架构设计与链路预算

* **学习重点**：
* **延迟预算拆解**：唤醒词（≤50 ms）→ VAD 端点（100 ms）→ ASR（≤200 ms）→ LLM 首 token（≤500 ms）→ TTS 首包（≤300 ms），总响应 < 1.5 s 的分配。
* **模块选型冻结**：前端 = WebRTC APM 裁剪版；ASR = SenseVoice-Small（Stage 2 已验证）；LLM = Qwen2.5-1.5B/3B 或 MiniCPM-o 端侧版；TTS = 蒸馏后的小模型。
* **接口定义**：各模块间的数据格式（16 kHz PCM / token / mel）、队列与背压设计、全双工打断。
* **RK3588 资源盘点**：4× A76 + 4× A55 + 6 TOPS NPU，CPU/NPU 任务分配策略。

* **💡 第 1-2 周 MVP 交付**：
> 产出《端侧语音助手系统设计文档》：模块图 + 数据流 + 延迟预算表 + 显存/内存预算表 + 风险清单（每个模块的 fallback 方案）。此文档即面试架构题的答卷模板。

#### 第 3-4 周：前端与 ASR 链路打通（板端）

* **学习重点**：
* **麦克风阵列采集**：ALSA/PulseAudio 采集、板载麦阵列；AEC 参考信号从音频输出回路引出。
* **前端移植**：WebRTC APM 的 ARM 编译与参数调优（Stage 3 成果直接上板）。
* **ASR 板端部署**：SenseVoice-Small → ONNX → RKNN（与性能优化 Stage 4 联动；若本阶段先行，先用 ONNX Runtime CPU 打通，RKNN 后补）。
* **流式管道**：VAD 触发 → 录音缓冲 → ASR 的增量处理，C++/Python 混合实现。

* **💡 第 3-4 周 MVP 交付**：
> 板端跑通「说话 → 文字」：实测 RK3588 上 ASR 的 RTF 与首字延迟，记录 CPU/NPU 利用率；与云端推理结果做一致性对比（识别率差距 < 2%）。

#### 第 5-6 周：端侧 LLM + TTS 链路打通

* **学习重点**：
* **端侧 LLM 选型与量化**：Qwen2.5-1.5B/3B（INT4，性能优化 Stage 5-6 的 GGUF/RKNN 成果）；KV cache 内存管理。
* **TTS 端侧化**：CosyVoice2-0.5B 蒸馏或 GPT-SoVITS 小模型的 ONNX 导出；首包延迟优化（分段合成、边生成边播）。
* **对话管理**：多轮上下文、语音打断（用户说话即截断 TTS 播放）、唤醒词引擎（sherpa-onnx / picovoice）。
* **全链路编排**：asyncio/多线程管道，打断响应时间 ≤ 200 ms。

* **💡 第 5-6 周 MVP 交付**：
> 板端跑通完整闭环：唤醒词 → 听 → 想 → 说，实测端到端延迟分布（100 次对话的 P50/P95）；实现语音打断并测量截断延迟。

#### 第 7-8 周：产品化打磨 + 压测 + 结课报告

* **学习重点**：
* **鲁棒性**：断网完全离线验证、长对话内存泄漏排查、高温降频测试。
* **质量压测**：不同信噪比（安静/电视背景/多人场景）下的全链路成功率。
* **可观测性**：端侧日志与延迟埋点，每个模块的耗时火焰图。
* **作品集包装**：录制 Demo 视频、GitHub 仓库整理、技术博客（系统架构 + 关键决策 + 踩坑记录）。

* **💡 第 7-8 周 MVP 交付（结课总交付）**：
> ① 可演示的板端离线语音助手（录屏 + 现场演示）；② 全链路延迟/成功率压测报告；③ 与云端同款模型的对比评测（延迟 ↓多少、精度损失多少）；④ 系统设计文档 + 结课技术博客。
