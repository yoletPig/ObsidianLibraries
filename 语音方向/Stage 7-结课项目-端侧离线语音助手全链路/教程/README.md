## 贯穿全阶段的一条主线

$$
\text{麦克风} \xrightarrow{\text{AEC/NS/AGC+VAD}} \text{干净语音} \xrightarrow{\text{SenseVoice}} \text{文字} \xrightarrow{\text{Qwen2.5 INT4}} \text{回答} \xrightarrow{\text{TTS 小模型}} \text{扬声器}
$$

全链路只有一个硬指标：**从用户说完到听到回答 < 1.5 s**。每个模块的一切选型、量化、优化，都为这一个数字服务。

## 技术选型（已冻结）

- 前端：WebRTC APM（裁剪版）+ Silero VAD；
- ASR：SenseVoice-Small（ONNX，先 CPU 打通、RKNN 后补）+ sherpa-onnx；
- LLM：Qwen2.5-1.5B/3B INT4（llama.cpp / rknn-llm）；
- TTS：蒸馏小模型（ONNX，边生成边播）；
- 唤醒：sherpa-onnx 或 picovoice。

## 前置依赖

- Stage 1-6 全部完成（前端信号处理、ASR、LLM 训练认知、TTS 合成）；
- RK3588 开发板 + 麦克风阵列 + 扬声器；性能优化方向未开始的模块先用 CPU 方案打通，后续回填；
- 交叉编译工具链（aarch64）、`sherpa-onnx`、`llama.cpp`。
