## 1. 第一性原理：声音是什么，数字又是什么

### 1.1 从空气振动到连续信号

声音的本质是空气压强的微小波动。说话时声带振动，扰动空气形成疏密波，传到麦克风振膜上，振膜的位移随时间变化。这个过程可以用一个**连续时间信号**描述：

$$
x(t), \quad t \in \mathbb{R}
$$

这里 $t$ 是时间（秒），$x(t)$ 是时刻 $t$ 的气压偏移（或麦克风输出的归一化电压）。两个关键物理属性：

- **频率（Hz）**：每秒钟振动的次数。人声基频（fundamental, $f_0$）男声约 85–180 Hz，女声约 165–255 Hz；而语音中承载"清晰度"的辅音摩擦、爆破成分可达 8 kHz 以上。
- **幅度**：振动的强度，对应响度。

计算机无法存储"对所有实数 $t$ 都成立的函数"，必须把它**离散化**。这一步就是采样。

### 1.2 采样的数学定义：冲激串相乘

采样可以严格地写成：用一个周期为 $T_s = 1/f_s$ 的冲激串（Dirac comb）去乘连续信号：

$$
x_s(t) = x(t) \cdot \sum_{n=-\infty}^{\infty} \delta(t - nT_s)
$$

得到的 $x_s(t)$ 只在 $t = nT_s$ 处非零，取值为 $x(nT_s)$。我们实际存储的就是这串数值：

$$
x[n] = x(nT_s), \quad n = 0, 1, 2, \dots
$$

这就是波形数组里**每一个数字的含义**：第 $n$ 个样本 = 第 $n$ 个采样时刻的气压偏移。$f_s$（采样率）决定时间分辨率——$f_s = 16000$ Hz 意味着每秒取 16000 个点，相邻样本间隔 $1/16000$ 秒 = 62.5 微秒。

### 1.3 采样定理：为什么是"两倍"

**Nyquist–Shannon 采样定理**：若连续信号 $x(t)$ 是带限的，最高频率为 $B$，则当采样率

$$
f_s \ge 2B
$$

时，$x(t)$ 可以由采样序列 $x[n]$ **无失真地完全重建**。$2B$ 称为奈奎斯特率，$f_s/2$ 称为奈奎斯特频率。

**为什么是两倍？** 直觉上，要"描出"一个周期为 $T$ 的正弦波，每个周期至少需要两个采样点（一个靠近波峰、一个靠近波谷）才能区分它和更低频的波形。若采样率不足，高频信号会被"误认"成一个低频信号——这个错误无法事后修复，因为它在采样瞬间就已经发生了。

**推导混叠频率**。设真实频率为 $f$，采样率为 $f_s$。采样后，频率 $f$ 与 $f \pm k f_s$（$k$ 为整数）的连续正弦波在所有采样点上取值完全相同（因为 $\cos(2\pi(f + k f_s) n T_s) = \cos(2\pi f n T_s + 2\pi k n) = \cos(2\pi f n T_s)$）。因此采样把整个频率轴按 $f_s$ 折叠，实际观测到的是折叠后的频率：

$$
f_{\text{alias}} = |f \bmod f_s|,\quad \text{再镜像折叠到 } [0, f_s/2]
$$

**例子**：$f_s = 16000$ Hz，真实信号 $f = 9000$ Hz。因为 $9000 > 8000$（奈奎斯特频率），它会被折叠成 $16000 - 9000 = 7000$ Hz。于是 9 kHz 的哨声在数字音频里"变成"了 7 kHz——永久失真。

### 1.4 抗混叠：采样前的低通滤波

既然混叠不可逆，唯一的对策是**在采样之前**用模拟低通滤波器（anti-aliasing filter）把高于 $f_s/2$ 的成分切掉。这就是为什么标准采样率是那些特定值：

| 采样率 | 奈奎斯特频率 | 用途 |
| --- | --- | --- |
| 8000 Hz | 4 kHz | 电话语音（人声基频+主要共振峰够用） |
| **16000 Hz** | 8 kHz | **ASR/语音处理事实标准** |
| 44100 Hz | 22.05 kHz | CD 音质（覆盖人耳 20 Hz–20 kHz） |
| 48000 Hz | 24 kHz | 专业音频、视频 |

本方向所有语音任务统一用 **16 kHz**。你的 `AudioPipeline` 会把一切输入重采样到 16 kHz。

## 2. 量化：把幅度也离散化

采样解决了"时间轴"的离散化，**量化（quantization）**解决"幅度轴"的离散化。每个样本的幅度被舍入到最近的量化电平。

### 2.1 位深与动态范围

若用 $b$ 位存储每个样本，则有 $2^b$ 个量化电平。最常见的 16-bit PCM：

- 电平数 $2^{16} = 65536$，取值范围 $[-32768, 32767]$。
- 归一化到浮点时通常除以 32768，得到 $[-1.0, 1.0)$。

量化引入**量化噪声**，其信噪比（SQNR）约为：

$$
\text{SQNR}_{\text{dB}} \approx 6.02\,b + 1.76
$$

所以 16-bit 约 98 dB，24-bit 约 146 dB。这也是为什么数字音频偏好更高位深——量化噪声更低。

### 2.2 存储格式：int16 vs float32

- **int16（PCM16）**：`.wav` 的经典格式，磁盘友好。
- **float32**：内存中做信号处理的标准格式，取值 $[-1.0, 1.0]$，避免中间计算的截断。

**黄金实践**：读入后立即转 `float32`，所有处理在浮点域进行，只在最终写出时再转回 `int16`。`soundfile` 默认返回浮点，正合此惯例。

## 3. 波形数组的解剖：Shape 到底代表什么

### 3.1 单声道 vs 多声道

一段时长 $D$ 秒、采样率 $f_s$ 的**单声道**音频，其波形数组形状为：

$$
\text{shape} = (N,) , \quad N = D \times f_s
$$

**多声道**（如立体声 2 声道）交错存储为 $(N, C)$，$C$ 为声道数。语音处理几乎总是先把多声道**混缩（downmix）**成单声道：

$$
x_{\text{mono}}[n] = \frac{1}{C}\sum_{c=1}^{C} x[n, c]
$$

**例子**：10 秒、16 kHz、单声道 → $N = 10 \times 16000 = 160000$ 个样本。这个数字你后面会反复用到：算帧数、算特征长度都从它出发。

### 3.2 读取与三要素

下面是最小读取脚本，交付物之一：

```python
import soundfile as sf
import numpy as np

# 读取（请替换为你的真实录音路径）
wave, sr = sf.read("my_voice.wav", dtype="float32")

# 多声道混缩为单声道
if wave.ndim > 1:
    wave = wave.mean(axis=1)

duration = len(wave) / sr
print(f"Shape      : {wave.shape}")     # (N,)
print(f"采样率     : {sr} Hz")          # 期望 16000，若不是则需重采样
print(f"时长       : {duration:.2f} s")
print(f"幅度范围   : [{wave.min():.3f}, {wave.max():.3f}]")
print(f"RMS 能量   : {np.sqrt(np.mean(wave**2)):.4f}")

# 断言：确认为一维、归一化幅度
assert wave.ndim == 1
assert wave.max() <= 1.0 and wave.min() >= -1.0
```

**预期输出**（一段 3 秒 16 kHz 录音）：

```
Shape      : (48000,)
采样率     : 16000 Hz
时长       : 3.00 s
幅度范围   : [-0.412, 0.387]
RMS 能量   : 0.0821
```

三要素 = **Shape（样本数）、采样率、时长**，且满足 $N = D \times f_s$。RMS 能量是后面算 SNR 的基础，先记住它。

## 4. 分帧与加窗：为频谱分析做原子准备

直接对整段信号做傅里叶变换会得到"整段平均"的频谱，丢失时间信息（一句话前半段和后半段的发音不同）。解决办法是**分帧（framing）**：把信号切成许多短片段，每段近似"平稳"，再逐段分析。

### 4.1 帧长、帧移与加窗

- **帧长（frame length / win_length）**：每帧的时间跨度，语音常用 25 ms。
- **帧移（hop size / hop_length）**：相邻帧起点间隔，常用 10 ms。
- **帧数**：

$$
\text{n\_frames} = 1 + \left\lfloor \frac{N - \text{frame\_len}}{\text{hop}} \right\rfloor
$$

16 kHz、25 ms、10 ms 时：frame_len = 400 样本，hop = 160 样本。10 秒（160000 样本）→ $1 + (160000-400)/160 = 998$ 帧，约等于"每秒 100 帧"这个重要经验值。

- **为什么要加窗？** 直接截断一帧等于乘了一个矩形窗，会在频域引入泄漏（spectral leakage）。改用平滑的窗函数（Hamming/Hann）让帧边缘渐变为零：

$$
w_{\text{Hann}}[n] = 0.5\left(1 - \cos\frac{2\pi n}{L-1}\right),\quad n=0,\dots,L-1
$$

```python
import numpy as np

def frame_signal(x: np.ndarray, frame_len: int, hop: int,
                 window: str = "hann") -> np.ndarray:
    """把一维波形切成重叠帧。返回 (n_frames, frame_len)。"""
    n_frames = 1 + (len(x) - frame_len) // hop
    # 用 stride trick 高效切帧（不复制数据）
    idx = (np.arange(frame_len)[None, :]
           + np.arange(n_frames)[:, None] * hop)
    frames = x[idx]                      # (n_frames, frame_len)
    if window == "hann":
        win = np.hanning(frame_len)
    elif window == "hamming":
        win = np.hamming(frame_len)
    else:
        win = np.ones(frame_len)
    return frames * win                  # 逐帧加窗

# 验证：10 秒 16kHz
x = np.random.randn(160000).astype(np.float32)
frames = frame_signal(x, frame_len=400, hop=160)
print(frames.shape)          # (998, 400)
assert frames.shape == (998, 400)
assert abs(frames[0, 0]) < 1e-6   # Hann 窗首样本≈0，证明加窗生效
```

**预期输出**：`(998, 400)`。这个 `(帧数, 帧长)` 的二维矩阵就是第 2 周 STFT 的直接输入。

## 5. 重采样：换采样率的正确姿势

### 5.1 原理

重采样到新采样率 $f_s'$ 的正确步骤是 **先低通滤波，再插值/抽取**，否则会混叠：

1. 若降采样（$f_s' < f_s$）：先用截止频率 $f_s'/2$ 的低通滤波器切掉新奈奎斯特频率以上的成分；
2. 再按新采样率取值（有理比 $f_s'/f_s = P/Q$ 时，可先上采样 $P$ 倍、滤波、再下采样 $Q$ 倍）。

### 5.2 纯 NumPy 线性插值实现（交付物）

这是本周的核心交付：不用 `scipy.signal.resample`，自己写一个最简单的线性插值重采样器，并演示混叠。

```python
import numpy as np
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt

def resample_linear(x: np.ndarray, sr_in: int, sr_out: int) -> np.ndarray:
    """线性插值重采样（教学版，演示原理）。"""
    dur = len(x) / sr_in                       # 时长不变
    n_out = int(dur * sr_out)
    # 输出样本在原时间轴上的位置（以输入样本索引为单位）
    t_out = np.arange(n_out) * (sr_in / sr_out)
    idx0 = np.floor(t_out).astype(int)
    idx1 = np.minimum(idx0 + 1, len(x) - 1)
    frac = t_out - idx0
    return (1 - frac) * x[idx0] + frac * x[idx1]

# ---- 演示：44.1kHz 正弦波重采样到 16kHz ----
sr_in, sr_out = 44100, 16000
dur, f = 1.0, 440.0                            # 1 秒 440Hz（低于奈奎斯特，安全）
t = np.arange(int(sr_in * dur)) / sr_in
x = np.sin(2 * np.pi * f * t)
y = resample_linear(x, sr_in, sr_out)
print(f"输入 {len(x)} 样本 @ {sr_in}Hz -> 输出 {len(y)} 样本 @ {sr_out}Hz")
assert abs(len(y) - dur * sr_out) <= 1

# ---- 演示混叠：输入 9kHz，采样率 16kHz ----
f_alias = 9000.0
t2 = np.arange(16000) / 16000
x2 = np.sin(2 * np.pi * f_alias * t2)
expected_alias = 16000 - f_alias               # 理论折叠到 7000Hz
# 用 FFT 验证峰值频率
spec = np.abs(np.fft.rfft(x2))
freqs = np.fft.rfftfreq(len(x2), d=1/16000)
peak = freqs[np.argmax(spec)]
print(f"9kHz 信号在 16kHz 采样下，FFT 峰值出现在 {peak:.0f}Hz（理论 {expected_alias:.0f}Hz）")
assert abs(peak - expected_alias) < 50
```

**预期输出**：

```
输入 44100 样本 @ 44100Hz -> 输出 16000 样本 @ 16000Hz
9kHz 信号在 16kHz 采样下，FFT 峰值出现在 7000Hz（理论 7000Hz）
```

第二个断言就是混叠的直接证据：9 kHz 的正弦波，在 16 kHz 采样后"变成"了 7 kHz。**生产环境请用 `librosa.resample` 或 `torchaudio.functional.resample`**（内部做带限滤波），这里的手写版只为理解原理。

## 6. 工程权衡与失效模式

### 6.1 权衡

- **采样率**：越高时间/频率分辨率越好，但数据量线性增长。语音用 16 kHz 是精度与成本的甜点。
- **帧长**：长帧频率分辨率好但时间分辨率差（测不准原理，见第 2 周）；25 ms 是语音的经验折中。
- **位深**：浮点处理 > 整型存储。

### 6.2 典型失效模式

1. **未重采样就喂模型**：模型期望 16 kHz，你喂了 44.1 kHz，语谱被整体"压缩"，ASR 全错。**定位**：打印 `sr`；**修复**：入口处统一重采样。
2. **混叠伪影**：录音时未开抗混叠滤波，高频噪声折叠进语音带内。**症状**：频谱里出现与内容无关的杂散峰；**修复**：硬件滤波 + 降采样前软件低通。
3. **削波（clipping）**：录音电平过高，样本顶到 ±1.0 被截断，波形顶部"削平"，引入大量谐波失真。**定位**：`wave.max() >= 0.99`；**修复**：降低录音增益。

## 7. 延伸思考题（含解析）

**Q1**：16 kHz 采样、10 秒的单声道语音，波形数组有多少个元素？若改为立体声呢？
**A**：单声道 $10 \times 16000 = 160000$。立体声 shape 为 $(160000, 2)$，混缩后回到 160000。

**Q2**：为什么语音任务几乎都用 16 kHz 而不是 8 kHz？
**A**：8 kHz 奈奎斯特频率仅 4 kHz，会丢掉大量辅音高频信息（如 /s/、/f/ 的摩擦成分在 4 kHz 以上），显著降低可懂度与识别率；16 kHz 保留到 8 kHz，兼顾质量与数据量。

**Q3**：`frame_signal` 里为什么用 `idx` 索引而不是 `for` 循环逐帧切片？
**A**：NumPy 高级索引一次性构造 `(n_frames, frame_len)`，避免 Python 层循环开销，且内存连续、可向量化。帧数上万时差异是数量级的。

**Q4**：线性插值重采样的主要缺陷是什么？生产用什么？
**A**：线性插值没有先做低通滤波，降采样时会混叠，且高频重建不平滑。生产用 `librosa.resample`（kaiser_best 窗同步滤波）或 `torchaudio.functional.resample`（多相滤波）。
