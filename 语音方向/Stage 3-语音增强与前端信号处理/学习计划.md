### 阶段三：语音增强与前端信号处理——降噪 / AEC / AGC / ANC（6 周）

**阶段核心目标**：掌握「脏音频 → 干净音频」的完整前端链路：AI 深度降噪（DeepFilterNet 系）、回声消除（AEC）、自动增益（AGC）、主动降噪（ANC）的自适应滤波原理，并对照工业事实标准 WebRTC APM 模块。本阶段是端侧语音助手可用性的关键——麦克风前端质量直接决定 ASR 上限。

---

### 📅 逐周学习路线与 MVP 交付

#### 第 1 周：噪声模型与经典增强方法

* **学习重点**：
* **噪声分类学**：平稳噪声（白噪声/粉噪声）vs 非平稳（键盘/街道），噪声功率谱估计（MCRA、最小值跟踪）。
* **谱减法进阶**：过减因子、音乐噪声（Musical Noise）伪影与谱下限（Spectral Floor）。
* **维纳滤波（Wiener Filter）**：MMSE 意义下的最优增益，先验信噪比（Decision-Directed）估计。
* **评价指标体系**：PESQ、POLQA、STOI、SI-SNR、DNSMOS（无参考深度学习打分，打榜必备）。

* **推荐论文**：
* *Speech enhancement using a minimum mean-square error short-time spectral amplitude estimator*（Ephraim-Malah MMSE-STSA）

* **💡 第 1 周 MVP 交付**：
> 手写 Decision-Directed 维纳滤波器（STFT 域），在 0/5/10 dB SNR 的带噪语音上测试，输出 PESQ/STOI 随 SNR 的变化曲线，并与 Stage 1 写的谱减法对比。

#### 第 2 周：AI 深度降噪——DeepFilterNet 系

* **学习重点**：
* **DeepFilterNet2/3 架构**：Encoder 双分支（帧级 + 组级特征）、Deep Filtering（时频域复数滤波器组）为什么比纯掩码估计好。
* **复数谱表示**：RI（实虚部）vs 幅度/相位两种参数化的优劣；因果（Causal）与低延迟约束。
* **实时约束**：帧长 10 ms、算法延迟 20 ms 级的工程实现；RTF < 1 在 CPU 上的意义。
* **其他流派**：Conv-TasNet（时域）、DTLN（双路轻量，端侧经典）、FullSubNet（全频+子频融合）。

* **推荐论文**：
* *DeepFilterNet: A Low Complexity Speech Enhancement Framework for Full-Band Audio*
* *DTLN: Dual-signal Transformation LSTM Network for Real-Time Speech Enhancement*

* **💡 第 2 周 MVP 交付**：
> ① 跑通 `deepfilternet` 官方推理，对比 DeepFilterNet3 与你的维纳滤波在 DNS Challenge 测试集上的 DNSMOS 分数；② 用 `onnxruntime` 把降噪模型导出为 ONNX 并测 CPU 延迟（为 Stage 8 端侧部署预热）。

#### 第 3 周：回声消除（AEC）

* **学习重点**：
* **问题本质**：扬声器外放声音被麦克风重新采集形成回声；远端参考信号（Reference）的作用。
* **自适应滤波器核心**：NLMS / RLS / Kalman 滤波器估计回声路径 $\hat{h}$，双讲（Double-talk）检测与步长冻结。
* **频域分块（FDAF/PBFDAF）**：为什么 AEC 必须在频域做，重叠保存法（Overlap-Save）。
* **非线性处理（NLP）与残余回声抑制（RES）**：线性滤波后的残留怎么压，舒适度噪声（Comfort Noise）。
* **WebRTC AEC3 拆解**：延迟估计（Delay Estimator）、滤波器发散控制——工业级实现的复杂度标杆。

* **推荐资料**：
* WebRTC `modules/audio_processing/aec3` 源码导读（重点读 `echo_path_variability.cc` 的注释）
* 论文：*Adaptive Filter Theory* (Haykin) 第 8-9 章选读

* **💡 第 3 周 MVP 交付**：
> 用 `scipy.signal` 手写频域 NLMS 回声消除器：合成「远端信号经模拟房间脉冲响应 → 麦克风」的回声数据，实现参考对齐 + 自适应滤波，画出回声路径收敛曲线（ERLE 随时间变化）。再跑一次 WebRTC APM（`py-webrtcvad` + `webrtc-noise-gain`）做对照。

#### 第 4 周：AGC、VAD 与主动降噪（ANC）

* **学习重点**：
* **AGC 两级结构**：数字增益（Digital）+ 模拟增益（Analog）；目标响度、起音/释放时间（Attack/Release）、限幅器（Limiter）防削波。
* **响度标准**：LUFS/LKFS（广播标准）与 EBU R128，语音通信的 -23 LUFS 目标。
* **VAD**：能量/过零率/谱熵传统方法 → WebRTC VAD（GMM）→ Silero VAD（端到端，当前事实标准）。
* **ANC 原理**：次级声源产生反相声波抵消；FXLMS（Filtered-x LMS）算法，为什么需要次级路径估计 $\hat{S}(z)$；前馈式（耳机）与反馈式的区别。
* **ANC 与 AI 降噪的边界**：ANC 消低频稳态噪声（引擎声），AI 降噪消非稳态噪声——两者互补而非竞争。

* **推荐论文**：
* *Active noise control: a tutorial review*（Kuo & Morgan）
* Silero VAD: *Silero VAD: pre-trained enterprise-grade voice activity detector*（GitHub README 即论文）

* **💡 第 4 周 MVP 交付**：
> ① 手写 AGC：实现目标 LUFS 追踪 + 平滑增益曲线 + 硬限幅，对音量忽大忽小的语音输出稳定波形；② 用 Python 数值仿真一个单通道前馈 ANC（FXLMS），画出次级路径失配对残余噪声的影响曲线；③ 集成 Silero VAD 到你的 `AudioPipeline`。

#### 第 5-6 周：WebRTC APM 全链路整合 + 阶段复盘

* **学习重点**：
* **APM 模块流水线**：AEC3 → NS（噪声抑制）→ AGC2 → VAD 的调用顺序与相互耦合（为什么 AEC 必须在 NS 之前）。
* **`webrtc-audio-processing` 绑定**：Python/C++ 调用，配置项（保守/激进档位）。
* **真实录音评测**：手机免提通话场景的完整链路质量评估方法。
* **前端与后端的接口**：增强后音频喂 ASR 的增益量化实验——前端提升 1 分贝，ASR CER 改善多少？

* **💡 第 5-6 周 MVP 交付**：
> 构建「录音 → AEC → NS → AGC → VAD → ASR」完整前端流水线（WebRTC APM + Silero VAD + Stage 2 的 FunASR），对 10 条带噪/带回声录音输出：① 各阶段音频对比试听；② DNSMOS 分数链；③ 前端开关对 ASR CER 的消融表。这将是 Stage 8 端侧助手的核心组件。
