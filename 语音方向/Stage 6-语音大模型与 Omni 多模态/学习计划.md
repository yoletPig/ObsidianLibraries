### 阶段六：语音大模型与 Omni 多模态——与你已有 VLM 知识的打通（6 周）

**阶段核心目标**：把你 Stage 1-5 的语音全栈知识与 VLM & VLA 阶段的架构知识**焊在一起**：语音-语言对齐（类 LLaVA 范式）、Speech-to-Speech 端到端、Qwen2.5-Omni / MiniCPM-o / Step-Audio 架构拆解，最终完成一次语音指令微调（Speech SFT），产出能听懂语音指令的端到端模型。这是你求职简历上「全模态」叙事的核心章节。

### 📅 逐周学习路线与 MVP 交付

#### 第 1 周：Speech-LLM 的三种范式

* **学习重点**：
* **范式 A：Speech-to-Text（级联的包装）**：ASR 前端 + LLM，伪端到端；延迟与误差传播的天花板。
* **范式 B：Speech-in-Text（音频特征注入）**：类 LLaVA 路线——Audio Encoder（Whisper Encoder / BEATs）+ Projector + LLM；Qwen-Audio / SALMONN / Kimi-Audio 谱系。**直接映射你 VLM 阶段的知识：音频塔 ≈ Vision Tower，Projector 完全同构**。
* **范式 C：Speech-to-Speech（全双工）**：LLM 直接输出语音 token（Moshi 的双工建模、GLM-4-Voice）；Thinker-Talker 架构（Qwen2.5-Omni）。
* **音频理解广度**：不只是语音——环境声分类、音频问答（AudioCaps）、音乐理解。

* **推荐论文**：
* *Qwen-Audio: Advancing Universal Audio Understanding via Unified Large-Scale Audio-Language Models*
* *SALMONN: Towards Generic Hearing Abilities for Large Language Models*

* **💡 第 1 周 MVP 交付**：
> 画出「Speech-LLM 三范式架构图」，并把你 VLM 阶段手绘的 LLaVA 图放在旁边逐项对照（Audio Encoder ↔ Vision Encoder、audio token ↔ image token 占位符替换），写出两者的所有同构点与差异点清单。

#### 第 2 周：Qwen2.5-Omni 深度拆解

* **学习重点**：
* **Thinker-Talker 架构**：Thinker（理解+文本生成）与 Talker（流式语音生成）的分工与 token 流；为什么比单模型 Speech-to-Speech 更稳。
* **TMRoPE（Time-aligned Multimodal RoPE）**：把视频时间轴与音频流在位置编码上对齐——你 2D-RoPE（Qwen2-VL 阶段）知识的直接升级。
* **全模态流式**：音频+视频同时输入、流式文本+流式语音同时输出的工程实现。
* **语音理解 + 生成的统一**：一个模型同时干 ASR、语音问答、TTS 三件事。

* **推荐论文**：
* *Qwen2.5-Omni Technical Report*（重点读 TMRoPE 与流式训练章节）

* **💡 第 2 周 MVP 交付**：
> 云部署 `Qwen2.5-Omni-7B`，实现三种交互模式：① 语音问答（输出文本+语音）；② 视频+音频联合理解；③ 打断测试（流式中插入新语音）。用你 VLM 阶段的维度追踪法，画出音频输入从 Whisper-style encoder 到 Thinker 的 Token 流全图。

#### 第 3 周：MiniCPM-o / Step-Audio / Moshi 对比

* **学习重点**：
* **MiniCPM-o 2.6**：端侧友好的 8B Omni 模型，实时语音对话（VAD 驱动的轮次管理）与「音色克隆」能力；端侧部署路径。
* **Step-Audio 2**：双模型架构（理解模型 + 生成模型）与工具调用语音化。
* **Moshi**：真正的双工（Full-Duplex）——模型同时听和说，Depth Transformer 与 Mimi codec；为什么双工是语音交互的终极形态。
* **横评**：全双工能力 / 端侧友好度 / 开源程度 / 中文质量四维度。

* **推荐论文**：
* *MiniCPM-o: Towards Multi-Modal Lightweight Large Language Model*
* *Moshi: a speech-text foundation model for real-time dialogue*

* **💡 第 3 周 MVP 交付**：
> 完成「三大 Omni 模型横评报告」：用统一的 10 条语音指令测试集（含打断、追问、方言口音），对比 Qwen2.5-Omni / MiniCPM-o / Step-Audio 2 的响应延迟、首包延迟、回答质量、克隆音色相似度；给出「端侧选谁、云端选谁」的结论。

#### 第 4 周：音频离散化与语音 Codec 深挖（与量化方向联动）

* **学习重点**：
* **三大 Codec**：EnCodec / SoundStream / Mimi（Moshi 的语义+声学混合 codec）；Semantic RVQ（第一层语义、后续层声学）的设计哲学。
* **Codec 与量化的血缘**：RVQ 本质就是向量量化——与你性能优化方向的 GPTQ/AWQ 标量量化互为镜像，本阶段为跨方向面试问题备弹药。
* **Token 化对下游的影响**：不同 codec 的 token 率（50/75/12.5 Hz）如何决定 LM 序列长度与延迟。

* **推荐论文**：
* *SoundStream: An End-to-End Neural Audio Codec*
* *High Fidelity Neural Audio Compression* (EnCodec)

* **💡 第 4 周 MVP 交付**：
> 实测三种 codec 的重建质量：同一段语音过 EnCodec（1.5/6/12 kbps）与 Mimi，计算重建语音的 PESQ/UTMOS，画出「码率-质量曲线」；解释为什么语义层（第一层 RVQ）单独解码出来是「内容对但音色丢失」。

#### 第 5-6 周：Speech SFT 微调实战 + 阶段复盘

* **学习重点**：
* **数据构造**：`(音频, 指令文本, 回答文本)` 三元组；用你的 Stage 2 ASR 给海量无标注音频打标签，构造 Speech-Instruction 数据（合成数据方法论直接复用你 VLM Stage 4 的经验）。
* **微调实操**：`ms-swift` 对 Qwen2-Audio 或 Qwen2.5-Omni 做 LoRA，冻结 audio encoder 只训 projector + LLM 低秩层——与 VLM LoRA 策略完全同构。
* **评测**：语音指令跟随准确率、ASR 子任务 WER 回归测试（微调后不能变聋）。
* **灾难性遗忘监控**：通用对话能力在语音微调后的保持度测量。

* **💡 第 5-6 周 MVP 交付**：
> ① 构造 1000 条语音指令数据集（500 条真实录音 + 500 条 TTS 合成——用你 Stage 5 的 CosyVoice 合成训练数据，完成一次漂亮的技能闭环）；② 云端微调 Qwen2-Audio 或 MiniCPM-o，输出微调前后的语音问答准确率对比、通用能力回归测试表；③ 写一份「Speech-LLM 与 VLM 训练方法论异同」总结（面试直接用）。
