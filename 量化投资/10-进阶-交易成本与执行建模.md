# 10 - 进阶：交易成本与执行建模

> 进阶篇第 1 章。05 篇把成本当作一个常数参数（cost_bps）；实盘中，成本是**随你自身行为变化的环境函数**——你下单本身会移动价格（冲击成本），你的策略越成功这条曲线越陡。本章把成本从"扣减项"升级为"建模对象"：成本结构拆解、滑点建模、执行算法思想、容量分析。这是回测与实盘之间最后一段可量化的差距。

## 1. 成本解剖：四层结构

| 层 | 构成 | 量级（A 股参考） | 性质 |
| --- | --- | --- | --- |
| 显性佣金 | 券商佣金 | 约万 1~万 3（各家不同，最低 5 元） | 固定，可谈 |
| 税费 | 印花税（卖出单边） | 万 5（2023-08-28 起） | 固定，政策性 |
| 过户费 | 沪市过户费 | 万 0.1 量级 | 固定 |
| **隐性滑点** | 价差 + 冲击 + 时机 | **波动大，常超过前三项之和** | 随行为变化 |

结论先行：**低频策略的成本近似常数；换手率越高的策略，成本模型的精度越是生死攸关**。日换手 100% 的策略，年成本 20%+ 里大半可能是滑点——对这类策略，"成本建模"就是"策略建模"本身。

## 2. 滑点建模：从常数到环境函数

### 2.1 三个组成部分

对一笔市价单，滑点 = **半价差** + **冲击成本** + **时机成本**：

1. **半价差（half-spread）**：吃掉买卖价差的一半，与流动性成反比——A 股大盘蓝筹价差常在 1 个 tick（0.01 元），小盘股可达数 tick；
2. **冲击成本（impact）**：你的单量推动价格的部分。业界常用平方根律建模（源自 Loeb 1983 与后续市场微观结构研究）：冲击 ≈ σ_daily × k × √(Q / ADV)，其中 Q 为你的单量、ADV 为日均成交量、k 为经验系数；
3. **时机成本（timing）**：从决策到成交期间价格的自然漂移——延迟一天执行的期望漂移就是 02 篇 shift(1) 的实盘对应物。

### 2.2 实现一个随行为变化的成本模型

```python
def slippage_bps(order_shares: float, adv_shares: float,
                 daily_vol: float, spread_bps: float,
                 impact_coef: float = 0.5) -> float:
    """平方根律滑点（单边，bp）。
    order_shares: 本单股数; adv_shares: 该股日均成交量（股）
    daily_vol: 日波动率; spread_bps: 半价差（bp）
    """
    participation = order_shares / adv_shares          # 参与率
    impact = daily_vol * impact_coef * participation ** 0.5
    return spread_bps + impact * 1e4
```

在回测引擎里用它替代常数：

```python
cost = slippage_bps(trade_shares, adv[symbol], vol[symbol], spread[symbol])
```

立刻得到两个此前不可见的事实：

1. **小市值股票的"纸面信号"在真实单量下不可执行**——参与率 5% 的单子滑点可达数十 bp；
2. **因子收益与可执行性的分层**：某因子在小盘组收益更高，但计入行为相关成本后可能归零——这正是 06 篇"分层回测只有两端有差异"的因子要警惕的深层原因之一。

### 2.3 成本敏感性测试的正确姿势

05 篇让成本×2 再跑；进阶做法是**扫描成本曲线**：把策略年化收益画成"参与率上限"的函数——

```
参与率上限 0.1% → 年化 12.1%
参与率上限 0.5% → 年化 9.8%
参与率上限 2.0% → 年化 3.2%   ← 曲线告诉你策略的"规模-收益"边界
```

## 3. 执行算法思想：VWAP/TWAP 与拆单

大单不能一次打出去（自己制造冲击），执行算法把大单在时间上展开。两种基准算法（实现极简，思想重要）：

- **TWAP（时间加权）**：把 N 股均分为 T 个时段各执行 N/T——与市场节奏无关，适合流动性稳定时；
- **VWAP（成交量加权）**：按时段的历史成交量分布（U 型：开盘收盘量大、午间小）分配单量——与市场同行，冲击更小。

```python
def vwap_schedule(total: float, horizon: int, volume_profile: np.ndarray):
    """按历史成交量分布分配未来 horizon 个时段的下单量。"""
    w = volume_profile / volume_profile.sum()
    return total * w          # 各时段下单量
```

实盘意义对个人投资者是**反向的**：你的回测默认"收盘价成交"，而执行算法存在的意义是逼近基准价。理解执行算法，是为了给回测的"成交价假设"定一个诚实的折扣（如"收盘价 ± 半个价差"），而不是为了自己写 VWAP 引擎。

## 4. 容量分析：策略能装多少钱

**容量（capacity）= 在收益衰减到不可接受前，策略能容纳的最大资金规模。** 推导思路（平方根律的直接应用）：

```
目标：冲击成本 ≤ alpha_per_trade 的一半（成本吃掉一半 alpha 是警戒线）
σ√(Q/ADV)·k ≤ alpha/2
→ Q_max = ADV × (alpha / (2kσ))²
→ 容量 = Q_max / 目标持仓占组合比例
```

例（警戒线取"冲击 ≤ 单笔 alpha 的一半"）：单笔 alpha 50bp（0.005）、日波动 2%、k=0.5 时，√(Q/ADV) ≤ 0.0025/(0.5×0.02) = 0.25 → Q_max ≈ **ADV 的 6.25%**；若单笔 alpha 只有 10bp（更常见的低频信号量级），同样的警戒线给出 √(Q/ADV) ≤ 0.0005/0.01 = 0.05 → Q_max ≈ **ADV 的 0.25%——日均成交 5 亿元的股票单笔上限约 125 万元**。这个量级让很多"漂亮回测"直接出局。影响容量的变量：alpha 强度（越强容量越大）、调仓频率（越频繁容量越小）、 universe 宽度（可分散的股票越多容量越大）。

结论：**回测报告不含容量分析，等于没回答"这策略能不能用"**。

## 5. 交易约束的真实形态（A 股语境）

回测引擎（05/09 篇）为教学刻意简化，实盘约束必须逐项检查：

| 约束 | 规则 | 对策略的影响 |
| --- | --- | --- |
| T+1 | 当日买入次日才能卖 | 日内止损不可行；隔夜风险敞口 |
| 涨跌停 | ±10%（主板，ST ±5%；科创板/创业板 ±20%） | 涨停买不进/跌停卖不出——**跌停连板是回测里"不存在"的流动性** |
| 最小单位 | 100 股整手 | 小资金组合分散受限（07 篇） |
| 融资融券 | 标的池 + 保证金 | 杠杆约束（07 篇立场：学习期不用） |
| 申购/减持规则 | 限售、大宗交易等 | 影响特定策略的可执行性 |

**涨跌停的正确回测处理**：达到涨停的买入信号 → 放弃该笔（不可成交），跌停的卖出 → 持仓顺延——而不是假装成交在停板价上（这是"隐性前视偏差"的一种：用了你在那个价格根本买不到的成交）。

## 6. 把执行建模接回回测系统

09 篇引擎的升级点（伪代码级别）：

```python
# 成交价假设从"当日收盘"升级为
fill_price = close * (1 + side * (spread_bps/2 + impact_bps) / 1e4)
# 成交量约束
fills = min(order_shares, participation_cap * adv)
# 停板约束
if limit_up_hit(symbol, date): skip_buy()
if limit_down_hit(symbol, date): defer_sell()   # 持仓顺延，进"待处理"队列
```

并在评估报表增加一列：**理论收益（无成本）→ 纸面收益（常数成本）→ 可实现收益（执行模型）** 的三层瀑布——差距最大的那段就是你的执行研究优先级。
