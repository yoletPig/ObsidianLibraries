# 13 - 进阶：从回测到实盘工程化

> 进阶篇第 4 章（量化系列完结篇）。前 12 章都在"研究"域；本章跨过那条最贵的缝隙：**研究代码 → 每天要跑的生产系统**。内容：研究与生产的代码边界、实时数据与信号生成的工程形态、交易接入的选项与合规边界、运行监控与失效处置。保持系列立场：学习阶段模拟盘优先，真金白银三思。

## 1. 研究代码与生产代码的边界

回测 notebook 直接上岗是事故温床。两类代码的职责差异必须制度化：

| 维度 | 研究代码 | 生产代码 |
| --- | --- | --- |
| 形态 | notebook / 脚本 | 服务/定时任务，进程化 |
| 数据 | 快照缓存，可重跑 | 实时流，错了不等人 |
| 依赖 | 随意试 | 锁定（uv 系列！），版本化部署 |
| 验收 | 指标好看 | 监控、告警、幂等、可回滚 |
| 失败 | 生气重来 | 降级、跳过、留痕、告警 |

**衔接协议**（工程共识做法）：

1. 研究产出的"策略配置"（因子权重、参数、universe 规则）固化为**版本化配置文件**，生产系统只读配置不写——研究迭代 = 发新配置版本，生产代码零改动（12 篇 ADR/版本化的延续）；
2. 生产侧**不搬运 notebook 逻辑**，而是把研究代码中"信号计算"部分抽成纯函数库（输入 DataFrame → 输出目标持仓），notebook 与生产调用**同一个库**——逻辑只写一遍，是防止研究/实盘信号漂移的根本手段；
3. 每次配置升级前跑 05 篇回归评测集（Agent 13 篇的 CI 门禁同款思想）。

## 2. 生产信号系统的最小形态

个人可维护的日频策略生产系统，四件套足矣：

```
┌────────────┐   ┌────────────┐   ┌────────────┐   ┌────────────┐
│ 数据任务    │ → │ 信号任务    │ → │ 比对/审批   │ → │ 订单生成    │
│ (收盘后)    │   │ (目标持仓)  │   │ (人工网关)  │   │ (次日执行)  │
└────────────┘   └────────────┘   └────────────┘   └────────────┘
     ↑ 每步：日志 + 失败告警 + 重跑安全（幂等）
```

工程要点：

1. **调度用现成工具**（cron/Airflow/Dagster 按规模选择），自研调度器是新手常见的过度工程；
2. **每一步幂等可重跑**（Agent 12 篇同款纪律）：数据任务重复跑不产生重复行（upsert），信号任务由"日期+配置版本"唯一确定；
3. **人工网关**：信号 → 目标持仓后**停一下**，人核对（持仓数量、单票权重、换手额）再放行订单生成——学习期的必备保险，成熟后可逐步自动化但保留审批日志；
4. **对账闭环**：目标持仓 vs 实际持仓的每日对账（13 篇数据篇的 reconciliation）——差异即事故，最先发现"部分成交/漏单/数据错误"。

## 3. 交易接入：选项与合规边界

| 接入方式 | 说明 | 适用 |
| --- | --- | --- |
| 手动下单 | 看目标持仓表，人工在券商 App 执行 | 学习期首选：摩擦逼你尊重每笔成本 |
| 券商条件单/网格单 | App 内置规则单 | 简单再平衡 |
| 券商 API / QMT/PTrade 类柜台程序化接口 | 券商提供的程序化接入（有开通门槛：资金/测试要求，各家不同） | 半自动执行 |
| 自建全自动化 | 信号→下单→回报全自动 | 成熟策略 + 完善风控之后 |

**合规红线（中国内地语境）**：

1. **不得使用未授权接口**（破解版行情/下单接口属于违规接入，且有资金安全风险）；
2. 程序化交易需遵守交易所关于**程序化交易的报告要求**（沪深交易所 2023 年起发布程序化交易管理相关通知，2024-2025 年持续细化——**以交易所最新规则为准**，程序化报备要求请查询沪深交易所官方渠道）；
3. 高频/异常交易监控标准（如单账户每秒申报笔数上限等）在交易所细则中明确定义——**个人策略远够不到高频阈值，但报告义务的适用范围要自己查清**。

> 本系列一贯立场在此重申：模拟盘验证 ≥ 6 个月、三道自测（赚谁的钱/失效信号/最大回撤承受）都能书面回答之前，不接入真金白银的自动化交易。

## 4. 运行监控：策略的"体检仪表盘"

生产监控分三层（对应 Agent 14 篇三支柱的量化版）：

**① 系统层**：数据任务完成率、延迟、缺口告警——数据断供是量化生产最常见事故（某数据源改接口/停牌日缺数据），必须先于策略层告警；

**② 执行层**：
- 订单成交率、部分成交率；
- 实际成交价 vs 决策价的偏差（滑点实现值 vs 10 篇模型假设值——**模型失效的第一个信号**）；
- 目标持仓 vs 实际持仓的对账差异；

**③ 策略层**（07/11 篇仪表盘的生产版）：
- 滚动实现收益 vs 回测同期基准的偏离；
- 滚动 IC / hit rate（11 篇衰减仪表盘）；
- 实际换手 vs 模型换手（超预期换手 = 信号噪声增大或数据异常）；
- **回测-实盘偏差归因**（live vs backtest attribution）：把偏差拆成成本假设、成交假设、数据差异三桶——"赚得比回测少"必须能定位到桶，否则不知道该修哪里。

## 5. 失效处置预案（提前写好的"灭火手册"）

| 触发 | 动作 |
| --- | --- |
| 数据缺口/异常值 | 暂停当日调仓，用上一日持仓，人工核数据后补跑 |
| 滑点连续 N 日超模型 2× | 冻结调仓频率提升，复查参与率与流动性（10 篇容量） |
| 策略滚动 IC 连续 3 期 < 0 | 降权/停用该因子（11 篇预案），保留对照仓观察 |
| 组合回撤触及熔断线（如 15%） | 全组合作战会议：归因是市场 beta 还是策略 alpha 失效——**降仓动作与归因结论绑定**，避免恐慌性清仓 |
| 系统故障无法交易 | 人工接管手册：今日目标持仓表 + 手动执行清单（这就是为什么信号输出要"人能看懂"） |

预案的本质（09 篇降级阶梯的量化版）：**失效不是要不要发生的问题，而是发生时你有没有提前决定好的动作**。

## 6. 收官：全系列知识地图

```
01 认知(预期/风险) ──→ 02 数据 ──→ 03 度量(收益/风险/夏普/回撤)
      → 04 信号 → 05 回测纪律(五陷阱) ←———— 全系列的验证中枢
      → 06 因子选股 → 07 组合风控 → 08 ML的真实位置 → 09 端到端实战
      → 10 执行成本 → 11 因子工程 → 12 组合优化 → 13 实盘工程(本篇)
```

最后三句忠告（全系列立场浓缩）：

1. **流程比策略值钱**：数据校验、无前视回测、成本真实、样本外纪律——这套流程本身就是超额收益的一部分，因为它阻止你亏"自欺"的钱；
2. **对任何宣称（包括本系列）保持验证习惯**：每篇的结论都请用自己的数据复算一遍——复算本身就是最好的练习；
3. **预期管理是一生的功课**：夏普 1 的策略会有整年亏损（03 篇），纪律的意义是让亏损发生在计划内。
